L2-06 · ControlLoop 中央运行调度闭环

由 ROS timer 以 control_hz 驱动的唯一中央调度点：ControlLoop.tick() 收异步 chunk → 投推理 request → 按 cursor 直取单步 raw action → 交接 L2-04 安全 → 交 L2-05 发布或 fallback，并记录 RuntimeMetrics。tick 不等待模型推理，request/result 都是 latest-only 异步交接。不做推理、平滑、融合、RTC 对齐或硬件适配。

L2-06 是 ACT 部署程序的唯一中央调度点。被 ROS timer 以 control_hz 同步调用 ControlLoop.tick(*, monotonic_s, ros_time_s, command_permit)，不等待模型推理（worker 异步生产、result latest-only 交接）。关键事实——worker / queue / request / result / cursor / fallback / metrics / permit-gate 全部由 L2-06 自己新增并拥有；它只通过 L2-02～05 的真实公共接口协作，不做推理 / 安全算法 / topic 适配 / 硬件 SDK / action 平滑或融合。

📖 阅读路径：先懂 Pi0.5 的 timer / queue / worker 三件套结构可复用 → 看 tick 四步 → 看一次 tick 走完全流程（v2 接口）→ 看 Pi0.5 与 ACT 第一版的根本差异（worker 归属 / permit / 真实接口）→ ACT 怎么改见维度3

这一维度只回答：Pi0.5 部署代码里，负责中央调度的 ControlLoop 是怎么一步步跑起来的，以及哪些能复用、哪些与 ACT 第一版（source-aligned）冲突。关键认知——可复用的是结构（timer + latest queue + cursor 骨架 + worker 线程模型），不可照搬的是融合策略（smoothstep / blend / pending-next chunk）和接口形态（ControlCommand.accepted / publish_safe）。ACT 第一版里，worker / queue / request / result 全部归 L2-06 自有，tick 多收一个 CommandPermit，且只调 L2-04/05 的真实公共接口。

这一节用白话讲。Pi0.5 的中央调度是一个叫 ControlLoop 的对象，由 ROS timer 周期性调它的 tick()，tick 不等模型，只跟两条"最新优先队列"打配合。ACT 第一版沿用这个骨架，但把 queue/worker 搬进 L2-06，并改接真实接口。
📖 术语词典（点开随时查）
ControlLoop
（控制循环）		整个程序的"总指挥"。每来一个时钟节拍（tick），它按固定顺序收菜、下单、取货、安检、发货。本 L2 唯一中央调度点。
tick()ControlLoop 的主方法。Pi0.5：tick(now)；ACT v2：tick(*, monotonic_s, ros_time_s, command_permit)——每拍多收一个由 UI 传入的 CommandPermit 作为授权 gate。
timer
（定时器）		ROS 提供的周期闹钟，按 1/control_hz 唤醒 UI node 的 _control_tick()，后者只调 ControlLoop.tick()。ACT UI 层只吸收 timer/装配边界。
latest-only queue
（最新优先队列）		新值覆盖旧值。Pi0.5 有 request/result 两条；ACT 第一版里这两条 queue（LatestQueue[T]）和背后的 worker（InferenceWorker）都是 L2-06 新增并拥有，不属于 L2-03。
cursor
（游标）		指向当前 chunk 里"该取第几步"的计数器。Pi0.5 有复杂的 blend/pending/next 机制；ACT 第一版简化为按 cursor 直接取单步，取完递增。
chunk
（动作块）		模型一次推理产出的一串连续动作（N 步 × 16D）。Pi0.5 是 26D state/14D action；ACT 是 16D/16D（TCP+gripper），规格不搬运。
blend / smoothstep
（融合）		Pi0.5 用 smoothstep_alpha + pending/next chunk 做跨块平滑过渡。这与 ACT 第一版边界冲突，第一版不复用。
InferenceWorker
（推理工人）		后台 daemon 线程，消费最新 request → 调模型 → 写最新 result。把 GPU 等待从 tick 移走。ACT 第一版里属 L2-06（A3），串行调同步的 ActInferenceService.predict_action_chunk。
CommandPermit
（命令许可）		ACT 第一版新增：每 tick 由 UI 从注入的 CommandPermitSource 读入；禁用+allow=OBSERVED，启用+deny=BLOCKED。Pi0.5 无此概念。

Pi0.5 ControlLoop.tick 四步流程

Pi0.5 的 tick 在 ROS timer 单线程里执行，任一步失败记 metrics 不崩溃，进 fallback。ACT 第一版沿用同一四步骨架，但接口与归属已改。

1

收 result

从 result latest queue 取最新 chunk（Pi0.5 _collect_result；ACT _collect_latest_result B4，非阻塞）。latest-only：旧 chunk 被覆盖。结构复用，ACTIVE/PENDING 管理归 L2-06。
2

投 request

若到了 prefetch 点且无 pending/in-flight，取 latest observation 打包成 InferenceRequest 写 request queue（ACT _maybe_submit_inference B5/C14）。ACT 结构复用；queue/worker 由 L2-06 自有。
3

取 action

从 active chunk 按 cursor 取单步 raw action（Pi0.5 含 smoothstep/blend 融合；ACT _take_cursor_action C17，去掉 blend）。ACT 不复用融合，改为 cursor 直取独立 copy。
4

安全 + 发布 + 记账

过 SafetyGuard → 构造 ActionPublishRequest → publish → 归约 outcome（ACT B7/C18/C19）。ACT 不复用 publish_safe/emit_fallback/ControlCommand.accepted，改调 L2-04/05 真实接口并消费 6 种 outcome。

跟一次 tick 走完全流程（Pi0.5 → ACT v2 对照）

① # ActDeployNode._control_tick (B9) 被 ROS timer 唤醒（UI 层） control_loop.tick(monotonic_s, ros_time_s, command_permit) # 调 ControlLoop.tick (B3)，多收 CommandPermit ② # 收最新 result（B4，非阻塞；匹配 in-flight id 才清） result = self._collect_latest_result() # C13 校验 success/error XOR、时间、age、shape if result: self._activate_pending(result, monotonic_s) # C15 激活 pending / 查 active age ③ # 读 fresh observation（L2-02，返回 ObservationSnapshot|None） obs = self._observation_provider(max_age_s) ④ # 投推理 request（编排，C14 判定；L2-06 自有 worker/queue） if self._should_submit_inference(obs): req = InferenceRequest(observation, request_id, submitted_at_s, trigger_cursor) request_queue.put_latest(req) # LatestQueue[T]，worker(A3) 在 L2-06 消费 ⑤ # 直取单步（C17，去掉 blend；返回独立 (16,) copy） candidate = self._choose_candidate(obs, monotonic_s) # B6 normal-only；无 candidate 交 B8 ⑥ # 安全交接（L2-04 真实接口，不新编号关键词） safety = safety_guard.filter_action(candidate.action, previous_safe_action=previous, latest_observation=obs) ⑦ # 发布（L2-05 真实接口；构造 request 交 publish） request = build_action_publish_request(action_id, safety, command_permit, ros_time_s, monotonic_s) result = action_publisher.publish(request) # 返回 ActionPublishResult self._apply_publish_outcome(request, result, safety, candidate, monotonic_s) # C19 归约 6 结局

回答四个核心问题

❶ 谁持有状态？

  • ControlLoop（L2-06，A4）：active/pending chunk、cursor、in-flight、fallback、publish reducer、fault latch、start/stop。
  • LatestQueue/RuntimeMetrics/InferenceWorker 由 L2-06 runtime 自有（A1/A2/A3）。

❷ 谁跨越外部边界？

  • UI（ActDeployNode）：ROS timer + CommandPermitSource + status/metrics publish。
  • L2-05：topic / 硬件命令发布。
  • runtime 层 ControlLoop：不直接读文件/订阅 topic/写硬件。

❸ 谁只负责加工 RAM 对象？

  • validate_inference_result（C13）、should_submit_inference（C14）、build_action_publish_request（C18）纯 RAM 计算。
  • cursor 选择与递增（C15/C17）。

❹ 谁负责 runtime 时序？

ControlLoop.tick() 是 ACT 唯一中央调度点。失败传播：reason → fallback（B8）或 fault latch（C25）；任一 runtime port 异常锁存 fault，启动配置失败不进 timer。

维度差异（决定不能照搬）：Pi0.5 是 14D/26D 关节空间，带 smoothstep/blend 跨 chunk 融合。ACT 第一版是 16D TCP 空间，第一版不做融合。Pi0.5 的 smoothstep_alpha、pending/next chunk、blend 状态机、旧 BimanualAction 规格全部不继承；其 publish_safe/emit_fallback/ControlCommand.accepted 接口已被 L2-04/05 真实公共接口取代。

协作关键事实（对照图②）：
「驱动」ROS timer 唤醒 _control_tick（B9，编排函数），它读 permit/双时钟后只调 ControlLoop.tick（B3，runtime 编排函数）。

「失败传播」任一 runtime port 异常 / 无 candidate / rejected → 锁存 fault（C25）或交 B8 fallback；启动配置失败不进 timer。
「相邻 L2 复用（不新编号）」L2-02 observation、L2-04 SafetyGuard.filter_action、L2-05 ActionPublisher.publish——L2-06 只调用不实现。

A1LatestQueue[T]class 打包（runtime）无参构造、CAPACITY=1 的 thread-safe latest-only channel；承载 request/result 异步交接。L2-06 新增并拥有，不归 L2-03。
A2RuntimeMetricsclass 打包（runtime）原子累计 tick/fallback/inference error 计数、publish outcome counters、两类 fault latch、deferred reason；产出 frozen RuntimeMetricsSnapshot。
A3InferenceWorkerclass 打包（runtime）daemon 线程，串行调同步 L2-03 service，把成功/异常都转成 InferenceResult；限频、stop-event、join。不决定 safety/fallback/publish。
A4ControlLoopclass 打包（runtime）持有 active/pending/cursor/in-flight/fallback/publish reducer/fault latch；唯一中央调度 B3；不 import UI，不直接 ROS publish。
A5ActDeployNodeclass 打包（ui）ROS composition root：装配、timer、permit、metrics、shutdown；调 L2-01 loader、装配 L2-02~05 与 L2-06 runtime；不实现图像/推理/安全算法。
