# Python 代码运行的计算机基础

## 定位

| 项 | 内容 |
|---|---|
| 对象 | Python 程序运行时涉及的基础计算机概念 |
| 性质 | 用户理解 `repo`、外部资源、内部对象、进程、实例化等概念的基础材料 |
| 状态 | 草案，后续根据实践慢慢补充 |

## 总览拓扑

```text
硬盘上的 Python 文件 / 外部资源
    ↓
操作系统启动 Python 解释器
    ↓
Python 进程
    ↓
进程占用 RAM
    ↓
Python 在 RAM 中创建对象
    ↓
变量名引用对象
    ↓
函数处理对象
```

## 基础概念

| 概念 | 当前理解 |
|---|---|
| 程序文件 | 硬盘上的 `.py` 文本文件；还没有运行 |
| Python 解释器 | 负责读取和执行 Python 代码的程序 |
| 操作系统 | 负责启动程序、创建进程、分配资源 |
| 进程 | 一个正在运行的程序实例 |
| RAM / 内存 | 程序运行时临时存放数据的地方 |
| Python 对象 | 当前 Python 进程 RAM 里，由 Python 管理的数据或运行实体 |
| 变量名 | Python 代码里的名字，用来引用 RAM 里的对象 |
| class | 创建对象的模板 |
| 实例化 | 按照 class 模板，在当前 Python 进程 RAM 里创建一个对象 |

## 外部资源、读取、内部对象

| 概念 | 当前理解 |
|---|---|
| 外部资源 | 程序运行时需要使用，但不直接写在当前 Python 代码里的东西 |
| 资源 | 程序需要拿来使用的材料；可以是文件、目录、模型权重、设备、网络服务等 |
| 读取 | 通过 Python 库或操作系统接口，把外部资源带入当前进程 |
| 解析 | 把读取到的原始内容变成 Python 能理解的数据结构 |
| 校验 | 判断读取和解析后的内容是否满足程序要求 |
| 内部对象 | 外部资源被读取、解析、校验后，放入当前 Python 进程 RAM 中，并由 Python 代码直接使用的对象 |

## 外部资源到内部对象

| 外部资源 | 读取 / 解析后 | 内部对象例子 |
|---|---|---|
| `manifest.json` | 读取 JSON 文件并解析 | `dict` 或 dataclass |
| `normalizers.json` | 读取统计参数并构造对象 | normalizer 对象 |
| checkpoint 文件 | 加载模型权重 | model / policy 对象 |
| bundle 目录 | 读取目录内多个文件 | bundle metadata、policy runtime 所需对象 |
| `.yaml` 配置文件 | 读取配置值并校验 | config 对象 |

## 关键区分

| 概念 | 位置 | 程序能否直接计算 |
|---|---|---|
| 外部资源 | 进程外部，例如硬盘、设备、网络 | 不能直接当 Python 数据计算，通常要先读取 |
| 内部对象 | 当前 Python 进程 RAM 内部 | 可以被 Python 函数直接使用 |
| 变量名 | Python 代码中 | 不是对象本身，只是引用对象的名字 |

## repo 的基础理解

| 角度 | 当前理解 |
|---|---|
| 输入 | 外部资源的位置、路径、格式或加载参数 |
| 动作 | 找到资源、读取资源、解析资源、校验资源 |
| 输出 | 当前 Python 进程 RAM 里的内部对象 |
| 一句话 | `repo` 负责把“进程外部的资源”变成“当前 Python 进程 RAM 里的内部对象” |
