# 阶段二场景四：输出程序与文件

## 预期输出程序

| 程序/模块 | 功能 | 输入 | 输出 |
| --- | --- | --- | --- |
| canonical dataset 初始化器 | 创建 dataset 目录、metadata、schema 模板和空索引 | dataset 名称、配置 | `canonical_dataset_mcap/` 骨架 |
| schema 生成/校验模块 | 生成和维护五个 schema 文件 | schema 定义 | `schema/*.json` |
| episode builder | 将 aligned MCAP 转换为 episode 目录 | aligned MCAP、schema | episode 目录结构 |
| step_index 生成器 | 生成 topic 到 step 的映射索引 | 对齐结果 | `step_index.parquet` |
| action 生成器 | 基于 TCP pose 写入左右 arm-base 下的绝对目标位姿 | step_index、TCP pose | 绝对 TCP 目标 action |
| masks 生成器 | 标记每个 step 各字段的有效性 | step_index、对齐质量 | `masks.parquet` |
| report 生成器 | 生成 alignment/quality/robot_constraint report | 各检查结果 | report 文件 |
| manifest 生成器 | 记录处理过程 | 处理参数 | `processing_manifest.json` |

## 当前 Web 临时桥接产物

普通 Web 批次在正式 canonical dataset 完全落地前，使用临时 Forge bridge 与 LeRobot v3 聚合转换器完成结果展示和格式检查：

| 程序/模块 | 功能 | 输入 | 输出 |
| --- | --- | --- | --- |
| Forge bridge | 读取 aligned MCAP，拼接 32 维 observation state 与 16 维绝对 TCP `t+1 action` | aligned MCAP | `04_forge_bridge/forge_ready.mcap`、`forge_bridge_schema.json`、`forge_bridge_report.json` |
| LeRobot 聚合转换器 | 将多个成功 bridge episode 聚合为一个 LeRobot v3 dataset | 成功 bridge dir 列表 | `<用户选择父目录>/<dataset_name>/` |
| Forge inspect / quality | 检查最终 dataset 的格式和基础质量 | LeRobot v3 dataset | sidecar `reports/forge_inspect.json`、`reports/forge_quality.json` |
| Web 可视化入口 | 按需打开最终 dataset 的外部 viewer 和结果页 3D 轨迹 | 最终 dataset 路径 | 新标签页 viewer、网页评测/轨迹视图 |

临时桥接的中间 MCAP、报告和日志必须留在受控 sidecar；不得混入用户选择的最终 dataset 目录。
