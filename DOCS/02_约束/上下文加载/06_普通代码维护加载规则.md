# 普通代码维护加载规则

## 适用范围

已有代码的小修、小增强、配置调整、测试补充或非 L3 的常规代码维护。

## 触发信号

用户要求修改已有代码、调整配置、补测试、优化实现，但没有指定 L3 文件，也不是明显 debug。

## 上下文加载顺序

1. 明确任务范围和允许修改边界。
2. 读取涉及阶段的必要知识主题页。
3. 读取相关约束，例如文件存放、架构分层、Git 或测试规则。
4. 读取工程工作台中的相关资产索引或当前进度。
5. 读取代码入口并实施修改。

## 必读入口

- 涉及阶段的 `DOCS/01_知识/<阶段>/` 相关主题页
- 涉及文件落点的约束文件
- 相关代码架构说明

## 禁止默认读取

- `DOCS/98_archive/`
- `DOCS/99_learning/`
- 无关阶段工程记录

## 阻断条件

- 任务范围不明确且修改有较大风险。
- 目标文件落点违反文件存放规范。
- 用户实际要求应走 L3 执行但未提供 L3 路径。

## 输出要求

说明修改内容、验证命令和未能验证的风险。
