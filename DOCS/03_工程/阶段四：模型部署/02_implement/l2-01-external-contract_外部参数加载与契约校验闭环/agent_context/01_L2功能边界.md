## 1. 一句话运行时职责

在程序启动阶段，把整个部署程序运行依赖的外部静态参数读入当前 Python 进程 RAM，做合规性校验，形成后续所有模块可以稳定 import 的配置对象、数据规格对象和 bundle 契约对象；非法参数在入口处直接失败，阻止程序进入半初始化的运行循环。

## 2. 输入

外部静态资源（进程外文件）：

```text
deploy.yaml                  # 运行配置：runtime / safety / topics / image / bundle 路径等
manifest.json                # ACT bundle 交付清单（schema_version、model 维度、observation、artifacts）
normalizers.json             # state/action normalizer 的 min/max/identity_indices
experiment_config.yaml       # bundle 内的训练实验配置（含 model/data 维度）
checkpoint 路径              # ACT 权重文件路径（bundle 内或显式指定）
```

> [!note] 输入边界
> 这些输入全部是**进程外文件**，读取动作跨进程边界，属于 `repo/` 层职责。本 L2 不接收任何 ROS topic 输入，不接收任何运行时（稳态）数据。

## 3. 输出

进入当前 Python 进程 RAM 后的稳定对象（被下游全部 L2 import）：

```text
DeployConfig                 # 聚合根配置对象（含 runtime / safety / topics / image / bundle 子配置）
StateSpec / ActionSpec       # 16D state / 16D action 的维度、段序、字段语义、值域定义
bundle contract 检查结果     # manifest/normalizers/experiment_config/checkpoint 存在性 + 元数据一致性校验结果
normalizer contract 检查结果 # normalizer 维度与 16D 契约一致性校验结果（含 ActionStateNormalizer 对象）
runtime / safety / topic 配置对象  # 作为 DeployConfig 子对象，被对应下游 L2 直接读取
```

> [!note] 输出边界
> 这些输出全部是**进程内 RAM 对象**，不再跨进程。DeployConfig 一旦构造成功并校验通过，在程序生命周期内视为不可变。详见 `03_ACT微元设计与协作.md` 的状态归属。

## 4. 负责内容

- 固定 `observation.state` 的 **16D** 维度、段序、字段语义和值域。
- 固定 `action` 的 **16D** 维度、段序、字段语义和值域。
- 固定 `/act/*` observation、policy_action、status、metrics、command topic 名。
- 固定 runtime 参数：`control_hz`、`inference_hz`、`chunk_size`、`mode`、fallback 策略等。
- 固定 safety 参数：TCP 单步限制、quaternion 检查、gripper width 值域等（含 Pi0.5 没有但 ACT 需要新增的 TCP/quaternion 项）。
- 校验 ACT bundle 交付物是否具备后续 L2-03 加载推理所需文件与元数据（存在性 + 元数据一致性）。
- 校验 normalizer 维度与 16D 契约一致。
- 把 `deploy.yaml` 的外部值整理成类型化、校验过的配置对象树。

## 5. 不负责内容

- 不订阅 ROS topic（属 L2-02）。
- 不创建 ROS publisher（属 L2-06）。
- 不加载 ACT 权重到模型对象 / 不做模型前向推理（属 L2-03）。
- 不启动控制循环 / 不安排 tick 调度（属 L2-07）。
- 不发送硬件命令（属 L2-06）。
- 不做 runtime 安全检查（属 L2-05；本 L2 只**定义** safety 参数，不**执行** safety 检查）。
- 不存放某次运行的具体配置值（具体 `.yaml` 值放 `src/model_deploy/act/config_files/`，不放 `config/`）。

## 6. 完成判据

- **合法配置能载入 RAM**：给一份字段齐全、取值合法的 `deploy.yaml` + 合法 bundle，能成功构造 `DeployConfig`、`StateSpec`/`ActionSpec`、bundle/normalizer contract 检查结果，且维度恒为 16D。
- **非法配置在入口处失败**：缺字段、维度非 16、topic 名非法、bundle 缺文件、normalizer 维度不一致、mode/hz/chunk 参数非法等情形，在构造阶段抛出明确异常并阻止程序进入运行循环（不进入半初始化状态）。
- **下游零猜测**：后续 L2 不需要猜 state/action/topic/bundle 长什么样，全部从本 L2 产出的对象读取。

## 8. 上下游

- **上游 L2**：无。本 L2 是全部后续 L2 的静态契约地基。
- **下游 L2**：所有 L2 都 import `DeployConfig` / `StateSpec` / `ActionSpec`。
  - L2-02：import 数据规格 / 读取 topic 配置（用 state codec 和 topic config 组装 snapshot）。
  - L2-03：读取 bundle / normalizer / runtime 配置（构造 ACT runtime 和 batch）。
  - L2-05：读取 action spec / safety config（对单步 action 做安全检查）。
  - L2-06：读取 topic / hardware / bridge 配置（发布 policy_action 和 command topic）。
  - L2-07：读取 runtime 配置（构造 ControlLoop）。
- **协作接口、RAM 对象所有权、启动装配时序**：见 `02_L1_ACT功能模块协作架构.md` 第 3 节（关键 RAM 对象与所有权）、第 4 节（启动阶段协作）、第 9 节（失败传播）。

## 9. 关键设计决策（已与用户确认）

以下决策在交互检查点经用户确认，已锁定，可直接进入 L3：

1. **16D state / 16D action 段序（源自阶段二数据清洗交付说明 `DOCS/01_知识/阶段二：数据清洗/数据清洗交付说明.md`）**：
   - **16D state**（去触觉，区别于训练数据的 32D）：`left_tcp_pose(7) + right_tcp_pose(7) + left_gripper_width(1) + right_gripper_width(1)`，排列为"所有左段→所有右段"。
   - **16D action**：`left_tcp_pose_t_plus_1(7) + left_gripper_width_t_plus_1(1) + right_tcp_pose_t_plus_1(7) + right_gripper_width_t_plus_1(1)`，排列为"左pose+左夹爪→右pose+右夹爪"（与 state 排列不同）。
   - action 是绝对动作（`action_t = target at step t+1`）。TCP pose 用 xyzw quaternion、归一化；夹爪 width normalized [0,1]。左右手分属 `left_arm_base`/`right_arm_base` 独立坐标系。
   - 详见 `types/README.md` 的 16D 维度契约表。
2. **`DeployConfig` 形态**：采用 frozen dataclass + `__post_init__` 校验 + `from_mapping` 构造，拆 `BundleConfig`/`RuntimeConfig`/`SafetyConfig`/`TopicsConfig`/`ImageConfig` 5 子配置，去掉 Pi0.5 的 `bridge`/`mux`。
3. **读取/校验分离**：`repo/` 只做"路径→RAM 对象"（含存在性检查），不做业务校验；业务校验归 `config/`。
4. **bundle contract 补强**：交叉校验 `manifest.json` model 维度、`experiment_config.yaml` model/data 维度、`RuntimeConfig` 维度三处一致（Pi0.5 只做存在性，ACT 补元数据一致性）。
5. **contract 失败策略**：配置非法→抛错阻止启动；bundle/normalizer contract 非法→默认阻止启动，可选切 fake-policy + env-blocked（需 mode 允许 + 显式 `bundle.allow_fake=true`）。
6. **TCP/quaternion safety 字段**：本 L2 在 `SafetyConfig` 预留字段占位（字段名+占位），具体数值留待 L2-05（safety 执行方）细化。
7. **`load_deploy_config` 入口**：放 `config/schema.py`。
