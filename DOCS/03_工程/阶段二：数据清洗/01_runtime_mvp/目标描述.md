# Runtime MVP 目标描述

## 核心目标

Runtime MVP 是阶段二数据清洗 pipeline 的最小运行时骨架。它负责把用户选择、配置、输入检查、run 目录、日志、manifest、错误摘要和 service 调用流程串起来。

本任务不实现真实清洗算法。真实业务处理由 `02_service/` 任务线负责。

Runtime MVP 的准确目标是跑通整体流程调度能力，而不是实现整体数据清洗功能。它先让 fake pipeline 能稳定跑起来，后续再逐步接入真实 Service。

## 推荐开发流程

阶段二后续开发按以下顺序推进：

1. 准备 Codex Harness：入口索引、架构文档、开发规则、禁止事项和验收方式。
2. 定义最小数据产物契约：先用文档明确 raw、cleaned、validated、aligned、canonical 和 exports 的职责边界。
3. 开发最小支撑层：最小 Types、Config、Repo，用于支撑 Runtime MVP。
4. 开发 Runtime MVP：场景选择、配置读取、输入检查、run 目录、fake service、日志、manifest、错误摘要和 fake smoke test。
5. 开发真实 Service：按五个场景逐步补真实业务逻辑，并按需扩展 Types、Config、Repo、contract test 和 smoke test。

## 目标工作流

目标完成后，用户或开发者可以通过阶段二入口选择要运行的场景或 smoke test。未来入口方向是：

```bash
./start_data_clean.sh --dev
```

Runtime 负责：

- 读取配置。
- 检查输入路径和必需参数。
- 创建独立 run 目录。
- 调用 fake service 或后续真实 service。
- 写出 run log。
- 写出 processing manifest。
- 在失败时写出 error summary。

## 成功标准

- 能用 fake service 跑通最小 pipeline。
- 每次运行都有独立 run 目录。
- 成功和失败都能留下可追溯日志。
- Runtime 不包含场景业务算法。
- 后续五个 service 场景可以接入同一 Runtime 骨架。
- Runtime、Service、Types、Config、Repo 的边界清楚，依赖方向不反转。
