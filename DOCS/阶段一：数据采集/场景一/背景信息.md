# 场景一背景信息：Baton Mini 双相机接入方案

## 0. 当前阶段结论

本阶段已经完成两台 Baton Mini 的多设备接入基础配置。

当前最终配置如下：

| 设备 | 用途方向 | 设备 IP | 网关 | namespace / topic 前缀 |
| --- | --- | --- | --- | --- |
| Baton Mini 1 | right | `192.168.1.10` | 默认不变 | `baton_mini_right` |
| Baton Mini 2 | left | `192.168.2.10` | `192.168.2.1` | `baton_mini_left` |

说明：

- 第一台相机 IP 保持默认：`192.168.1.10`。
- 第一台只修改 namespace，用于区分右侧相机。
- 第二台相机修改了 IP 和网关：IP 为 `192.168.2.10`，网关为 `192.168.2.1`。
- 第二台 namespace 设置为 `baton_mini_left`。
- ROS namespace / topic 名不建议带空格；如果客户端里写成 `baton_mini right`，应改为 `baton_mini_right`。

## 1. 项目背景

当前项目目标是复现或改造 FASTUMI 数据采集流程，需要同时接入两台 Baton Mini 相机，用于采集机器人学习数据。

本阶段重点不是训练模型，而是先解决：

```text
两台 Baton Mini 如何同时接入 Ubuntu 上位机；
两台设备的数据如何在 ROS2 中被清楚地区分；
后续如何被 Octopus / MCAP / FASTUMI 数据处理流程接收。
```

本场景属于“逐个启动 4 个相机节点”的前置背景之一。两台 Baton Mini 的接入和命名确认后，才能继续验证：

```text
BatonMini right 节点是否可独立启动；
BatonMini left 节点是否可独立启动；
Octopus 是否能看到两组不冲突的 BatonMini topic；
Octopus 是否能把对应 topic 录制进 MCAP。
```

## 2. 官方文档中的核心信息

### 2.1 Baton Mini 可以自己在设备内部发布 ROS2 topic

官方 ROS2 多机通信文档说明：Baton Mini 设备内部已经安装操作系统，并配置好了 ROS2 Humble 环境；设备上电后会自动运行程序读取传感器数据，并打包成 ROS2 topic 发布出来。

也就是说，存在一种路线：

```text
Baton Mini 内部 ROS2 程序
    ↓
设备自己发布 topic
    ↓
Ubuntu 上位机直接订阅 / 接收 topic
```

这种方式要求：

```text
Ubuntu 上位机也有 ROS2 环境；
设备和电脑处于可通信网络中；
ROS_DOMAIN_ID 一致。
```

官方文档说明 ROS_DOMAIN_ID 默认值是 `0`。如果上位机没有额外配置过，一般保持默认即可。

### 2.2 多设备同时接入时，必须避免 IP 冲突

Baton Mini 出厂默认 IP 都是：

```text
192.168.1.10
```

如果多个设备同时接入主机，会发生 IP 地址冲突，所以需要把不同设备改成不同 IP。官方示例中，第二台设备设置为：

```text
IP 地址：192.168.2.10
网关地址：192.168.2.1
```

这正是本项目当前采用的配置。

### 2.3 多设备同时接入时，必须修改 topic 前缀 / namespace

设备 ROS2 发出的话题前缀默认是：

```text
/baton_mini/
```

多台设备同时接入时，需要设置各自的前缀，用来区分不同设备的话题。官方示例使用：

```text
baton_mini1
baton_mini2
```

本项目根据左右相机语义改成：

```text
baton_mini_right
baton_mini_left
```

这样比 `baton_mini1` / `baton_mini2` 更直观，后续 FASTUMI 数据处理时也更容易理解。

### 2.4 设备 IP 固定，上位机 IP 可能变化

官方多设备文档说明：设备接入电脑时会生成一个模拟网卡，并通过 DHCP 给电脑分配 IP。设备 IP 是固定的，但电脑 IP 是随机分配的。

这意味着：

```text
相机 IP：
固定，例如 192.168.2.10

Ubuntu 上 USB 网卡 IP：
可能每次不同，例如 192.168.2.12、192.168.2.15
```

所以后续写 launch 或启动命令时要注意：

```text
server_ip = 相机 IP，固定
local_ip  = Ubuntu 上对应 USB 网卡 IP，需要用 ifconfig / ip addr 查看
```

## 3. 两种技术路线判断

### 3.1 路线 A：相机内部直接发布 ROS2 topic

逻辑：

```text
Baton Mini 内部 ROS2 节点
    ↓
发布 topic
    ↓
Ubuntu 上位机直接接收
```

优点：

- 少运行一层上位机 SDK 节点。
- 如果 ROS2 多机通信配置顺利，直接 `ros2 topic list` 就能看到设备 topic。

缺点：

- 依赖设备内部 ROS2 环境。
- 多设备时需要处理 ROS2 多机通信、网卡、DDS、namespace 等问题。
- 如果 topic 不稳定，排查链路相对分散。

### 3.2 路线 B：Ubuntu 上位机运行 SDK Demo，再由上位机发布 topic

逻辑：

```text
Baton Mini 硬件
    ↓
USB / TCP / SDK 数据流
    ↓
Ubuntu 上位机运行 baton_mini_sdk_demo
    ↓
SDK 节点重新发布 ROS2 topic
    ↓
Octopus / MCAP / FASTUMI 数据处理流程接收
```

官方 USB Demo 文档说明：ROS 模式下，代码放入 ROS 工作空间后编译；编译出的程序通过 USB 的 TCP 接收图像和 IMU 数据，通过接口函数控制设备算法并接收位姿结果，最后再通过 ROS 话题重新发布出去。

优点：

- 更适合 FASTUMI 数据采集工程化。
- 两台相机的节点、参数、topic 名可以在上位机 launch 文件中统一管理。
- 后续更容易接入 Octopus、MCAP、数据同步和调试日志。
- 符合“上位机统一调度多传感器”的工程习惯。

缺点：

- 需要在 Ubuntu 上编译和运行 SDK Demo。
- 每台相机都需要配置对应的 `server_ip` 和 `local_ip`。
- 两台相机要同时跑两个节点实例，topic 名必须避免重复。

## 4. 本项目选择的路线

本项目选择：

```text
路线 B：Ubuntu 上位机运行 SDK Demo，并由上位机发布 ROS2 topic
```

核心理由：

```text
FASTUMI 最终需要在上位机中统一录制、同步和处理数据；
两台 Baton Mini 只是数据源；
ROS2 topic 应该在上位机侧统一命名、统一管理、统一录制。
```

因此后续结构应为：

```text
Baton Mini Right
    ↓
Ubuntu SDK 节点 right
    ↓
/baton_mini_right/imu
/baton_mini_right/odometry
/baton_mini_right/fast_odom
/baton_mini_right/image_left
/baton_mini_right/image_right

Baton Mini Left
    ↓
Ubuntu SDK 节点 left
    ↓
/baton_mini_left/imu
/baton_mini_left/odometry
/baton_mini_left/fast_odom
/baton_mini_left/image_left
/baton_mini_left/image_right
```

说明：用户提供的阶段总结中多处写作 `fast_odometry`。本仓库当前源码 `src/baton_mini_sdk_demo/src/io/ros_interface.cpp` 中默认参数名为 `fast_odom_topic`，默认 topic 为 `/baton_mini/fast_odom`。因此场景一文档统一采用 `fast_odom`，除非后续明确修改源码或 launch 配置。

## 5. 关键概念注释

### 5.1 上位机

本项目里的上位机就是：

```text
Ubuntu 电脑
```

它负责：

```text
运行 SDK 节点；
接收相机数据；
发布 ROS2 topic；
通过 Octopus 录制 MCAP；
为 FASTUMI 数据处理提供原始数据。
```

### 5.2 IP 地址

IP 地址可以理解为设备在网络里的地址。两台设备不能使用同一个 IP。

本项目中：

```text
右相机：192.168.1.10
左相机：192.168.2.10
```

### 5.3 网关

网关可以理解为这个网段的出口地址。

在本项目中，第二台相机设置为：

```text
IP：192.168.2.10
网关：192.168.2.1
```

### 5.4 namespace

namespace 可以理解为给一台设备的所有 topic 加统一前缀。

例如：

```text
baton_mini_left
```

最终 topic 会变成：

```text
/baton_mini_left/imu
/baton_mini_left/odometry
```

作用是区分左右两台相机的数据来源。

### 5.5 ROS_DOMAIN_ID

ROS_DOMAIN_ID 可以理解为 ROS2 通信房间号。只有在同一个“房间号”里的 ROS2 节点才能互相发现。

官方文档说明默认值为：

```text
0
```

当前阶段建议先不改，保持默认。

## 7. 后续网络验证流程

### 7.1 只接右相机验证

右相机配置：

```text
IP：192.168.1.10
namespace：baton_mini_right
```

Ubuntu 上执行：

```bash
ifconfig
```

或：

```bash
ip addr
```

然后测试：

```bash
ping 192.168.1.10
```

能 ping 通，说明右相机网络正常。

### 7.2 只接左相机验证

左相机配置：

```text
IP：192.168.2.10
namespace：baton_mini_left
```

Ubuntu 上执行：

```bash
ifconfig
```

或：

```bash
ip addr
```

应该看到某个 USB 网卡获得：

```text
192.168.2.x
```

然后测试：

```bash
ping 192.168.2.10
```

能 ping 通，说明左相机网络正常。

### 7.3 两台同时接入验证

两台同时插入 Ubuntu 后，执行：

```bash
ifconfig
```

理想状态是看到类似：

```text
usb0：192.168.1.x
usb1：192.168.2.x
```

然后分别执行：

```bash
ping 192.168.1.10
ping 192.168.2.10
```

两个都能 ping 通，说明两台设备网络层接入正常。

## 8. 后续启动 SDK 节点时需要填写的参数

### 8.1 右相机 SDK 节点

```text
server_ip = 192.168.1.10
local_ip  = Ubuntu 上 192.168.1.x 的 USB 网卡 IP

imu_topic         = /baton_mini_right/imu
odom_topic        = /baton_mini_right/odometry
fast_odom_topic   = /baton_mini_right/fast_odom
image_left_topic  = /baton_mini_right/image_left
image_right_topic = /baton_mini_right/image_right
```

### 8.2 左相机 SDK 节点

```text
server_ip = 192.168.2.10
local_ip  = Ubuntu 上 192.168.2.x 的 USB 网卡 IP

imu_topic         = /baton_mini_left/imu
odom_topic        = /baton_mini_left/odometry
fast_odom_topic   = /baton_mini_left/fast_odom
image_left_topic  = /baton_mini_left/image_left
image_right_topic = /baton_mini_left/image_right
```

其中：

```text
server_ip = 相机自己的 IP
local_ip  = Ubuntu 电脑对应 USB 网卡的 IP
```

当前代码事实：

- `src/baton_mini_sdk_demo/src/io/ros_interface.cpp` 支持读取 `imu_topic`、`odom_topic`、`fast_odom_topic`、`image_left_topic`、`image_right_topic` 参数。
- `src/baton_mini_sdk_demo/launch/baton_mini.launch.py` 当前只声明并传入 `server_ip` 与 `local_ip`。
- 如果要从 launch 文件直接启动 right/left 两个实例，后续需要补充节点名、topic 参数或 remap/namespace 配置。
