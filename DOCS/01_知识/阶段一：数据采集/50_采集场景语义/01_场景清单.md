# 采集场景清单

本页描述阶段一五个采集场景的语义定位和递进关系。场景的命令、进度、执行记录属于工程区，本页只保留语义层面的稳定知识。

## 定位

本页回答：阶段一验证过哪些传感器组合？每个场景验证什么？

本页不包含具体命令、当前进度或执行记录——这些归工程区 `DOCS/03_工程/阶段一：数据采集/`。

## 五个场景

| 场景 | 语义定位 | 验证的传感器组合 |
|---|---|---|
| 场景一 | 单节点链路验证 | 逐个启动相机节点，验证单节点能否独立启动、稳定发布 topic、被 Octopus 订阅并录制成 MCAP |
| 场景二 | 一键启动验证 | 用一个脚本调用 ROS2 launch，一键启动全部相机节点（2 Baton Mini + 2 GoPro） |
| 场景三 | Octopus 全链路录制验证 | Octopus 订阅 8 个目标 topic，GUI 实时看 8 路状态并导出总 MCAP 文件 |
| 场景四 | UI 可视化布局验证 | Octopus UI 改造，展示左/右手 GoPro 视频、位姿、触觉的可视化布局 |
| 场景五 | 硬件身份稳定映射验证 | 传感器序列号与固定 topic 稳定绑定，无论插拔顺序/USB 枚举如何变化都稳定发布 |

## 递进关系

```text
场景一（单节点能起来）
  → 场景二（多节点一键起来）
    → 场景三（Octopus 订阅 8 路并录成 MCAP）
      → 场景四（UI 可视化布局贴合采集任务）
        → 场景五（硬件身份兜底，保证可重复）
```

- **场景一 → 场景二**：从逐个单节点启动到脚本一键启动全部相机。
- **场景二 → 场景三**：从相机节点齐备到 Octopus 订阅 8 路 topic（相机+触觉+位姿）并完整录制。
- **场景四**：UI 层改造，让 Octopus 显示贴合 FASTUMI 采集任务的 6 路可视化布局。
- **场景五**：硬件稳定性兜底，解决"插拔顺序/USB 枚举变化导致 topic 漂移"问题。
