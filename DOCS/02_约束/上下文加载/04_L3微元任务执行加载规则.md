# L3 微元任务执行加载规则

## 适用范围

用户明确要求执行、调度或验收某个 L3 微元任务文件；或给出阶段四 L2 dispatch 要求主 Agent 分配 sub-agent。

## 触发信号

- 用户给出具体 L3 文件路径并要求执行。
- 用户给出 L2 dispatch 并要求调度一组 L3。
- 用户要求验收 L3、验收卡片、L2 Gate 或阶段四执行-验收迭代。

## 上下文加载顺序

1. 读取用户指定的 L3 文件、dispatch 文件或验收卡片。
2. 校验用户指定路径、实际读取路径、文件名编号和正文 `L3 编号` 一致。
3. 如果 L3 涉及代码新增、修改、补测、bug 修复或配置调整，读取 `DOCS/02_约束/编程执行/Agent编程执行原则.md`。
4. 如果 L3 涉及架构边界、跨层依赖、公共 type / schema / provider / adapter，读取 `DOCS/02_约束/编程执行/架构边界与机械约束原则.md`。
5. 如果任务属于阶段四：模型部署，读取 `skills/stage4-l3-orchestrator/SKILL.md`。
6. 阶段四任务继续读取：
   - `DOCS/02_约束/工作流/阶段四开发工作流/阶段四模型部署程序改造工作流.md`
   - `DOCS/02_约束/工作流/阶段四开发工作流/attachments/L3微元改造任务模板.md`
   - `DOCS/02_约束/工作流/阶段四开发工作流/attachments/ACT代码树分层与产物落点约束.md`（产物落点权威，决定源码/测试/配置的唯一落点）
   - `DOCS/03_工程/阶段四：模型部署/02_l2_change_packages/01_L1_ACT功能模块边界.md`（Agent 权威模块边界）
   - `DOCS/03_工程/阶段四：模型部署/02_l2_change_packages/02_L1_ACT功能模块协作架构.md`（Agent 权威协作上下文）
   - 所属 L2 文档
   - 对应验收卡片
7. 阶段二任务继续读取阶段二任务体系中与 L3 执行相关的规则。
8. 按 L3 的允许修改范围进入代码和测试。

## 阶段四 L3 执行前防呆校验

阶段四 L3 执行 agent 在实现前必须完成以下校验；任一失败即阻断：

- L3 所属 L2 ID 必须属于新版 7 个功能闭环 L2：
  `l2-01-external-contract`、`l2-02-observation-snapshot`、`l2-03-act-inference`、`l2-04-action-smoothing`、`l2-05-safety-guard`、`l2-06-action-publisher`、`l2-07-control-loop`。
- L3 文件必须来自 `DOCS/03_工程/阶段四：模型部署/03_tasks/task/active/<new-l2>/`。
- dispatch 必须来自 `DOCS/03_工程/阶段四：模型部署/03_tasks/task/dispatch/<new-l2>.yaml`。
- 验收卡片必须来自 `DOCS/03_工程/阶段四：模型部署/03_tasks/cards/<new-l2>/`。
- 验收证据目录必须来自 `DOCS/03_工程/阶段四：模型部署/05_acceptance/<new-l2>/`。
- 必读上下文必须包含新版阶段四工作流、L1 Agent Markdown 架构文档、当前 L2 的 5 个主文档、当前 L2 六层设计文档和 ACT 代码树分层与产物落点约束。
- 允许修改路径只能落在 `src/model_deploy/act/`、当前 L2 对应工程文档、当前 L2 对应 task/card/acceptance 路径。
- 如果 L3 文件把 `ACT Contract Delta`、`AS-IS Contract -> TO-BE Contract -> Contract Delta` 或旧 L2 ID 写成任务来源，必须阻断。

## 阻断条件

- 用户没有给出具体 L3 文件、dispatch 文件或验收卡片路径。
- L3 路径、文件名编号和正文编号不一致。
- 当前分支不符合 L3 所属分支要求。
- L3 未明确允许修改范围。
- 阶段四 L3 缺少 `acceptance_card` 或 `acceptance_mode`。
- 阶段四 L3 使用旧 L2 ID：`l2-01-types`、`l2-02-config`、`l2-03-assembly`、`l2-04-publish`、`l2-05-hardware`。
- 阶段四 L3、dispatch、验收卡片或 acceptance 路径来自 legacy / archive 目录。
- 阶段四 L3 把 Pi0.5 路径写成当前修改落点，或允许修改 `src/model_deploy/pi05/` / `pi05_old/`。
- 验收 agent 试图修改源码、dispatch、卡片或 Git 状态。

## 输出要求

- 执行 agent：只更新当前 L3 文件、允许修改的代码 / 测试和 L3 明确要求的验收记录。
- 验收 agent：只输出或登记验收反馈，不改源码。
- 主 Agent：汇总执行 / 验收状态、阻断原因和下一轮建议。
