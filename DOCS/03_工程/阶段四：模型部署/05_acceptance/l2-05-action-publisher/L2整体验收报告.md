## 1. 端到端门控不变量（默认关闭的 command 发布穿透闭环）

本 L2 的核心验收不变量：**只有“显式 CLI 开启 AND CommandPermit.allowed”才允许四路 command 写入；缺省不开启时四路 command 调用数恒为 0，仅写 `policy_action` 与 `command/status`。**

由 `ui/action_publisher.py` `ActionPublisher.publish` 调用链（`action_publisher.py:602` 附近的门控编排）逐路验证：

| 入口状态 | allow_command | outcome | 四路 command 写入 | 证据 |
|---|---|---|---|---|
| CLI 未开启（`command_output_enabled=False`） | False | OBSERVED | **0**（仅 policy_action + status） | deploy_044 `TestGatingG10`（OBSERVED/cmd=0，reason=COMMAND_OUTPUT_DISABLED） |
| CLI 开启 + permit=False | False | BLOCKED | **0**（reason=permit.reason_code） | deploy_044 `TestGatingG10`（BLOCKED/cmd=0，reason=ESTOP_NOT_READY） |
| CLI 开启 + permit=True | True | PUBLISHED / PARTIAL / FAILED | 全成功=4；policy 失败=0；首路失败→停止剩余并保留真实 count | deploy_044 `TestCommandEntryG11` / `TestPartialFailureG12` |

闭环路径：`deploy_041` C1–C7（冻结契约 + CLI 默认关闭）→ `deploy_042` B1/C9–C11（safe 16D → 完整 C4）→ `deploy_043` B2/C8/C12–C14（C4 → 五消息 bundle，无 status、无 publish）→ `deploy_044` A1/B3/C15–C21（双门控写出 policy/command/status，返回真实 C6）→ `deploy_045` 集成 Gate 汇总。整条链路本地/mock 闭环无失败。

`status` 仅在最终 C6 形成后构造，JSON 中 `driver_accepted` / `hardware_reached` 恒为 `null`（不伪造 driver/硬件成功，`_last_result` 与返回 result 一致）。
