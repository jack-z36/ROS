# L2 能力模块说明：位姿转换配置生成

## 1. 能力名称

```text
位姿转换配置生成
```

## 2. 所属位置

阶段：阶段二：数据清洗
L1：service_s1
场景：场景一：提取夹爪开合以及位姿转换
模块类别：工具对接类
来源功能模块清单：`DOCS/阶段二：数据清洗/02_service/场景一/功能模块清单.md`

## 3. 一句话目标

```text
生成以单侧 UMI 初始坐标系作为 common_frame 的 FrameAlignmentConfig。
```

## 4. 核心方案

首版不再额外定义桌面 `origin_frame`。默认：

```text
common_anchor = left
common_frame = left_umi_start_frame
```

当 `common_anchor: left` 时：

```text
T_common_left_camera(t) = T_left_start_left_camera(t)
T_common_right_camera(t) = T_common_right_start * T_right_start_right_camera(t)
T_common_tcp(t) = T_common_camera(t) * T_camera_tcp
```

## 5. 现实代码入口

现有 `src/data_clean/ui/mcap_calibration_wizard.py` 已有旧 common frame 采样和 transform YAML 写回逻辑。L3 应在该入口上改造为 [[FrameAlignmentConfig]]，而不是继续扩展 `start_from_common` 旧方案。

## 6. 上游关系

- 固定底座给出 `left_start_frame` 和 `right_start_frame` 的相对外参。
- 左右 Baton Mini 在固定底座内 reset/start tracking。
- 需要左右 camera 到 TCP 的 [[TcpFromCameraExtrinsic]]。

## 7. 下游关系

- [[common frame 位姿转换]] 使用 [[FrameAlignmentConfig]]。
- [[CommonFrameCameraPose]] 和 [[CommonFrameTcpPose]] 被写入 cleaned/canonical 数据产物。
- 场景二按 TCP common pose 做位姿滤波、异常检测和 IK 前置处理。

## 8. 职责边界

本能力负责：

1. 定义 `frame_alignment.common_anchor`、`pose_streams` 和 `extrinsics`。
2. 把旧 `start_from_common` 配置生成迁移到 `common_from_*_start`。
3. 统一 `camera_from_tcp` 命名和矩阵方向。

本能力不负责：

1. 判断底座 CAD 或人工测量是否准确。
2. 执行场景二滤波、IK 或异常修复。

## 9. 最小验收标准

| 检查项 | 预期 |
|---|---|
| 左 UMI 静止在底座内 | `left_camera_pose_common` 接近单位位姿 |
| 右 UMI 静止在底座内 | `right_camera_pose_common` 接近 `common_from_right_start` |
| 左右同时静止 5 秒 | `left_tcp_pose_common`、`right_tcp_pose_common` 不明显漂移 |
| 已知方向移动 | common frame 下位置变化方向符合预期 |
| 左右 TCP 距离 | 接近底座 CAD 或人工测量距离 |

| L3 编号 | L3 任务名称 | 任务类别 | 输入 | 输出 | 主要修改范围 | 验收方式 |
|---|---|---|---|---|---|---|

## 11. 给 L3 任务生成的约束

1. 默认 `common_anchor` 必须是 `left`。
2. 不允许只改字段名来切换左右 anchor，外参方向必须重新计算。
3. raw pose 必须保留，用于排查漂移、单位、四元数顺序和跳变。
