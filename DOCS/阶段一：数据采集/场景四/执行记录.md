### 实现内容

- `OpDockWidget` 的 topic 列表现在使用可扩展高度，并按至少 8 行设置最小高度，避免 8 个目标 topic 被下方空白挤压隐藏。
- `MainWindow` 默认主界面改为 6 个 FASTUMI 面板：Left GoPro、Right GoPro、Left Pose、Right Pose、Left Tactile、Right Tactile。
- `MainWindow::subscribeTopics()` 只默认订阅场景四 8 个目标 topic，不再默认创建旧 Realsense / Inspire 显示订阅。
- GoPro 图像显示复用 `ImageDockWidget`，订阅 `/gopro_left/image_raw` 和 `/gopro_right/image_raw`，使用 `rclcpp::SensorDataQoS()`。
- 图像转换中已改为按每行实际可复制长度拷贝，避免 FFmpeg frame stride 大于 ROS image step 时越界读取。
- 新增 `OdometryDockWidget`，用于显示 `nav_msgs/msg/Odometry` 的 frame、stamp、position、orientation、linear/angular velocity 和最近 10 秒 xyz 曲线。
- 新增 `PressureDockWidget`，用于按左右手分别汇总两路 `hwk_pressure_interfaces/msg/PressureFrame`，显示 gripper_1 / gripper_2 热力图、max、avg、矩阵尺寸和更新时间。
- Octopus 构建依赖新增 `nav_msgs` 和 `hwk_pressure_interfaces`。

### 排查结论

Right GoPro UI 不显示的直接原因不是 Octopus 图像控件本身，而是 `/gopro_right/image_raw` 当时没有正常发布。

启动日志显示两个 GoPro launch 实例都串成了 left 参数：

```text
there are now at least 2 nodes with the name /gopro_left/gopro_left_camera
Buffer failure on capture start: Device or resource busy (16)
```

同时两个相机实例都尝试使用 left 侧采集卡位置：

```text
usb-0000:00:0d.0-3.4.1.4
```

硬件映射和总配置本身是正确的：

```text
gopro.right -> /dev/v4l/by-path/...3.4.1.3... -> /gopro_right/image_raw
gopro.left  -> /dev/v4l/by-path/...3.4.1.4... -> /gopro_left/image_raw
```

根因是同一个 `gopro_pose_record.launch.py` 被 `all_sensor_nodes.launch.py` include 两次；在新增 `v4l2-ctl --set-parm` 后，相机节点通过 `OnProcessExit` 延迟启动，导致 `LaunchConfiguration` 的取值时机暴露出左右 GoPro include 之间的作用域串扰。

### 修改内容

- 修改 `launch/all_sensor_nodes.launch.py`：每个 GoPro include 外层增加 `GroupAction(scoped=True, forwarding=False)`，隔离 right/left launch 参数作用域。
- 修改 `src/gopro_camera_launch/launch/gopro_pose_record.launch.py`：改用 `OpaqueFunction` 在 include 自己的上下文中立即解析所有 `LaunchConfiguration`，再把解析后的普通字符串传给 `v4l2-ctl` 和延迟启动的 `v4l2_camera_node`。
- 保留 `v4l2-ctl -d <video_device> --set-parm <frame_rate>` 先执行、相机节点后启动的顺序。
