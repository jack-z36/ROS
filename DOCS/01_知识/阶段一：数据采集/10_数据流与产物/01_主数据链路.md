# 主数据链路

本页描述阶段一从硬件传感器到 raw MCAP 的完整数据链路，以及各 ROS 包在链路中的角色。

## 定位

本页是阶段一数据流的"地图"。它回答两个问题：
1. 数据从哪来、经过哪些环节、最终到哪去？
2. `src/data_collection/` 下的 5 个 ROS 包各自承担什么职责？

本页不涉及单个传感器的消息字段细节（见 `20_传感器模态语义/`），也不涉及 Octopus 内部如何运转（见 `30_Octopus运转逻辑/`）。

## 全局链路

```text
物理传感器
  │
  ├─ GoPro(经USB采集卡) ─────────────► /gopro_{left,right}/image_raw
  ├─ Baton Mini 双目VIO相机 ────────► /baton_mini_{left,right}/{imu,odometry,fast_odom,image_left,image_right}
  └─ 华威科压力传感器(4串口) ──────► /pressure/{left,right}_hand/gripper_{1,2}
                                          │
                                          ▼
                              ┌───────────┴───────────┐
                              │     Octopus (Qt6)      │
                              │  ┌─────────────────┐   │
                              │  │  显示链路节点    │   │ ──► 实时UI面板(图像/位姿/触觉)
                              │  │   (octopus)      │   │
                              │  └─────────────────┘   │
                              │  ┌─────────────────┐   │
                              │  │  录制链路节点    │   │ ──► raw MCAP 文件
                              │  │   (recorder)     │   │
                              │  └─────────────────┘   │
                              └───────────────────────┘
```

## 五个 ROS 包的角色

| ROS 包 | 链路角色 | 发布/生产的 topic 或产物 |
|---|---|---|
| `hwk_pressure_interfaces` | 契约定义（纯接口包） | `msg/PressureFrame.msg`，不发布任何 topic |
| `hwk_pressure_driver` | 触觉数据发布者 | `/pressure/{left,right}_hand/gripper_{1,2}` |
| `gopro_camera_launch` | 图像数据发布者 | `/gopro_{left,right}/image_raw` + `/camera_info` |
| `baton_mini_sdk_demo` | 位姿与图像数据发布者 | `/baton_mini_{left,right}/{imu,odometry,fast_odom,image_left,image_right}` |
| `VTLA_octopus-master/octopus` | 数据消费者 + 唯一的 raw MCAP 生产者 | 显示 UI + raw MCAP 文件 |

关键拓扑事实：

- Octopus 是阶段一唯一的"汇聚节点"，它消费前 4 个包发布的所有 topic。
- Octopus 内部有**两个相互独立的 ROS 节点**：显示节点 `octopus`（服务实时 UI）和录制节点 `recorder`（服务 MCAP 写盘）。二者不共享订阅、不共享 executor、不共享线程。详见 `30_Octopus运转逻辑/01_双链路架构总览.md`。
- raw MCAP 是阶段一**唯一**交付给下游的产物。

## 三种传感器模态

阶段一采集三类模态的数据，每类对应一个独立的物理硬件链路：

| 模态 | 硬件 | 发布节点 | 详见 |
|---|---|---|---|
| 图像 | GoPro + USB 采集卡（v4l2 接入） | `gopro_camera_launch` | `20_传感器模态语义/01_图像模态_GoPro.md` |
| 位姿与运动 | Baton Mini 双目 VIO 相机 | `baton_mini_sdk_demo` | `20_传感器模态语义/02_位姿模态_BatonMini.md` |
| 触觉压力 | 华威科灵巧手压力传感器 | `hwk_pressure_driver` | `20_传感器模态语义/03_触觉模态_HWK.md` |

注意：相机本体可替换，但 topic 名锁定为 `/gopro_*/image_raw` 不变。详见各模态页。

## 与阶段二的衔接边界

阶段一交付 raw MCAP，阶段二在此基础上做后续处理：

```text
raw MCAP (阶段一产物)
  → cleaned MCAP   (阶段二：滤波、去噪、剔除无效帧)
  → MCAP_A         (阶段二：位姿提取、ArUco 夹爪宽度)
  → aligned MCAP   (阶段二：跨 topic 时间对齐)
  → 训练格式桥接产物 (阶段二：LeRobot dataset)
```

阶段一的边界：
- 只保证原始采集链路正确，raw MCAP 中的消息是传感器原始序列化数据。
- 不提前把阶段二的清洗、滤波、对齐或 action 语义混入采集层。
- 不承诺 topic 之间的时间同步——跨 topic 对齐是阶段二的工作（见 `03_时间戳与时钟模型.md`）。
