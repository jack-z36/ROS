# 阶段二实现路线图

## 文档目标

本路线图用于明确阶段二五个场景的交付边界，但不提前规定具体源码文件名、配置文件名或内部模块拆分方式。

它只回答三类问题：

1. 每个场景应形成哪类软件能力。
2. 这些软件能力应自动化完成什么处理。
3. 处理后应输出什么数据产物，交给哪个下游场景。

具体脚本名、模块名、配置文件名和代码目录结构，应在真正实现该场景时根据当时的代码结构决定，并记录到对应场景的 `输出程序与文件.md` 和包内架构文档中。

## 总流水线

```text
raw MCAP
  -> [场景一] 清洗、夹爪宽度提取、common frame 相机位姿转换
  -> cleaned MCAP
  -> [场景二] 滤波、异常值处理、IK 与 MuJoCo 可行性验证
  -> validated MCAP
  -> [场景三] 多 topic 统一时间轴对齐
  -> aligned MCAP + alignment_report
  -> [场景四] 构建 episode/step/action/mask/schema
  -> canonical_dataset_mcap/
  -> [场景五] 导出模型训练格式
  -> exports/
```

## 路线图粒度规则

本文件只写中粒度交付物：

| 允许写 | 不在本文件提前规定 |
| --- | --- |
| 需要一个“批处理入口” | 入口脚本必须叫什么名字 |
| 需要一组“处理模块” | 每个模块必须拆成哪些 `.py` 文件 |
| 需要“配置能力” | 配置文件必须放在哪里、叫什么 |
| 需要“报告生成能力” | 报告生成器类名、函数名、文件名 |
| 需要“数据输出契约” | 内部实现目录结构 |

例外：已经存在并被验证过的场景一资产，可以作为当前现状记录；尚未实现的场景二到场景五，只记录能力类别，不预设文件路径。

## 场景一：提取夹爪开合以及位姿转换

### 目标

从 raw MCAP 中生成 cleaned MCAP。cleaned MCAP 应补齐夹爪宽度语义，并把左右 Baton Mini raw pose 转换到 common frame 下的相机 pose。TCP pose 不在本场景强行固化，可在后续由 common-frame 相机 pose 叠加相机到 TCP 外参得到。

### 软件能力

- 批处理入口：用户可以对一批 raw MCAP 发起清洗。
- 配置加载能力：读取输入目录、输出目录、目标 topic、左右位姿转换参数和夹爪标定参数。
- 夹爪宽度提取能力：从视觉标定或图像信息中生成左右夹爪宽度语义。
- common frame 位姿转换能力：把左右 raw pose 转到统一空间表达。
- 标定能力：支持生成或更新夹爪宽度和 common frame 相关参数。
- 基础校验能力：检查输入 topic、输出文件、配置完整性和失败原因。

当前已有实现包括 `start_data_clean.sh` 和 `src/data_clean` 中的清洗、标定、MCAP IO、ROS2 编解码、位姿转换和校验能力。后续如果重构文件名或拆分模块，以最新 `输出程序与文件.md` 和包内架构文档为准。

### 自动化处理

1. 扫描 raw MCAP 输入。
2. 校验必需 topic 和配置。
3. 提取或写入夹爪宽度语义。
4. 转换左右 common frame 相机位姿。
5. 写出 cleaned MCAP。
6. 记录清洗结果、失败原因和配置来源。

### 数据输出

| 输出 | 用途 |
| --- | --- |
| cleaned MCAP | 场景二输入。 |
| 清洗报告 | 人工复查和后续问题定位。 |
| 标定结果/位姿转换参数 | 后续批量清洗复用。 |

### 完成标准

- 用户能批量处理 raw MCAP。
- cleaned MCAP 中能定位图像、触觉、夹爪宽度和左右 common frame 相机 pose。
- 清洗失败时有明确失败原因。

## 场景二：硬件数据可靠性验证

### 目标

从 cleaned MCAP 生成 validated MCAP。validated MCAP 应尽量保留真实物理运动，同时修复或标记噪声、突变、丢帧、不可执行轨迹等问题。

### 软件能力

- 批处理入口：用户可以对 cleaned MCAP 执行可靠性验证。
- 滤波能力：对位姿、触觉、夹爪宽度等序列进行平滑处理。
- 异常检测能力：发现跳变、缺失、非法值、速度/加速度异常、触觉突变等问题。
- 异常补全能力：对可修复片段进行插值、邻近补全或其他策略处理。
- 机器人约束验证能力：通过 IK、关节限制、速度/加速度限制、workspace 限制等判断轨迹是否可执行。
- 仿真验证能力：在 MuJoCo 或等价仿真环境中回放或检查轨迹。
- 报告能力：记录异常、修复、丢弃、不可执行片段和判断依据。

### 自动化处理

1. 读取 cleaned MCAP 中需要验证的序列。
2. 执行滤波和异常检测。
3. 对可修复异常进行补全，对不可修复异常保留标记。
4. 执行 IK 和机器人运动约束检查。
5. 执行仿真验证或生成仿真检查摘要。
6. 写出 validated MCAP 和验证报告。

### 数据输出

| 输出 | 用途 |
| --- | --- |
| validated MCAP | 场景三输入。 |
| 异常报告 | 说明哪些数据点或片段有问题。 |
| 修复记录 | 说明哪些数据被补全、平滑或替换。 |
| 机器人约束报告 | 场景四质量报告和 masks 的来源之一。 |
| 仿真验证摘要 | 人工复查和安全判断。 |

### 完成标准

- validated MCAP 可作为时间对齐输入。
- 每个被修改、补全、丢弃或标记的数据段都可追溯。
- 机器人不可执行片段不会静默流入后续训练数据。

## 场景三：MCAP 多 topic 时间轴对齐

### 目标

从 validated MCAP 生成 aligned MCAP，并让图像、位姿、触觉、夹爪宽度等 topic 统一到同一条 step 时间轴。

### 软件能力

- 批处理入口：用户可以对 validated MCAP 执行时间对齐。
- 统一时间轴生成能力：根据目标频率和起止策略生成 step 时间戳。
- topic 对齐能力：为每个 step 找到各字段的最近邻、插值结果或聚合结果。
- 位姿插值能力：处理位置和四元数插值，避免错误的姿态插值方式。
- 高频数据聚合能力：对触觉等高频数据做窗口聚合或降采样。
- 缺失和超时标记能力：标记无法可靠对齐的字段或 step。
- 对齐报告能力：统计频率、误差、缺失率、插值比例和丢弃情况。

### 自动化处理

1. 读取 validated MCAP 的目标 topic 时间戳。
2. 生成统一 step 时间轴。
3. 对齐每个 step 的图像、位姿、触觉和夹爪字段。
4. 记录每个字段的来源、对齐方式和时间误差。
5. 标记缺失、复用、插值、超时和丢弃情况。
6. 写出 aligned MCAP 和 alignment report。

### 数据输出

| 输出 | 用途 |
| --- | --- |
| aligned MCAP | 场景四输入。 |
| alignment report | 场景四 masks、quality report 和人工验收依据。 |
| 对齐索引中间产物（可选） | 可辅助生成 `step_index.parquet`，但不是必须固定格式。 |

### 完成标准

- 每个 step 都有统一时间戳。
- 每个 observation 字段都能追溯来源或明确标记无效。
- 对齐质量有机器可读报告。

## 场景四：构建标准 canonical dataset

### 目标

从 aligned MCAP 构建 `canonical_dataset_mcap/`。这是阶段二的核心中间数据契约，后续导出器应只依赖它，而不回头读取 raw、cleaned、validated 或 aligned 中间过程。

### 软件能力

- dataset 构建入口：用户可以从一批 aligned MCAP 构建 canonical dataset。
- schema 生成能力：定义 observation、action、frame、topic、quality 等全局契约。
- episode 构建能力：把每次示教组织成 episode 目录和 episode 元信息。
- step index 生成能力：把 topic 世界映射到 step 世界。
- action chunk 生成能力：生成 UMI 风格 relative trajectory action。
- mask 生成能力：标记字段级和 step 级可用性，并记录 invalid reason。
- 报告汇总能力：汇总对齐质量、数据质量和机器人约束结果。
- manifest 能力：记录输入、参数、处理过程和可追溯信息。
- dataset 校验能力：检查 schema、index、episode、masks、reports 是否一致。

### 自动化处理

1. 初始化 canonical dataset 结构。
2. 生成 dataset 级元信息和 schema。
3. 为每个 aligned MCAP 创建 episode。
4. 写入或引用 episode 数据本体。
5. 生成 step index。
6. 生成 action chunk。
7. 生成 masks 和 invalid reason。
8. 汇总 alignment、quality、robot constraint 等报告。
9. 生成 processing manifest。
10. 生成 dataset index。
11. 执行 dataset 完整性校验。

### 数据输出

```text
canonical_dataset_mcap/
├── dataset_meta.json
├── dataset_index.parquet
├── schema/
├── episodes/
│   └── episode_xxxxxx/
│       ├── episode_meta.json
│       ├── data.mcap
│       ├── step_index.parquet
│       ├── masks.parquet
│       ├── alignment_report.json
│       ├── quality_report.json
│       ├── robot_constraint_report.json
│       └── processing_manifest.json
└── exports/
```

### 完成标准

- schema 能解释所有 episode。
- dataset index 登记的路径真实存在。
- step index 能定位数据本体或派生字段。
- action chunk 是相对于同一个当前起点的未来轨迹，不是逐步 delta。
- masks 包含 invalid reason。
- 删除 `exports/` 后仍可从 canonical dataset 重新导出训练格式。

## 场景五：模型训练格式导出器

### 目标

从 canonical dataset 导出目标模型训练格式。该场景只做格式适配，不回头修复上游数据。

### 软件能力

- 导出入口：用户可以选择目标训练格式并发起导出。
- canonical dataset 读取能力：读取 schema、dataset index、episode、step index 和 masks。
- 样本过滤能力：根据 masks 排除不可训练 step。
- 格式适配能力：把 canonical observation/action 映射为目标训练框架需要的字段、shape、dtype 和目录结构。
- 多格式扩展能力：支持在确定模型后增加新的导出格式。
- 导出校验能力：确认导出数据能被目标训练代码或最小读取脚本加载。
- 导出报告能力：记录样本数量、过滤数量、字段映射和失败原因。

### 自动化处理

1. 读取 canonical dataset。
2. 按 masks 过滤不可训练 step。
3. 定位 observation 和 action。
4. 转换为目标格式。
5. 写出训练数据。
6. 生成导出报告。
7. 执行导出校验。

### 数据输出

| 输出 | 用途 |
| --- | --- |
| 目标训练格式数据 | 阶段三模型训练输入。 |
| 导出报告 | 记录导出统计、字段映射和过滤原因。 |
| 导出校验结果 | 证明训练程序或读取脚本可以加载数据。 |

### 完成标准

- exporter 只依赖 canonical dataset。
- 不可训练 step 不进入训练集。
- 导出结果可被目标训练流程读取。

## 推荐实施拆分

### 第一批：先冻结数据契约，不冻结代码结构

1. 完成场景一剩余标定/位姿转换能力。
2. 明确 cleaned MCAP 中必须保留哪些语义字段。
3. 草拟 validated MCAP、aligned MCAP、canonical dataset 的数据契约。
4. 草拟关键报告字段：异常报告、机器人约束报告、alignment report、masks。

### 第二批：实现可靠性验证和时间对齐

1. 实现场景二的可靠性验证闭环。
2. 用一个 cleaned MCAP 跑出 validated MCAP 和报告。
3. 实现场景三的时间对齐闭环。
4. 用一个 validated MCAP 跑出 aligned MCAP 和 alignment report。

### 第三批：构建 canonical dataset

1. 实现场景四 dataset 构建闭环。
2. 先支持单 episode，再扩展到多 episode。
3. 先跑通 schema、step index、masks、reports，再优化 action 和质量评分。
4. 用一个 aligned MCAP 生成完整 canonical dataset。

### 第四批：模型格式明确后再做导出

1. 选定第一版目标训练格式。
2. 实现场景五最小 exporter。
3. 用 canonical dataset 导出最小训练集。
4. 用训练读取脚本验证导出结果。

## 场景间依赖

| 下游场景 | 依赖的上游产物 |
| --- | --- |
| 场景二 | cleaned MCAP、夹爪宽度、common frame 相机 pose。 |
| 场景三 | validated MCAP、异常和机器人约束报告。 |
| 场景四 | aligned MCAP、alignment report、上游质量/约束报告。 |
| 场景五 | canonical dataset、目标训练格式说明。 |

## 边界说明

- 场景一补齐基础语义，不负责滤波、IK 或时间对齐。
- 场景二负责可靠性和物理可行性，不负责统一 step 时间轴。
- 场景三负责时间对齐，不负责 canonical dataset schema。
- 场景四负责 canonical dataset，不负责导出具体训练格式。
- 场景五负责训练格式导出，不负责修复上游数据。
