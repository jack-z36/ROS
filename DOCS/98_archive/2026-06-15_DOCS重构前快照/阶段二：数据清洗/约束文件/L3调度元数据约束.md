# L3 调度元数据约束

本文约束阶段二 L3 微元任务的调度元数据。目标是让主 Agent 能读取一个功能组任务池，判断哪些 L3 可并行执行、哪些必须串行等待，并把单个 L3 安全分发给 sub-agent。

## 1. 适用范围

本约束适用于后续新生成的 L3 微元任务和功能组调度索引。

默认不批量改写已经存在的 active L3。已有任务只有在重新生成、重排或用户明确要求时，才补充本约束中的调度字段。

## 2. L3 文件内调度元数据

每个新生成的 L3 文件必须在“任务定位”之后包含 `dispatch` YAML 块：

```yaml
dispatch:
  task_id: service_s1_002
  task_file: DOCS/阶段二：数据清洗/03_tasks/task/active/service-s1-g2/service_s1_002_xxx.md
  group: service-s1-g2
  branch: service-s1
  wave: 1
  parallel_group: service-s1-g2-p1
  depends_on: []
  must_run_after: []
  can_run_parallel_with: []
  blocks: []
  conflict_scope:
    files: []
    modules: []
    config_keys: []
  dispatch_status: ready
```

字段含义：

| 字段 | 含义 |
|---|---|
| `task_id` | 当前 L3 编号，必须与正文 `L3 编号` 一致。 |
| `task_file` | 当前 L3 文件相对仓库根目录路径，必须与正文 `当前任务文件路径` 一致。 |
| `group` | 当前功能组目录，例如 `runtime-g1` 或 `service-s1-g2`。 |
| `branch` | 当前 L3 应执行的 Runtime 分支或 Service 场景分支。 |
| `wave` | 推荐执行波次，数字越小越先执行。 |
| `parallel_group` | 主 Agent 可优先并行分发的一组任务标识。 |
| `depends_on` | 硬依赖 L3 编号；依赖未完成并归档前，不得执行当前 L3。 |
| `must_run_after` | 顺序约束；用于表达非接口硬依赖但必须后置的任务。 |
| `can_run_parallel_with` | 明确允许并行的 L3 编号；为空时由 `parallel_group` 与 `conflict_scope` 判断。 |
| `blocks` | 当前 L3 完成后会解锁的后续 L3 编号。 |
| `conflict_scope.files` | 当前 L3 可能修改的文件路径。 |
| `conflict_scope.modules` | 当前 L3 可能修改的模块或包名。 |
| `conflict_scope.config_keys` | 当前 L3 可能修改的配置键。 |
| `dispatch_status` | 调度状态，只允许 `ready`、`blocked`、`waiting_user`。 |

所有仓库内路径必须使用相对仓库根目录路径，不得写 Windows 盘符路径、Linux 绝对路径或本机工作区路径。

## 3. 并行与串行规则

主 Agent 分发 L3 时必须遵守：

1. `depends_on` 是硬依赖。依赖任务未移动到 `task/completed/<L1归档目录>/<功能组>/` 前，当前任务不可执行。
2. `dispatch_status=blocked` 或 `dispatch_status=waiting_user` 的任务不可分发。
3. 同一 `parallel_group` 的任务可以并行，但仍必须检查 `conflict_scope`。
4. 两个任务如果 `conflict_scope.files`、`conflict_scope.modules` 或 `conflict_scope.config_keys` 有交集，不得并行分发。
5. `wave` 小的任务优先。高 wave 任务只有在低 wave 硬依赖完成后才可进入候选集合。
6. 不跨功能组自动混派，除非用户明确要求。

## 4. 功能组调度索引

从同一个 L2 功能模块生成一组 L3 时，必须同步生成或更新功能组调度索引：

```text
DOCS/阶段二：数据清洗/03_tasks/task/dispatch/<功能组>.yaml
```

索引结构固定为：

```yaml
dispatch_index:
  group: service-s1-g2
  branch: service-s1
  source_l2: DOCS/阶段二：数据清洗/02_service/场景一/L2能力模块/夹爪开合配置生成.md
  max_parallel_agents: 3
  waves:
    - wave: 1
      parallel_group: service-s1-g2-p1
      tasks: [service_s1_002, service_s1_003]
    - wave: 2
      parallel_group: service-s1-g2-p2
      depends_on: [service_s1_002, service_s1_003]
      tasks: [service_s1_004]
  tasks:
    service_s1_002:
      file: DOCS/阶段二：数据清洗/03_tasks/task/active/service-s1-g2/service_s1_002_xxx.md
      title: xxx
      depends_on: []
      conflict_scope:
        files: []
        modules: []
        config_keys: []
```

`task/dispatch/` 是调度索引目录，不属于 `task/active/<功能组>/`，也不随单个 L3 归档移动。

## 5. 主 Agent 与 sub-agent 边界

主 Agent 可以读取并维护 `task/dispatch/<功能组>.yaml`，用于调度、收敛和重新计算下一批任务。

sub-agent 只执行被分配的单个 L3 文件：

- 不得自行挑选同目录其他 L3。
- 不得修改 `task/dispatch/<功能组>.yaml`。
- 不得写 `DOCS/总执行日志.md`、阶段二 `执行记录/`、`当前进度.md` 或共享 `执行记录.md`。
- 完成后仍按当前 L3 文件要求勾选成功标准、追加执行摘要并归档。

## 6. 默认必读位置

后续新生成 L3 的“必读约束文档”必须包含本文：

```text
DOCS/阶段二：数据清洗/约束文件/L3调度元数据约束.md
```
