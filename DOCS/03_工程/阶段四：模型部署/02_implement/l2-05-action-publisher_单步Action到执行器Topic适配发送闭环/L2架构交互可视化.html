阅读路径：先看唯一出口定位 → 单次调用 → 边界墙 → 输入/输出契约。

维度 2 · Pi0.5 如何运作

阅读路径：先懂三个旧 node → 跟一次旧命令 → 看目录证据 → 看哪些只能参考。

Pi0.5 没有独立 publisher：旧职责分散在 deploy node、bridge、mux。它证明需要窄输出对象，也反向证明不能照搬 14D joint、串行订阅和 shadow command。

白话：旧程序像三道转运站——第一站发四个包裹，第二站拆包转发，第三站看 deadman/模式再选路。新 L2-05 取消中间订阅站，L2-06 先给最终通行证，L2-05 从 RAM 一次构造输出。
术语小词典
词这里是什么意思
Pi05VlaDeployNode旧“大而全”节点：观测、推理、ControlLoop 和 publisher 混在一起。
Bridge订阅旧 command，再转换/转发；新边界明确不需要。
Mux监听 teleop/VLA/deadman/enable 后仲裁；这些事实由 L2-06 汇总为最终授权。
本地原子性四路都构造成功才开始 publish；不是 ROS 事务，也不保证同时执行。

维度 3 · 开发蓝图

阅读路径：先看创建/调用关系 → 再点六层 → 最后核对 class 内的 3.5 层微元。

四层有产物：types 说数据、config 固定输出映射、service 做纯 RAM 计划、ui 做唯一 ROS 副作用。repo/runtime 明确无产物。

装配与单 tick 协作

types/action_publish.py

frozen request、authorization、targets、plan、result；不含 ROS message。

PublishAuthorization / ActionPublishRequest / ActionPublishResult

数据mode、最终 allowed、action_id、两个时间、逐通道事实。
不变量mode 合法、时间 finite、sent 与 failure 不矛盾。

config/schema.py + deploy.yaml

CommandOutputConfig：左右 frame、输入 0..1、输出 0..100、deadband、最小间隔、QoS。

CommandOutputConfig

数据启动期只读配置。
计算范围、frame、非负 interval/deadband 校验。

本 L2 不在该层新增源码产物

原因：所有输入已在 RAM；ROS publish 属 ui。上游对象：DeployConfig。验收：无 repo diff、无文件/网络/硬件读取。

service/action_output_adapter.py

无状态函数：safe 来源复核、16D 拆分、gripper 映射、四路 targets、mode plan。

纯函数集合（不创建无状态 class）

计算函数require_safe_action / map_gripper_command / build_command_targets / build_publish_plan。
副作用无；任一失败不返回部分 bundle。

本 L2 不在该层新增源码产物

原因：tick、time、auth、fallback、retry、metrics 属 L2-06。上游对象：ActionPublishRequest。验收：0 timer/thread/queue。

ui/action_publisher.py

唯一有状态 class：六 publisher + gripper 防刷 cache + last result；同步 publish，无 subscription/timer。

ActionPublisher

数据publisher handles、last gripper target/time、last result。
计算函数message builders、deadband、status JSON。
状态更新仅成功 gripper publish 后更新对应 cache。
数据读写最多六个 ROS publish。
编排函数publish(request) 执行构造→门控→写出→status→result。
集成护栏：当前 L2-04 设计若把夹爪 safe action 当 0..100，本 L2 必须拒绝 50/100 输入，不能做双尺度兼容。当前旧 mode property 也不能用于 shadow command。
