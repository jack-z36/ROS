# 非具体编程规划加载规则

## 适用范围

输出 Markdown、架构梳理、数据定义、功能定义、L2/L3 规划、从零编写程序的蓝图阶段。不直接改代码。

## 触发信号

用户要求生成或讨论文档、架构、数据定义、功能模块、L2/L3、微元任务、开发蓝图。

## 上下文加载顺序

1. 读取相关阶段知识主题页，先建立语义上下文。
2. 读取对应约束：文档体系、工作流、阶段二任务体系等。
3. 读取对应工程工作台中的现有进度。
4. 只在准备产出正式文档时读取模板文件。

## 阶段四 L2 功能设计专门分支

当用户要求完善、设计、拆分或审查阶段四模型部署 L2 功能模块时，必须进入本分支。这里的 L2 指新版 ACT 7 个运行时功能闭环，不是旧 `types / config / assembly / publish / hardware` layer-based L2。

必须读取：

1. `DOCS/02_约束/工作流/阶段四开发工作流/阶段四模型部署程序改造工作流.md`
2. `DOCS/02_约束/工作流/阶段四开发工作流/attachments/ACT代码树分层与产物落点约束.md`
3. `DOCS/02_约束/认知偏好/用户认知框架与讲解偏好.md`
4. `DOCS/03_工程/阶段四：模型部署/02_l2_change_packages/00_L1_ACT部署程序任务文档.md`
5. `DOCS/03_工程/阶段四：模型部署/02_l2_change_packages/01_L1_ACT功能模块边界.md`
6. `DOCS/03_工程/阶段四：模型部署/02_l2_change_packages/02_L1_ACT功能模块协作架构.md`
7. `skills/stage4-l2-designer/SKILL.md`

阶段四 L2 功能设计禁止默认读取：

- 阶段二 L2 模板、阶段二任务体系或阶段二开发范式。
- `DOCS/02_约束/工作流/原工作流/` 下模板。
- `DOCS/03_工程/阶段四：模型部署/02_l2_change_packages/_legacy_layer_based_act/`。
- `DOCS/03_工程/阶段四：模型部署/03_tasks/_legacy_layer_based_act/`。
- `DOCS/03_工程/阶段四：模型部署/03_tasks/_archived_pi05/`。
- `DOCS/03_工程/阶段四：模型部署/01_contracts/*Contract Delta*` 作为 L2 拆解权威。

阶段四 L2 功能设计只能在需要补充 topic、shape、bundle 或硬件语义时按需读取 `01_contracts/`，且必须说明引用目的。Pi0.5 源码只能作为结构参考和微元拆解对象，不得覆盖当前 L1/L2 责任边界。

## 阻断条件

- 无法判断目标语义应归知识、约束还是工程。
- 目标文档落点不符合文档分类规范。
- 阶段二 L2/L3 规划未读取阶段二任务体系约束。
- 阶段四 L2 功能设计无法确认目标 L2 属于新版 7 个功能闭环 L2。
- 阶段四 L2 功能设计把旧 L2 ID、legacy 目录、Contract Delta 或阶段二模板作为当前任务权威。
