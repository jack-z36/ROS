# 场景二执行约束：一键启动全部相机 ROS 节点

## 1. 启动入口约束

- 用户入口固定为工作区根目录脚本：`start_all_sensor.sh`。
- `.sh` 脚本只负责 source ROS 环境、检查必要文件、调用总 launch，不在脚本里硬编码 topic 名称。
- 总 launch 文件固定为：`launch/all_sensor_nodes.launch.py`。
- 可变设备信息集中维护在：`config/all_sensor_nodes.yaml`。

## 2. 命名与解耦约束

- 两台 Baton Mini 必须使用不同 node name 和不同 topic 前缀。
- 两台 GoPro 必须使用不同 node name、namespace、camera name 和 frame id。
- topic / namespace / 设备路径调整时，优先修改 `config/all_sensor_nodes.yaml`。
- 每个业务 topic 的发布开关和名称必须集中放在 `config/all_sensor_nodes.yaml` 的 `topics.<topic_key>.enabled` 与 `topics.<topic_key>.name`。
- GoPro 原始 `v4l2_camera_node` 必须运行在隐藏 namespace 中，公开 namespace 只暴露 relay 后的已启用业务 topic。
- 不把 Octopus 录制逻辑放进相机启动 launch，Octopus / MCAP 录制保持独立。

## 3. 当前默认配置

| 设备 | 默认配置 |
| --- | --- |
| Baton Mini right | `192.168.1.10`，本机 `local_ip: auto`，默认只发布 `/baton_mini_right/odometry` |
| Baton Mini left | `192.168.2.10`，本机 `local_ip: auto`，默认只发布 `/baton_mini_left/odometry` |
| GoPro right | `/dev/v4l/by-path/pci-0000:00:0d.0-usb-0:3.2:1.0-video-index0`，namespace `/gopro_right`，默认只发布 `/gopro_right/image_raw` |
| GoPro left | `/dev/v4l/by-path/pci-0000:00:0d.0-usb-0:3.4.4.2:1.0-video-index0`，namespace `/gopro_left`，默认只发布 `/gopro_left/image_raw` |

## 4. 验证约束

- 运行前应确认 Baton Mini 网络/IP 连通，GoPro 采集卡设备路径存在。
- 成功启动后至少检查 `ros2 topic list`，确认配置中 `enabled: true` 的左右 Baton Mini 与左右 GoPro topic 均出现且互不冲突。
- 需要录制时，先确认 Octopus 能看到目标 topic，再进入 MCAP 录制验证。
