# 人类验收关卡规则

## 适用范围

- 阶段：阶段四：模型部署
- 任务模式：阶段四 L2 改造工作包的验收与合入
- 适用对象：L2 Gate 通过后、合入 `model_deploy` 分支前的人工确认环节
- 不适用对象：单个 L3 的局部验收（由验收 sub-agent 按验收卡片完成）、纯知识查询

## 核心判断

L2 Gate 是 AI 侧的自动化验收（单测、dry-run、shadow-run），它判断「这一组 L3 是否形成可运行阶段成果」。
但 Gate 通过不等于可以合入。阶段四的每个 L2 改造只有经过**人类亲自运行测试并签字确认**后，才允许合入 `model_deploy` 并删除三级开发分支。

人类验收关卡是 Gate 与 Git 自动同步之间的一道硬关卡：AI 不得越过。

## 关卡位置

```text
L2 required L3 全部达到可解释状态（PASS_LOCAL / DEFER_TO_L2_GATE / BLOCKED_ENV / BLOCKED_HARDWARE_EXPECTED）
  → AI 执行 L2 整体验收（Gate），产出 05_acceptance/<l2>/验收结果.md 和 L2整体验收报告.md
  → 【本规则】AI 暂停，向用户报告 Gate 结果，交付《人类验收清单》
  → 【本规则】人类按清单亲自运行测试（命令 + 观察点 + 通过现象）
  → 【本规则】人类在 验收结果.md 末尾「人类验收」段签字（勾选通过 + 用户名 + 日期）
  → 只有签字通过，AI 才执行阶段四 Git 操作规则的「Gate 后合入流程」
  → 若人类不通过，反馈给执行 sub-agent 修正，最多 3 轮，仍不通过则停止并向用户报告
```

## 验收清单设计原则

对照《编程执行/架构边界与机械约束原则.md》「机械约束优先级」：已能机械执行的规则以机械检查为准。

1. **优先可机械运行**：验收项尽量是可复制运行的命令（pytest、dry-run 脚本、config 校验脚本）。AI 跑过的人工也能直接跑。
2. **人工观察仅限真机**：只有涉及硬件行为（机械臂运动、急停、夹爪动作、SDK 返回码）才用纯人工观察。软件侧不接受「我觉得没问题」式的主观判断。
3. **明确通过现象**：每项必须写出看到什么才算通过（shape、段序、数值范围、stdout 关键行、topic echo 内容、生成文件）。不含模糊表述。

## 验收清单必含项

每个 L2 的人类验收清单写入 `05_acceptance/<l2>/人类验收清单.md`，必含：

| 字段 | 说明 |
|---|---|
| 验收项编号 | 逐项编号，便于人类勾选 |
| 运行命令 | cwd、完整命令、必要环境变量。可直接复制运行 |
| 测试输入 | mock 数据路径、构造的 bundle/config、ROS topic 或真机条件 |
| 观察点 | stdout 关键行、日志文件、ROS topic、生成文件、metrics |
| 通过现象 | 明确到 shape / 段序 / 数值范围 / 状态 / 人工现象才算 OK |
| 失败现象与排查入口 | 常见失败表现 + 排查命令 |
| 验收性质 | `机械`（可运行命令）或 `人工`（仅真机行为） |

## 签字格式

人类验收结论写入 `05_acceptance/<l2>/验收结果.md` 末尾「人类验收」段：

```markdown
## 人类验收

- 验收人：<用户名>
- 验收日期：YYYY-MM-DD
- 验收结论：[ ] 已通过　[ ] 不通过
- 逐项结果：
  - 验收项 1：<命令> → <通过现象> → [ ] 通过
  - 验收项 2：<命令> → <通过现象> → [ ] 通过
  - ...
- 备注：<若不通过，填写失败项和反馈>
```

未填写或勾选「不通过」时，视为人类验收未通过，AI 不得合入。

## 与 Git 自动同步的关系

本规则修改《阶段四：模型部署 Git操作规则.md》的「Gate 后合入流程」前置条件：

- 原前置条件：Gate 通过
- 现前置条件：**Gate 通过 且 人类验收签字通过**

AI 执行 Gate 后合入流程前，必须先检查 `验收结果.md` 的「人类验收」段：
- 未填写 → 停止，向用户报告「等待人类验收」
- 勾选「不通过」→ 停止，向用户报告「人类验收未通过」
- 勾选「已通过」+ 用户名 + 日期 → 允许执行合入流程

## 阻断条件

出现以下任一情况，AI 停止自动同步并向用户报告：

- `验收结果.md` 不存在或缺少「人类验收」段。
- 人类验收段未勾选、勾选「不通过」、或缺少用户名/日期。
- 验收清单中标记为「机械」的验收项，无法在当前环境复现（记录环境缺口，不作为通过）。
- 真机相关 L2（L2-05）缺少急停准备、风险确认或现场人工观察记录。

## 与循环工程的关系

Ralph / OpenCode 阶段四循环调度中，L2 Gate agent 产出 `L2整体验收报告.md` 后，主 Agent 必须暂停该 L2 的自动推进，转为「等待人类验收」状态，并在循环状态摘要中标注：

```text
L2-XX 状态：等待人类验收（Gate 已通过，待用户签字）
```

主 Agent 不得在未收到人类签字的情况下自行执行合入或推进下游 L2。
