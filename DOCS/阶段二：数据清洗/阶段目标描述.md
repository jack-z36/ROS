# 阶段二：数据清洗目标描述

## 阶段定位

阶段二负责把阶段一生成的 raw MCAP 从 topic 日志转换成 canonical dataset。

更准确地说，数据清洗流程是从 raw MCAP 的 topic 世界，转换成 canonical dataset 的 episode/step/observation/action 世界。

## 核心目标

阶段二的目标不是简单改变文件格式，而是完成三件事：

- 把多 topic 数据按统一时间轴对齐。
- 把每个 step 上的数据组织成 observation 和 action。
- 生成一套 MCAP-centric canonical dataset，使后续可以稳定导出到 LeRobot、HDF5、Zarr 等训练格式。

## 目标数据流

阶段二的数据流是：

raw MCAP 进入清洗程序后，程序读取所有目标 topic，检查 topic 是否存在，检查 msg type 是否符合 schema，建立统一时间轴，把图像、位姿、触觉、夹爪宽度对齐到每个 step；随后把左右 TCP 位姿转换到 common frame，生成 observation，按 UMI 风格生成 action/action chunk，再生成 `step_index.parquet`、`masks.parquet`、`alignment_report.json`、`quality_report.json`、`robot_constraint_report.json`、`processing_manifest.json`，最终输出 `canonical_dataset_mcap`。

## canonical dataset 定义

阶段二的 canonical dataset 不是纯 `npy` 数据集，不是单个 HDF5 文件，也不是训练框架专用格式。它也不只是“清洗后 MCAP 加几个说明文件”。

canonical dataset 是阶段二输出给训练阶段的标准数据契约。它必须同时回答以下问题：

- 这批数据集是谁、什么版本、包含哪些 episode。
- 每个 episode 是什么任务、来自哪个 raw MCAP、是否成功。
- 每个 episode 中有哪些统一 step，每个 step 的时间戳是多少。
- 每个 step 的 observation 从 `data.mcap` 的哪些消息或派生字段得到。
- 每个 step 的 action/action chunk 如何由未来 TCP 轨迹和夹爪宽度生成。
- 每个位姿字段属于哪个坐标系，单位和四元数顺序是什么。
- 哪些 step 可训练，哪些 step 应被 mask 掉，原因是什么。
- 时间同步质量、数据质量、机器人约束检查和处理过程是否可追溯。
- 后续 exporter 应如何稳定导出 LeRobot、HDF5、Zarr 或其他训练格式。

因此它是一个 MCAP-centric 的标准中间态数据集：

- dataset 级：`dataset_meta.json`、`dataset_index.parquet`、`schema/`。
- episode 级：`episode_meta.json`、`data.mcap`、`step_index.parquet`、`masks.parquet`、`alignment_report.json`、`quality_report.json`、`robot_constraint_report.json`、`processing_manifest.json`。
- 导出级：`exports/lerobot`、`exports/hdf5`、`exports/zarr`。

### 最终目录结构

`canonical_dataset_mcap/` 的最终目录结构固定为：

```text
canonical_dataset_mcap/
├── dataset_meta.json
├── dataset_index.parquet
├── schema/
│   ├── observation_schema.json
│   ├── action_schema.json
│   ├── frame_schema.json
│   ├── topic_schema.json
│   └── quality_schema.json
├── episodes/
│   └── episode_000001/
│       ├── episode_meta.json
│       ├── data.mcap
│       ├── step_index.parquet
│       ├── masks.parquet
│       ├── alignment_report.json
│       ├── quality_report.json
│       ├── robot_constraint_report.json
│       └── processing_manifest.json
└── exports/
    ├── lerobot/
    ├── hdf5/
    └── zarr/
```

- `dataset_meta.json`
- `dataset_index.parquet`
- `schema/observation_schema.json`
- `schema/action_schema.json`
- `schema/frame_schema.json`
- `schema/topic_schema.json`
- `schema/quality_schema.json`
- `episodes/episode_000001/episode_meta.json`
- `episodes/episode_000001/data.mcap`
- `episodes/episode_000001/step_index.parquet`
- `episodes/episode_000001/masks.parquet`
- `episodes/episode_000001/alignment_report.json`
- `episodes/episode_000001/quality_report.json`
- `episodes/episode_000001/robot_constraint_report.json`
- `episodes/episode_000001/processing_manifest.json`
- `exports/lerobot/`
- `exports/hdf5/`
- `exports/zarr/`

其中 `schema/` 目录只包含 `observation_schema.json`、`action_schema.json`、`frame_schema.json`、`topic_schema.json`、`quality_schema.json` 五个文件，不单独设置 `sync_schema.json`。同步规则写入 `alignment_report.json`、`processing_manifest.json`，以及必要时写入 `quality_schema.json` 中的时间误差质量字段。

`exports/` 是派生产物目录，不是 canonical dataset 的主定义。即使删掉 `exports/`，也应该能从 dataset 级 schema 和 episode 级数据重新导出训练格式。

### dataset 级语义

`dataset_meta.json` 描述整批数据集，应至少记录：

- `dataset_name`
- `dataset_version`
- `created_at`
- `project_name`
- `robot_setup`
- `sensor_setup`
- `schema_version`
- `total_episodes`
- `total_steps`
- `task_list`
- `description`

`dataset_index.parquet` 是全局 episode 索引，应至少记录：

- `episode_id`
- `episode_path`
- `task_name`
- `language_instruction`
- `num_steps`
- `duration_sec`
- `success`
- `valid_for_training`
- `quality_score`
- `data_mcap_path`
- `step_index_path`
- `masks_path`

### schema 级语义

`schema/` 目录定义全数据集统一的数据契约。

`observation_schema.json` 定义 `observation_t` 的字段、类型、shape、单位、来源 topic、是否必需、是否参与训练和预处理方式。

`action_schema.json` 定义 `action_t/action_chunk_t` 的语义。当前项目采用 UMI 风格 relative trajectory action：每个未来目标都相对于同一个当前推理起点 TCP 位姿，而不是相对于上一个未来目标。

`frame_schema.json` 定义 `left_baton_raw_frame`、`right_baton_raw_frame`、`left_tcp_frame`、`right_tcp_frame` 和 `common_frame`，并说明 common frame 的原点、轴向、单位、四元数顺序以及左右 raw pose 到 common-frame TCP pose 的转换方式。

`topic_schema.json` 定义 `data.mcap` 中 topic 与训练语义字段之间的映射，例如 raw topic、processed topic、observation 字段和 action 计算来源之间的关系。

`quality_schema.json` 定义 masks 和质量字段，例如缺帧、同步误差、位姿跳变、触觉异常、夹爪检测失败、action 越界和是否可训练。

### episode 级语义

每个 `episodes/episode_xxxxxx/` 表示一次完整示教，不只是一个文件夹。

`episode_meta.json` 描述单条 episode 的任务语义、来源 raw MCAP、起止时间、操作者、场景、语言指令、是否成功和备注。

`data.mcap` 保存该 episode 的多模态时间序列数据。canonical dataset 不抛弃 MCAP；MCAP 仍是可回放、可追溯、可重新解析的数据本体。

`step_index.parquet` 是 canonical dataset 的核心索引。它把 `data.mcap` 从 topic 世界映射到 step 世界，应至少表达：

- `episode_id`
- `step_id`
- `timestamp`
- 每个 observation 字段对应的 topic、message 时间戳、message index 或可定位引用。
- action chunk 的起点、未来 horizon、对应未来 step 范围。
- 与同步相关的最近邻/插值标记和时间误差。

`masks.parquet` 记录每个 step 的有效性，应至少表达：

- `valid_step`
- `valid_image_left`
- `valid_image_right`
- `valid_left_pose`
- `valid_right_pose`
- `valid_left_tactile`
- `valid_right_tactile`
- `valid_left_gripper`
- `valid_right_gripper`
- `valid_action`
- `valid_language`
- `valid_for_training`
- 必要时记录 invalid reason。

`alignment_report.json` 汇总同步质量，包括各 topic 原始频率、统一采样频率、平均/最大对齐误差、缺失帧数量、插值次数、最近邻匹配次数和丢弃 step 数量。

`quality_report.json` 汇总数据质量，包括图像坏帧、位姿跳变、触觉异常、夹爪异常、action 异常、有效 step 比例、质量分数和是否建议进入训练集。

`robot_constraint_report.json` 汇总机器人执行约束相关检查。它不替代部署阶段的在线安全模块，但需要在数据清洗阶段记录离线可检查的问题，例如 TCP 轨迹是否超出预设 workspace、单步平移/旋转是否异常、夹爪宽度是否越界、左右手距离或动作是否存在明显不可执行风险。

`processing_manifest.json` 记录处理过程，包括处理脚本版本、处理时间、输入 raw MCAP、输出 data.mcap、使用的 schema 版本、标定参数版本、同步参数、action horizon、控制频率和处理是否成功。

### canonical dataset 的不变量

一个合格的 canonical dataset 必须满足：

- dataset 级 schema 能解释所有 episode。
- `dataset_index.parquet` 中登记的 episode 路径和文件真实存在。
- 每个 episode 的 `step_index.parquet` 能定位到 `data.mcap` 中的消息或明确的派生字段。
- `observation_schema.json` 中声明的必需字段，要么在 step 中可定位，要么在 masks 中标记无效。
- `action_schema.json` 中声明的 action 计算方式必须可从 common-frame TCP 轨迹和夹爪宽度复现。
- `frame_schema.json` 必须足以解释 `left_tcp_pose_common` 和 `right_tcp_pose_common` 的坐标系、单位和姿态表示。
- `masks.parquet` 必须能让 exporter 过滤不可训练 step。
- `robot_constraint_report.json` 必须记录离线机器人约束检查结果，即使第一版只支持基础 workspace/action range 检查，也要保留该文件位置。
- `processing_manifest.json` 必须能追溯该 episode 是由哪个 raw MCAP、哪套参数、哪版脚本生成的。

## 成功标准

阶段二成功时应满足：

- raw MCAP 能被读取并检查目标 topic。
- 统一时间轴和 step 索引能够建立。
- `observation_t` 和 `action_t/action_chunk_t` 的语义被 schema 明确描述。
- 左右 Baton Mini raw pose 能转换成 common frame 下的左右 TCP pose。
- masks 能标记哪些 step 可用于训练。
- report 和 manifest 能说明对齐质量、数据质量和处理过程。
- canonical dataset 能作为后续训练格式导出的唯一可信中间态。
