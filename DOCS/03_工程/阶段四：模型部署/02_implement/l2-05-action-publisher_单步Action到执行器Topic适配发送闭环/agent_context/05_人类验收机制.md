# L2-05 人类验收机制

> [!info] 文档契约
> - 消费对象：人类验收者、陪同 Agent、L2 Gate 与 Git 合入流程。
> - 权威性：定义人类可执行验收清单、观察点、风险和签字格式。
> - 上游来源：`04_L2验收机制.md`。
> - 不负责范围：不授权默认真机动作，不把 BLOCKED 写成 PASS。
> - 运行目录：`/home/hit/ROS/worktrees/l2-05-action-publisher`。

## 1. 验收原则

- CLI `--enable-command-output` 默认缺省；第一轮验收必须证明四路 command 为 0。
- 命令总开关打开后仍必须由 L2-06 `CommandPermit.allowed=True` 才能发布 command。
- 本地/mock 能验证的内容必须运行，不得因无 ROS/硬件跳过。
- `/act/command/status` 是发送回执，不是控制命令；`driver_accepted`、`hardware_reached` 默认未知。
- 真机执行前必须有 ROS 观察证据、人工授权、急停就绪和 driver readiness。

## 2. 人类验收清单

### H01 · 统一验证脚本

```bash
cd /home/hit/ROS/worktrees/l2-05-action-publisher
bash src/model_deploy/act/scripts/l2_05_verify.sh
```

| 项 | 内容 |
|---|---|
| 环境 | Python；ROS 可缺失 |
| 输入 | 默认测试 fixtures/fake publishers |
| 观察点 | 分层 PASS/FAIL/BLOCKED、FAIL 完整位置链、summary |

```bash

```

| 项 | 内容 |
|---|---|

### H09 · 真实硬件（默认阻断）

执行前必须同时满足：

- 人类明确授权本次 command-enabled 运行。
- 急停可触达且已验证。
- driver readiness 可观察。
- H01-H08 通过，并保存 ROS 观察证据。
- 左右 arm/gripper topic 与目标设备逐项核对。

任一条件缺失：

```text
BLOCKED_HARDWARE_EXPECTED
```

不得把“未执行”写成通过。本文不提供默认真机命令；具体命令由现场验收卡在授权后填写。

## 3. 关键观察解释

| 现象 | 正确解释 |
|---|---|
| `OBSERVED` + command=0 | CLI 未开启；正常观察结果，不是失败。 |
| `BLOCKED` + reason | CLI 已开但动态许可阻断；检查 L2-06/driver safety facts。 |
| `PUBLISHED` | 计划内 ROS publish 调用完成；不等于硬件到位。 |
| `PARTIAL` | 部分 Topic 已写出且不可回滚；必须停止并由 L2-06 处理。 |
| `driver_accepted=null` | L2-05 未订阅 driver feedback；未知是正确值。 |
| `hardware_reached=null` | L2-05 无硬件到位证据；未知是正确值。 |
