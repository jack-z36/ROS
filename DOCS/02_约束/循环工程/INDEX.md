# 循环工程约束索引

## 消费 Agent

- 全部 Agent

## 本文职责

本文只负责把 Ralph / OpenCode 循环工程任务路由到对应的原子行为约束文件。

## 不负责

本文不承载阶段四当前进度、执行记录、Git 状态、L3 任务正文或各角色的完整行为规则。

## 适用范围

- 阶段：阶段四：模型部署
- 任务模式：Ralph / OpenCode 循环调度、执行、验收、状态恢复和 L3 原子提交
- 适用对象：OpenCode 主 Agent、执行 sub-agent、验收 sub-agent、L2 Gate agent

## 核心边界

阶段四循环工程的当前子目标是：在无真机环境下推进阶段四软件侧闭环到 `deploy_022`，并为 `deploy_023` 保留明确的 blocked 条件和真机交接材料。

每轮循环主单位是一个 L2 工作包；L3 是执行、验收、证据记录和 Git 原子提交的最小单位。

## 角色入口

| 角色 | 消费清单 | 说明 |
|---|---|---|
| 主 Agent | `01_主Agent行为约束.md` | 只列主 Agent 需要消费的行为文件 |
| 执行 sub-agent | `02_执行SubAgent行为约束.md` | 只列执行 sub-agent 需要消费的行为文件 |
| 验收 sub-agent | `03_验收SubAgent行为约束.md` | 只列验收 sub-agent 需要消费的行为文件 |
| L2 Gate agent | `04_L2Gate行为约束.md` | 只列 L2 Gate agent 需要消费的行为文件 |

## 行为原子入口

所有具体行为约束都放在：

```text
DOCS/02_约束/循环工程/behaviors/
```

先读取 `behaviors/INDEX.md`，再按角色消费清单读取对应行为文件。

## 文档原则

- 每个 `behaviors/` 约束文档只负责一个行为。
- 角色文档只负责列出消费清单，不得复写行为规则。
- 每个约束文档必须声明消费 Agent、本文职责和不负责范围。
- `DOCS/02_约束/循环工程/` 只写行为规则，不写当前进度或执行记录。
- 阶段四当前状态必须写入 `DOCS/03_工程/阶段四：模型部署/00_status/` 或既有工程证据目录。
