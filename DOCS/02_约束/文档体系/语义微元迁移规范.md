# 语义微元迁移规范

## 适用范围

- 阶段：全局
- 任务模式：文档体系维护、旧 DOCS 迁移、文档去重
- 适用对象：从旧文档迁移到 `01_知识/`、`02_约束/`、`03_工程/`、`99_learning/` 的内容
- 不适用对象：完整旧快照归档

## 强制规则

迁移单位是语义微元，不是文件。一个旧文件可以被拆到多个目标目录；多个旧文件的重复语义可以合并为一个新文档。

迁移前必须维护 `DOCS/语义迁移审计表.md`，字段固定为：

```text
source_path | source_heading | 语义摘要 | 语义类型 | 目标路径 | 处理动作 | 是否权威 | 备注
```

`语义类型` 只能使用：

- 知识
- 约束
- 工程
- learning
- archive

`处理动作` 只能使用：

- 抽取新建
- 合并去重
- 原样迁移
- 标记历史
- 移入learning
- 废弃但归档保留

## 禁止事项

- 禁止因为旧文件名叫 `背景信息.md` 就整体迁入知识。
- 禁止因为旧文件名叫 `执行约束.md` 就整体迁入约束。
- 禁止把含有历史旧规则的执行日志作为当前规则迁移。
- 禁止迁移后留下无人维护的重复权威入口。

## 维护规则

迁移完成后，`DOCS/语义迁移审计表.md` 必须移入 `DOCS/98_archive/` 下对应重构过程记录目录。
