# 配置与启动

本页描述 Octopus 的配置文件机制（scanner.json）和阶段一采集程序的整体启动流程。

## 定位

本页回答：Octopus 的运行配置存在哪、有哪些字段？阶段一的所有传感器节点和 Octopus 按什么顺序启动？

本页不涉及录制链路内部机理（见 `03_录制链路.md`），不涉及硬件身份配置（见 `40_身份与稳定性/`）。

## scanner.json 配置文件

### 文件位置

`config::load()` 用 Qt `QStandardPaths::GenericConfigLocation` 拼出路径，当前机器通常对应：

```text
/home/hit/.config/scanner.json
```

`Scanner` 启动时调用 `config::load()`，应用退出或设置保存时调用 `config::save()` 覆盖写回。

### 配置字段

| 配置项 | 来源 | 含义 |
|---|---|---|
| `language` | scanner.json | UI 语言 |
| `theme` | scanner.json | UI 主题，影响部分图表配色 |
| `recording.mcap.path` | scanner.json；启动脚本写为 `mcap` | MCAP 输出目录 |
| `recording.mcap.compression` | scanner.json | MCAP 压缩方式（ZSTD 等） |
| `recording.mcap.topics` | scanner.json 或 config.cpp 内置 | Operation 面板默认展示并勾选的录制 topic |
| `layout.visibility.topics_panel` | 运行期全局配置 | Topics 面板是否显示 |

### 默认值规则

- `recording.mcap.path` 为空时，默认写 Qt Documents 目录；项目启动脚本会提前用 `configure_octopus_scanner.py` 改成 `mcap`。
- `recording.mcap.topics` 为空时，`config.cpp` 内置 8 个默认 topic（见 `20_传感器模态语义/04_核心topic清单.md`）。

### OpDockWidget 只读一次

Operation 面板（`OpDockWidget`）**只在构造时读取** `config::recording::mcap::topics` 生成复选列表。启动后修改 scanner.json **不会自动刷新**已创建的列表。

如需修改默认录制 topic，应在启动 Octopus 前修改 scanner.json，或通过 Settings 对话框修改后重启。

## 阶段一整体启动流程

阶段一采集需要按顺序启动多个 ROS 节点。典型启动入口是 `start_all_sensor.sh`。
如果不使用触觉芯片，可改用 `start_baton_gopro.sh`，它复用同一套
Baton Mini / GoPro 配置与启动检查，但会关闭压力节点及触觉身份校验：

```text
start_all_sensor.sh
  ├── 启动左 Baton Mini 节点      → /baton_mini_left/*
  ├── 启动右 Baton Mini 节点      → /baton_mini_right/*
  ├── 启动左 GoPro 节点(v4l2)     → /gopro_left/*
  ├── 启动右 GoPro 节点(v4l2)     → /gopro_right/*
  ├── 启动触觉压力驱动节点        → /pressure/*
  └── 启动 Octopus(手动或脚本)    → 显示 + 录制
```

`start_baton_gopro.sh` 的启动拓扑为：

```text
start_baton_gopro.sh
  ├── 启动左 Baton Mini 节点
  ├── 启动右 Baton Mini 节点
  ├── 启动左 GoPro 节点(v4l2)
  └── 启动右 GoPro 节点(v4l2)
```

### 启动顺序的重要性

1. **传感器节点必须先于 Octopus 启动**：Octopus 录制链路在 Start 时刻查询 ROS graph，若传感器 topic 尚未注册会被静默跳过。
2. **左右相机用独立 scope**：左右两路 v4l2 相机通过独立进程/scope 启动，防止参数串扰（`OpaqueFunction` 立即解析参数）。
3. **触觉驱动依赖身份映射**：`pressure_driver_node` 启动时读取 `hardware_identity_map.yaml`，严格模式下无匹配 UID 会致命错误。

### 单包启动方式

各 ROS 包可单独启动用于调试：

| 包 | 启动命令 |
|---|---|
| `gopro_camera_launch` | `ros2 launch gopro_camera_launch gopro_pose_record.launch.py` |
| `baton_mini_sdk_demo` | `ros2 launch baton_mini baton_mini.launch.py` |
| `hwk_pressure_driver` | `ros2 launch hwk_pressure_driver pressure_driver.launch.py` |
| `octopus` | `./start_octopus.sh` 或 `install/octopus/lib/octopus/octopus` |

## 构建方式

```bash
# 构建全部采集相关包
colcon build --packages-select \
  hwk_pressure_interfaces hwk_pressure_driver \
  gopro_camera_launch baton_mini \
  octopus --cmake-args -DCMAKE_BUILD_TYPE=Release
```

Octopus 额外依赖 Qt 6.8、FFmpeg、Assimp、MCAP C++、spdlog、nlohmann_json、zstd、glm。直接运行安装产物时需自行保证 ROS2 环境、Qt/FFmpeg 动态库路径和 scanner.json 已配置。
