## 1. 一句话运行时职责

在稳态运行阶段，作为后台计算角色，把 L2-06 提交的 `InferenceRequest` 中的 `ObservationSnapshot` 加工成 LeRobot ACT 模型可消费的 batch，调用 ACT policy 前向推理，输出 shape 为 `(chunk_size, 16)` 的 `ActionChunk`，写入结果队列供 L2-06 收集；通过 `InferenceWorker` 后台线程异步解耦，保证 GPU 推理不阻塞 control tick。

## 2. 输入

```text
ObservationSnapshot          # 来自 L2-02，含 images / state / encoded_state(16,) / captured_at_s
InferenceRequest             # 来自 L2-06，从 inference_request_queue 取（latest-only）
DeployConfig                 # 来自 L2-01：bundle 路径 / runtime 参数 / dtype / chunk_size / task
ACT bundle                   # manifest.json / normalizers.json / experiment_config.yaml / adapter 权重
normalizers.json             # state/action 的 min/max/identity_indices（长度须匹配 16D）
experiment_config.yaml       # 模型结构配置（交叉校验，不覆写维度）
```

这些输入中，`ObservationSnapshot` 和 `InferenceRequest` 是稳态运行时从 RAM 队列读取；`DeployConfig`、bundle、normalizers、experiment_config 是启动阶段一次性加载到 RAM 并稳定持有。本 L2 不直接订阅 ROS topic（那是 L2-02 的事）。

## 3. 输出

```text
ActionChunk(
  actions=np.ndarray shape (chunk_size, 16),
  obs_time=...,               # 继承自 InferenceRequest.obs_time
  infer_start_time=...,       # 推理开始单调时间
  ready_time=...,             # 推理完成单调时间
  action_dt=...,              # = 1/control_hz，供 L2-06 对齐
  request_id=...              # 继承自 InferenceRequest.request_id
)
SharedBuffer.chunk_result_queue   # latest-only，供 L2-06 收集
推理 metrics：inference_count / inference_latency / inference_error_count
```

本 L2 输出的是**整个 chunk**，不是单步 action。第一版的单步 raw action 由 L2-06 从 active chunk 按 cursor 直取（边界不变量 #3）。

## 4. 负责内容

- 加载 ACT policy runtime（真实或 fake），持有统一推理接口 `predict_action_chunk(observation) -> np.ndarray (chunk_size, 16)`。
- 将 `ObservationSnapshot` 映射为 LeRobot ACT 模型可消费的 batch（处理 batch key：`observation.state`、`observation.images.*`、`task`）。
- 加载并使用 state/action normalizer：推理前对 16D state 做 `normalize`，推理后对 chunk 做 `unnormalize`，把模型输出还原到物理尺度。
- 通过 `InferenceWorker` 后台线程消费 `inference_request_queue`，执行推理，把结果写入 `chunk_result_queue`，异步解耦 GPU 推理与 control tick。
- 按配置 `inference_hz` 限速（避免推理 actor 空转过载）。
- 校验 policy 输出 shape（必须 `(chunk_size, 16)`），非法 shape 抛异常。
- 记录推理 metrics：成功计数、延迟（含 EMA）、失败计数、`last_error`。
- 提供 fake-policy 路径，保证无真实 bundle 时仍能本地验收统一推理接口与调度行为。

## 5. 不负责内容

- 不负责 ROS callback / 传感器订阅 / 图像预处理（属 L2-02）。
- 不负责 `ObservationSnapshot` 是否字段齐全或新鲜（属 L2-02 校验；本 L2 只消费）。
- 不决定何时发起推理（属 L2-06 提交 `InferenceRequest`）。
- 不负责 `ActionChunk` 的首版单步选择 / cursor 维护 / chunk 切换（属 L2-06）。
- 不实现 action 平滑、smoothstep blend、跨 chunk 融合、RTC 类时间对齐（后续优化，非第一版 Gate）。
- 不做单步 action 的 policy-action 通用安全检查（属 L2-04）。
- 不发布 `/act/policy_action` 或任何 topic（属 L2-05）。
- 不转换硬件命令格式 / 不调用硬件 SDK（属 L2-05）。
- 不启动 `control_timer` / 不安排 tick 调度（属 L2-06）。
- 不导出 bundle / 不训练模型 / 不计算 normalizer 统计量（训练侧职责，本 L2 只读已导出的 bundle）。

## 6. 完成判据

- **fake-policy 路径（无真实 bundle）**：给定合法 `ObservationSnapshot`，fake-policy runtime 必须输出 shape `(chunk_size, 16)` 的 float32 `ActionChunk`；`InferenceWorker` 能从 request_queue 消费 request 并把 chunk 写入 result_queue；推理 metrics 正确累计。
- **real-policy 路径（真实 bundle 就绪后）**：real-policy dry-run 对合法 snapshot 输出同样 shape `(chunk_size, 16)` 的 action chunk，延迟可观察，异常被捕获并记录为 `inference_error`。
- **shape 契约**：policy 输出 `actions.shape[1]` 必须为 16，否则抛 `ValueError`，不产出非法 chunk。
- **异步解耦**：推理在后台线程执行，不阻塞 control tick（L2-06 在 mock 闭环验收中确认）。
- **下游零猜测**：L2-06 通过 `chunk_result_queue` 收到 shape 确定的 `ActionChunk`，不需猜测维度或时间戳。
- **无平滑逻辑泄漏**：本 L2 不包含 `blend_steps`、`smoothstep_alpha`、`_blend_next_action`、cross-chunk fusion、RTC 类代码。

## 7. 代码层落点

| 代码层 | 本 L2 是否落点 | 落点内容 |
|---|---|---|
| `types/` | 否 | 复用 L2-01 的 `ActionSpec`（16D 维度校验）。本 L2 不新增 types 产物：`ActionChunk` / `InferenceRequest` / `ObservationSnapshot` 数据结构在第一版按"跨 L2 共享 RAM 对象"处理，归 runtime 层 `shared_buffer` 承载（与 Pi0.5 一致）。 |
| `config/` | 否 | 复用 L2-01 的 `DeployConfig.runtime`（device/dtype/chunk_size/task/inference_hz）和 `SafetyConfig.clamp_normalized_action`。本 L2 不新增配置 schema。 |
| `repo/` | 是 | ACT policy loader（加载真实/fake policy runtime + preprocessor + normalizer）、bundle 读取复用 L2-01 的 `bundle_reader`/`manifest_parser`/`normalizer_loader`/`experiment_config_loader`。 |
| `service/` | 是 | ACT batch adapter（snapshot→batch）、normalizer 使用（normalize/unnormalize）、统一推理接口封装。 |
| `runtime/` | 是 | `InferenceWorker` 后台线程（消费 request_queue→推理→写 result_queue + metrics）、`ActionChunk`/`InferenceRequest` 数据结构（若 L2-01 未统一提供则本 L2 在 `shared_buffer` 承载）。 |
| `ui/` | 否 | 不创建 ROS node、不订阅、不发布。 |
| `tests/` | 是 | `tests/repo/`、`tests/service/`、`tests/runtime/`、`tests/integration/`（fake-policy mock 闭环）。 |

## 8. 上下游

- **上游**：
  - L2-01（bundle / normalizer / runtime 配置 + `DeployConfig` + `ActionSpec`）。
  - L2-02（`ObservationSnapshot` 契约，可先用 mock snapshot 开发）。
- **下游**：
  - L2-06 通过 `chunk_result_queue` 收集 `ActionChunk`，按 cursor 直取 raw single action（第一版）。
- **协作方式**：与 L2-06 通过 request/result queue 异步解耦（见 `03_L1_ACT功能模块协作架构.md` §7.2 Inference 后台轴、§9 同步与异步边界）。

## 9. 仍待用户决策的问题

以下问题在 L3 生成前需要明确（当前文档已给出推荐默认，用户可在验收时调整）：

1. `ActionChunk` / `InferenceRequest` / `ObservationSnapshot` 数据结构是否由 L2-01 在 `types/` 统一提供，还是由本 L2 在 `runtime/shared_buffer.py` 承载？**当前推荐**：参照 Pi0.5 放 `runtime/shared_buffer.py`，避免 L2-01 膨胀；若用户要求 types 层统一，则在 L2-01 补充。
2. fake-policy 的具体生成策略（零向量 / 随机 / 正弦波 / 录制回放）？**当前推荐**：可配置，默认零向量 + request_id 关联，保证 shape 与延迟可观察。
3. ACT 模型是否复用 LeRobot ACT 实现（`lerobot.policies.act`）？**当前推荐**：是，参照 Pi0.5 复用 LeRobot processor pipeline 的方式复用 LeRobot ACT。
