## 0. 边界来源与漂移处理

当前 checkout 的 L1 文档仍残留旧语义。本文按用户指定的详细边界锁定以下纠正：

| 漂移项 | 本 L2 最终边界 |
|---|---|
| `/act/policy_action` 被写成输入或串行 bridge 中间量 | 纯输出；与四路 command 并行派生。 |
| `latest arm/gripper state` 被写成输入 | 不是输入；L2-05 不订阅、不回读状态。 |
| workspace / IK 被写成 L2-05 检查 | 属外部 driver；L2-05 不实现。 |
| gate/deadman/急停原始信号被写成 L2-05 输入 | L2-06 汇总为最终发布授权；L2-05 只消费最终授权。 |
| Pi0.5 shadow-run 发布四路 command | ACT shadow-run 严禁四路 command。 |

Pi0.5 仅作为源码结构参考，不得覆盖上述边界。旧 layer-based L2、旧 Contract Delta 和阶段二模板均不是任务来源。

## 1. 一句话运行时职责

L2-05 是 ACT 部署程序唯一 ROS command 出口：每个 control tick 接收 L2-04 已安全通过的 16D TCP action、L2-06 的最终发布授权与时间，把同一策略意图并行投影为观测通道和四路执行器 command；默认 shadow，不拥有调度、安全算法或硬件驱动。

## 2. 输入

| 输入 | 来源 | 传递方式 | 约束 |
|---|---|---|---|
| `SafetyResult` 中的 safe `ActionSpec` | L2-04，经 L2-06 传递 | RAM 同步调用 | `accepted=True`、action 非空、16D、finite；夹爪仍为 ACT `[0,1]`。 |
| `DeployConfig` | L2-01 | 启动期注入、稳态只读 | 提供 command topics、运行 mode、frame 与输出映射配置。 |
| `PublishAuthorization` | L2-06 | RAM 同步调用 | 只含汇总后的 mode、command_allowed、reason；不暴露原始 gate topic。 |
| `action_id` 与当前时间 | L2-06 | RAM 同步调用 | `action_id` 用于 status 关联；ROS 时间用于 header，单调时间用于 deadband。 |

明确不是输入：

- `/act/policy_action` 或任何 ROS topic；本 L2 不创建 subscription。
- raw action、`ActionChunk`、active chunk 或 cursor。
- latest arm/gripper state、workspace 参数、IK solver。
- 原始 deadman、急停、enable、driver state topic。

## 3. 输出

### 3.1 观测通道

| Topic | 第一版消息 | 语义 |
|---|---|---|
| `/act/policy_action` | `std_msgs/msg/Float32MultiArray` | 原样 16D safe action，保持 ACT 内部单位；表示“本 tick 策略想做什么”。 |
| `/act/command/status` | `std_msgs/msg/String`，JSON schema | 至少含 `action_id`、`safety_ok`、`sent_to_driver`、`failure_reason`，并区分 policy publish、command publish 与硬件执行未知。 |

### 3.2 真实 command 通道

| Topic | 第一版消息 | frame / 单位 |
|---|---|---|
| `/act/command/arm/left_target` | `geometry_msgs/msg/PoseStamped` | `left_arm_base`，position=m，quaternion=(x,y,z,w)。 |
| `/act/command/arm/right_target` | `geometry_msgs/msg/PoseStamped` | `right_arm_base`，position=m，quaternion=(x,y,z,w)。 |
| `/act/command/gripper/left_target` | `std_msgs/msg/Float64` | 大象夹爪命令 `0..100`，0=闭合，100=张开。 |
| `/act/command/gripper/right_target` | `std_msgs/msg/Float64` | 同上。 |

选择标准 ROS 消息是第一版已锁定的实现决定：当前 `src/model_deploy/act/` 不是独立 ROS interface package；内部 `ActionPublishResult` 仍提供强类型语义，未来可在不改变本 L2 边界的前提下迁移自定义 msg。

## 4. 模式矩阵

| mode | 本地构造/返回 | `/act/policy_action` | `/act/command/status` | 四路 command |
|---|---|---|---|---|
| `dry-run` | 必须 | 不要求 | 不要求 ROS；必须返回 RAM 结果 | 禁止 |
| `shadow-run` | 必须 | 必须 | 必须 | 禁止 |
| `safe-run` + 未授权 | 必须 | 必须 | 必须，reason=`not_authorized` | 禁止 |
| `safe-run` + 已授权 | 必须 | 必须 | 必须 | 允许；先全部构造成功，再依次 publish |

`RuntimeConfig.publishes_command_topics` 当前把 shadow/safe 合并的旧行为不得被 L2-05 使用。L2-05 必须依据上表与显式 `PublishAuthorization` 双重门控。

## 5. 负责内容

- 拒绝任何没有 `SafetyResult.accepted=True` 的输入，raw action 不能绕过 L2-04。
- 按固定段序拆分 16D：`[0:7]` 左 TCP、`[7:14]` 右 TCP、`[14]` 左爪、`[15]` 右爪。
- 保持左右 frame、position=m、quaternion=(x,y,z,w) 语义。
- 将夹爪 `[0,1]` 线性映射为 `0..100`；输入不在 `[0,1]` 时失败，不能把上游 `0..100` 再放大。
- 从同一 safe action 并行构造 policy 观测通道与四路 command 通道。
- 在任一路 command publish 前完成四路本地构造和校验；构造/授权失败时四路均不发布。
- 再次核验 mode 与最终授权，防止 shadow/未授权命令泄漏。
- 持有夹爪最近成功发布目标和时间，执行 deadband 与最小间隔，避免重复刷写设备队列。
- 生成逐调用 publish 结果与 command status，不把 ROS publish 调用成功写成硬件已执行或到位。
- ROS publish 抛异常时返回明确失败；L2-06 决定 fallback、重试或停止。

### 5.1 四路“原子性”的精确边界

```text
允许声称：四路消息必须先全部在 RAM 构造和校验成功，才开始任一路 publish。
禁止声称：ROS 多 topic 是事务，或四台设备一定同时接收/执行。
```

运行期某一路 publish 抛异常时，已经发出的消息无法回滚。status 必须记录 `partial_ros_publish:<n>/4`，`sent_to_driver=false`，交 L2-06 处理。夹爪因 deadband 被有意跳过属于发布计划的一部分，不等于构造失败。

## 6. 不负责内容

- 不调用 ACT policy，不做 batch、推理或反归一化。
- 不选择 action step，不管理 `ActionChunk`、cursor、queue、timer 或 tick。
- 不重新实现 L2-04 的 shape/NaN/quaternion/TCP delta 等通用安全算法；只复核安全通过标记和本输出契约。
- 不读取 arm/gripper 实时状态，不做 workspace、IK、MoveIt、碰撞规划或硬件级限位。
- 不汇总原始 gate/deadman/急停/driver readiness；这些属于 L2-06 与外部 driver。
- 不决定 fallback、不拥有全局 metrics、不自行重试。
- 不调用 RM65 SDK、driver API、Modbus、USB-485 或夹爪串口。
- 不订阅 `/act/policy_action`，不建立旧 bridge/mux 串行链路。
- 不实现 action smoothing、跨 chunk 融合、RTC 或复杂时间重采样。

## 7. 可持有的最小状态

| 可以持有 | 用途 |
|---|---|
| 六个 ROS publisher handle | 程序全生命周期外部输出资源。 |
| 左/右最近成功发布的夹爪目标与单调时间 | deadband 与最小发布间隔。 |
| 最近一次 `ActionPublishResult` | 即时 status 和诊断。 |

| 不可持有 | 所有者 |
|---|---|
| active chunk / cursor / fallback / retry 状态 | L2-06 |
| previous safe action 的控制状态 | L2-06 |
| 原始硬件授权信号 | L2-06 / 外部 driver |
| 全局 RuntimeMetrics | L2-06 |

## 8. 上下游

- 上游 L2-01：`DeployConfig`、command topics、mode、frame/output mapping。
- 上游 L2-04：`SafetyResult` 与 safe `ActionSpec`。
- 控制调用方 L2-06：`action_id`、当前时间、最终发布授权、同步调用时机；消费 `ActionPublishResult`。
- 下游 L2：无。
- 外部下游：ROS middleware → RM65/大象夹爪 driver 节点 → 执行器；外部监控/日志消费 policy/status。

## 9. 完成判据

- 16D safe action 可稳定映射为 2 个 `PoseStamped`、2 个 `Float64(0..100)` 和 16D policy message。
- `[0:7]`/`[7:14]` 左右段、frame、quaternion 顺序、米制单位无交换。
- dry/shadow/safe 四种矩阵路径均有 mock 测试；shadow 与 safe 未授权路径四路 command 调用计数必须为 0。
- 四路构造任一失败时四个 publisher 调用计数均为 0。
- safe-run 授权路径四路构造成功后按计划 publish；运行期部分异常如实报告、绝不伪造事务回滚。
- 夹爪重复目标和过快目标受 deadband/最小间隔约束，状态只在成功发布后更新。
- 模块无 subscription、无 timer、无 workspace/IK、无厂商 SDK import。
- `/act/command/status` 能区分本地拒绝、policy 已发布、command 已提交、下游接受未知、真实到位未知。
