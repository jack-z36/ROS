# 阶段二实现路线图

## 文档目标

本文定义阶段二新版实现顺序。它服务于后续 L2/L3 拆解，重点回答：

1. 当前阶段二最终要交付什么。
2. 哪条数据链路必须优先跑通。
3. 每个场景的 P0 能力边界是什么。
4. 每批开发完成后如何验收。

旧路线图已经归档到：

```text
DOCS/归档/2026-05-28_阶段二旧宏观路线图_五场景canonical方案/
```

## 一、新版目标与主线

阶段二最终目标：

```text
生成 LeRobotDataset v3，用于 LeRobot 框架执行 ACT 模型训练。
```

新版实现主线：

```text
raw MCAP
  -> cleaned MCAP
  -> MCAP_A / validated MCAP
  -> aligned MCAP
  -> LeRobotDataset v3
  -> ACT 训练前检查
```

旧版 `canonical_dataset_mcap/` 与通用 `exports/` 不再是 P0 主线。

## 二、路线图粒度规则

本文件只写场景级与功能模块级交付，不提前规定具体源码文件名。

允许写：

- 需要哪些软件能力。
- 每个能力处理什么输入、输出什么产物。
- 什么算当前阶段可验收。
- 后续 L2/L3 必须围绕哪个产物契约展开。

不在本文件写：

- 具体 `.py` 文件必须叫什么。
- 类名、函数名、内部目录结构。
- LeRobotDataset v3 的完整官方字段细节。

LeRobotDataset v3 的精确格式必须在实现场景四 L2/L3 时按当时使用的 LeRobot 官方版本核对。

## 三、场景实施总览

| 场景  | P0 目标                                            | P0 输出                          | 不做什么                    |
| --- | ------------------------------------------------ | ------------------------------ | ----------------------- |
| 场景一 | 从 raw MCAP 得到 cleaned MCAP，位姿转换到 arm-base（机械臂基坐标系 per RM65 base）。 | cleaned MCAP（含 arm-base TCP pose + raw pose）、清洗报告、转换配置。 | 不做滤波、对齐、LeRobot 数据集。 |
| 场景二 | 从 cleaned MCAP 得到 MCAP_A / validated MCAP。       | MCAP_A、滤波/补全/异常/写出摘要。          | 不做 IK、MuJoCo、关节限位标注。    |
| 场景三 | 从 MCAP_A 得到 aligned MCAP。                        | aligned MCAP、alignment report。 | 不构建 LeRobotDataset v3。  |
| 场景四 | 从 aligned MCAP 构建 LeRobotDataset v3。             | LeRobotDataset v3、转换报告、读取校验。   | 不训练 ACT，不维护通用 exporter。 |
| 场景五 | 验证数据集进入 ACT 训练前流程。                               | 训练前检查结果、交付报告。                  | 不回头修复上游数据，不扩展多格式导出。     |


## 四、场景间依赖

| 下游 | 直接依赖 |
|---|---|
| 场景二 | cleaned MCAP、夹爪语义、机械臂 base 坐标系位姿链路。 |
| 场景三 | MCAP_A / validated MCAP、滤波/补全/异常报告。 |
| 场景四 | aligned MCAP、alignment report、上游质量报告。 |
| 场景五 | LeRobotDataset v3、LeRobot 版本和 ACT 训练前检查要求。 |

## 五、L2/L3 生成约束

后续使用阶段二开发范式生成 L2/L3 时，必须遵守：

1. 不再把 `canonical_dataset_mcap/` 作为当前目标产物。
2. 场景四 L2/L3 必须面向 LeRobotDataset v3。
3. 场景五 L2/L3 只做训练前验证和交付，不做通用 exporter。
4. 场景二 L2/L3 不得重新引入 IK、关节限位、MuJoCo 仿真作为 P0 validated 输出。
5. 涉及真实 MCAP 的 L3 必须声明本机测试数据要求和 run 目录产物。
6. Service 场景最终验收必须由用户运行 `./start_data_clean.sh --dev`。
