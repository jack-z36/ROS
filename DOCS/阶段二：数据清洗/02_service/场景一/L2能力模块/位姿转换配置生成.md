# L2 能力模块说明：位姿转换配置生成

## 1. 能力名称

```text
位姿转换配置生成
```

## 2. 所属位置

阶段：阶段二：数据清洗
L1：service_s1
场景：场景一：提取夹爪开合以及位姿转换
模块类别：工具对接类
来源功能模块清单：`DOCS/阶段二：数据清洗/02_service/场景一/功能模块清单.md`

## 3. 一句话目标

```text
通过标定采样与位姿求逆，生成以单侧 UMI 初始坐标系作为 common_frame 的 FrameAlignmentConfig。
```

## 4. 核心方案

首版不再额外定义桌面 `origin_frame`。默认：

```text
common_anchor = left
common_frame = left_umi_start_frame
```

含义是：左手 UMI / 左 Baton Mini 启动时的初始坐标系，就是本条 episode 的公共坐标系。

当 `common_anchor: left` 时：

```text
common_from_left_start = Identity
T_common_left_camera(t) = T_left_start_left_camera(t)
T_common_right_camera(t) = T_common_right_start * T_right_start_right_camera(t)
T_common_tcp(t) = T_common_camera(t) * T_camera_tcp
```

其中 `common_from_right_start = T_common_right_start` 不是由固定底座直接给出。它通过一次右手标定采样间接生成：

```text
右手 Baton Mini 相机移动到 common_frame 对应的标定位姿
↓
读取右手 Baton Mini raw pose: T_right_start_common
↓
T_common_right_start = inverse(T_right_start_common)
↓
写入 FrameAlignmentConfig.extrinsics.common_from_right_start
```

`T_right_start_common` 表示：当右手相机处在 `common_frame` 标定位姿时，该标定位姿在 `right_start_frame` 下的位置和姿态。因为后续每帧转换需要的是 `right_start_frame -> common_frame`，所以配置生成器必须对采样得到的 `T_right_start_common` 求逆。

## 5. 现实代码入口

现有 `src/data_clean/ui/mcap_calibration_wizard.py` 已有旧 common frame 采样和 transform YAML 写回逻辑。L3 应在该入口上改造为 [[FrameAlignmentConfig]]，而不是继续扩展 `start_from_common` 旧方案。

## 6. 上游关系

- 默认 `common_anchor = left`，`common_frame = left_umi_start_frame`。
- 固定底座 / 标定位姿用于保证右手 Baton Mini 能被放到与 `common_frame` 定义一致的物理位姿。
- 右手 Baton Mini 在该标定位姿下输出 `T_right_start_common`。
- 配置生成器对 `T_right_start_common` 求逆，得到 `common_from_right_start`。
- 仍然需要左右 camera 到 TCP 的 [[CameraFromTcpExtrinsic]]，且矩阵方向必须统一。

## 7. 下游关系

- [[arm-base 位姿转换]] 使用 [[FrameAlignmentConfig]]。
- [[CommonFrameCameraPose]] 和 [[CommonFrameTcpPose]] 被写入 cleaned/canonical 数据产物。
- 场景二按 TCP common pose 做位姿滤波、异常检测和 IK 前置处理。

## 8. 职责边界

本能力负责：

1. 读取或接收标定采样得到的 `T_right_start_common`。
2. 对 `T_right_start_common` 求逆，生成 `common_from_right_start`。
3. 定义 `frame_alignment.common_anchor`、`pose_streams` 和 `extrinsics`。
4. 把旧 `start_from_common` 配置生成迁移到 `common_from_*_start`。
5. 统一 `camera_from_tcp` 命名和矩阵方向。

本能力不负责：

1. 判断人工把右手 Baton Mini 放到 `common_frame` 标定位姿是否足够准确。
2. 判断底座或夹具制造误差。
3. 执行滤波、IK 或异常修复。

## 9. 算法输入 / 处理 / 输出

### 9.1 输入

| 输入 | 含义 | 约束 |
|---|---|---|
| `common_anchor` | 公共坐标系锚点 | 默认 `left` |
| `pose_streams` | 左右 Baton Mini pose topic 信息 | 必须包含左右输入 topic |
| `T_right_start_common` | 右手 Baton Mini 位于 `common_frame` 标定位姿时输出的 raw pose | 表示 `common_frame` 标定位姿在 `right_start_frame` 下的位置和姿态 |
| 左右 camera/TCP 外参 | 相机中心和 TCP 之间的固定外参 | 必须统一使用 `camera_from_tcp` 或明确等价字段，不允许与 `tcp_from_camera` 混用 |

### 9.2 处理

1. 若 `common_anchor = left`，则：

   ```text
   common_from_left_start = Identity
   ```

2. 对右手标定采样求逆：

   ```text
   T_common_right_start = inverse(T_right_start_common)
   common_from_right_start = T_common_right_start
   ```

3. 写入 [[FrameAlignmentConfig]].`extrinsics`。
4. 保证外参命名方向统一，不允许把 `camera_from_tcp` 和 `tcp_from_camera` 混用。

### 9.3 输出

输出 [[FrameAlignmentConfig]]，至少包含：

| 字段 | 含义 |
|---|---|
| `frame_alignment.common_anchor` | 公共坐标系锚点，默认 `left` |
| `frame_alignment.pose_streams` | 左右 pose 输入 topic 与输出语义 |
| `extrinsics.common_from_left_start` | 左手 start frame 到 common frame 的外参，默认单位变换 |
| `extrinsics.common_from_right_start` | 右手 start frame 到 common frame 的外参，由 `inverse(T_right_start_common)` 得到 |
| 左右 camera/TCP 外参 | 用于后续 `T_common_tcp = T_common_camera * T_camera_tcp` |

## 10. 最小验收标准

| 检查项 | 预期 |
|---|---|
| 左 UMI 静止在底座内 | `left_camera_pose_common` 接近单位位姿 |
| 右 Baton Mini 放到 `common_frame` 标定位姿 | 求逆后的 `common_from_right_start` 应能让右手该帧转换结果接近单位位姿 |
| 左右同时静止 5 秒 | `left_tcp_pose_common`、`right_tcp_pose_common` 不明显漂移 |
| 已知方向移动 | common frame 下位置变化方向符合预期 |
| 左右 TCP 距离 | 接近底座 CAD 或人工测量距离 |
| 只做平移无旋转测试 | 求逆后的平移方向应与输入相反；但一般 SE(3) 位姿求逆不等于简单取负数 |

## 12. 给 L3 任务生成的约束

1. 默认 `common_anchor` 必须是 `left`。
2. 不允许只改字段名来切换左右 anchor，外参方向必须重新计算。
3. raw pose 必须保留，用于排查漂移、单位、四元数顺序和跳变。
4. 不允许把 `tcp_from_camera` 当成 `camera_from_tcp` 使用。
5. `common_from_right_start` 必须来自 `inverse(T_right_start_common)`，不能写成“固定底座直接给出”。
