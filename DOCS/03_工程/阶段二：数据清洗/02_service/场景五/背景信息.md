# 阶段二场景五：背景信息

## 场景定位

canonical dataset 是阶段二的标准中间态，但模型训练通常需要特定框架的数据格式。场景五负责把 canonical dataset 派生为阶段三可直接消费的训练数据。

本场景的核心原则是：训练格式是派生产物，canonical dataset 才是可信源。

## canonical dataset 与训练格式的关系

canonical dataset 保留统一语义：

- observation/action 的定义。
- episode 和 step 索引。
- masks 和 invalid reason。
- schema version 和处理追溯。

训练格式则服务于具体模型或框架，可能关注：

- 字段命名。
- 数组 shape。
- dtype。
- 图像保存方式。
- action horizon。
- 文件组织方式。

因此 exporter 必须读取 canonical dataset 的契约，而不是直接猜 topic 或绕过 masks。

## 导出原则

- exporter 只消费 canonical dataset。
- exporter 必须读取 schema，而不是硬编码猜测字段语义。
- exporter 必须按 masks 过滤不可训练 step。
- exporter 必须记录来源 episode、schema version、过滤统计和字段映射。
- `exports/` 是可再生派生产物，删除后应能从 canonical dataset 重新生成。

## 可能的导出目标

最终训练格式取决于阶段三模型选择。常见方向包括：

- LeRobot 类格式。
- HDF5 类数组格式。
- Zarr 类 chunked 数据格式。
- 其他由目标模型要求决定的格式。

本背景文件不提前规定必须先实现哪一种格式。

## 与阶段三的关系

场景五完成后，阶段三应能直接使用导出结果启动训练或至少通过最小读取脚本验证数据可加载。

如果阶段三模型格式尚未确定，本场景可以先停留在接口和约束设计层，不应过早实现无目标的 exporter。

## 风险与未知

- 目标模型和训练格式尚未最终确定。
- 图像保存方式会影响训练读取性能。
- 不同训练框架对 action、语言指令和多模态字段的要求可能不同。
- 第一版 exporter 应以最小可验证闭环为目标，避免一次性支持过多格式。
