# 工作流：从零编写程序

本工作流适用于用户需要从零开始创建新程序、新脚本、新模块或新功能的场景。当交互模式识别判定为"从零编写程序"时，必须按以下步骤严格执行。

## 适用条件

- 用户要求创建一个当前代码库中不存在的程序或模块
- 用户描述了一个全新的功能需求
- 用户明确说"写一个新程序"、"新建脚本"、"从零实现"等

不适用的情况：
- 对已有代码的小修小补
- 配置文件调整
- Bug 修复
- 已有功能的小幅增强

## 工作流步骤

### 步骤一：需求追问（grill-me）

**动作：** 使用 `/grill-me` skill 对用户进行持续追问，直到充分理解要编写的程序的全部细节。

必须追问清楚的维度：

1. **功能目标** — 这个程序最终要实现什么？解决什么问题？
2. **输入输出** — 输入是什么（文件、topic、参数）？输出是什么（文件、topic、日志）？
3. **运行环境** — 在哪里运行？（ROS2 节点、独立脚本、launch 启动）
4. **依赖关系** — 依赖哪些已有的包、库、节点？被谁调用？
5. **数据流** — 数据从哪来，经过什么处理，到哪去？
6. **边界条件** — 异常情况如何处理？有什么约束？
7. **成功标准** — 什么条件下算完成？如何验证？

**出口条件：** 当以上所有维度都有明确答案，且用户确认无误时，进入步骤二。

### 步骤二：定位阶段与场景，加载文档

**动作：** 根据用户描述的程序归属，定位到具体的阶段和场景，加载相关文档。

1. 根据程序功能判断属于哪个阶段（数据采集/数据清洗/模型训练/模型部署）
2. 阅读该阶段的四个阶段级文档
3. 判断属于哪个已有场景，或是否需要创建新场景
4. 如果属于已有场景，阅读该场景的五个固定文档
5. 如果需要新场景，使用 `ros-scene-docs` skill 创建场景文档体系

**出口条件：** 完成文档加载，明确程序所属阶段和场景，进入步骤三。

### 步骤三：产出程序蓝图并切换 Plan 模式

**动作：** 根据前两步收集的信息，整理出程序蓝图，然后提醒用户切换到 Plan 模式。

程序蓝图应包含：
- 程序名称和文件路径
- 核心功能和职责
- 输入输出规格
- 依赖列表
- 目录结构
- 关键接口设计
- 测试策略概述

**提醒用户：** "蓝图已整理完成，请切换到 Plan 模式（输入 `/plan`）以生成详细执行计划。"

**出口条件：** 用户切换到 Plan 模式后，生成执行计划，用户确认计划后进入步骤四。

### 步骤四：测试驱动开发（TDD）

**动作：** 使用 `/tdd` skill 按照红-绿-重构循环执行开发。

1. 根据执行计划，为每个功能模块编写测试
2. 运行测试，确认测试失败（红灯）
3. 编写最小实现代码使测试通过（绿灯）
4. 重构代码，确保测试仍然通过
5. 重复以上循环直到所有功能完成

**出口条件：** 所有测试通过，程序功能完整，进入步骤五。

### 步骤五：更新当前场景进度（handoff）

**动作：** 使用 `/handoff` skill 生成交接摘要，然后用交接内容更新当前场景的 `当前进度.md`。

1. 执行 `/handoff` 生成当前工作的完整交接文档
2. 将交接内容整理后写入当前场景的 `当前进度.md`
3. 确保进度文档准确反映：已完成的功能、待处理事项、已知风险

**出口条件：** 场景的 `当前进度.md` 已更新，进入步骤六。

### 步骤六：更新输出程序与文件、执行记录

**动作：** 更新场景级文档。

1. 在当前场景的 `输出程序与文件.md` 中追加本次新增的程序、脚本和配置文件条目
2. 在当前场景的 `执行记录.md` 中追加本次执行的完整记录，包括：
   - 日期时间
   - 用户需求描述
   - 实施过程
   - 遇到的问题和解决方案
   - 最终结论

**出口条件：** 场景的 `输出程序与文件.md` 和 `执行记录.md` 已更新，进入步骤七。

### 步骤七：更新阶段级文档

**动作：** 更新阶段目录下的当前进度和阶段产出文件。

1. 更新当前阶段的 `当前进度.md`，反映本场景的最新进展
2. 更新当前阶段的 `阶段产出.md`，追加本次新增的软件资产

**出口条件：** 阶段的 `当前进度.md` 和 `阶段产出.md` 已更新，工作流结束。

## 流程概览

```
grill-me 需求追问
       ↓
  定位阶段场景，加载文档
       ↓
  产出蓝图，提示切换 Plan 模式
       ↓
  生成并确认执行计划
       ↓
  tdd 测试驱动开发（红-绿-重构循环）
       ↓
  handoff 更新场景当前进度
       ↓
  更新输出程序与文件、执行记录
       ↓
  更新阶段当前进度、阶段产出
```
