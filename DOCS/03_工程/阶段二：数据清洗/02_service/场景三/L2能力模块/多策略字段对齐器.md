# L2 能力模块说明：多策略字段对齐器

## 1. 能力名称

```text
多策略字段对齐器
```

## 2. 所属位置

阶段：阶段二：数据清洗  
L1：service_s3  
场景：场景三：MCAP 多 topic 时间轴对齐  
模块类别：数据计算类  
来源功能模块清单：`DOCS/03_工程/阶段二：数据清洗/02_service/场景三/功能模块清单.md`

## 3. 一句话目标

```text
按字段策略把图像、位姿、触觉和夹爪等源数据映射到统一 step，并输出逐 step-field 的 FieldAlignmentResult。
```

## 4. 能力角色

本能力是场景三 P0 主链路的字段对齐算法层。它位于 [[统一Step时间轴生成器]] 之后、对齐索引与报告数据生成器之前，消费 [[StepTimeline]]、[[SourceTopicCatalog]]、[[McapAInputValidationSummary]]、[[Scene3AlignmentConfig]] 和 [[TargetFieldMapping]]，按 [[FieldAlignmentStrategy]] 输出 [[FieldAlignmentResult]]。

已按 `grill-me` 约束完成意图澄清：本能力新增 [[FieldAlignmentResult]] 作为第 4 模块到第 5 / 6 模块之间的中间数据；图像只保存引用；pose、gripper 和触觉聚合等轻量派生值允许内联；夹爪首版直接按 `step_time_ns` 最近邻，不跟随同侧图像；触觉窗口以 step 为中心，半宽为半个 step 周期；开发者入口独立暴露 `scene3_field_alignment_check`。

## 5. 上游关系

- 直接上游是 [[统一Step时间轴生成器]] 输出的 [[StepTimeline]]。
- 输入守门上游是 [[MCAP_A输入盘点与校验器]] 输出的 [[SourceTopicCatalog]] 和 [[McapAInputValidationSummary]]。
- 契约上游是 [[对齐契约与配置定义]] 输出的 [[Scene3AlignmentConfig]]、[[TargetFieldMapping]]、[[FieldAlignmentStrategy]] 和 [[FieldAlignmentStatus]]。
- 本能力只通过 repo / reader 读取 MCAP_A 源消息用于对齐计算，不修改 MCAP_A，也不重新盘点 topic/time/type。

## 6. 下游关系

- 对齐索引与报告数据生成器读取 [[FieldAlignmentResult]]，生成 [[AlignmentIndex]] 和 [[AlignmentReport]] 所需统计数据。
- aligned MCAP 与 sidecar 写出器读取 [[FieldAlignmentResult]] 中的引用和轻量派生值，写出 aligned MCAP。
- 开发者入口 `scene3_field_alignment_check` 读取小样本 timeline / catalog / config，输出字段对齐调试结果。
- 场景三完整 smoke test 间接依赖本能力，验证多模态字段都投影到同一条 step 时间轴。

| 上游功能 | 上游接口 / 产物 | 本能力如何依赖 | 对齐状态 | 处理方式 |
|---|---|---|---|---|
| 对齐契约与配置定义 | [[Scene3AlignmentConfig]] | 读取目标频率、策略、阈值和 target fields | 已对齐 | 复用 |
| 对齐契约与配置定义 | [[TargetFieldMapping]] | 确定每个字段的 source topic、output topic、modality 和 strategy | 已对齐 | 复用 |

| MCAP_A 输入盘点与校验器 | [[SourceTopicCatalog]] | 判断字段来源是否存在、类型是否匹配、时间戳是否可用 | 已对齐 | 复用 |

## 8. 职责边界

本能力负责：

1. 对每个 [[StepTimeline]] step 和每个可配置目标字段执行策略化对齐。
2. 实现图像最近邻、pose 插值+slerp、pose fallback 最近邻、触觉半 step 窗口聚合和夹爪最近邻。
3. 输出 [[FieldAlignmentResult]]，记录 source topic、source time、dt、状态、邻居、窗口、样本数、覆盖率、fallback reason、引用和轻量派生值。
4. 对非基准字段缺失、超时或不可用进行字段级降级表达，不阻塞其他字段。

本能力不负责：

1. 不生成 [[StepTimeline]]。
2. 不重新盘点 MCAP_A topic、message type、样本数或时间戳排序。
3. 不生成 [[AlignmentIndex]] 或 [[AlignmentReport]]。
4. 不写 aligned MCAP、Parquet、JSON report 或写出摘要。
5. 不决定训练 mask、episode 构建或 canonical dataset schema。

## 9. 计算职责

| 计算项 | 输入 | 输出 | 影响下游 |
|---|---|---|---|
| 字段可用性门控 | [[SourceTopicCatalog]].`field_entries`、[[TargetFieldMapping]] | `status=unavailable` 或继续对齐 | 避免非基准字段问题阻塞主链路 |
| 图像最近邻 | [[StepTimeline]]、图像 source topic 消息时间 | 图像字段 [[FieldAlignmentResult]] | aligned MCAP 写出器按引用写图像 |
| 夹爪最近邻 | [[StepTimeline]]、夹爪 source topic 消息时间和值 | 夹爪字段 [[FieldAlignmentResult]] | 第 6 模块写出轻量 gripper 值 |
| Pose 插值+slerp | [[StepTimeline]]、pose 前后邻居 | pose 字段 [[FieldAlignmentResult]] | 第 6 模块写出插值 pose |
| Pose fallback 最近邻 | 插值邻居不足或超阈值 | `status=fallback_nearest` 的 [[FieldAlignmentResult]] | 报告生成器统计 fallback 比例 |
| 触觉窗口聚合 | [[StepTimeline]]、触觉窗口内样本 | 触觉字段 [[FieldAlignmentResult]] | 第 5 / 6 模块消费聚合统计和值 |

## 10. 计算规则

| 规则 | 触发条件 | 计算 / 判断方式 | 结果表达 |
|---|---|---|---|
| 输入必须可消费 | [[McapAInputValidationSummary]].`status != consumable` | 不执行字段对齐 | 生成失败摘要或停止，由调用方表达 `input_not_consumable` |
| 字段不可用不阻塞 | `field_entries.availability != available` | 对该字段每个 step 输出不可用结果或按实现批量表达 | [[FieldAlignmentResult]].`status=unavailable` |
| 图像只做最近邻 | modality 为 `image` | 找 `step_time_ns` 最近样本，比较 `max_dt_ms` | 命中为 `aligned`，超阈值为 `timeout` |
| 夹爪直接最近邻 | modality 为 `gripper` | 直接对 `step_time_ns` 找最近样本，不依赖同侧图像 | 命中为 `aligned`，超阈值为 `timeout` |
| Pose 优先插值 | strategy 为 `interpolation_slerp` 且存在有效前后邻居 | position 线性插值，orientation 四元数 slerp | `status=interpolated`，内联轻量 pose 值 |
| Pose fallback | 前后邻居不足或插值邻居超阈值 | 按最近邻策略寻找 pose 样本 | `status=fallback_nearest`，填写 `fallback_reason` |
| 触觉半 step 窗口 | strategy 为 `window_aggregate` | 以 `step_time_ns` 为中心，窗口半宽为 step 周期一半 | `status=aggregated`，记录窗口、样本数和覆盖率 |
| 空触觉窗口 | 窗口内无样本 | 不生成聚合值 | `status=missing_time` |

## 11. 输出结果结构

| 字段 | 类型 | 含义 | 有效性要求 | 下游使用方式 |
|---|---|---|---|---|
| [[FieldAlignmentResult]] | result object / list | 逐 step-field 对齐结果 | 每个 `step_index + field_name` 最多一条主记录 | 第 5 模块汇总为 [[AlignmentIndex]] / [[AlignmentReport]] |
| `message_ref` | string/null | 原始消息引用 | 图像成功对齐时必填 | 第 6 模块读取原始 payload |
| `derived_value` | object/null | 轻量派生值 | pose / gripper / tactile 聚合成功时可填 | 第 6 模块写 aligned MCAP |
| `status` | [[FieldAlignmentStatus]] | 对齐状态 | 必须覆盖正常、插值、聚合、fallback、缺失、超时、不可用 | 第 5 模块统计 |
| `alignment_method` | string | 实际方法 | 不得只依赖 status 表达方法 | 人工复查和报告统计 |

## 12. 异常与边界输入

| 边界情况 | 预期结果 | reason / error 表达 | 是否阻塞下游 |
|---|---|---|---|
| 输入 summary 不可消费 | 不执行字段对齐 | `input_not_consumable` | 是 |
| 某个目标字段 topic 缺失 | 该字段输出不可用结果 | `unavailable` / `missing_topic` | 否 |
| 图像最近邻超阈值 | step 保留，图像字段超时 | `timeout` | 否 |
| 夹爪样本缺失或超阈值 | 夹爪字段缺失或超时 | `missing_time` / `timeout` | 否 |
| Pose 插值只有单侧邻居 | fallback 最近邻 | `fallback_nearest` + `missing_neighbor` | 否 |
| Pose 无任何可用样本 | pose 字段缺失 | `missing_time` | 否 |
| 触觉窗口无样本 | 触觉字段缺失 | `missing_time` | 否 |
| 字段策略未知 | 配置或实现错误 | `invalid_input` | 是，停止当前字段或当前 run |

## 13. 可验证样例

| 样例 | 输入特征 | 预期输出 | 验证方式 |
|---|---|---|---|
| 图像命中 | step 附近存在图像样本且未超阈值 | `status=aligned`，`message_ref` 非空 | service test |
| 图像超时 | 最近图像样本超 `max_dt_ms` | `status=timeout`，不删除 step | service test |
| 夹爪最近邻 | 夹爪样本距离 step 最近 | 直接按 step 选样，不读取图像结果 | service test |
| Pose 插值 | step 落在两个 pose 样本之间 | position 插值、orientation slerp，`status=interpolated` | numeric test |
| Pose fallback | 缺少前邻居或后邻居 | 最近邻结果，`status=fallback_nearest` | fallback test |
| 触觉聚合 | 半 step 窗口内有多个触觉样本 | `status=aggregated`，样本数和覆盖率正确 | aggregation test |
| 字段不可用 | catalog 标记 optional 字段缺失 | 输出 `status=unavailable`，其他字段继续 | degradation test |

## 18. 给 L3 任务生成的约束

后续从本 L2 生成 L3 任务时，必须遵守：

1. 每个 L3 只能解决一个核心目标。
2. 每个 L3 必须先判断任务类别，并使用对应 L3 类别模板。
3. 本能力拆出的 L3 必须写入功能组 `service-s3-g4`，不得混入 `service-s3-g1`、`service-s3-g2` 或 `service-s3-g3`。
4. 每个 L3 必须复用 [[StepTimeline]]、[[SourceTopicCatalog]]、[[McapAInputValidationSummary]]、[[Scene3AlignmentConfig]]、[[TargetFieldMapping]] 和 [[FieldAlignmentResult]]。
5. 第 4 模块不得生成 [[AlignmentIndex]]、[[AlignmentReport]]、aligned MCAP 或写出摘要。
6. 图像字段不得内联完整 payload，只能保存引用和对齐元数据。
7. pose、gripper 和触觉聚合等轻量派生值允许内联到 [[FieldAlignmentResult]]。
8. 夹爪首版必须直接按 `step_time_ns` 最近邻，不跟随同侧图像来源时间。
9. 触觉窗口必须以 `step_time_ns` 为中心，半宽为半个 step 周期，并记录窗口范围、样本数和覆盖率。
10. 每个 Service 场景 L3 必须写明它对应或影响 `./start_data_clean.sh --dev` 下的 `scene3_field_alignment_check` 或场景三完整 smoke test。
11. L3 自动化验收只证明局部实现正确；场景最终验收必须由用户本人运行 `./start_data_clean.sh --dev` 后确认。
