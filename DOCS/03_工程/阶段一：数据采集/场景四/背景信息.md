## 2. 为什么新增本场景

场景三已经把重点放在 Octopus 订阅 8 个目标 topic、选择录制 topic、生成 MCAP 文件上。

用户最新指出，当前 Octopus UI 还存在两个影响实际操作的问题：

- 操作页面中 topic 列表区域高度不足，虽然下面仍有大量空白空间，但部分 topic 被隐藏，需要滚动鼠标滚轮才能查看。
- 主显示界面仍是旧任务的显示布局，例如左右手触觉、左右手视觉、头部视觉等，不符合当前需要查看左右手 GoPro、左右手位姿和左右手触觉数据的目标。

因此场景四专门记录 Octopus UI 改造任务，避免把 UI 布局需求混入场景三的 MCAP 录制验收中。

## 5. 相关 Octopus 模块

根据 `DOCS/Octopus_architecture.md`，场景四可能涉及以下 Octopus 模块：

| 模块 | 可能职责 |
| --- | --- |
| `octopus/src/mainwindow.cpp` | 组装主窗口、创建显示订阅、把 ROS2 消息路由到页面组件。 |
| `octopus/src/pages/op-panel.cpp` | Operation / 操作面板，显示录制 topic 列表并触发开始 / 停止录制。 |
| `octopus/src/pages/image-widget.cpp` | 图像面板，可用于 GoPro `sensor_msgs/msg/Image` 显示；场景四增量要求在画面上显示实时 FPS。 |
| `octopus/src/pages/odometry-panel.*` | 场景四新增位姿面板，显示 `nav_msgs/msg/Odometry` 数值和 xyz 曲线。 |
| `octopus/src/pages/pressure-panel.*` | 场景四新增触觉面板，显示同手两路 `PressureFrame` 热力图和统计值。 |
| `octopus/src/pages/joint-state-panel.cpp` | 当前关节状态图表实现，可作为位姿数据图表化显示的参考，但 odometry 不等同于 joint state。 |
| `octopus/src/pages/hand-panel.cpp` | 原有触觉手模型面板，可作为触觉显示参考，但当前压力数据类型和旧 Inspire tactile image 不同。 |
| `octopus/src/mcap-recorder.cpp` | 录制链路，应保持与显示链路解耦，除非发现 UI 改造影响录制配置。 |
| `octopus/src/utils/config.*` | 默认 topic、显示配置、录制配置可能从这里读取或保存。 |

当前 Octopus 源码位于：

```text
src/data_collection/VTLA_octopus-master/octopus
```

## 6. 系统链路位置

场景四处在整体链路的显示层和操作层：

```text
传感器节点 / ROS2 topic
    ↓
Octopus 显示订阅
    ↓
Operation 面板完整展示 topic
    ↓
GoPro / 位姿 / 触觉数据可视化面板
    ↓
用户确认数据状态并操作采集
```

录制链路仍应沿用场景三：

```text
Operation 面板
    ↓
McapRecorder
    ↓
generic ROS2 subscriptions
    ↓
MCAP writer
    ↓
.mcap 文件
```

显示链路和录制链路必须继续保持解耦。

## 7. 当前已知风险和未知项

已知风险：

- 操作页 topic 列表布局可能由固定高度、dock 布局或控件 stretch 策略导致，需要从 `op-panel.cpp` 和外层 dock 布局共同排查。
- 原有触觉显示链路可能面向 `sensor_msgs/msg/Image` 类型触觉图，不一定能直接显示 `hwk_pressure_interfaces/msg/PressureFrame`。
- 原有关节状态图表面向 `sensor_msgs/msg/JointState`，不能直接等同于 `nav_msgs/msg/Odometry` 位姿显示。
- UI 改造不得破坏已修复的 MCAP 录制 topic 列表、QoS 兼容和 schema 支持。

待确认：

- 左右手位姿数据最终需要显示为数值、曲线、轨迹，还是简化状态面板。
- 四路压力数据最终需要显示为热力图、曲线、数值表，还是左右手汇总状态。
- 目标窗口尺寸和布局是否需要适配不同分辨率。
- 是否需要保留旧显示面板作为可选视图，还是完全移除旧布局。
