## 1. 原子结论

L2-06 从 `ActionChunk` 取出的 `raw single action` 是 shape 为 `(16,)` 的单步动作。其中左右 TCP 段表达的是**绝对目标位姿**，不是“本拍移动多少”的增量指令。

因此，L2-04 不能只看当前 raw action 就判断“单步变化是否超限”。它必须把当前绝对目标与一个具有明确语义的绝对位姿基准进行比较：

对当前第一版负责的 TCP 平移检查：

```text
tcp_xyz_delta = current_raw_target_xyz - comparison_anchor_xyz
```

quaternion 姿态变化不能用四个分量直接相减；若后续把旋转 delta 纳入 L2-04，必须在详细设计中另行定义相对旋转度量。本文不把该算法伪装成已确认边界。

比较基准只用于计算变化量，不参与生成模型动作，也不把绝对位姿改写成增量动作。

## 2. 输入及其唯一用途

| 输入 | 创建或维护方 | L2-04 中的用途 | 明确不代表什么 |
|---|---|---|---|
| `raw single action, shape (16,)` | L2-06 从 active chunk 按 cursor 取出 | 提供本拍左右 TCP 绝对目标位姿和夹爪目标，作为被检查对象。 | 不是 TCP 位姿增量，不包含比较基准。 |
| `previous safe action` | L2-06 维护 | 提供上一拍已经通过 L2-04 的绝对目标位姿，用于检查相邻安全目标指令的连续性。 | 不等于机器人当前实测位姿，也不证明该动作已被驱动器执行。 |
| `latest ObservationSnapshot` | L2-02 创建并写入 latest-only buffer，L2-06 读取后传入 | 在其新鲜且能暴露左右 TCP pose 时，提供机器人当前实测绝对位姿；可用于首拍/缺少 previous action 时建立基准，或用于检查目标与实测状态的偏差。 | 不是上一拍安全指令，也不由 L2-04 创建或维护。 |
| `SafetyConfig` | L2-01 | 提供单步变化阈值及相关安全策略参数。 | 不负责提供运行时位姿状态。 |

`previous safe action` 与 `latest ObservationSnapshot` 不能互相冒充：

- 前者回答“相邻两拍安全目标指令是否连续”；
- 后者回答“目标是否远离机器人当前实测状态”，并可在首拍提供启动基准。

是否只采用其中一个、按优先级回退，或同时执行两类检查，属于 L2-04 的详细算法设计；不得通过模糊命名把两种安全语义合并为同一个判断。

## 3. 所有权与协作边界

```text
L2-01 SafetyConfig -------------------------┐
L2-02 latest ObservationSnapshot -----------┤
L2-06 raw single action + previous safe ----┼-> L2-04 SafetyGuard -> SafetyResult
                                            └-----------------------> L2-06 决定 fallback / publish
                                                                        -> L2-05 执行外部输出
```

L2-04 负责：

- 消费传入的 RAM 对象，对绝对目标位姿执行单步变化计算和安全判断；
- 保证每一种比较都使用语义匹配的基准；
- 在 `SafetyResult` 中给出可定位的检查结果或原因。

L2-04 不负责：

- 创建 raw action，或管理 `ActionChunk`、cursor、active chunk；
- 持有 `previous safe action` 或维护 `latest ObservationSnapshot`；
- 把“上一拍已通过的目标”宣称为“机器人已经到达的位置”；
- 选择 hold、continue-old-chunk、safe-stop 等 fallback；
- 发布 ROS topic、转换硬件命令、调用硬件 SDK；
- workspace、IK、碰撞、急停、deadman、hardware gate 等硬件级安全检查。

## 4. 必须保持的不变量

1. 当前 16D TCP action 必须始终按绝对目标位姿解释，任何下游不得按增量位姿消费。
2. 单步变化检查必须显式声明使用的是“上一安全目标基准”还是“当前实测位姿基准”。
3. `previous safe action` 只能表示上一拍通过 L2-04 的安全目标；它不能替代硬件反馈。
4. `latest ObservationSnapshot` 用作基准前必须满足 freshness 和 TCP pose 可用性要求；缺失或过期必须成为显式状态，不能静默使用零向量。
5. 两种基准都不可用时不得伪造零位姿或其他隐式基准；是跳过该检查、返回拒绝还是请求 fallback，由详细设计和配置决定，并且该分支必须可测试、可观测。
6. L2-04 全程只做 RAM 内计算，不读取 ROS topic、不访问硬件、不拥有 runtime 时序。

## 5. 已确认边界与后续设计项

### 5.1 已确认

- raw single action 的 TCP 段是绝对目标位姿。
- `previous safe action` 和 `latest ObservationSnapshot` 都是比较基准输入，不是动作生成输入。
- 两个基准分别表达“指令连续性”和“实测状态关系”，语义不可混用。
- L2-04 只负责检查并返回 `SafetyResult`；状态持有、fallback 和外部输出属于其他 L2。

### 5.2 不由本原子边界决定

- 只检查上一安全目标、只检查实测位姿，还是两者都检查；
- 两个基准同时存在时的优先级和组合规则；
- 超限后采用 clamp 还是 reject；
- 平移阈值、旋转阈值、quaternion 容差和夹爪值域；
- 两个基准都不可用时的运行策略。

这些项目必须在 L2-04 的 ACT 微元设计、`SafetyConfig` 和 L2 Gate 中显式确定，不能由实现 Agent 自行猜测。
