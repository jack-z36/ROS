# L2-03 功能边界：ObservationSnapshot 到 ActionChunk

> [!info] 边界来源
> 本文只细化当前 L1 中已经确认的 L2-03 业务边界。Pi0.5 和 LeRobot ACT 源码只能帮助决定内部组织方式，不能扩大消费内容、产出内容或运行职责。

## 1. 一句话职责

L2-03 使用启动期已经进入当前 Python 进程 RAM 的配置、两个 normalizer 和 ACT policy，把一个合法 `ObservationSnapshot` **同步**加工为一个只含物理 actions 的 `ActionChunk`。

“同步”只定义函数语义：一次调用成功返回一个完整 chunk，失败抛出明确异常。调用时机、执行线程、排队方式和失败后的运行策略全部属于 L2-06。

## 2. 输入边界

### 2.1 启动期稳定依赖

```text
DeployConfig
state_normalizer: ActionStateNormalizer
action_normalizer: ActionStateNormalizer
已加载并完成 device/eval 等启动配置的 ACT policy
```

约束：

- 四项依赖由 L2-01 创建或加载，由 L2-06 在组装阶段注入 L2-03。
- L2-03 可以长期持有这些引用，但按只读依赖使用。
- `state_normalizer` 与 `action_normalizer` 是两个独立实例，不得交换或合并。
- L2-03 不接收 bundle、manifest、normalizers 文件、experiment config 或 checkpoint 路径。
- 测试 policy 可以通过相同接口注入，但真实/测试 policy 的选择和加载不属于 L2-03。

### 2.2 单次业务输入

```text
ObservationSnapshot
├── images: Mapping[logical_camera_name, model_ready_image]
├── state: structured observation state
├── encoded_state: np.ndarray (16,), physical semantics
└── captured_at_s: snapshot time metadata
```

L2-03 实际读取 `images` 和 `encoded_state`。`state` 可供上游诊断，但不重新编码；`captured_at_s` 不参与本 L2 计算，也不透传到输出。

### 2.3 图像前置契约

`ObservationSnapshot.images` 必须已经由 L2-02 完成模型像素级预处理：

- 使用训练/部署契约要求的相机、颜色、尺寸、通道布局、dtype 和数值约定。
- 单张图像尚未添加 batch 维。
- key 使用稳定的逻辑相机名；L2-03 只做与 `observation.images.<camera>` 的确定性键绑定。

L2-03 只验证该契约并完成 tensor/batch/device 适配，不 resize、不换色、不缩放、不根据数值猜测图像范围，也不补做未注入统计量的视觉归一化。

## 3. 输出边界

成功时只返回：

```text
ActionChunk
└── actions: np.ndarray
    ├── shape: (chunk_size, 16)
    ├── dtype: float32
    ├── values: 全部有限
    └── semantics: 已从模型尺度恢复到部署侧物理 action 尺度
```

每一行的 16D 段序固定为：

| 段 | 物理语义 | 单位/值域 | 坐标系 |
|---|---|---|---|
| `[0:3]` | 左 TCP position | `m` | `left_arm_base` |
| `[3:7]` | 左 TCP quaternion `(x,y,z,w)` | 模长约为 1 | `left_arm_base` |
| `[7:10]` | 右 TCP position | `m` | `right_arm_base` |
| `[10:14]` | 右 TCP quaternion `(x,y,z,w)` | 模长约为 1 | `right_arm_base` |
| `[14]` | 左夹爪开合值 | ACT `[0,1]` 物理语义 | 无 |
| `[15]` | 右夹爪开合值 | ACT `[0,1]` 物理语义 | 无 |

`ActionChunk` 明确不含：

```text
request_id
observation/inference/ready time
latency/action_dt
queue or worker state
retry/error/fallback state
cursor or selected step
```

L2-03 把 `ActionChunk` 交给 L2-06。L2-06 选择单步 raw action 后，L2-04 才消费该单步 action；L2-04 不直接消费整个 chunk。

## 4. 内部宏观流程

```text
总编排入口
├── 一级阶段一：Observation 批次准备
│   ObservationSnapshot -> policy device 上的 ACT batch
├── 一级阶段二：ACT 前向推理
│   ACT batch -> raw normalized action tensor
└── 一级阶段三：ActionChunk 后处理
    raw normalized action tensor -> physical ActionChunk
```

三个一级阶段是 L2-03 对整体功能的第一次封装；总入口只负责串联，不把 batch 或 raw tensor 暴露给 L2-06。

## 5. 负责内容

- 从 snapshot 取得 `encoded_state` 与所需图像。
- 检查 snapshot 与 ACT 模型输入结构是否兼容；这不是 freshness 检查。
- 把 16D physical state 转成 CPU float tensor。
- 只调用一次 `state_normalizer.normalize()`。
- 把模型就绪图像绑定到 policy 声明的 `observation.images.*` key。
- 添加 batch 维并把完整 batch 对齐到 policy device。
- 只调用 `policy.predict_action_chunk(batch)` 完成一次 chunk 前向计算。
- 严格验证 raw policy 输出的类型、rank、batch、chunk 和 action 维度。
- 去除 batch 维，只调用一次 `action_normalizer.unnormalize()`。
- 转成 CPU、连续的 `np.ndarray`，最终 dtype 固定为 `float32`。
- 严格验证最终 shape、dtype 和有限值后构造 `ActionChunk`。
- 失败时不返回伪造、部分或修补后的 chunk。

## 6. 不负责内容

### 6.1 启动资源

- 不读取配置文件或 bundle。
- 不加载 manifest、normalizer 参数、experiment config、checkpoint 或 adapter。
- 不创建 normalizer。
- 不构建、选择、加载、移动、compile 或启动配置 policy。
- 不实现生产 fake-policy 分支。

### 6.2 Observation

- 不订阅或解码 ROS observation message。
- 不维护 observation 字段缓存。
- 不执行图像像素级预处理。
- 不检查字段采集时间或 snapshot freshness。
- 不重建 16D state 段序。

### 6.3 推理运行

- 不调用 `policy.select_action()`。
- 不创建 thread、worker、timer、queue 或 `InferenceRequest`。
- 不决定何时发起推理，不限频，不 timeout、不取消、不 retry。
- 不记录 request ID、时间、latency、计数器、日志策略或 runtime metrics。
- 不维护 active chunk、cursor、历史 chunk 或单步选择。

### 6.4 Action 与输出

- 不 clamp raw normalized action。
- 不 crop、pad、重复或静默修补 chunk。
- 不交换 16D 段序。
- 不做 action smoothing、temporal ensemble、跨 chunk 融合或 RTC。
- 不做 L2-04 的安全判断。
- 不构造或发布 ROS message，不调用机器人硬件。

## 7. 状态、副作用与并发

| 项目 | L2-03 结论 |
|---|---|
| 稳定状态 | 只持有 config、两个 normalizer、policy 及从其提取的只读输入规格 |
| 单次中间值 | batch、raw tensor、physical array；只存在于当前调用栈 |
| 可变调度状态 | 无 |
| 进程外副作用 | 无 |
| 调用并发 | L2-03 不建锁、不调度并发；L2-06 默认应串行调用同一个 policy 实例 |
| 失败处理 | 异常直接返回 L2-06；L2-03 不吞没、不重试、不 fallback |

GPU tensor 搬运和 policy 前向在本设计中属于 RAM/tensor 业务计算，不等于向机器人硬件写命令，也不产生持久化外部状态。

## 8. 失败边界

| 失败类别 | L2-03 行为 | 明确禁止 |
|---|---|---|
| state 不能 tensor 化 | 抛明确输入转换异常 | 用零向量替代 |
| state normalize 失败或产出非法值 | 抛异常 | 跳过 normalizer |
| 必需图像缺失或 shape/dtype 不兼容 | 抛输入契约异常 | 按 dict 顺序猜相机、静默 resize |
| batch/device 对齐失败 | 抛底层异常并保留原因链 | 自动切换 device |
| policy 前向失败 | 原样或带上下文向上抛出 | retry、返回旧 chunk |
| raw 输出不是 `(1, chunk_size, 16)` | 拒绝 | 截断、补齐或 squeeze 任意维 |
| raw/final action 含 NaN/Inf | 拒绝 | clamp 或替换异常元素 |
| action unnormalize 失败 | 拒绝 | 把 normalized action 当物理 action 返回 |

L2-06 负责把这些失败映射为运行状态、metrics、旧 chunk 继续或其他 fallback。

## 9. 代码层落点

| 层 | 本 L2 是否新增产物 | 边界 |
|---|---|---|
| `types/` | 是 | `ActionChunk`，只含 actions |
| `config/` | 否 | 复用 L2-01 `DeployConfig` |
| `repo/` | 否 | normalizer 和 loaded policy 均由 L2-01 提供 |
| `service/` | 是 | 一个 inference service class、三个一级阶段函数及纯计算辅助函数 |
| `runtime/` | 否 | 所有时间/线程/queue/chunk 生命周期归 L2-06 |
| `ui/` | 否 | ROS 输入归 L2-06，ROS command 输出归 L2-05 |

推荐源码树：

```text
src/model_deploy/act/
├── types/action_chunk.py
└── service/
    ├── act_inference.py
    ├── observation_batch.py
    └── action_chunk_postprocess.py
```

## 10. 上下游协作

```text
L2-01 -> DeployConfig + state/action normalizer + loaded policy
L2-02 -> ObservationSnapshot
L2-06 -> 组装 L2-03 service，并在自有推理运行轴中同步调用
L2-03 -> ActionChunk
L2-06 -> 添加 request/time/error 运行记录，管理 active chunk/cursor
L2-06 -> 选择 raw single action
L2-04 -> 对 raw single action 做必要安全检查
```

## 11. 完成判据

- 不依赖 ROS、worker、queue 或真实时钟即可直接单测一次同步调用。
- 合法 snapshot 经三个一级阶段得到严格 `(chunk_size,16)`、`float32`、有限值的 `ActionChunk`。
- state tensor 转换与 state normalize 是两个独立可验收微元。
- stub policy 证明只调用 `predict_action_chunk` 一次，绝不调用 `select_action`。
- state/action normalizer 各在正确阶段调用且各调用一次。
- raw shape 不匹配时严格失败，不存在 clamp/crop/pad/reorder。
- `ActionChunk` 只有 actions，不存在任何运行元数据字段。
- L2-03 新增源码只落在 `types/`、`service/` 和对应测试目录。

## 12. 已确认事项

本轮设计已经确认：

1. 三个一级阶段加一个极薄总入口。
2. State tensor 表达转换与 State 数值归一化解耦。
3. 一个无调度状态的 service class 聚合稳定依赖。
4. 输入/输出辅助计算分别聚合到两个 service 文件。
5. `types/` 只新增 `ActionChunk`；`config/repo/runtime/ui` 不新增 L2-03 产物。

本文不再保留 fake-policy 策略、repo policy loader 或 ActionChunk 时间字段等旧待决项。
