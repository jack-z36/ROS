## 环境 B：model_deploy 环境

**目标**：跑通 `src/model_deploy/act/` 的推理逻辑和全部单元测试。后续连真机时再补 ROS/硬件驱动。

### B1. 创建环境（按约束文档约定，全局命名）
```bash
conda create -n model_deploy python=3.12 -y
conda activate model_deploy
```
- 用 `-n`（name）建全局命名环境 `model_deploy`，遵循 `16_环境依赖配置行为.md` 强制规定。
- 验证：`conda info --envs` 看到 model_deploy；`python --version` = 3.12.x。

### B2. 安装 PyTorch（cu128，RTX 5080 Blackwell 必需）
```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
```
- **必须用 cu128 索引**（非默认 cu13x）：RTX 5080 是 Blackwell sm_120 架构，需 PyTorch >= 2.7.0 + CUDA 12.8 wheel。从 cu128 索引拉取的是专门为此构建的 wheel。
- 验证 GPU：
```bash
python -c "import torch; print('torch', torch.__version__); print('cuda:', torch.cuda.is_available()); print('gpu:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'N/A')"
```
预期：`cuda: True`，`gpu: NVIDIA GeForce RTX 5080`。

### B3. 安装 act 其余依赖
```bash
pip install numpy pyyaml opencv-python pytest
```
- act 核心层只需 `torch+numpy+pyyaml`，opencv 可选（有 numpy 回退），pytest 跑测试。
- **不装 lerobot/transformers/peft/diffusers**：这些是 pi05 专用，你 pi05 只阅读不运行。

### B4. 验证 model_deploy 环境（跑 act 全部测试）

### B5. 创建依赖清单文件 + 修正文档命名冲突
- 在 `src/model_deploy/` 下创建 `environment.yml` 和 `requirements.txt`，锁定 torch cu128、numpy、pyyaml、opencv、pytest 版本，并注释说明 RTX 5080 需 cu128 索引。修复 pi05/README 引用缺失文件的问题。

## 不做的事（明确边界）

- **不碰 data_collection**（C++ ROS 编译不适合 conda）。
- **不装 lerobot 全家桶**（pi05 只阅读）。
- **不装 CUDA Toolkit（nvcc）**（PyTorch wheel 自带 CUDA runtime，act 不编译 CUDA 扩展）。
- **不在 ~/.bashrc 做永久改动**（用 conda activate 临时激活）。
- **现在不集成 ROS rclpy 到 model_deploy 环境**（act 核心层无需 ROS 即可跑测试；等真连机时再处理 rclpy 集成，作为后续独立任务）。
- **不装硬件驱动**（未连真机）。
- **不动 data_clean 的 forge bridge 部分**（`/home/hit/forge` 源码不存在，最终 LeRobot v3 转换暂不可用，但前面的清洗/对齐链路完整可用）。

## 风险与应对

1. **PyPI 不可达**：第 0 步会先发现。应对：尝试清华/阿里镜像源，或手动从可达机器下载 wheel 再本地安装。会停下问你。
2. **torch cu128 wheel 体积大（约 2-3GB）**：首次下载慢，耐心等待。
3. **data_clean 的 mcap 包 PyPI 装失败**：若第 0 步 PyPI 可达但 mcap 单独失败，会报告具体错误，不擅自换不完整副本（文档明确警告 octopus 3rdparty 副本缺文件）。
