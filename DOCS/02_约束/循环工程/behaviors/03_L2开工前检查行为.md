# L2 开工前检查行为

## 消费 Agent

- 主 Agent

## 本文职责

本文只约束主 Agent 在目标 L2 开工前必须完成的分支、工作区、远端、Gate 前置和共享文件检查。

## 不负责

本文不定义 Git 提交过程、不选择 L3、不执行验收。

## 检查项

| 检查 | 要求 |
|---|---|
| 当前分支 | 必须等于目标 L2 分支，或工作区干净时切换到目标 L2 分支 |
| 工作区 | 不得存在其他 L2 的未提交改动 |
| 远端 | remote 必须是 `origin`，URL 必须是 `https://github.com/jack-z36/ROS.git` |
| 上游 Gate | 目标 L2 的上游 Gate 必须满足依赖要求 |
| dispatch | 目标 L2 dispatch 必须存在且可解析 |
| 验收目录 | 目标 L2 `05_acceptance/<l2>/` 必须存在 |
| L2 身份 | 目标 L2 必须属于新版第一版 6 个功能闭环 L2 ID |
| 设计目录 | 目标 L2 必须存在新版 L2 设计目录，并引用 L1 Agent 架构上下文 |
| legacy 隔离 | 目标 L2 不得来自 `_legacy_layer_based_act/`、`_archived_pi05/` 或旧 layer-based L2 ID |
| 共享文件 | 有共享文件时必须声明 owner 和串行顺序 |

## 阻断条件

任一检查失败，主 Agent 必须停止本轮 L2 推进并记录阻断原因。

## 禁止事项

- 禁止在 `model_deploy` 上执行 L3 实现或提交。
- 禁止在工作区混杂时切换分支。
- 禁止忽略中文 Git 提示或长输出中的分支变化。
- 禁止以旧 L2 ID 或 legacy 目录作为开工目标。
