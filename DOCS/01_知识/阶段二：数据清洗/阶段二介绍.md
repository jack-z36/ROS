# 阶段二：数据清洗

## 1. 阶段目标

**本阶段定位**：阶段二是数据处理的中枢环节，负责把阶段一采集得到的 raw MCAP 处理成 LeRobotDataset v3，用于 PI0.5 / ACT 训练前输入。它不是简单另存 MCAP，而是要把多 topic 原始日志逐步整理成 step 级 observation/action 数据。

**本阶段输入**：raw MCAP（阶段一产物）
- 包含双目图像、双臂位姿、触觉和夹爪宽度的多 topic 日志
- 原始传感器数据，未经清洗和对齐

**本阶段输出**：LeRobotDataset v3
- 标准训练数据集格式
- 包含 observation.state（默认 32 维）和 action（默认 16 维）
- 支持 PI0.5 / ACT 训练框架
- 包含配置快照、处理报告、质量摘要和可追溯产物

**支撑下游**：
- 阶段三（模型训练）：提供训练数据集
- 阶段四（模型部署）：共享数据定义和消息契约

**本阶段不负责**：
- 不启动 Octopus，不负责实时采集
- 不修改原始 MCAP；所有处理写入独立产物目录
- 不做实时数据处理，所有操作都是离线批处理
- 不决定训练策略（差分、相对化等属于训练侧）

**注意事项**：
1. **topic 世界 vs step 世界**：理解从多 topic 原始日志到 step 级数据的转换
2. **双时间戳**：图像用 `header.stamp`，位姿用 `publish_time`，触觉用 `header.stamp`
3. **action 语义**：`action_t = target at step t+1`，是绝对动作，差分属于训练侧
4. **坐标系分离**：左右手 TCP pose 分别属于 `left_arm_base` 和 `right_arm_base`
5. **format-only vs formal**：`format-only` 只用于开发 smoke，正式生产需要 arm-base pose

## 4. 下一步优化方向

| 优化方向 | 当前问题 | 优化目标 | 优先级 |
|---|---|---|---|
| 正式 canonical dataset | 当前 LeRobot v3 是临时桥接路径 | 建立 MCAP-centric canonical dataset | P0 |
| IK 求解器 | 场景二缺少运动学验证 | 集成 IK 求解器进行轨迹可行性验证 | P1 |
| 关节限制检查 | 无法检测关节超限 | 增加关节限制、速度/加速度限制检查 | P1 |
| MuJoCo 仿真验证 | 缺少仿真环境验证 | 集成 MuJoCo 进行轨迹仿真验证 | P2 |
| 性能优化 | 大数据量处理时性能瓶颈 | 优化批处理性能和内存使用 | P2 |
| 错误恢复增强 | 部分异常处理可以更完善 | 增强错误恢复和重试机制 | P2 |

## 5. 快速上手指南

### 5.1 环境准备
```bash
# 确保已安装依赖
# 系统依赖
sudo apt install python3-serial python3-yaml
sudo apt install ros-jazzy-v4l2-camera v4l-utils

# Conda 环境会自动创建
# 路径：src/data_clean/.conda-envs/data-clean/
```

### 5.2 编译与启动
```bash
# 进入工作空间
cd 01-doing/ROS

# 启动 Web UI（推荐）
./start_data_clean.sh

# 或命令行模式
./start_data_clean.sh --cli --latest 1
```

### 5.3 数据处理流程
1. **Web UI 模式**：
   - 打开浏览器访问 `127.0.0.1`
   - 新建任务，选择输入目录
   - 预览 MCAP 文件，确认健康状态
   - 创建任务，等待处理完成
   - 查看结果和质量报告

2. **命令行模式**：
   ```bash
   # 处理最新 1 个 MCAP
   ./start_data_clean.sh --cli --latest 1
   
   # 处理所有 MCAP
   ./start_data_clean.sh --cli --all --workers auto
   
   # 干运行（不实际处理）
   ./start_data_clean.sh --cli --dry-run --latest 5
   ```

### 5.4 验证输出
```bash
# 检查 LeRobotDataset v3 结构
ls -la asset/阶段二：数据清洗/prod/exports/lerobot/<dataset_name>/

# 查看质量报告
cat asset/阶段二：数据清洗/prod/exports/lerobot/<dataset_name>/reports/forge_quality.json

# 查看 observation.state 维度
python3 -c "
import json
with open('asset/阶段二：数据清洗/prod/exports/lerobot/<dataset_name>/meta/info.json') as f:
    info = json.load(f)
print('observation.state dim:', info['features']['observation.state']['shape'])
print('action dim:', info['features']['action']['shape'])
"
```

### 5.5 常见问题
1. **Conda 环境问题**：确保 `start_data_clean.sh` 能找到 `.conda-envs/data-clean/`
2. **MCAP 读取失败**：检查 MCAP 文件是否完整，schema 是否匹配
3. **位姿异常**：检查 Baton Mini 位姿 topic 是否正常，单位是否正确
4. **Web UI 无法访问**：检查端口是否被占用，或尝试 `127.0.0.1:8000`
5. **质量分数低**：查看 `reports/forge_quality_flagged.json` 了解具体问题

## 6. 数据处理流水线

### 6.1 主数据链路
```text
raw MCAP
  -> [场景一] cleaned MCAP
  -> [场景二] MCAP_A
  -> [场景三] aligned MCAP
  -> [临时桥接] forge_ready.mcap
  -> [Forge Python fallback] LeRobotDataset v3
```

### 6.2 各阶段产物语义

| 产物 | 语义 | 主要下游 |
|---|---|---|
| raw MCAP | 阶段一采集的原始多 topic 日志 | 场景一清洗 |
| cleaned MCAP | 补齐夹爪宽度、位姿派生和基础清洗后的 MCAP | 场景二可靠性处理 |
| MCAP_A | 经过异常检测、修复、滤波和主数据写出的中间 MCAP | 场景三 step 对齐 |
| aligned MCAP | 按统一 step 时间轴对齐后的语义 MCAP | LeRobot v3 构建 |
| LeRobotDataset v3 | 当前阶段二目标数据集格式 | PI0.5 / ACT 训练前检查 |

### 6.3 observation/state 语义（默认 32 维）

| 索引范围 | segment ID | 维度 | 分量 | 单位 | 语义 |
|---|---|---|---|---|---|
| [0, 7) | left_tcp_pose | 7 | x, y, z, qx, qy, qz, qw | m + quaternion_xyzw | step t 时左手 arm-base TCP 位姿 |
| [7, 14) | right_tcp_pose | 7 | x, y, z, qx, qy, qz, qw | m + quaternion_xyzw | step t 时右手 arm-base TCP 位姿 |
| [14, 15) | left_gripper_width | 1 | width | normalized [0, 1] | step t 时左夹爪宽度 |
| [15, 16) | right_gripper_width | 1 | width | normalized [0, 1] | step t 时右夹爪宽度 |
| [16:32] | tactile_* | 4x4 | mean, std, min, max | raw sensor value | 四路触觉统计 |

### 6.4 action 语义（默认 16 维）

| 索引范围 | segment ID | 维度 | 分量 | 单位 | 语义 | 时间偏移 |
|---|---|---|---|---|---|---|
| [0, 7) | left_tcp_pose_t_plus_1 | 7 | x, y, z, qx, qy, qz, qw | m + quaternion_xyzw | step t+1 时左手 arm-base 绝对 TCP 目标位姿 | +1 step |
| [7, 8) | left_gripper_width_t_plus_1 | 1 | width | normalized [0, 1] | step t+1 时左夹爪目标宽度 | +1 step |
| [8, 15) | right_tcp_pose_t_plus_1 | 7 | x, y, z, qx, qy, qz, qw | m + quaternion_xyzw | step t+1 时右手 arm-base 绝对 TCP 目标位姿 | +1 step |
| [15, 16) | right_gripper_width_t_plus_1 | 1 | width | normalized [0, 1] | step t+1 时右夹爪目标宽度 | +1 step |

> [!warning] action 段落排列与 state 不同
> state 按"所有左段 -> 所有右段"分组排列，而 action 按"左 pose + 左夹爪 -> 右 pose + 右夹爪"交替排列。action 不包含触觉段落。
