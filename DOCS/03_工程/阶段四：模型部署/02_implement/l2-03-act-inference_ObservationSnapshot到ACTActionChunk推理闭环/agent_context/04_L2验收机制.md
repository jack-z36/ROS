# L2-03 验收机制

## 1. Gate 目标

证明 L2-03 能在 fake-policy 路径下完整跑通「`ObservationSnapshot` → batch → 推理 → `ActionChunk` → result_queue」链路，输出 shape 严格 `(chunk_size, 16)`；推理异常被捕获并记录为 `inference_error`；异步解耦不阻塞调用方。real-policy 路径在真实 bundle 就绪后补验，无 bundle 时标 `env-blocked`。

Gate 同时确认第一版不包含 action smoothing / blend / RTC 类逻辑。

## 2. Gate 验收项

| 验收项 | 验证层级 | 测试输入 | 观察点 | 通过现象 | 失败现象 |
|---|---|---|---|---|---|
| fake-policy 输出 shape 契约 | unit | mock ObservationSnapshot（合法 16D state + 图像） | pytest / assert | `predict_action_chunk` 返回 `(chunk_size, 16)` float32 ndarray | shape 错误或抛异常 |
| batch adapter 构造 | unit | mock snapshot | batch dict | batch 含 `observation.state`(16,)、`observation.images.*`、`task`；state 已 normalize 到 [-1,1] | 缺 key 或 state 未归一化 |
| normalizer 双向一致 | unit | 16D 向量 | normalize→unnormalize 往返 | 往返后与原值一致（允许浮点误差） | 维度不匹配或往返失真 |
| shape 非法拒绝 | unit | mock policy 返回 (chunk_size, 14) | exception | 抛 `ValueError`（shape[1]!=16） | 静默产出非法 chunk |
| InferenceWorker 异步链路 | mock / dry-run | mock request_queue + fake-policy + mock result_queue | 后台线程行为 | worker 消费 request → chunk 写入 result_queue → metrics.count 递增 → 不阻塞调用线程 | worker 阻塞、chunk 未写入、metrics 未更新 |
| 推理异常处理 | mock | fake-policy 注入抛异常 | metrics | `record_inference_error` 被调，`inference_error_count` 递增，worker 不崩溃继续下一个 request | worker 崩溃或异常未记录 |
| inference_hz 限速 | mock | 连续 request | 时间间隔 | 相邻 `_run_request` 间隔 ≥ `1/inference_hz` | 空转过载 |
| 无平滑逻辑泄漏 | static-review | 源码/docs | `rg` 输出 | 不存在 `smoothstep_alpha`/`_blend_next_action`/`blend_steps`/cross_chunk_fusion/rtc 作为能力 | 出现第一版外平滑逻辑 |
| real-policy dry-run（可选） | dry-run | 真实 ACT bundle + GPU | chunk shape | 输出 `(chunk_size, 16)`，延迟可观察 | 标 `env-blocked`（无 bundle/GPU）直到就绪 |

## 4. .sh 验收脚本设计需求

本 L2 的人类验收维度使用**单脚本 + 终端翻译表**范式（见 `html要求.md` §5）。脚本 `src/model_deploy/act/scripts/l2_03_verify.sh` 由后续 L3 微元任务生成，本节给出脚本的完整设计需求。

### 4.1 终端输出格式

按架构层分组打印，与维度3 六层落点视觉对齐：

```
=== L2-03 ACT Inference 验收 ===
[ types ]
PASS|FAIL|BLOCKED <label>  <一句话说明>
[ config ]
...
[ repo ]
...
[ service ]
...
[ runtime ]
...
[ integration ]
...
[ ui / 边界 ]
...
────────────────────────────────
N PASS / N FAIL / N BLOCKED
```

**标签列表**（每个标签对应一个验证点，标签名固定）：

| 标签 | 层 | 验证内容 | 可否 BLOCKED |
|---|---|---|---|
| `contract.action_dim` | types | 16D action 维度校验（复用 L2-01） | 否 |
| `contract.importable` | types | 契约可 import，无 ROS 依赖 | 否 |
| `config.reuse_only` | config | 不新增 config 源码 | 否 |
| `repo.fake_policy_shape` | repo | fake-policy 输出 (chunk_size, 16) | 否 |
| `repo.fake_policy_interface` | repo | 统一 predict_action_chunk 接口 | 否 |
| `service.batch_build` | service | snapshot → batch 构造 | 否 |
| `service.normalizer_roundtrip` | service | normalize→unnormalize 往返一致 | 否 |
| `runtime.worker_async` | runtime | worker 异步不阻塞调用线程 | 否 |
| `runtime.worker_error_recovery` | runtime | 推理异常不崩溃 | 否 |
| `runtime.latest_queue` | runtime | LatestQueue latest-only 语义 | 否 |
| `runtime.shared_buffer` | runtime | SharedBuffer + metrics 计数 | 否 |
| `integration.fake_full_loop` | 集成 | fake-policy 全链路集成 | 否 |
| `boundary.no_smoothing` | 边界 | 无平滑逻辑泄漏 | 否 |
| `boundary.no_ros` | 边界 | repo/service/runtime 无 ROS import | 否 |
| `boundary.no_ui` | 边界 | ui 层无 .py 产物 | 否 |
| `repo.real_policy_dryrun` | repo | 真实 bundle + GPU 推理 | **是**（无 bundle 时 BLOCKED） |

### 4.2 FAIL 定位格式

FAIL 行必须附定位块（缩进，`├─`/`└─` 树形），含以下字段：

```
├─ 文件: <目标源码路径>
├─ class: <class 名，模块级函数标"无 class">
├─ 微元: <微元名> <微元类型小标签>
├─ pytest: <pytest 节点路径>
└─ 摘要: <错误简短描述>
```

### 4.3 退出码规则

- 全部 PASS（允许存在 BLOCKED）→ 退出码 `0`
- 任一 FAIL → 退出码 `1`
- **BLOCKED ≠ 失败**：仅因环境缺失（无 bundle/GPU/ROS）无法执行的项标 BLOCKED，不影响退出码

### 4.4 BLOCKED 判定规则

以下情况标 BLOCKED（不是失败）：
- 无真实 ACT bundle + GPU → `repo.real_policy_dryrun` BLOCKED
- L2-01 DeployConfig/ActionSpec 未落地 → 相关标签 BLOCKED（上游未完成）
- 无 ROS 环境 → `boundary.no_ros` 的 ROS 集成部分 BLOCKED

## 6. 不允许合入条件

- fake-policy 路径未证明 shape 契约（`(chunk_size, 16)`）。
- InferenceWorker 异步链路未证明不阻塞调用方。
- 推理异常未证明被捕获并记录。
- 源码或文档暗含第一版外平滑逻辑。
- 人类验收未签字。
- real-policy 路径未补验就声称真机推理可用（除非真实 bundle + 授权 + 急停就绪）。
