# L2-02 验收机制

## 1. Gate 目标

证明 L2-02 能在无 ROS / 无硬件环境下通过 mock 输入生成完整、新鲜、合法的 `ObservationSnapshot`，并能在缺字段、过期或编码非法时拒绝生成 snapshot。真实 ROS 订阅只作为环境依赖项记录，不在无 ROS 环境下写成通过。

## 2. 后续实现切片草案

本节只描述未来实现覆盖面，不生成 L3 文件、dispatch 或验收卡片。

| 覆盖项 | 目标 | 验收模式 |
|---|---|---|
| snapshot 公共契约 | `ObservationSnapshot`、structured state、diagnostics 可 import | unit / import |
| collector | mock image / pose / gripper 能生成 snapshot | unit / mock |
| stale / missing gate | 缺字段和过期字段返回 `None` 并暴露诊断 | unit / mock |
| latest buffer | 连续写入只读到最新 snapshot，过期读取返回 `None` | unit / mock |
| ROS adapter | 无 ROS 环境可 import；有 ROS 时可绑定 topic callback | static-review / env-blocked |

## 3. 验证标签表（细粒度，每标签对应一个子功能模块）

每个标签可追溯到维度 3 图②六层落点的具体 classbox 微元。人类验收脚本（§4）的每一行输出对应下表一行；任一 FAIL 都能据此定位到"哪个层 / 哪个文件 / 哪个微元"。

| 标签 | 层 | 对应微元（维度3图②） | 测试输入 | 通过现象 | 失败现象 |
|---|---|---|---|---|---|
| `contract.encoded_state_dim` | types | ObservationSnapshot 数据 / 计算函数 | 构造 encoded_state，合法与非法 shape | 合法 shape (16,) 通过；非 (16,) 抛 ValueError | 非法维度被静默接受 |
| `contract.importable` | types | —（契约对象本身） | 无 ROS 环境下 `from act.types.observation import …` | import 成功，不拉入 service/runtime | import 失败或拉入下游实现 |
| `collector.mock_snapshot` | service | `snapshot()` 计算函数 | 两路 image + 左右 TCP pose + 左右 gripper width | 生成 ObservationSnapshot，`encoded_state.shape == (16,)`，`captured_at_s` 单调 | shape ≠ 16 / 缺字段 / 抛异常 |
| `collector.missing_reject` | service | `snapshot()` + `missing_fields()` | 缺任一 image/pose/gripper | `missing_fields()` 返回字段名，`snapshot()` 为 None | 缺字段仍生成不完整 snapshot |
| `collector.stale_reject` | service | `snapshot()` + `stale_fields()` | 旧 stamp 或极小 `max_age_s` | stale 诊断非空，`snapshot(max_age_s)` 为 None | 过期字段静默通过 |
| `preprocess.image` | service | `preprocess_observation_image` 计算函数 | 原始 RGB image + image_config | 输出符合目标 shape/dtype | 不支持的 shape/dtype 未抛异常 |
| `buffer.latest_only` | runtime | `set_observation` 内部状态更新函数 | 连续写 A 再写 B | `latest_observation()` 返回 B，replaced 计数递增 | 返回旧 snapshot 或保留历史队列 |
| `buffer.max_age` | runtime | `latest_observation` 计算函数 | 写入后过 max_age_s 再读 | 超龄返回 None，stale 计数更新 | 超龄仍返回旧 snapshot |
| `adapter.no_ros_importable` | ui / 边界 | —（ROS import 策略） | 无 ROS Python 环境 | types/service/runtime 可 import 与单测；ui 的 ROS import 可选/延迟 | 无 ROS 时核心模块 import 失败 |
| `boundary.no_overreach` | 边界 | —（L2 责任墙） | `rg` 扫 service/runtime/ui 源码 | 无 `predict_action_chunk\|ActionChunk\|SafetyGuard\|publish\|hardware\|driver` 实现 | L2-02 越界实现推理/控制/硬件 |
| `boundary.no_config_repo` | 边界 | —（落点判定） | `find` config/repo 目录 | 无 L2-02 新增 .py | config/repo 出现越界产物 |
| `adapter.real_subscription` | ui | `create_subscriptions` 数据读写函数 | 有 ROS 环境（当前缺） | （有 ROS 时）绑定 topic callback 成功 | **BLOCKED_ENV**（当前无 ROS，非失败）|

## 4. 统一验收脚本设计需求（后续 L3 生成依据）

> **本节是后续 L3 微元任务生成人类验收脚本的设计依据，本轮不创建脚本本身。**
> 脚本把 §3 的全部标签自动跑完，在终端简洁打印分层分组结果，让人类一眼看出"哪个层、哪个子功能模块出问题"。

### 4.1 脚本路径与入口

- 建议路径：`src/model_deploy/act/scripts/l2_02_verify.sh`（或仓库约定的验收脚本目录）。
- 入口：`bash scripts/l2_02_verify.sh`，cwd 为仓库根 `/home/hit/ROS`。
- 幂等、可重复运行；不依赖真机/真 ROS（缺则对应项标 BLOCKED）。

### 4.2 终端输出格式规约（分层分组 + FAIL 定位 + 汇总）

按架构层分块打印，每块下列标签；与维度 3 图②六层落点视觉对齐。

```
=== L2-02 ObservationSnapshot 验收 ===

[ types ]
  PASS  contract.encoded_state_dim   16D 维度校验
  PASS  contract.importable          契约可 import

[ service ]
  PASS  collector.mock_snapshot      mock 全字段→snapshot
  PASS  collector.missing_reject     缺字段→None
  FAIL  collector.stale_reject       过期→None
    ├─ 文件: service/observation_collector.py
    ├─ 微元: snapshot() / stale_fields() 计算函数
    ├─ pytest: tests/service/test_stale.py::test_stale_reject
    └─ 摘要: AssertionError: expected None, got ObservationSnapshot(...)
  PASS  preprocess.image             图像预处理

[ runtime ]
  PASS  buffer.latest_only           覆盖语义
  PASS  buffer.max_age               max_age_s 生效

[ ui / 边界 ]
  PASS  adapter.no_ros_importable    无 ROS 可 import
  PASS  boundary.no_overreach        无越界
  PASS  boundary.no_config_repo      config/repo 无产物
  BLOCKED  adapter.real_subscription 无 ROS 环境

────────────────────────────────
 8 PASS / 1 FAIL / 1 BLOCKED
```

- 每标签一行：`PASS|FAIL|BLOCKED` + 标签名 + 一句话说明。
- **FAIL 必须附简要定位**（缩进 `├─/└─`）：相关源码文件、对应微元（维度3图②）、失败的 pytest 节点、错误摘要前几行。
- 末行汇总：`N PASS / N FAIL / N BLOCKED`。

### 4.3 退出码规约

| 终态 | 退出码 |
|---|---|
| 全部 PASS（BLOCKED 可存在）| `0` |
| 任一 FAIL | `1` |

BLOCKED 是环境约束（缺 ROS / 缺上游 L2-01），不是失败；仅 BLOCKED 不影响退出码为 0。

### 4.4 BLOCKED 判定

| 条件 | 标签 |
|---|---|
| 当前环境无 ROS 2 Python package | `adapter.real_subscription` → BLOCKED_ENV |
| L2-01 state codec / DeployConfig 未落地 | 依赖上游的标签 → BLOCKED_ENV（上游未完成）|

### 4.5 标签→微元可追溯要求

脚本每个标签的输出必须能映射回维度 3 图②的具体 classbox 微元（见 §3 表"对应微元"列）。这是 HTML 维度 4「终端输出翻译表」能成立的根基——人类看到任意一行 FAIL，都能查到对应的层、文件、3.5 层功能微元。

## 5. Blocked 项

| blocked 项 | 类型 | 处理 |
|---|---|---|
| 当前环境无 ROS 2 Python package | `BLOCKED_ENV` | 不影响 service/runtime mock Gate；真实 subscription 验收等待 ROS 环境 |
| L2-01 state codec / DeployConfig 未落地 | `BLOCKED_ENV` 或上游未完成 | L2-02 代码实现前需同步 L2-01 基座 |
| 真机传感器未接入 | `BLOCKED_HARDWARE_EXPECTED` | 本 L2 不要求 real-robot 通过，只记录交接条件 |

## 6. 失败现象

- `ObservationSnapshot` 被放在 `service/` 或 `runtime/` 后导致 L2-03 / L2-06 依赖下游实现细节。
- `snapshot()` 在缺字段时仍生成对象。
- stale timeout 不生效。
- ROS adapter 的 import 使无 ROS 环境无法运行 service/runtime 单测。
- L2-02 中出现模型推理、action chunk 消费、safety 或硬件发送逻辑。

## 7. 下游与 Git 判断

- 当 mock Gate 全部通过，允许 L2-03 使用 `ObservationSnapshot` 契约进行 fake-policy / batch adapter 设计。
- 当 latest buffer Gate 通过，允许 L2-06 设计读取 latest observation 的调度逻辑。
- 本文件不授权合入 `model_deploy`；Git 合入仍必须等待 L2 Gate、验收结果和人类验收签字。
