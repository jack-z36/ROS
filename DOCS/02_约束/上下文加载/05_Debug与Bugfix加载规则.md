# Debug 与 Bugfix 加载规则

## 适用范围

用户报告 bug、异常行为、测试失败、数据不对、网页或运行链路故障，并要求定位或修复。

## 触发信号

“debug”“报错”“失败”“不对”“修 bug”“定位问题”“为什么没有输出”。

## 上下文加载顺序

1. 明确故障现象、复现入口和涉及阶段。
2. 读取 `DOCS/02_约束/编程执行/Agent编程执行原则.md`，确认复现、修改边界和验收闭环。
3. 读取对应阶段知识中与数据语义或架构相关的主题页。
4. 读取对应工程工作台中的当前进度、debug 专题或相关执行记录。
5. 读取相关约束，确认允许修改范围、文件存放和测试要求。
6. 如果失败涉及架构边界、跨层数据 shape、公共接口或重复出现的 taste 规则，读取 `DOCS/02_约束/编程执行/架构边界与机械约束原则.md`。
7. 进入代码、日志、测试或数据样例定位。
8. 修复前确认是否需要把失败模式升级为测试、lint、结构测试或验收脚本。

## 必读入口

- 对应阶段 `DOCS/01_知识/<阶段>/`
- 对应阶段 `DOCS/03_工程/<阶段>/`
- `DOCS/02_约束/编程执行/Agent编程执行原则.md`
- 涉及代码修改时读取相关约束

## 禁止默认读取

- 历史归档全文
- learning 长文
- 与故障无关的全阶段文档

## 阻断条件

- 无法确定复现入口或故障范围。
- 需要修改的文件不在允许写入范围内。
- 诊断需要外部数据或用户操作但当前不可获得。

## 输出要求

说明复现结果、定位依据、修改范围和验证结果。
