# L3 功能组目录约束

## 1. 约束目的

本约束用于防止 L3 微元任务被错误堆放到同一个功能组目录。功能组目录不是某个 L1 或某个场景的总任务池，而是某个 L2 功能模块的专属任务池。

## 2. 核心规则

```text
一个 L2 功能模块 = 一个功能组目录。
```

功能组目录必须严格对应 `功能模块清单.md` 中的功能模块序号：

```text
第 1 个功能模块 -> <L1前缀>-g1
第 2 个功能模块 -> <L1前缀>-g2
第 3 个功能模块 -> <L1前缀>-g3
...
```

示例：

```text
service_s1 功能模块 1 -> service-s1-g1
service_s1 功能模块 2 -> service-s1-g2
service_s1 功能模块 3 -> service-s1-g3
```

## 3. 禁止事项

- 禁止把同一个 L1 或同一个场景下的所有 L3 都放进 `g1`。
- 禁止把跨多个 L2 功能模块的任务放进单个功能组目录。
- 禁止为了省目录，把配置生成、数据计算、校验、文档同步等不同功能模块的 L3 混放。
- 禁止在功能模块清单尚未稳定时提前创建一批含义不明的 `gN` 目录。

## 4. 生成 L3 前必须执行的检查

生成任意 L3 前，必须先读取当前 L1 / 场景的 `功能模块清单.md`，并完成以下检查：

1. 确认该 L3 来源于哪个 L2 功能模块。
2. 读取该功能模块在清单中的序号。
3. 根据序号确定唯一功能组目录。
4. 写入前检查目标目录是否与功能模块序号一致。

## 5. 目录命名规则

Runtime：

```text
runtime-g<功能模块序号>/
```

Service：

```text
service-s1-g<功能模块序号>/
service-s2-g<功能模块序号>/
service-s3-g<功能模块序号>/
service-s4-g<功能模块序号>/
service-s5-g<功能模块序号>/
```

## 6. 场景一当前映射示例

以 `DOCS/阶段二：数据清洗/02_service/场景一/功能模块清单.md` 为准：

| 功能组目录 | 对应功能模块 | 可放入的 L3 类型 |
|---|---|---|
| `service-s1-g1/` | cleaned MCAP 契约稳定 | 接口契约、默认路径、上下游文档同步等 L3 |
| `service-s1-g2/` | 夹爪开合配置生成 | 浏览器 GoPro 标定配置生成相关 L3 |
| `service-s1-g3/` | 夹爪宽度提取 | gripper width 计算、插值、输出相关 L3 |
| `service-s1-g4/` | 位姿转换配置生成 | `frame_alignment` 配置生成和加载相关 L3 |
| `service-s1-g5/` | common frame 位姿转换 | raw pose 保留、camera/TCP common pose 计算相关 L3 |
| `service-s1-g6/` | 基础校验与输出契约检查 | validator、输出 contract、失败原因相关 L3 |

## 7. 归档规则

完成后的 L3 必须移动到带 L1 / 场景归档层的 completed 功能组目录：

```text
03_tasks/task/active/<功能组>/<task>.md
->
03_tasks/task/completed/<L1归档目录>/<功能组>/<task>.md
```

`<L1归档目录>` 固定映射如下：

| L1 / 场景 | completed 归档目录 |
|---|---|
| Runtime MVP | `01-runtime/` |
| Service 场景一 | `02-service-s1/` |
| Service 场景二 | `03-service-s2/` |
| Service 场景三 | `04-service-s3/` |
| Service 场景四 | `05-service-s4/` |
| Service 场景五 | `06-service-s5/` |

示例：

```text
03_tasks/task/active/runtime-g1/runtime_mvp_001_xxx.md
->
03_tasks/task/completed/01-runtime/runtime-g1/runtime_mvp_001_xxx.md

03_tasks/task/active/service-s1-g2/service_s1_002_xxx.md
->
03_tasks/task/completed/02-service-s1/service-s1-g2/service_s1_002_xxx.md
```

不得从 `active/service-s1-g5/` 归档到 `completed/02-service-s1/service-s1-g1/`，也不得把 Service 场景一任务归档到 `completed/01-runtime/`。

移动任务文件后，如果原 `03_tasks/task/active/<功能组>/` 目录已经没有任何任务文件或其他保留文件，必须删除该空目录，不得长期保留空 active 功能组目录。

## 8. 错误恢复

如果发现 L3 已经放错目录，必须先纠正目录归属，再继续生成或执行后续任务。纠正时同步检查任务文件中的“完成后交接”路径，确保 completed 目录同时匹配 L1 / 场景归档目录和 active 功能组。
