# 用户概念体系 — 共享术语速查表

## 定位

本文件是**用户与 Agent 交流的共享术语合集**。Agent 在每次交互开始前必须先加载本文件，确保使用用户的概念体系进行沟通。

| 项 | 内容 |
|---|---|
| 消费对象 | Agent（每次交互必加载） |
| 权威性 | 用户与 Agent 之间的术语权威。详细解释见本目录下其他文件 |
| 读取时机 | **每次交互开始前** |
| 上游来源 | `用户认知框架与讲解偏好.md`、`Python代码运行的计算机基础.md` |

## 程序理解分层模型

用户用以下分层模型拆解和理解程序：

| 层级 | 名称 | 对应实体 |
|---|---|---|
| 第一层 | 程序 | 一个能运行的 Python 项目 |
| 第 1.5 层 | 程序行为视角 | 数据流：数据从哪进、被哪个架构层处理、从哪出 |
| 第二层 | 文件夹架构 | `types / config / repo / service / runtime / ui` 六类目录 |
| 第三层 | 文件 | 目录里的单个文件 |
| 第 3.25 层 | class 打包函数 | class 封装了编排函数和基础功能微元 |
| 第 3.375 层 | 编排函数 | 对基础功能微元的封装与调度（顺序、条件、失败处理） |
| 第 3.5 层 | 基础功能微元 | 文件内的数据、计算函数、数据读写函数、内部状态更新函数 |
| 第四层 | 变量 | 名字与 RAM 中对象的绑定 |
| 第五层 | 基本语法 | 一行里的语法单元 |

## 第二层：六架构概念（核心术语）

| 概念 | 一句话定义 |
|---|---|
| `types` | 定义数据长什么样——字段、类型、shape、合法值。最上游的数据语言层 |
| `config` | 定义运行参数的类型和默认值。位于 types 之后，依赖 types |
| `repo` | 把进程外部资源（文件/模型/配置）读取、解析、校验，变成 RAM 里的内部对象 |
| `service` | 业务计算层。接收 RAM 里的内部对象，计算后输出新的内部对象 |
| `runtime` | 运行流程组织层。决定"什么时候调谁、多久调一次、谁先谁后、失败怎么办" |
| `ui` | 外部交互层。订阅 ROS topic / 发布 action / 消息转换。最下游 |

## 第 3.5 层：五种功能微元

| 功能微元 | 一句话定义 | 边界特征 |
|---|---|---|
| 数据 | 定义变量名、存储结构、数值类型 | 如 `ACTION_DIM = 14` |
| 计算函数 | 输入 RAM 数据 → 输出新 RAM 数据或判断 | 不读写进程外部资源 |
| 内部状态更新函数 | 修改 RAM 里已有对象的状态 | 修改 buffer/queue/cache |
| 数据读写函数 | 从进程外部读入数据，或写出到外部 | 跨越进程边界（文件/ROS/硬件） |
| 编排函数 | 按顺序/条件调度功能微元，决定失败处理 | 位于 class(3.25) 和基础微元(3.5) 之间 |

## 关键区分

| 概念对 | 区分 |
|---|---|
| 外部资源 vs 内部对象 | 外部资源在进程外（硬盘/设备/网络），不能直接计算；内部对象在 RAM 里，可被函数直接使用 |
| 变量名 vs 对象 | 变量名是代码里的名字，对象是 RAM 里的数据实体 |
| class vs 实例 | class 是文件中定义的结构模板；`class()` 实例化后在 RAM 里创建对象，进入第四层变量 |
| 编排函数 vs 计算函数 | 编排函数不引入新计算逻辑，只决定调用顺序和条件；计算函数引入新计算逻辑 |

## Agent 交互质量概念

用户用以下从 "AI 回答质量" 拓展而来的维度评估和指导 Agent 的多轮交互行为：

### 语义相关度 — Agent 工作是否命中意图

| 概念 | 一句话定义 | 反面 |
|---|---|---|
| 意图对齐 | Agent 是否精准理解真实意图并以此驱动行动，而非停留在字面 | "碎动作"：做了很多事但都不触及核心需求 |
| 边界守持 | Agent 是否在授权范围内行动——该深入时深入，该止步时止步，该确认时确认 | 越权执行或遗漏关键步骤 |
| 产出可执行性 | Agent 的产出能否直接使用——代码能跑、文档正确、决策可落地 | "看起来很完整"但实际需要大量补全 |

### 语义的表现形式 — Agent 工作过程如何呈现

| 概念 | 一句话定义 | 反面 |
|---|---|---|
| 思考呈现 | Agent 如何展示推理链，标注事实/推断/待确认，让用户判断可信度 | "黑箱操作"（看不到推理）或"信息倾泻"（淹没在细节中） |
| 行动节奏 | Agent 何时静默执行、何时进度播报、何时暂停确认 | "过度询问"导致疲劳，或"静默黑洞"让用户不知道是否还在工作 |
| 信息密度控制 | Agent 如何根据场景调整输出信息量——在太简略和太详细之间找平衡 | 简答场景长篇大论，复杂问题一笔带过 |

### Agent 交互特有维度

| 概念 | 一句话定义 | 反面 |
|---|---|---|
| 交互闭环 | 用户指令 → 理解 → 执行 → 反馈结果 → 明确下一步，闭环不断裂 | 执行完无总结、结果模糊、无下一步提示、静默失败 |
| 上下文持续性 | Agent 记住本次对话中已确认的事实、决策和约束，不重复提问、不遗忘、不自相矛盾 | "失忆"（重复搜索已知信息）或"自相矛盾"（推翻已有结论） |
