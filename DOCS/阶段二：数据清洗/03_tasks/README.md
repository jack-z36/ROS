# 阶段二任务记录机制

`03_tasks/` 用于记录阶段二具体开发任务的计划、对话确认、执行边界和完成归档。它不替代阶段级文档、Runtime MVP 六件套、Service 六件套或 `总执行日志.md`。

## 目录结构

```text
03_tasks/
├── README.md
├── active/
│   └── 001_runtime_mvp_harness.md
└── completed/
    └── README.md
```

## 职责边界

- `active/`：保存当前正在推进或下一步要推进的任务计划。
- `completed/`：保存已经完成的任务记录，任务完成后从 `active/` 移入这里。
- `总执行日志.md`：只记录跨阶段、公共维护或阶段级摘要，不承载任务细节。

## 执行前对话机制

执行 active 任务前，必须先阅读该任务文件的“对话确认区”：

- 如果用户意图、成功标准、范围边界或入口机制不清楚，先和用户确认。
- 每轮优先问少量高影响问题，不一次性铺开所有细节。
- 用户确认后的结论应写回任务文件。
- 如果任务文件中的待确认问题已经清空，才能进入执行计划。

## active 到 completed 的流转

任务完成后：

1. 在任务文件末尾追加执行摘要。
2. 写明实际修改文件、验证命令、结论和遗留风险。
3. 将任务文件从 `active/` 移到 `completed/`。
4. 将本次执行记录和当前状态快照写入 `DOCS/阶段二：数据清洗/执行记录/`。
