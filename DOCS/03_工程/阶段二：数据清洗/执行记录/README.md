# 阶段二 Win 端规划记录与历史执行记录目录

本目录用于保存 Win 主机上的阶段二规划记录、讨论沉淀和历史执行记录。Ubuntu L3 执行端不再写入本目录。

## 目录职责

阶段二后续不再优先把新的规划过程追加到各级目录中的固定 `执行记录.md` 或 `当前进度.md`。

Win 主机需要沉淀规划记录时，可以写入：

```text
DOCS/03_工程/阶段二：数据清洗/执行记录/
```

本目录承载两类文件：

1. Win 端规划记录：记录某次文档整理、功能拆解、模板调整或讨论沉淀。
2. 历史执行记录：保留旧流程下已经产生的执行记录，供查询，不再作为 Ubuntu L3 输出目标。

## 命名规则

文件名允许两类命名方式。

### 方式一：时间命名

适合零散维护、阶段性整理、对话沉淀、状态快照。

```text
MMDDHH_<简短主题>.md
```

示例：

```text
051518_执行记录目录统一.md
051520_service_s1状态快照.md
```

其中：

- `MM`：月份，两位数字。
- `DD`：日期，两位数字。
- `HH`：小时，24 小时制，两位数字。
- `<简短主题>`：用短中文或短英文描述记录对象。

### 方式二：时间 + 微元任务命名

该方式为历史兼容命名。新的 Ubuntu L3 执行结果写入当前 L3 文件末尾，不再写入本目录。

```text
MMDDHH_<L3微元任务名>.md
```

示例：

```text
051520_service_s1_001_gripper_marker_detection.md
```

同一个文件内同时记录执行过程、当前状态、未完成事项和下一步建议，不再拆成多个文件。

## 文件内容建议

每个执行记录文件至少包含：

```text
# <记录标题>

## 基本信息

- 时间：
- 归属 L1：
- 归属场景：
- 关联 L2：
- 关联 L3：

## 用户请求

## 执行内容

## 涉及文件

## 观察结果

## 当前状态

## 未完成事项

## 下一步建议
```

## 与旧文件的关系

历史上已有的 `执行记录.md` 和 `当前进度.md` 暂时保留，避免破坏既有索引和历史引用。

从双机协作规则建立后，Ubuntu L3 执行端不得写入本目录。Win 主机如需阶段汇总，应在拉取 Ubuntu 的 completed L3 后统一整理。

## 使用原则

- 不要求 Ubuntu L3 执行端创建独立执行记录。
- 不把长执行过程继续追加进阶段级 `当前进度.md`。
- 阶段级、任务线级、场景级 `当前进度.md` 后续只保留粗粒度状态和指向本目录的索引。
- 如果一次任务无法明确归入阶段二，应继续写入 `DOCS/总执行日志.md`。
