# Service 执行约束

## 必读文档

处理任何 service 场景前，必须先阅读：

- `DOCS/02_约束/文档体系/文档分类与目录规范.md`
- `AGENTS.md`
- `DOCS/阶段二：数据清洗/AGENTS.md`
- 阶段二四个阶段级文档。
- `02_service/AGENTS.md`
- `02_service/目标描述.md`
- `02_service/背景信息.md`
- `02_service/执行约束.md`
- `02_service/执行记录.md`
- `02_service/当前进度.md`
- `02_service/输出程序与文件.md`
- 对应场景六件套。

## 分层约束

- Service 不能解析 UI 菜单。
- Service 不能直接管理 Runtime 生命周期。
- Service 不能绕过 Repo 直接把存储细节散落到业务逻辑里。
- Service 不得覆盖 raw MCAP。

## 产物约束

- 每一级产物必须能被下游明确消费。
- 会影响数据语义的配置、参数和版本必须进入报告或 manifest。
- 不可训练 step 必须进入 masks 和报告，不能静默丢弃。

## 验收边界

不能把以下情况算作 service 场景完成：

- 只创建目录或空文件，没有真实输入输出验证。
- 没有报告或 manifest。
- 没有更新对应场景的 `输出程序与文件.md`。
- 修改程序行为但没有同步包内架构文档。
