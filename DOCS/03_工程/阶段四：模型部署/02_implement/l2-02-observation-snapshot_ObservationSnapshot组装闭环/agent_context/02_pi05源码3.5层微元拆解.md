# Pi0.5 源码 3.5 层微元拆解：L2-02

## 1. 源码范围

本文件只记录对 L2-02 有用的 Pi0.5 结构参考。Pi0.5 不定义当前 ACT L2 边界，复用决策必须经过 L1/L2 当前边界重写。

| Pi0.5 文件 | 参考对象 | 与 L2-02 的关系 | 复用判断 |
|---|---|---|---|
| `DOCS/03_工程/阶段四：模型部署/pi05_old/pi05_test/pi05/deploy/src/pi05/deploy/runtime/observation_collector.py` | `ObservationCollector` | 字段缓存、齐全性、新鲜度、snapshot 构造 | 结构复用 |
| `DOCS/03_工程/阶段四：模型部署/pi05_old/pi05_test/pi05/deploy/src/pi05/deploy/runtime/shared_buffer.py` | `ObservationSnapshot`、`SharedBuffer.latest_observation` | snapshot 数据结构和 latest-only buffer | 结构复用 |
| `DOCS/03_工程/阶段四：模型部署/pi05_old/pi05_test/pi05/deploy/src/pi05/deploy/ros_nodes/pi05_vla_deploy_node.py` | ROS callbacks、`_publish_observation_if_ready` | topic callback、图像 decode、字段更新、缺字段日志 | 参考理解 |
| `DOCS/03_工程/阶段四：模型部署/pi05_old/pi05_test/pi05/common/src/pi05/common/data/state_codec.py` | `BimanualState`、`encode_bimanual_state` | 旧 26D state 编码和 structured state 思路 | 结构复用 |

ACT 差异：

- ACT 第一版 observation state 是 16D，不是 Pi0.5 旧 26D。
- ACT 输入 topic 是 `/act/observation/*`，不是 Pi0.5 旧 topic 配置。
- ACT 设计要求 `ObservationSnapshot` 作为跨 L2 公共契约放在 `types/`，避免下游依赖 L2-02 service / runtime 实现。

## 2. 3.5 层微元表

| 源码文件 | class / 函数 / 数据 | 3.5 层微元类型 | 输入 | 输出或副作用 | 与其他微元的协作关系 | 对 ACT 设计的启发 |
|---|---|---|---|---|---|---|
| `observation_collector.py` | `ObservationCollector.REQUIRED_IMAGE_KEYS` | 数据 | 无 | 图像字段名集合 | 被 `_has_required_locked` 和 `missing_fields` 使用 | ACT 改为从 `DeployConfig` 读取 required image keys |
| `observation_collector.py` | `_images`、`_values`、`_stamps` | 数据 | callback 更新值 | RAM 内最新字段缓存和时间戳 | `update_*` 写入，`snapshot` 读取 | ACT 保留字段缓存，但字段名改为 ACT topic/state 契约 |
| `observation_collector.py` | `update_image` | 内部状态更新函数 | image name、image tensor | 更新 `_images` 和 image stamp | ROS callback 调用，snapshot 后续读取 | ACT service 层保留 RAM 更新函数，不直接依赖 ROS message |
| `observation_collector.py` | `update_proprioception` | 内部状态更新函数 / 计算函数 | legacy joint positions | 解码 left/right arm q 并更新缓存 | 调 `decode_picotele_proprioception` | ACT 不照搬 proprioception；改为 TCP pose + gripper width 输入 |
| `observation_collector.py` | `update_hand` | 内部状态更新函数 | side、hand value | 更新 hand cache 和 stamp | callback 调用 | ACT 改为 gripper width/state 更新 |
| `observation_collector.py` | `update_vector` | 内部状态更新函数 | key、vector | 更新 pose / rpy cache 和 stamp | callback 调用 | ACT 可保留通用 vector 更新形式 |
| `observation_collector.py` | `_has_required_locked` | 计算函数 | `_images`、`_values` | bool | `snapshot` 调用 | ACT 保留齐全性检查，但字段集合改为 ACT 必需字段 |
| `observation_collector.py` | `_has_stale_field_locked` | 计算函数 | now、`max_age_s`、stamps | bool | `snapshot` 调用 | ACT 保留字段级新鲜度 gate |
| `observation_collector.py` | `missing_fields` | 计算函数 | `_images`、`_values` | missing field list | 日志和 Gate 观察点 | ACT 必须作为可观察诊断暴露 |
| `observation_collector.py` | `snapshot` | 编排函数 / 计算函数 | 缓存字段、`max_age_s` | `ObservationSnapshot` 或 `None` | 调齐全性、新鲜度、state codec | ACT snapshot 构造是 L2-02 service 核心 |
| `shared_buffer.py` | `ObservationSnapshot` dataclass | 数据 | images、state、encoded_state、captured_at_s | 冻结 observation 对象 | policy runtime、control loop 消费 | ACT 放入 `types/observation.py`，编码维度改为 16D |
| `shared_buffer.py` | `SharedBuffer._latest_observation` | 数据 | `ObservationSnapshot` | latest-only RAM 槽 | `set_observation` 写，`latest_observation` 读 | ACT 拆成 `ObservationBuffer`，只承载 observation |
| `shared_buffer.py` | `SharedBuffer.set_observation` | 内部状态更新函数 | snapshot | 覆盖 latest observation、更新 dropped count | callback / service 写入 | ACT 保留覆盖语义，指标命名改为 observation metrics |
| `shared_buffer.py` | `SharedBuffer.latest_observation` | 计算函数 | `max_age_s` | snapshot 或 `None` | ControlLoop 调用 | ACT 保留读取时 max age gate |
| `pi05_vla_deploy_node.py` | `_create_subscriptions` | 数据读写函数 / 编排函数 | DeployConfig topics | ROS subscription 副作用 | 绑定 `_image_cb`、`_point_cb` 等 callback | ACT ui 层拆出 ROS adapter；真实 ROS import 可选 |
| `pi05_vla_deploy_node.py` | `_image_cb` | 数据读写函数 / 编排函数 | ROS Image / CompressedImage | decode、preprocess、update collector | 调 `_decode_image`、`preprocess_rgb_image`、`update_image` | ACT ui 层只做 message 到 RAM 的转换，不做核心业务 |

## 3. Pi0.5 class 封装盘点

| class | 源码路径 | 封装了哪些 3.5 层微元 | 内部状态 | 生命周期 / 并发特征 | 为什么适合 class | ACT 中的处理建议 |
|---|---|---|---|---|---|---|
| `ObservationCollector` | `deploy/src/pi05/deploy/runtime/observation_collector.py` | 数据缓存、字段更新时间、update 函数、齐全性检查、新鲜度检查、snapshot 构造 | `_images`、`_values`、`_stamps`、`_lock`、required image keys | callback 多线程可能并发写，内部使用 lock | 需要跨多次 callback 保留字段和时间戳 | 结构复用为 `service/observation_collector.py::ObservationCollector`，字段改为 ACT 16D observation 契约 |
| `ObservationSnapshot` | `deploy/src/pi05/deploy/runtime/shared_buffer.py` | 冻结 observation 数据对象 | 无可变状态 | 一次 snapshot 生命周期，创建后只读 | 作为跨模块 RAM 数据契约 | 迁移为 `types/observation.py::ObservationSnapshot`，避免下游依赖 runtime |
| `SharedBuffer` | `deploy/src/pi05/deploy/runtime/shared_buffer.py` | latest observation、request queue、result queue、metrics | `_latest_observation`、queue、metrics、lock | 长生命周期 runtime 对象，多模块共享 | 持有多个运行时共享状态 | L2-02 只抽出 observation 部分为 `runtime/observation_buffer.py::ObservationBuffer` |
| `Pi05VlaDeployNode` | `deploy/src/pi05/deploy/ros_nodes/pi05_vla_deploy_node.py` | subscription 创建、callbacks、timer、publisher、worker 装配 | ROS node、collector、shared_buffer、control_loop、worker | ROS node 生命周期，MultiThreadedExecutor | 外部交互和装配天然适合 node class | ACT L2-02 只参考 callback 和 adapter；完整 node 装配留给 L2-06 |

## 4. 不可照搬项

- 不照搬 26D state 和 legacy proprioception `[right6, left6]` 语义。
- 不把 Pi0.5 的 `SharedBuffer` 整体搬入 L2-02；request queue、chunk queue 和全局 metrics 属于后续 L2 / L2-06。
- 不让 L2-02 的 `ui` 层直接实现核心 snapshot 业务规则；核心规则必须在 service/runtime 可无 ROS 测试。
- 不在无 ROS / 无硬件环境下声明真实 topic 订阅已通过。
