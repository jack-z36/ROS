# 场景四目标描述：修改 Octopus UI 展示订阅 topic 与目标数据可视化

## 1. 核心目标

场景四的核心目标是修改数据采集程序 Octopus 的 UI 界面，使它更贴合当前 FASTUMI 采集任务。

本场景重点包括两部分：

- 操作页面需要直接展示程序订阅的全部目标 topic，避免当前 topic 列表只显示一部分、其余内容必须滚动鼠标滚轮才能看到的问题。
- 主显示区域需要去掉旧的左右手触觉、左右手视觉、头部视觉显示布局，改为当前任务需要的左/右手 GoPro视频、左/右手位姿数据、左/右手触觉数据可视化。

## 2. 目标操作流程

理想使用流程是：

```text
启动 8 路目标数据源
    ↓
启动 Octopus
    ↓
在操作页面直接看到程序订阅的全部目标 topic
    ↓
确认每个 topic 的订阅 / 录制选择状态
    ↓
在主显示区域看到左手 GoPro、右手 GoPro、左手位姿、右手位姿、左手触觉、右手触觉等数据面板
    ↓
开始采集 / 结束采集
    ↓
继续沿用场景三的 MCAP 录制验证链路
```

## 3. 目标 topic 范围

场景四沿用场景三当前的 8 个目标 topic：

| 类别             | topic                              | 当前用途                      |
| ---------------- | ---------------------------------- | ----------------------------- |
| Baton Mini right | `/baton_mini_right/odometry`     | 右侧 Baton Mini 位姿 / 里程计 |
| Baton Mini left  | `/baton_mini_left/odometry`      | 左侧 Baton Mini 位姿 / 里程计 |
| GoPro right      | `/gopro_right/image_raw`         | 右侧 GoPro 视频帧             |
| GoPro left       | `/gopro_left/image_raw`          | 左侧 GoPro 视频帧             |
| 左手触觉 1       | `/pressure/left_hand/gripper_1`  | 左手夹爪 1 压力数据           |
| 左手触觉 2       | `/pressure/left_hand/gripper_2`  | 左手夹爪 2 压力数据           |
| 右手触觉 1       | `/pressure/right_hand/gripper_1` | 右手夹爪 1 压力数据           |
| 右手触觉 2       | `/pressure/right_hand/gripper_2` | 右手夹爪 2 压力数据           |

如果后续目标 topic 数量或名称变化，必须同步更新场景三和场景四文档，避免 UI 显示范围、录制范围和验证范围不一致。

## 4. 成功标准

场景四完成时，应满足：

```text
1. Operation / 操作页面能在目标窗口尺寸下直接看到 8 个目标 topic，不需要通过滚轮才能发现隐藏 topic；
2. 操作页面仍能表达每个 topic 的订阅或录制选择状态；
3. 主显示区不再保留旧任务的左右手触觉、左右手视觉、头部视觉布局作为主要界面；
4. 主显示区改为左手 GoPro、右手 GoPro、左手位姿、右手位姿、左手触觉、右手触觉等当前目标数据的可视化；
5. GoPro 图像 topic 能显示实时画面；
5.1 左右 GoPro 图像面板必须显示实时帧率信息；
6. Baton Mini odometry topic 能以可理解方式显示左右手位姿数据；
7. 四路压力 topic 能汇总为左右手触觉数据可视化；
8. 修改 UI 不破坏场景三的 MCAP 录制链路；
9. 生成的 MCAP 仍可用 `ros2 bag info` 或等效工具验证 8 个目标 topic。
```

只修改面板标题、但没有真实数据接入和显示，不算完成。

## 5. 与前序场景的关系

场景一和场景二解决传感器节点启动问题。

场景三解决 Octopus 对 8 个目标 topic 的订阅、录制和 MCAP 输出问题。

场景四在场景三的基础上继续推进 Octopus UI，使用户不仅能完成录制，还能在图形界面中清楚看到全部订阅 topic 和当前任务真正关心的数据可视化。

## 6. 一句话总结

场景四要实现的是：把 Octopus 从旧的通用显示布局改成当前 FASTUMI 采集任务可用的界面，操作页完整展示 8 个目标 topic，主界面显示左右 GoPro、左右位姿和左右触觉数据，同时不破坏场景三的 MCAP 录制能力。
