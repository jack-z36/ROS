L2-02 · 传感器订阅与 ObservationSnapshot 组装闭环

把外部 observation topics 转换成完整、新鲜、合法的 RAM 对象 ObservationSnapshot，并写入 latest-only buffer。它是外部传感器世界进入 ACT 部署程序内存的入口。本页用 4 个维度交互呈现：功能边界、Pi0.5 对应部分如何运作、开发蓝图、人类验收标准。

本页只是人类快速浏览入口，不作为 L3 生成依据。

这一节用白话讲。每个专业术语第一次出现时都会解释，点开"术语词典"可以随时查。
📖 术语词典（点开随时查）
callback
（回调）		ROS 收到一条消息时，自动调用你预先注册的函数。L2-02 的 ui 层就是一串 callback：每来一张图或一个 pose，就触发对应的 handle 函数。
ObservationCollector
（字段收集器）		一个"记事本"对象。每次 callback 到来，它就把某个字段的最新值和时间戳记下来。凑齐所有必需字段后，它能判断"能不能拼一个完整的 snapshot"。
snapshot某一时刻所有字段的快照——两张图、左右 TCP pose、左右夹爪宽度，再加上用 state codec 编码出的 16D 向量。snapshot 一旦创建就只读。
latest-only buffer只保留最新一份 snapshot 的缓存。新 snapshot 来了就把旧的覆盖掉，不存历史。下游 L2-06 随时来读最新的那份。
max_age_s
（最大年龄）		新鲜度阈值。如果某个字段最后一次更新距现在超过 max_age_s 秒，就判它"过期"，不拼 snapshot。防止用到陈旧数据。
monotonic stamp
（单调时间戳）		用 time.monotonic() 记下的、不会因系统时钟回拨而倒退的时间。用来算字段年龄，比墙钟更可靠。
state codec
（状态编码器）		L2-01 提供的函数，把结构化状态（TCP pose + gripper width）编成模型要的 16D 向量。L2-02 的 collector 调它，自己不重新实现编码。
try_publish_observation局部编排点。每次 callback 更新完字段后，尝试拼一次 snapshot；拼成功就写 buffer，拼不成功只记诊断。

① 整体流程：一次 callback 的四个步骤

Pi0.5 这部分代码是事件驱动的：每来一条消息就跑一遍下面的流程。任一步失败（缺字段 / 过期 / decode 错），都不写非法 snapshot。

1

消息到达

ROS callback 触发：ui adapter 收到一条 image / pose / gripper message。跨进程边界：从 ROS 到程序内存。
2

解码 + 更新缓存

adapter 把消息解码成 RAM 值（图片张量、pose 数组、gripper 宽度），调 collector 的 update_* 方法。collector 更新字段值 + monotonic 时间戳。
3

尝试拼 snapshot

try_publish_observation：检查必需字段齐全？都在 max_age_s 内？是 → 调 L2-01 编 16D → 构造 ObservationSnapshot。否 → 只记诊断，不拼。
4

写 latest buffer

snapshot 构造成功 → 写入 ObservationBuffer.set_observation，覆盖上一份。下游 L2-03/L2-06 读 latest_observation 拿到最新的。

② 跟一个 TCP pose 字段走完全流程

以左臂 TCP pose 为例，看它怎么从一条 ROS 消息变成 snapshot 里的 16D 向量的一段。

# ROS topic: /act/observation/arm/left_tcp_pose ① # ui adapter 收到消息（跨进程边界，从 ROS 到 RAM） msg = Pose(position=[x,y,z], orientation=[qx,qy,qz,qw]) adapter.handle_tcp_pose("left", msg) ② # collector 更新左臂字段缓存 + monotonic 时间戳（纯 RAM 内） collector.update_tcp_pose("left", position=[x,y,z], orientation=[qx,qy,qz,qw]) # → _values["left_tcp"] = ..., _stamps["left_tcp"] = time.monotonic() ③ # try_publish_observation：齐全性 + 新鲜度检查 missing = collector.missing_fields() # 其他必需字段都在吗？ stale = collector.stale_fields(now, max_age_s) # → 若 missing 或 stale 非空 → 记诊断，不拼 snapshot ④ # 齐全且新鲜 → 调 L2-01 state codec 编 16D encoded = state_codec.encode(left_tcp, right_tcp, left_grip, right_grip) snapshot = ObservationSnapshot(images, state, encoded_state=encoded, captured_at_s=now) buffer.set_observation(snapshot) # 覆盖 latest # ── 如果消息 decode 失败（比如 orientation 非法四元数）会怎样？ ②' # adapter 检测到非法 shape / quaternion log warning，不更新 collector 缓存 # → 该字段保持旧值或缺失，下一步 snapshot 判定会把它当 missing/stale 处理。

③ Pi0.5 参考对象 + ACT 差异

🔬 Pi0.5 源码盘点（结构复用）

  • observation_collector.py::ObservationCollector — 字段缓存、齐全性、新鲜度、snapshot 构造 → 结构复用
  • shared_buffer.py::ObservationSnapshot — snapshot 数据结构 → 结构复用（迁移到 types/）
  • shared_buffer.py::SharedBuffer.latest_observation — latest-only buffer → 结构复用
  • state_codec.py::BimanualState / encode_bimanual_state — 结构化状态 + 编码 → 结构复用
  • pi05_vla_deploy_node.py — ROS callback / _publish_observation_if_ready → 仅作理解参考

⚠️ 不可照搬项

  • Pi0.5 是 26D state（含本体感知 [right6,left6]）；ACT 是 16D（TCP pose + gripper width）
  • Pi0.5 topics 名是旧名；ACT 用 /act/observation/*
  • 不整体搬入 SharedBuffer（request queue / chunk queue / 全局 metrics 归后续 L2 / L2-06）
  • ui 层不实现核心 snapshot 业务规则（规则必须能在 service/runtime 无 ROS 测试）
  • 无 ROS / 无硬件环境不得写成"真实 subscription 已通过"
维度差异（决定不能照搬）：Pi0.5 是 26D state（关节角表示，含本体感知），把 ObservationSnapshot 放在 runtime/；ACT 是 16D / 16D（TCP pose + gripper width），且要求 ObservationSnapshot 作为跨 L2 公共契约放在 types/observation.py。所以这部分代码的结构（callback → 缓存 → 齐全新鲜 → snapshot → latest）可复用，但数值与落点必须重写。详见维度 3 与权威 MD。

④ 回答四个核心问题（谁持有状态、谁跨边界、谁加工、谁管时序）

❶ 谁持有状态？

两个对象持有"会长期存在、会变化"的状态：

  • ObservationCollector：持有 _images / _values / _stamps + _lock（callback 可能并发写，用 lock 保护）。
  • ObservationBuffer：持有 _latest_observation + _lock + metrics。

ObservationSnapshot 本身创建后只读，不算可变状态。

❷ 谁跨越外部边界？

只有 ui 层的 adapter：

  • ObservationRosAdapter 订阅 topic、收 ROS message
  • decode_image_message 把 ROS image 转成 RAM 张量

service / runtime / types 不碰 ROS，保证无 ROS 环境可测。L2-02 不发布任何 topic。

❸ 谁只负责加工 RAM 对象？

  • collector 的 update_* / missing_fields / stale_fields
  • snapshot 构造（含调 L2-01 编 16D）
  • preprocess_observation_image（图片 RAM 内变换）

这些都是"输入在内存、输出也在内存"的纯计算。

❹ 谁负责 runtime 时序？

答：全局节奏归 L2-06。

L2-02 只有局部编排点 try_publish_observation（每次 callback 后触发）。全局 ControlLoop.tick()、推理触发时机、chunk cursor 都是 L2-06 的事。L2-02 是被动响应，不主动调度。

维度 3 · 开发建议与蓝图

📖 阅读路径：了解代码如何分层组织 → 代码写完后用维度4检查产物与越界

L2-02 把 Pi0.5 混在 collector/buffer/node 里的 observation 能力拆清：types/ 定义跨 L2 数据语言；service/ 做 RAM 字段组装 + 齐全 + 新鲜；runtime/ 存 latest-only observation；ui/ 把 ROS 消息转成 service 可消费的 RAM 值。落到六层中的四层（types/service/runtime/ui），config 和 repo 不落点。

这张图回答"运行起来后，各层模块怎么协作"——按步骤①→⑤看箭头方向：ui 是驱动方（callback 触发），service 做字段组装，runtime 只被写入；下游 L2-06 反过来读 runtime。每一步都标了对应的 3.5 层微元类型，可与图②对照。L2-01 只在编译时注入配置，不参与运行时调用（虚线）。

types/ · 跨 L2 数据契约层（3 个 frozen dataclass）

这一层只定义"数据长什么样"——观察状态、snapshot、新鲜度结果。不读配置、不依赖 ROS、不维护 buffer。ObservationSnapshot 放在这里，让 L2-03/L2-06 只依赖 types/，不依赖 L2-02 的实现。

ObservationState（frozen dataclass）

结构化观察状态：左右 TCP pose + 左右夹爪宽度。供 state codec 编码。

数据left_tcp_position / right_tcp_position — 结构：frozen dataclass 字段；数值类型：tuple 或 np.array，shape (3,)，float（x,y,z）left_tcp_orientation / right_tcp_orientation — 结构：frozen dataclass 字段；数值类型：tuple 或 np.array，shape (4,)，float（四元数 qx,qy,qz,qw）left_gripper_width / right_gripper_width — 结构：frozen dataclass 字段；数值类型：float（米）
ObservationSnapshot（frozen dataclass）

完整的、冻结的 observation 契约对象。L2-03 推理与 L2-06 控制的输入。创建后只读。

数据images — 结构：dict（key 为 topic/相机名，value 为图像张量）；数值类型：np.ndarray，每张 shape 由 image_config 决定（如 (3,H,W)），float 或 uint8state — 结构：ObservationState（frozen dataclass）；数值类型：见 ObservationStateencoded_state — 结构：np.ndarray；数值类型：float，shape (16,)（state codec 编码后）captured_at_s — 结构：标量字段；数值类型：float（time.monotonic() 秒）
计算函数validate_encoded_state_dim / __post_init__ — 输入：自身 encoded_state（np.ndarray）；输出：无返回（合法则通过）；encoded_state.shape ≠ (16,) 时 抛 ValueError
ObservationFreshnessResult（frozen dataclass）

齐全性 + 新鲜度检查结果。供诊断与 buffer 记录。

数据missing_fields — 结构：list；数值类型：str（缺失字段名）stale_fields — 结构：list；数值类型：str（过期字段名）field_ages_s — 结构：dict（key 字段名，value 年龄秒）；数值类型：floatready — 结构：标量字段；数值类型：bool（missing 与 stale 均空时为 True）

文件：src/model_deploy/act/types/observation.py。依赖方向：stdlib / typing / dataclasses / numpy，不得 import config/repo/service/runtime/ui。验收覆盖：16D encoded_state、下游 import 无需拉入 service/runtime、非法维度被拒。
参考 Pi0.5：shared_buffer.py::ObservationSnapshot（维度 26D → 16D，落点 runtime → types）。

config/ · 本 L2 不落点

原因：L2-02 直接消费 L2-01 的 DeployConfig（topics.observation / image / 新鲜度超时）和 state spec/codec 配置。重新声明会造出两个配置权威，破坏 L1「L2-01 是静态契约地基」的边界。

使用的配置对象：DeployConfig.topics.observation、DeployConfig.image、DeployConfig.safety.stale_observation_timeout_s（或等价 runtime freshness 参数）、L2-01 state spec/codec。

验收确认：不产生 src/model_deploy/act/config/*；缺配置 / 非法 topic / 非法 image shape 由 L2-01 Gate 覆盖。

repo/ · 本 L2 不落点

service/ · RAM 内 observation 组装层（2 个文件）

这一层做 RAM 内业务计算：接收 ui 转来的 RAM 值、维护字段缓存、齐全性+新鲜度检查、调 state codec 编 16D、构造 ObservationSnapshot。不 import ROS、不创建 timer/thread、不写硬件/topic。

ObservationCollector（class，observation_collector.py）

字段收集器：缓存每字段最新值 + 时间戳，判断能不能拼 snapshot。Pi0.5 参考：observation_collector.py::ObservationCollector（结构复用，字段改为 ACT 16D 契约）。

数据_images — 结构：dict；数值类型：key 为 str（相机名），value 为 np.ndarray（图像张量）_values — 结构：dict；数值类型：key 为 str（如 "left_tcp"/"right_gripper"），value 为 tuple/np.array（pose）或 float（gripper width）_stamps — 结构：dict；数值类型：key 为 str，value 为 float（time.monotonic() 秒）_lock — 结构：threading.Lock；callback 可能并发写，内部用它保护_required_fields — 结构：set/list；数值类型：str（必需字段名，来自 L2-01 配置）
内部状态更新函数update_image(name, image) — 修改对象：_images[name] 与 _stamps[name]；如何修改：写入新图像张量 + 记录当前 monotonic 时间update_tcp_pose(side, position, orientation) — 修改对象：_values[f"{side}_tcp"] 与对应 _stamps；如何修改：写入 pose 值 + 时间戳；position/orientation shape 非法时 抛异常update_gripper_state(side, width) — 修改对象：_values[f"{side}_gripper"] 与对应 _stamps；如何修改：写入 width 值 + 时间戳；非法 width 时抛异常或记录
计算函数missing_fields() — 输入：无（读 _values 与 _required_fields）；输出：list[str]，缺失的必需字段名stale_fields(now, max_age_s) — 输入：now（float，monotonic 秒）+ max_age_s（float）；输出：list[str]，过期字段名（now - _stamps[f] > max_age_s）snapshot(max_age_s) — 输入：max_age_s（float）；输出：ObservationSnapshot（齐全且新鲜时，调 L2-01 state codec 编 16D 构造）或 None + 诊断（缺字段/过期）；codec 失败抛明确异常或返回诊断
preprocess_observation_image（函数，image_preprocess.py）
计算函数preprocess_observation_image(image, image_config) — 输入：image（np.ndarray，原始图像）+ image_config（L2-01 对象，含目标 shape/dtype/resize）；输出：ACT 图像张量/数组（按 image_config 处理后的 shape/dtype）；不支持的 shape/dtype 抛异常

文件：service/observation_collector.py、service/image_preprocess.py。允许依赖：types/observation.py、L2-01 state spec/codec/config 对象、stdlib、numpy。禁止依赖：runtime/observation_buffer.py、ui/observation_ros_adapter.py、ROS 包、ACT policy runtime。
验收覆盖：mock 全字段→snapshot；缺字段→None+missing 列表；stale→None+stale 列表；无 ROS 可 import 与单测。

runtime/ · latest-only observation 缓存层（1 个文件）

这一层负责时间/状态/队列/调度语义。L2-02 的 runtime 只保存 latest-only observation，并提供按 max age 读取最新 snapshot 的能力。不存推理请求队列、action chunk 队列、ControlLoop cursor（那些归后续 L2 / L2-06）。

ObservationBuffer（class，observation_buffer.py）

latest-only 缓存：只留最新一份 snapshot，新覆盖旧。Pi0.5 参考：SharedBuffer.set_observation / latest_observation（ACT 只抽出 observation 部分）。

数据_latest_observation — 结构：单值引用；数值类型：ObservationSnapshot 或 None_lock — 结构：threading.Lock；保护对 latest 的并发读写metrics — 结构：ObservationMetrics（dataclass）；记录就绪/覆盖/过期计数 + 最近诊断

计算函数latest_observation(max_age_s=None) — 输入：max_age_s（float 或 None）；输出：ObservationSnapshot 或 None（超过 max_age_s 则判 stale，返回 None 并可能更新 stale counter）metrics_snapshot() — 输入：无；输出：dict（metrics 当前值副本）

ui/ · ROS 消息边界层（1 个文件）

这一层是外部交互边界：把 ROS observation 消息转成 service 可消费的 RAM 值，并在 callback 后尝试把 ready snapshot 写入 runtime buffer。不实现核心 snapshot 业务规则、不调 ACT 模型、不发硬件命令。

ObservationRosAdapter（class，observation_ros_adapter.py）

ROS 订阅 + 消息解码 + callback 转发。Pi0.5 参考：_create_subscriptions / _image_cb / _point_cb / _hand_cb / _publish_observation_if_ready / _decode_image——ACT 必须拆进 adapter，不整体搬 deploy node。

数据node — 结构：ROS node handle 引用（延迟导入）collector — 结构：ObservationCollector 引用；数值类型：service 对象buffer — 结构：ObservationBuffer 引用；数值类型：runtime 对象config — 结构：DeployConfig 引用（L2-01 对象，含 topics/image config）last_log_time — 结构：标量字段；数值类型：float（monotonic 秒，用于日志限速）
数据读写create_subscriptions(node) — 从哪读：ROS topic（来自 config.topics.observation，6 个：image/arm/gripper × 左右）；读出什么：subscription handles（绑定 callback 到 topic）；缺 topic 抛异常decode_image_message(msg) — 从哪读：ROS image message（进程外部消息）；读出什么：RGB RAM 图像（np.ndarray）；不支持的编码 抛异常
编排函数handle_image(name, msg) — 顺序：decode_image_message → collector.update_image → try_publish_observation；调用条件：每来一条 image msg；失败处理：decode 失败只 log warning，不更新 collectorhandle_tcp_pose(side, msg) — 顺序：解析 pose → collector.update_tcp_pose → try_publish_observation；调用条件：每来一条 tcp_pose msg；失败处理：非法 shape 抛/记录handle_gripper_state(side, msg) — 顺序：解析 width → collector.update_gripper_state → try_publish_observation；调用条件：每来一条 gripper msg；失败处理：非法 width 抛/记录try_publish_observation() — 顺序：查 missing_fields → 查 stale_fields → 调 snapshot() → 写 buffer.set_observation；调用条件：每次 callback 后；ready 才写 buffer；失败处理：缺字段只记诊断，不写

ROS import 策略：真实 ROS 包延迟导入或包在 adapter init 路径，保证 types/service/runtime 在无 ROS 环境 importable。无 ROS 时，真实 subscription 验收 = BLOCKED_ENV，但 mock 消息解码 + 静态检查仍跑。

文件：ui/observation_ros_adapter.py。允许依赖：types/observation.py、config 公开对象、service/observation_collector.py、service/image_preprocess.py、runtime/observation_buffer.py、ROS 包（仅 ui 层）。禁止：L2-03 policy runtime、L2-04 SafetyGuard、L2-05 命令发布/硬件驱动、L2-06 ControlLoop 内部。

反模式（Gate 会判失败）：把 ObservationSnapshot 放在 service/ 或 runtime/ 导致 L2-03/L2-06 依赖下游实现；snapshot() 在缺字段时仍生成对象；stale 超时形同虚设；ui adapter 的 import 使无 ROS 环境 service/runtime 单测跑不起来；L2-02 里出现推理 / ActionChunk 消费 / safety / 硬件发送逻辑。
