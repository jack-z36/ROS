# 状态恢复行为

## 消费 Agent

- 主 Agent

## 本文职责

本文只约束主 Agent 在每轮循环开始时如何恢复阶段四真实状态。

## 不负责

本文不决定目标 L2、不派发任务、不修改状态、不执行 Git。

## 必须读取

- `DOCS/03_工程/阶段四：模型部署/00_status/INDEX.md`
- `DOCS/03_工程/阶段四：模型部署/00_status/current_loop_snapshot.md`
- `DOCS/03_工程/阶段四：模型部署/00_status/l2_progress_status.md`
- `DOCS/03_工程/阶段四：模型部署/00_status/l3_dispatch_status.md`
- `DOCS/03_工程/阶段四：模型部署/00_status/git_sync_status.md`
- `DOCS/03_工程/阶段四：模型部署/00_status/hardware_block_status.md`
- `DOCS/03_工程/阶段四：模型部署/03_tasks/task/dispatch/*.yaml`
- 各 L2 的 `05_acceptance/<l2>/验收结果.md`

## 输出

必须先输出当前状态摘要，至少包含：

- L2 Gate 状态。
- 当前可推进 L2 候选。
- 已知 blocked 项。
- Git pending push 项。
- 下一步需要进入的行为文件。

## 禁止事项

- 禁止凭记忆恢复进度。
- 禁止把 `00_status` 摘要当作唯一权威来源。
- 禁止在状态冲突时继续执行；必须指出冲突并以 dispatch、验收结果和 Git 实际状态为准。
