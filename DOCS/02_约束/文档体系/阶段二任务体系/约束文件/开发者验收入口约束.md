# 开发者验收入口约束

本文约束阶段二 Service 场景一到场景五的 L2 设计、L3 拆分和最终验收方式。目标是确保所有功能最终都能通过统一开发者入口被人工选择、运行、查看产物和判断正确性。

## 一、统一入口

阶段二 Service 场景的开发者端最终验收统一从仓库根目录执行：

```bash
./start_data_clean.sh --dev
```

`--dev` 表示进入开发者引导界面，不直接执行正式生产流程。

开发者引导界面的一级菜单固定对应阶段二五个 Service 场景：

```text
开发者引导界面
  1. 场景一：提取夹爪开合以及位姿转换
  2. 场景二：硬件数据可靠性验证
  3. 场景三：MCAP 多 topic 时间轴对齐
  4. 场景四：构建标准 canonical dataset
  5. 场景五：模型训练格式导出器
```

## 二、场景功能检验菜单

选择某个场景后，必须进入该场景的功能检验菜单。该菜单按功能组织，不按内部脚本文件组织。

每个场景至少必须保留一个：

```text
场景完整 smoke test
```

该 smoke test 用于按该场景内部主要处理链路跑通一次最小样本。

每个 L2 能力模块设计时，必须说明它对应或影响哪个开发者检验项：

- 新增一个功能检验项。
- 接入已有功能检验项。
- 只影响场景完整 smoke test。
- 暂不暴露到开发者菜单，并说明原因。

## 三、开发者端输出

每次功能检验或场景 smoke test 的输出只要求两类：

1. 测试产物：用于判断功能是否按预期运行的调试输出、中间结果或小样本结果。
2. 运行日志：记录输入、配置、执行步骤、关键状态、错误信息和输出位置。

开发者端输出必须与正式生产输出隔离。每次功能检验必须保留独立运行目录，目录内至少包含测试产物和运行日志。

禁止把开发调试产物写入正式 canonical dataset 目录，禁止污染正式生产输出。

## 四、配置读取与临时覆盖

开发者端默认读取用户端生产配置，以保证功能检验接近真实生产契约。

开发者引导界面允许临时覆盖部分参数，但临时覆盖只对本次开发调试运行生效。

只有开发者明确选择“保存到配置文件”时，才允许把覆盖结果写回正式配置。

L2 / L3 文档不得把临时覆盖默认设计成自动写回配置文件。

## 五、交互闭环

开发者端交互闭环固定为：

```text
./start_data_clean.sh --dev
  -> 选择场景
  -> 选择该场景下的功能检验项或完整 smoke test
  -> 选择小样本输入和调试输出位置
  -> 可选：临时覆盖配置
  -> 执行检验
  -> 查看测试产物和运行日志
  -> 判断功能是否正确
```

开发者端交互应呈现为“页面 / 终端向导调用脚本”的体验，而不是要求开发者记住每个内部脚本的路径和参数。

开发者只需要知道自己要检验哪个场景、哪个功能；入口程序负责根据选择调用对应脚本、传递配置、创建调试输出目录并写入运行日志。

## 六、L2 文档必须说明的内容

Service 场景一到场景五的每个 L2 能力模块说明中，必须包含“开发者验收入口设计”内容：

1. 所属一级场景菜单。
2. 对应的功能检验项名称。
3. 是否影响场景完整 smoke test。
4. 小样本输入要求。
5. 调试输出目录要求。
6. 测试产物清单。
7. 运行日志最低字段。
8. 是否允许临时覆盖配置。
9. 是否允许保存覆盖到配置文件。
10. 该能力完成后，开发者如何通过 `./start_data_clean.sh --dev` 人工判断正确性。

如果某个 L2 只是底层类型、配置或工具函数，也必须说明它被哪个功能检验项或 smoke test 间接覆盖。

## 七、L3 文档必须说明的内容

Service 场景一到场景五的每个 L3 微元任务中，必须说明：

1. 本 L3 对应哪个场景菜单。
2. 本 L3 对应或影响哪个功能检验项。
3. 本 L3 是否影响场景完整 smoke test。
4. 本 L3 是否需要修改开发者入口、菜单项、脚本调用、运行日志或测试产物。
5. 本 L3 的自动化验收命令只能证明局部实现正确；最终场景验收仍由用户本人通过 `./start_data_clean.sh --dev` 运行。

如果本 L3 不直接接入开发者入口，必须写明“不直接接入开发者入口，但由 `<功能检验项或 smoke test>` 间接覆盖”。

## 八、场景最终验收

完成一个场景的全部 L3 微元任务后，不由 Agent 宣称该场景最终验收完成。

Agent 只能在交接摘要中说明：

```text
建议用户运行 ./start_data_clean.sh --dev，选择场景 <N>，执行 <功能检验项或场景完整 smoke test> 做最终验收。
```

场景最终验收必须由用户本人运行开发者入口、查看测试产物和运行日志后确认。
