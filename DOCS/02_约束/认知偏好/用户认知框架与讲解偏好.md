# 用户程序理解分层概念体系

## 定位

| 项   | 内容                                           | 简单例子 |
| ---- | ---------------------------------------------- | -------- |
| 对象 | Python 项目                                    | `act_deploy/` 这个项目能启动一个推理程序 |
| 性质 | 用户当前用于理解、拆解和描述程序的分层概念体系 | 用这套表去拆解“3 路图像 + 14D action”的部署程序 |
| 状态 | 草案，后续根据实践慢慢补充                     | 现在先定义 `types/config/repo/service/runtime/ui` |

## 总览

| 层级      | 名称           | 对应实体                                                  | 作用                   | 简单例子 |
| --------- | -------------- | --------------------------------------------------------- | ---------------------- | -------- |
| 第一层    | 程序           | 一个能运行的 Python 项目                                  | 理解整体               | 启动后接收相机图像，输出 14D action |
| 第 1.5 层 | 程序行为视角   | 数据流                                                    | 理解程序运行时数据怎么走 | 图像 `(3,224,224)` 进入程序，最后变成 action `[0.1, -0.2, ...]` |
| 第二层    | 文件夹架构     | `types / config / repo / service / runtime / ui` 六类目录 | 理解程序的六个架构概念 | `service/` 负责把 observation 算成 action |
| 第三层    | 文件           | 目录里的文件                                              | 理解单个文件           | `action_codec.py` 负责处理 action |
| 第 3.25 层 | class 打包函数 | 文件里定义的 class                                        | 理解 class 如何封装多个功能微元 | `ObservationCollector` 打包图像缓存和 snapshot 生成逻辑 |
| 第 3.5 层 | 文件内功能微元 | 文件里的功能单元                                          | 理解文件由哪些功能组成 | 一个文件里可能同时有 `ACTION_DIM = 14` 和 `decode_action()` |
| 第四层    | 变量           | 文件里定义或使用的变量                                    | 理解名字和数据的绑定   | `control_hz = 30` |
| 第五层    | 基本语法       | 一行里的语法单元                                          | 理解一行由什么组成     | `=` 表示把右侧对象绑定给左侧名字 |

## 第一层：程序

| 概念 | 当前理解                 | 简单例子 |
| ---- | ------------------------ | -------- |
| 程序 | 一个能运行的 Python 项目 | 运行 `python deploy.py` 后，程序持续接收输入并输出动作 |

## 第 1.5 层：程序行为视角

| 概念   | 当前理解                                                                                                                                                                                                                                                                                                                                 | 简单例子 |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 数据流 | 数据流是用第二层架构概念描述：一份数据从外部进入程序后，先被哪个架构层接住，变成什么内部数据，又被哪个架构层加工、保存、调度，最后从哪里输出。<br />它的实用目的，是帮助我理解他人的程序，以及描述我想创建的程序。<br />它不是单纯的一条直线，而是一张围绕输入和输出展开的运行过程图。 | ROS topic 输入一张图像 `(480,640,3)`，进入 `ui` 后变成 RAM 里的 tensor `(3,224,224)`，最后经 `service` 变成 14D action |

## 第二层：文件夹架构

| 概念        | 当前理解                                                                                                                                                                                                                                                                                                                                                                                                | 简单例子 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `types`   | 定义数据长什么样，它只负责回答一个问题：程序里被传来传去的数据，应该长什么样。<br />具体包括：这个数据有哪些字段、每个字段是什么类型、如果是数组则有多少维、每一维或每一段分别代表什么、哪些取值是固定选项、什么样的数据一眼就算非法。<br />`types/` 是程序架构中最上游的数据语言层。<br />它不关心配置从哪里来、不关心文件怎么读、不关心业务怎么处理、不关心运行时怎么调度、不关心 UI/ROS 怎么交互。 | 定义 `Action` 必须是 14 个 `float`，例如 `[0.1, -0.2, 0.0, ...]` |
| `config`  | `config/` 是程序架构中的运行参数语言层。它位于 `types` 之后，依赖 `types` 提供的数据语言，用来定义程序运行时有哪些可配置参数、这些参数是什么类型、默认值是什么、哪些配置值明显非法。<br />它不负责存放某次运行的具体配置值；<br />具体值放在 `config_files/`。<br />它的职责是把外部配置值整理成后续层可以稳定使用的配置对象。                                                                  | 定义 `control_hz` 是 `float`，本次配置值可以是 `30.0` |
| `repo`    | `repo/` 是程序架构中的外部资源读取层。它位于 `config` 之后，依赖 `types` 和 `config`。它负责根据配置找到进程外部的资源，读取、解析、校验这些资源，并把它们变成当前 Python 进程 RAM 里的内部对象，供后续层直接使用。它不负责业务处理、运行时调度或 UI/ROS 交互。相关基础概念见 `Python代码运行的计算机基础.md`。                                                                               | 从 `/models/act/checkpoint.pt` 读取模型权重到 RAM 里的 `policy` 对象 |
| `service` | `service/` 是程序架构中的业务计算层。它位于 `repo` 之后，依赖 `types`、`config` 和 `repo`。<br />从输入输出角度看，`service/` 接收已经在当前 Python 进程 RAM 里的输入对象，调用计算函数，按照程序目标把它们加工成新的内部对象或判断结果。<br /><br />它不负责把外部资源读进 RAM，不负责安排循环、线程或执行时机，也不负责直接和 ROS/硬件交互。                                              | 输入 observation，输出 action，例如把 26D 状态和 3 路图像加工成 14D action |
| `runtime` | `runtime/` 是程序架构中的运行流程组织层。它位于 `service` 之后，依赖 `types`、`config` 和 `service`。<br />它负责根据时间、状态、事件和失败条件，调度计算函数、内部状态更新函数以及必要的数据读写函数，把一次性的处理能力组织成持续运行的程序流程。<br />它关心的是“什么时候调谁、多久调一次、谁先谁后、是否并发、失败后怎么办”，而不是具体业务怎么算。                                     | 每 `1/30` 秒调用一次取动作和发布动作流程 |
| `ui`      | `ui/` 是程序架构中的外部交互层。它位于最下游，依赖前面的 `types`、`config`、`repo`、`service`、`runtime`。<br />它负责让程序和外部世界交换数据：把外部输入转换成 Python 进程 RAM 里的内部对象，也把内部对象转换成外部系统能接收的消息、命令或输出。<br />在 ROS 项目中，`ui/` 主要负责 ROS Node、topic 订阅、topic 发布和 message 转换。它不负责核心业务计算，也不负责内部运行流程编排。  | 从 `/camera/color/image_raw` 收到图像消息，把 `/action_cmd` 发布给机械臂 |

## 第 3.25 层：class 打包函数

| 概念 | 当前理解                                                                                                                                                                                                                                                                                 | 简单例子 |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| class | class 是第 3.25 层的打包函数。它不是最底层功能微元，而是把第 3.5 层的数据、计算函数、数据读写函数、内部状态更新函数、编排函数打包进一个命名结构中。<br />class 本身是文件里的封装定义；`class()` 实例化后得到的对象进入第四层变量。<br />理解 class 时，先拆它内部打包了哪些 3.5 层功能微元。 | `ObservationCollector` 打包 `_images={}`、`_values={}`、`update_image("left", tensor)` 和 `snapshot()`；`collector = ObservationCollector()` 后，`collector` 是第四层变量 |

## 第 3.5 层：文件内功能微元

| 功能微元         | 当前理解                                                                                                                                                                             | 简单例子 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- |
| 数据             | 定义变量的 变量名、内部数据结构以及各个部分存储的数值类型的那部分代码。                                                                                                              | `ACTION_DIM = 14`，其中变量名是 `ACTION_DIM`，数值是 `14` |
| 计算函数         | 输入是 RAM 里的数据；<br />输出是新的 RAM 内部数据或判断结果。<br />它不直接读写进程外部资源。理解计算函数，重点是看清楚输入数据和输出数据的特征边界。                               | 输入 `[1.0, 2.0]`，输出归一化后的 `[0.1, 0.2]` |
| 内部状态更新函数 | 输入是 RAM 里的已有对象和新值；<br />输出不是一个全新的业务结果，而是 RAM 里已有对象的状态被更新。<br />它修改的是进程内部对象，例如 buffer、queue、cache。                          | 把最新 action `[0.1, -0.2]` 写入 `latest_action` |
| 数据读写函数     | 输入通常是路径、topic、硬件句柄或待写出的数据；<br />输出是从进程外部读入的数据，或进程外部资源被写入后的结果。<br />它的边界特征是发生了文件、ROS topic、网络、硬件等进程边界交互。 | 输入路径 `config.yaml`，输出 RAM 里的配置字典 `{"control_hz": 30}` |
| 编排函数         | 输入是函数、状态、事件、时间条件或失败条件；<br />输出是一个被组织起来的执行流程。<br />它的重点不是算出新数据，而是决定什么时候调谁、按什么顺序调、失败后怎么办。                   | 每 0.033 秒依次执行“取观测 -> 推理 -> 发布动作” |

## 第四层：变量

| 概念 | 当前理解                                                                                                                                                                                                 | 简单例子 |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 变量 | 变量可以从三个角度理解：<br />变量名、存储的数据结构、各部分存储的数据类型。<br />它最终对应硬盘或 RAM 中的一块数值区域；<br />在 Python 运行时，变量表现为一个名字绑定到当前 Python 进程 RAM 里的对象。 | `action = [0.1, -0.2, 0.0]`：变量名是 `action`，结构是列表，内部数值类型是 `float` |
