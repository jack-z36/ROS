# L3 现有实现盘点约束

## 1. 约束目的

阶段二很多 L3 不是从零开发，而是在已有程序基础上做接口稳定、架构适配、配置迁移或契约补测。生成这类 L3 时，任务文件必须明确说明现有代码已经实现了什么，避免执行端重复造轮子或误删已有能力。

## 2. 适用范围

当 L3 满足任一条件时，必须遵守本约束：

- 用户说明“这个功能之前已经写过”。
- L2 或功能模块清单中提到“已有实现”“对接已有程序”“改造现有代码”。
- L3 的执行对象包含已有 `src/` 代码文件。
- 任务目标是接口对接、配置迁移、契约稳定、补测试或报告补齐。

## 3. 必须包含的章节

这类 L3 必须包含以下章节：

```text
## 现有程序盘点
## 本 L3 的真实改造边界
```

## 4. 现有程序盘点必须写什么

至少写清：

1. 相关现有文件路径。
2. 每个文件已经实现的能力。
3. 现有数据结构、类、函数或入口。
4. 现有行为与目标契约的差距。
5. 已知风险，例如命名方向、精度损失、统计字段语义不准、报告缺字段。

不得只写：

```text
复用现有代码
对接现有接口
已有实现
```

必须具体到文件和能力。

## 5. 真实改造边界必须写什么

必须明确：

- 本 L3 应复用哪些现有能力。
- 本 L3 只允许改造哪些行为。
- 本 L3 禁止重写哪些已存在能力。
- 哪些问题留给其他功能组 L3。

## 6. 禁止事项

- 禁止把已有程序说成待实现空白。
- 禁止在没有现有程序盘点的情况下要求执行端“实现某功能”。
- 禁止把多个已有模块的改造揉进一个 L3。
- 禁止让执行端自行猜测现有程序是否可复用。

## 7. 验收要求

生成 L3 后，必须能回答：

```text
1. 这个功能现有代码在哪？
2. 现有代码已经做到了什么？
3. 这次到底改什么？
4. 什么不能改？
5. 哪些验收是针对已有实现补测试，而不是从零实现？
```

如果回答不了，说明 L3 任务文件不合格，必须重写。
