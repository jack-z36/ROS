# Pi0.5 源码 3.5 层微元拆解：L2-01

> [!info] 说明
> - Pi0.5 源码只作为结构参考，不覆盖当前 ACT L2-01 边界。
> - 本文目标：讲清 Pi0.5 部署代码中与 L2-01（外部参数加载与契约校验）对应的功能模块**是如何运作的**。
> - 第一版已去除独立 action smoothing L2；Pi0.5 中如存在平滑、mux、bridge 或复杂时间对齐思想，不进入本 L2 设计。
> - 路径基于实际源码树（src-layout），文件位于 `pi05_test/pi05/<deploy|common>/src/pi05/...`。

## 0. L2-01 对应 Pi0.5 的哪一部分

L2-01 的运行时职责是「把外部静态参数读入 RAM、做合规校验、冻结为契约对象」。Pi0.5 部署代码中完成同一件事的功能模块是**部署配置装载 + bundle 装载**，分布在两个包：

| Pi0.5 文件（真实路径） | 对应 L2-01 的哪部分 |
|---|---|
| `deploy/src/pi05/deploy/config/schema.py` | 配置 schema + 装载编排 + 类型化校验（types/config 层职责） |
| `common/src/pi05/common/runtime/bundle.py` | bundle/manifest/normalizer 外部读取（repo 层职责） |
| `common/src/pi05/common/config/schema.py` | experiment_config 结构（repo 层交叉校验参考） |
| `common/src/pi05/common/data/normalization.py` | normalizer 数据对象（repo 层反序列化 + service 层计算） |
| `common/src/pi05/common/robot/action_spec.py` | ACTION_DIM/STATE_DIM 常量 + action 拆装（types 层） |
| `common/src/pi05/common/data/state_codec.py` | state 拼装成 26D（types 层 codec） |

> [!important] 维度差异（决定不能照搬）
> Pi0.5 是 **26D state / 14D action**（`ARM_DOF=6`、`HAND_DOF=1`，关节角表示）。
> ACT 第一版是 **16D state / 16D action**（TCP pose + gripper width）。
> 因此 Pi0.5 的维度常量、codec、normalizer 长度都只能作为结构参考，数值必须重写。

## 0.5 给计算机小白的白话开场

如果你不熟悉 Python 工程术语，先读这段，再往下看。

这一部分代码做的事，可以用一句话概括：**把一个写满运行参数的 yaml 文件，变成程序里一个"只读、不会变、随时可查"的配置对象**。就像把一份纸质表格誊抄进一块刻好的石碑——誊抄时检查每一栏有没有填错，刻完之后谁都改不动，后面所有人只能读、不能改。

理解下面几个词就够了（用《用户认知框架与讲解偏好.md》的概念体系解释）：

| 术语 | 白话解释 |
|---|---|
| **yaml 文件** | 一个用缩进表示层级的文本文件，里面写满 `键: 值`，比如 `control_hz: 30`。人能直接读，程序也能读。这里它就是那张"纸质表格"。 |
| **raw mapping**（原始映射） | 程序把 yaml 文件读进内存后，得到的"一整坨没检查过的键值对"。它**还没有任何类型保证**——`control_hz` 的值可能是数字 30，也可能是手误写成的字符串 `"三十"`，此时还没人查。 |
| **校验**（validate） | 检查每个值是不是"该有的样子"：该是数字的地方是不是数字、是不是正数、是不是在允许的选项里。查出一个错就立刻报错停下，不让程序带病往下走。 |
| **类型化校验器**（typed validator） | 一个个"专门检查某一类值"的小函数。比如 `_positive_float` 专门负责"必须是正的小数"，`_choice` 专门负责"必须是这几个选项之一"。每个配置字段都配一个对应的校验器。 |
| **typed 值**（类型确定的值） | 经过校验器检查通过后的值。程序拿到它时**已经确定**它就是某种类型（比如确定是正小数），后面不用再担心它突然变成别的乱七八糟的东西。 |
| **dataclass** | Python 的一种"带固定字段的容器"。可以理解成一张预先印好栏位的小卡片，每个栏位有名字。`RuntimeConfig` 就是这样一张卡片，上面印着 `control_hz`、`chunk_size` 等栏位。 |
| **frozen dataclass**（冻结的 dataclass） | 一张"刻了就不能改"的卡片。一旦把值填进去，谁都不能再修改它的字段。这正是 L2-01 要的效果——配置进内存后就锁死，全程序都按这套锁死的值运行。 |
| **`__post_init__`** | dataclass 卡片"填完值之后"自动触发的一段检查代码。它检查的不是单个字段，而是**字段之间的关系**，比如"`execute_horizon` 不能大于 `chunk_size`"。 |
| **bundle**（模型包） | 训练好的模型导出成一个目录，里面装着权重、清单、归一化参数等文件。部署程序不重新训练，只读这个包。 |
| **manifest.json**（清单） | bundle 目录里的一个文件，像快递箱上的发货单，写清楚这个包里有什么、维度是多少、是什么时候打的包。 |
| **normalizers.json**（归一化参数） | bundle 里的另一个文件，记录怎样把传感器原始数值"压"到 [-1, 1] 区间（模型只认这个区间的输入）。 |
| **抛异常 / 报错中止** | 程序发现配置不对时，不假装没事继续跑，而是当场报错退出。这比"带着错误配置勉强运行"安全得多。 |

### 一个配置项走完全流程的例子

以 yaml 里的 `runtime: control_hz: 30` 这一行为例，跟着它走一遍：

```text
① 写在 deploy.yaml 里：        control_hz: 30            （文本，还没人检查）
② yaml.safe_load 读进内存：     raw["runtime"]["control_hz"] = 30  （成了 raw mapping 的一部分）
③ _deploy_from_mapping 装配：   调 _positive_float(raw, "control_hz", default=30.0)
④ 校验器 _positive_float 检查： 30 是数字、>0 → 通过 → 返回 30.0（typed 值）
⑤ 填进 RuntimeConfig 卡片：      runtime = RuntimeConfig(control_hz=30.0, ...)
⑥ 卡片填完触发 __post_init__：   检查 30.0 > 0 → 通过
⑦ 进 DeployConfig，冻结：        deploy_config.runtime.control_hz 永远是 30.0，谁也改不了
⑧ 后续 L2-06 用：                tick 周期 = 1 / deploy_config.runtime.control_hz
```

如果 yaml 里手误写成 `control_hz: "abc"`：第④步 `_positive_float` 发现 `float("abc")` 失败 → 抛 `DeployConfigError` → 程序立刻停下，不会进入第⑤步。这就是"非法配置在入口处失败"。

## 1. 运行机制：Pi0.5 这部分是怎么运作的

入口是 `load_deploy_config(path)`（`deploy/config/schema.py`）。它把一次「读 yaml → 装配 → 校验 → 冻结」组织成一条线性流程：

```text
load_deploy_config(path)
  1. yaml.safe_load(path)            → raw mapping          [数据读写函数 · 跨进程边界]
  2. DeployConfig.from_mapping(raw)  → _deploy_from_mapping [编排函数]
       按 bundle / runtime / image / topics / safety / bridge / mux 顺序：
       a. 每个字段调用类型化校验器（_str/_choice/_positive_float/_bool/...）  [计算函数 · RAM 内]
       b. 缺必填或类型错 → 抛 DeployConfigError，立即中止
  3. RuntimeConfig.__post_init__     [计算函数 · RAM 内]
       关系校验：control_hz>0、execute_horizon≤chunk_size、prefetch≤execute_horizon、
                 fallback_policy ∈ 枚举 …  不满足即抛 DeployConfigError
  4. 返回 frozen DeployConfig        [数据 · 全生命周期不可变]
```

bundle 部分单独成一组外部读取函数（`common/runtime/bundle.py`），在装配完成后或装配过程中按 `bundle_dir` 读取：

```text
load_bundle_manifest(bundle_dir)      → 读 manifest.json → dict          [数据读写函数 · 跨进程边界]
load_bundle_normalizers(bundle_dir)   → 读 normalizers.json → 构造两个
                                         ActionStateNormalizer 对象        [数据读写函数 + 计算]
resolve_bundle_adapter_dir(bundle_dir)→ 检查 adapter/ 目录存在           [数据读写函数]
```

关键协作关系（回答「谁持有状态 / 谁调用谁 / 谁跨边界 / 谁负责时序」）：

- **谁持有状态**：`DeployConfig`（frozen，启动期一次创建，全生命周期只读）；`ActionStateNormalizer` 实例（bundle 加载后稳定持有 min/max/range/identity_mask）。
- **谁调用谁**：`load_deploy_config` 调 `_deploy_from_mapping`；后者调 `_str/_choice/_positive_float` 等校验器；校验器产出 typed 值喂给各 `@dataclass(frozen=True)` 构造器；构造后触发 `__post_init__` 关系校验。
- **谁只负责加工 RAM 对象**：类型化校验器（`_str/_choice/_bool/_positive_float/_float_list`）、`RuntimeConfig.__post_init__` 关系校验、`ActionStateNormalizer.normalize/unnormalize`（纯 RAM 内 min-max 变换）。
- **谁跨越外部边界**：`yaml.safe_load`（读 deploy.yaml）、`load_bundle_manifest`（读 manifest.json）、`load_bundle_normalizers`（读 normalizers.json）、`resolve_bundle_adapter_dir`（stat adapter 目录）。本 L2 **不写**外部文件、不订阅 topic。
- **谁负责 runtime 时序或失败处理**：**无**。本 L2 启动期同步调用一次，不进入稳态 tick；失败方式只有「抛异常阻止启动」，不存在 fallback、重试或并发。

## 4. class 封装盘点

| class | 源码路径 | 封装了哪些 3.5 层微元 | 内部状态 | 生命周期 / 并发特征 | 为什么适合 class | ACT 中的处理建议 |
| --- | --- | --- | --- | --- | --- | --- |
| `DeployConfig` | `deploy/config/schema.py` | 数据 + 关系校验（经 `__post_init__`） | 子配置对象树 | 启动期创建一次，无并发 | 聚合根配置，生命周期贯穿全程序 | frozen dataclass |
| `RuntimeConfig` | `deploy/config/schema.py` | 数据 + 关系校验 | hz、chunk、mode、fallback、blend_steps 等 | 启动期创建一次 | 多字段关系校验，后续多 L2 读取 | frozen dataclass（去 blend_steps） |
| `SafetyConfig` | `deploy/config/schema.py` | 数据 + 校验 | 单步限制、hand_min/max、joint_limits | 启动期创建一次 | L2-04 需要稳定读取 | frozen dataclass |
| `TopicsConfig` 等 topic 配置 | `deploy/config/schema.py` | 数据 + 命名空间校验 | `/pi05_vla/*` topic 名 | 启动期创建一次 | L2-02/L2-05 共用 | frozen dataclass（改 `/act/*`） |
| `ActionStateNormalizer` | `common/data/normalization.py` | 数据 + 计算函数（normalize/unnormalize） | min/max/range/identity_mask | bundle 加载后稳定使用 | 有内部参数，重复调用 normalize/unnormalize | 结构复用 |

> 其余类型化校验器（`_str/_choice/...`）、`load_bundle_manifest`、`encode_bimanual_state`、`split_bimanual_action` 等**只做纯转换或单次读盘，无内部状态**，按判断原则应优先**函数**，不封装为 class。

## 5. 禁止继承的 Pi0.5 行为

- 不继承 Pi0.5 的 26D/14D 旧维度作为 ACT 当前 16D/16D 维度。
- 不继承 Pi0.5 的 `/pi05_vla/*` topic namespace 作为 `/act/*` 命名。
- 不把 bridge/mux 旧配置段搬入 L2-01 第一版。
- 不在本 L2 增加 `blend_steps`、`smoothstep_window`、`cross_chunk_fusion`、`rtc_alignment` 等平滑或复杂时间对齐配置（Pi0.5 的 `blend_steps=3` 属于此类，必须去除）。
