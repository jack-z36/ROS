## 2. 总量与分层

```text
A 层（3.25 Class）      1 个：A1
B 层（3.375 编排函数）  5 个：B1-B5
C 层（3.5 原子微元）   15 个：C1-C15
```

这里的“20 个功能微元”指 `B1-B5 + C1-C15`；`A1` 是把它们打包成对象的 Class，不把它重复计为业务功能。

| 编号 | 层级/类型 | 名称 | 父级 | 职责 |
|---|---|---|---|---|
| A1 | 3.25 Class | `SafetyGuard` | 无 | 持有不可变 policy，封装 B1-B5；无运行时可变状态。 |
| B1 | 3.375 编排 | `filter_action` | A1 | 对外入口：候选检查→选基准→双臂投影→结果。 |
| B2 | 3.375 编排 | `_validate_candidate_action` | A1/B1 | 组织 C6-C8 与复用 `split_action`，得到合法候选。 |
| B3 | 3.375 编排 | `_project_arm_pose` | A1/B5 | 组织 C10-C11，投影单侧 TCP pose。 |
| B4 | 3.375 编排 | `_project_gripper` | A1/B5 | 组织 C12-C13，投影单侧夹爪。 |
| B5 | 3.375 编排 | `_project_bimanual_action` | A1/B1 | 调 B3×2、B4×2，再调 C14-C15。 |
| C1 | 3.5 数据 | `SafetyStatus` | types | `PASS/ADJUSTED/REJECTED`。 |
| C2 | 3.5 数据 | `SafetyCode` | types | 稳定问题/调整原因码。 |
| C3 | 3.5 数据 | `SafetyFinding` | types | 一条 side/code/before/after 检查记录。 |
| C4 | 3.5 数据 | `_ComparisonReference` | service | 带来源标签的内部基准对象。 |
| C5 | 3.5 数据 | `SafetyResult` | types | 交付 L2-06/L2-05 的冻结结果。 |
| C6 | 3.5 计算 | `require_action_vector_16` | B2 | 严格 shape `(16,)` 检查。 |
| C7 | 3.5 计算 | `require_finite_action` | B2 | NaN/Inf 检查。 |
| C8 | 3.5 计算 | `canonicalize_quaternion` | B1/B2 | 校验并单位化内部 `xyzw` quaternion。 |
| C9 | 3.5 计算 | `select_comparison_reference` | B1 | previous→observation→缺失拒绝。 |
| C10 | 3.5 计算 | `limit_translation_step` | B3 | 三维欧氏位移投影。 |
| C11 | 3.5 计算 | `limit_rotation_step` | B3 | 最短弧旋转角/Slerp 投影。 |

## 3. 调用树

```text
A1 SafetyGuard
└── B1 filter_action
    ├── B2 _validate_candidate_action
    │   ├── C6 require_action_vector_16
    │   ├── C7 require_finite_action
    │   └── C8 canonicalize_quaternion ×2
    ├── C9 select_comparison_reference
    │   └── C8 canonicalize_quaternion ×2（reference）
    └── B5 _project_bimanual_action
        ├── B3 _project_arm_pose ×2
        │   ├── C10 limit_translation_step
        │   └── C11 limit_rotation_step
        ├── B4 _project_gripper ×2
        │   ├── C12 clamp_gripper_range
        │   └── C13 limit_gripper_step
        ├── C14 build_safe_action
        └── C15 validate_safe_action_invariants
```

重复调用左右两侧不是新增编号：一个 C/B 微元必须有一份实现、两次调用。

## 4. 整体协作逻辑

```text
candidate absolute action
    + previous safe action / fresh observation
    + immutable SafetyConfig
        ↓
B1 先确认候选是否可讨论
        ↓
C9 建立唯一、带来源的比较基准
        ↓
B5 把左右 pose 与夹爪投影到本拍安全边界
        ↓
C5 SafetyResult
        ↓
L2-06 决定发布或 fallback；L2-05 执行外部适配
```

没有任何 C 微元读写外部资源；没有任何 A/B/C 微元拥有跨 tick 状态。`previous_safe_action` 的更新只属于 L2-06。

## 5. 上游复用对象（不编号）

| 对象 | 所属 | 在本体系中的作用 |
|---|---|---|
| `ActionSpec`、`split_action` | L2-01 types | 16D 固定布局与结构化拆分。 |
| `SafetyConfig` / ActionDomain | L2-01 config | A1 的静态 policy 输入。 |
| `ObservationSnapshot` | L2-02 types | C9 的实测基准输入。 |
| `previous_safe_action` | L2-06 runtime | C9 的命令连续性基准输入。 |
