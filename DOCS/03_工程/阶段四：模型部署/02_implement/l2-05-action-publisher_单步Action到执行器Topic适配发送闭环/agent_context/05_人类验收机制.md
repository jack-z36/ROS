  'DOCS/03_工程/阶段四：模型部署/02_implement/l2-05-action-publisher_单步Action到执行器Topic适配发送闭环'

- 失败：缺文件、旧六层目录、HTML 组件/来源缺失或旧模板污染；先修设计包。

### H04 · ROS shadow（有 ROS 环境时）

```bash
python3 -m pytest -q src/model_deploy/act/tests/shadow/test_action_publisher_shadow.py
```

- 环境：ROS graph 可用，使用 fake safe action，不连接真实 command consumer。
- 观察点：policy/status 消息与四路 command 计数。
- 通过：`/act/policy_action`、`/act/command/status` 可见；四路 command 均为 0。
- 失败：policy/status 缺失或任一 command 出现；立即停止节点，检查 mode/authorization 双门控。
- 无 ROS：记录 `BLOCKED_ENV`，不得勾通过。
- 风险：中；必须确认 command topic 无真实订阅者。

### H05 · safe-run 未授权保护（ROS 环境）

使用测试 harness 启动 `safe-run + command_allowed=false`：

```bash
python3 -m pytest -q src/model_deploy/act/tests/shadow/test_action_publisher_safe_gate.py
```

- 观察点：policy/status 有输出，四路 command=0，status reason=`not_authorized`。
- 通过：三项同时满足。
- 失败：任何四路 command；立即停止，禁止进入真机。
- 风险：中；仍须保持 command topic 与硬件隔离。

### H06 · 真机验收（默认阻断）

本设计不提供可复制粘贴的真机启动命令。只有以下条件全部有证据时，现场负责人才能按独立运行手册执行：

- H01-H05 已通过。
- 明确的人类授权与验收负责人在场。
- 急停可用，RM65 碰撞防护/关节限位、工具/负载配置有效。
- 工作区清空，下游 driver 能区分 accepted/executed/reached。
- 先以低速、单步、最小范围测试；夹爪命令 0..100 已标定。

缺一项：记录 `BLOCKED_HARDWARE_EXPECTED`。禁止用 ROS publish success 代替硬件到位证据。

## 3. 观察语义翻译

| 看到的现象 | 只能说明 | 不能说明 |
|---|---|---|
| policy_action 有消息 | 策略意图已进入 ROS 观测通道 | command 已发、硬件会动 |
| `sent_to_driver=true` | 本次计划的 command publish 调用完成 | driver accepted、硬件执行/到位 |
| command topic 有消息 | ROS middleware 接到候选目标 | 机械臂/夹爪已经安全执行 |
| driver accepted | driver 接受目标 | 执行完成或无碰撞 |
| hardware reached | 需外部反馈证明到位 | 不能由 L2-05 自己推断 |
