## 0. 边界来源与上游漂移

当前 checkout 的 L1 文档仍残留旧语义。本文按用户最新确认锁定以下边界：

| 漂移项 | 本 L2 最终边界 |
|---|---|
| `dry-run / shadow-run / safe-run` 三模式 | 删除运行模式枚举；改为 CLI 静态总开关 + L2-06 每 tick 动态许可。 |
| `/act/policy_action` 被写成输入或串行 bridge 中间量 | 纯输出；与四路 command 从同一 safe action 派生。 |
| `latest arm/gripper state` 被写成输入 | 不是输入；L2-05 不订阅、不回读状态。 |
| workspace / IK 被写成 L2-05 检查 | 属外部 driver；L2-05 不实现。 |
| gate/deadman/急停原始信号被写成 L2-05 输入 | L2-06 汇总为 `CommandPermit`；L2-05 只消费最终许可。 |
| 左右不同 frame 直接贴值 | 第一版只接受一个权威 `pose_frame_id`；无 TF 转换不允许改贴 frame。 |
| `SafetyResult.accepted` | 过期；当前契约使用 `SafetyStatus.PASS / ADJUSTED / REJECTED`。 |

Pi0.5 仅作为源码结构参考，不得覆盖上述边界。旧 layer-based L2、Contract Delta 和阶段二模板均不是任务来源。

## 1. 一句话运行时职责

L2-05 是被 L2-06 每 tick 同步调用的唯一 ROS action 输出端口：它把 L2-04 交付的 safe 16D TCP action 依次加工为 Topic 候选载荷和标准 ROS message，再依据 CLI 静态总开关与 L2-06 动态许可选择并发布 policy、四路 command 和逐 action status，最后把真实发布事实作为 `ActionPublishResult` 返回 L2-06。

## 2. 输入

### 2.1 启动期只读输入

| 输入 | 来源 | 传递方式 | 约束 |
|---|---|---|---|
| `DeployConfig.command_output` | L2-01/启动装配 | 构造 `ActionPublisher` 时注入 | 含 `pose_frame_id`、夹爪映射、deadband、最小间隔、QoS。 |
| `command_output_enabled` | 显式 CLI `--enable-command-output` | 启动装配写入最终只读配置 | 默认 `False`；不得由 YAML 持久化默认值静默置真。 |
| node-like publisher factory | L2-06/UI 装配入口 | 构造期注入 | 只用于创建六个 publisher；L2-05 不拥有 node 生命周期。 |

### 2.2 每 tick RAM 输入

| 输入 | 来源 | 传递方式 | 约束 |
|---|---|---|---|
| `SafetyResult` | L2-04，经 L2-06 传递 | `ActionPublishRequest` | `PASS/ADJUSTED` 必须有 `ActionSpec`；`REJECTED` 禁止 policy/command。 |
| `CommandPermit` | L2-06 | `ActionPublishRequest` | `allowed: bool` + `reason_code`；不暴露原始 gate topic。 |
| `action_id` | L2-06 | `ActionPublishRequest` | 稳定关联 result/status 与当前 tick。 |
| `ros_time_s` | L2-06 | `ActionPublishRequest` | 用于 `PoseStamped.header.stamp`。 |
| `monotonic_s` | L2-06 | `ActionPublishRequest` | 用于夹爪 deadband/最小间隔；必须非负、finite。 |

明确不是输入：

- `/act/policy_action` 或任何 ROS subscription。
- raw action、`ActionChunk`、active chunk 或 cursor。
- latest arm/gripper state、workspace 参数、IK solver、TF 变换器。
- 原始 deadman、急停、enable、driver state topic。
- `RuntimeConfig.mode` 或 `PublishAuthorization.mode`。

## 3. 输出

### 3.1 RAM 返回对象

```text
ActionPublishResult
├── action_id
├── safety_status
├── command_output_enabled
├── command_permitted
├── outcome: REJECTED | OBSERVED | BLOCKED | PUBLISHED | PARTIAL | FAILED
├── policy_action_published
├── command_publish_count
├── gripper_skipped
├── command_plan_completed
├── status_published
├── reason_code
├── driver_accepted=None
└── hardware_reached=None
```

L2-06 直接消费 RAM result，不通过 ROS topic 回读自己的决策。

### 3.2 ROS 观察通道

| Topic | 第一版消息 | 语义 |
|---|---|---|
| `/act/policy_action` | `std_msgs/msg/Float32MultiArray` | 原样 16D safe action；表示本 tick 策略意图。 |
| `/act/command/status` | `std_msgs/msg/String`（JSON） | 逐 action 发送回执；根据真实发布结果在 B3 末尾构造。 |

### 3.3 ROS 执行器 command 通道

| Topic | 第一版消息 | frame / 单位 |
|---|---|---|
| `/act/command/arm/left_target` | `geometry_msgs/msg/PoseStamped` | `pose_frame_id`；position=m，quaternion=`xyzw`。 |
| `/act/command/arm/right_target` | `geometry_msgs/msg/PoseStamped` | 与左臂使用同一权威 `pose_frame_id`。 |
| `/act/command/gripper/left_target` | `std_msgs/msg/Float64` | 大象夹爪 `0..100`。 |
| `/act/command/gripper/right_target` | `std_msgs/msg/Float64` | 大象夹爪 `0..100`。 |

标准 ROS message 只是第一版 transport；内部类型化对象保留业务语义，未来迁移自定义 msg 不改变 L2 边界。

## 4. 发布决策

L2-05 不存在运行模式枚举。四路 command 的唯一总判据是：

```text
publish_commands =
    command_output_enabled
    AND CommandPermit.allowed
    AND B1 TopicPayloadBundle 构造成功
    AND B2 RosMessageBundle 构造成功
```

| CLI 总开关 | 动态许可 | policy | 四路 command | status | outcome |
|---|---|---|---|---|---|
| False | 任意 | 发 | 禁止 | 发 | `OBSERVED` |
| True | False | 发 | 禁止 | 发，记录许可原因 | `BLOCKED` |
| True | True | 发 | 允许；夹爪仍经 deadband | 发 | `PUBLISHED/PARTIAL/FAILED` |

补充约束：

- `SafetyStatus.REJECTED` 时不发布 policy/command，只尽力发 status，outcome=`REJECTED`。
- B1/B2 任一失败时不调用 policy/command publisher，只尽力发 status，outcome=`FAILED`。
- policy publish 失败时不进入 command 分支。
- CLI 关闭不等于跳过计算：B1/B2 仍应完成，保证观察路径能验证拆分、单位、frame 和消息构造。

## 5. 负责内容

- 通过三个编排函数形成闭环：
  1. B1 `build_topic_payloads()`：safe action → 五路 transport-neutral 候选载荷。
  2. B2 `build_ros_messages()`：候选载荷 → policy + 四路 command ROS message。
  3. B3 `ActionPublisher.publish()`：选择并发布 Topic，形成 result/status。
- 复核 `SafetyResult.status` 与 action 存在性，不允许 raw action 绕过 L2-04。
- 按固定段序拆分 16D：`[0:7]` 左 TCP、`[7:14]` 右 TCP、`[14]` 左爪、`[15]` 右爪。
- 将夹爪 `[0,1]` 线性映射为 `0..100`；越域直接失败，不 clip、不猜尺度。
- 使用单一 `pose_frame_id`，保持 position=m、quaternion=`xyzw`。
- 在第一次 policy/command publish 前完成 B1/B2 全部构造；B2 不提前构造最终 status。
- CLI 总开关与 `CommandPermit` 双条件门控真实 command。
- 持有夹爪最近成功发布目标和时间，执行 deadband/最小间隔。
- 发布逐 action status，区分观察、阻断、完整发布、部分发布和失败。
- ROS publish 异常时如实返回部分事实；L2-06 决定 fallback、重试或停止。

### 5.1 本地完整构造与 ROS 非事务边界

```text
允许声称：B1/B2 的五个候选消息必须全部在 RAM 构造成功，才开始 policy/command publish。
禁止声称：ROS 多 Topic 是事务，或所有设备一定同时接收/执行。
```

运行期某一路 command publish 抛异常时，已发消息无法回滚。result 必须记录实际成功数与 `PARTIAL`，并停止剩余 command；status 尽力发布，L2-06 接管后续处理。

## 6. 不负责内容

- 不解析 CLI；只消费启动装配后的 `command_output_enabled`。
- 不调用 ACT policy，不做 batch、推理或反归一化。
- 不选择 action step，不管理 `ActionChunk`、cursor、queue、timer 或 tick。
- 不重新实现 L2-04 的 quaternion/TCP delta/投影算法。
- 不读取 arm/gripper 实时状态，不做 workspace、IK、TF、MoveIt 或碰撞规划。
- 不汇总原始 gate/deadman/急停/driver readiness；这些属于 L2-06 与外部 driver。
- 不决定 fallback、不拥有全局 metrics、不自行重试。
- 不调用 RM65 SDK、driver API、Modbus、USB-485 或夹爪串口。
- 不订阅 `/act/policy_action`，不建立旧 bridge/mux 串行链路。
- 不实现 action smoothing、跨 chunk 融合、RTC 或复杂时间重采样。

## 7. 可持有的最小状态

| 可以持有 | 用途 |
|---|---|
| 六个 ROS publisher handle | policy、左右臂、左右爪、status 外部写出。 |
| 左/右最近成功发布的夹爪目标与单调时间 | deadband 与最小发布间隔。 |
| 最近一次 `ActionPublishResult` | 即时诊断与 RAM 查询。 |
| immutable `CommandOutputConfig` | 启动后只读输出策略。 |

| 不可持有 | 所有者 |
|---|---|
| active chunk / cursor / fallback / retry | L2-06 |
| previous safe action | L2-06 |
| 原始硬件授权信号 | L2-06 / 外部 driver |
| 全局 RuntimeMetrics | L2-06 |
| ROS node 生命周期 | L2-06/UI 装配入口 |

## 8. 上下游

- 上游 L2-01：16D action spec、topics、输出映射配置和最终只读 `DeployConfig`。
- 上游 L2-04：`SafetyResult` 与 safe/adjusted `ActionSpec`。
- 控制调用方 L2-06：`CommandPermit`、action_id、两种时间、同步调用时机；消费 `ActionPublishResult`。
- 下游 L2：无。
- 外部下游：ROS middleware → driver 节点 → 执行器；监控/日志消费 policy/status。

## 9. 完成判据

- B1/B2/B3 三编排函数及其 C 层原子微元可独立测试。
- `PASS/ADJUSTED` 可发布，`REJECTED` 禁止 policy/command；不存在 `result.accepted`。
- 16D 左右段、单一 frame、`xyzw`、米制单位和夹爪映射正确。
- 未传 CLI 时 command publisher 调用数恒为 0。
- CLI 打开但 permit=False 时 command 调用数恒为 0，reason 可读。
- CLI 打开且 permit=True 时按计划发布；夹爪 deadband 跳过不计失败。
- B1/B2 任一失败时 policy/四路 command 调用数均为 0。
- 部分 ROS publish 如实返回 `PARTIAL`，不伪造回滚或硬件成功。
- status 能区分 `REJECTED/OBSERVED/BLOCKED/PUBLISHED/PARTIAL/FAILED`。
- 模块无 subscription、timer、workspace/IK/TF、厂商 SDK import。
