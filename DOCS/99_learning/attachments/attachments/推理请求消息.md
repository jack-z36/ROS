> [!abstract]
> 把某次观测封装成后台推理线程可消费的请求

## 基本信息

| 属性 | 值 |
| --- | --- |
| 变量名 | `InferenceRequest, request` |
| 参考系 | 不适用；这是程序数据流节点，不是几何坐标变换结果 |
| 相对原点 | 不适用 |
| 物理锚点 | 纯数学对象 / 调度消息 |

## 关键澄清

### 1. 它在哪个参考系下？

不适用。这里的“参考系”不是机器人空间坐标系，而是程序流水线中的数据阶段。

### 2. 它相对哪个原点？

不适用。它不是空间点或位姿变换结果。

### 3. 它对应哪个物理点 / 物理对象？

纯数学对象 / 调度消息。如果它是缓存、请求或 batch，则无对应物理点，这是纯数学对象 / 程序容器。

### 4. 它是不是最终输出？

否。

### 5. 它不是什么？

它不应被误解为“整个推理程序的最终命令”。只有 ROS 控制命令输出才是下游执行系统真正收到的命令。

## 对应源码

request = InferenceRequest(observation=observation, obs_time=observation.captured_at_s, request_id=self.request_id, trigger_step=self.active_cursor)
