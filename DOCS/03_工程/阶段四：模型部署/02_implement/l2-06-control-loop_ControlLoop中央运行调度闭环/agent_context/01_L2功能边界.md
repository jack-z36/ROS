## 运行责任与边界

**L2：**ControlLoop 中央运行调度闭环。

**Runtime responsibility：**由 ROS timer 以 `control_hz` 调用 `ControlLoop.tick()`；tick 以最小状态机收集异步 chunk、提交下一次推理、从 active chunk 按 cursor 直取单步、调用安全与发布能力，并记录 status/metrics。

**Inputs：**`DeployConfig`；L2-02 写入的 `latest_observation`；L2-03 的 request/result latest-only queue 和 `ActionChunk`；L2-04 `SafetyGuard`；L2-05 publisher/command adapter。

**Outputs：**`InferenceRequest`；16D raw single action；传给 L2-05 的 safe action 或 fallback（hold / safe-stop / status-only）；`RuntimeMetrics`、运行状态。

**Owns：**request id / request pending、active chunk / cursor、chunk 合法性与过期判定、fallback 原因、tick 次序和 L2-06 汇总指标。

**Does not own：**外部配置解析、ROS observation callback、ACT batch/模型前向、通用 safety 计算、topic/hardware 格式适配或硬件 SDK；不做 action smoothing、跨 chunk 融合或 RTC 对齐；不生成 `ControlDecision` 对象。

**Upstream L2：**L2-01 提供静态契约，L2-02 提供 observation，L2-03 提供推理 actor，L2-04 提供 `SafetyResult`，L2-05 提供输出接口。

**Downstream L2：**L2-05 是命令与状态的外部输出边界；metrics/status 由 UI 发布。

## 状态与失败不变量

1. tick 不等待模型推理；request/result 都是 latest-only 异步交接。
2. 只有 `ActionChunk` shape、有限值、年龄和 cursor 都合法才可读出 raw action。
3. 无 observation、无可用 chunk、推理错误、chunk 非法/过期、SafetyResult reject 都必须进入 fallback，并写 reason/metrics。
4. `safe action` 直接交 L2-05；fallback 也由 L2-05 输出，禁止虚构中间决策对象。
5. 真机动作永远受 L2-05 gate 管理；本 L2 的验证不等于真机通过。

## 完成判据与未决项

mock 闭环中可观察到：无 observation 不提交有效 request；有 observation 提交 request；返回 chunk 后按 cursor 直取一项；末段 prefetch；safety reject fallback；成功发布后 metrics 更新。

外部 topic、硬件 driver、E-stop 和真实 fallback 执行语义尚未在本工作树确认，均为 shadow/真机验收的 `BLOCKED` 条件；不阻塞 mock L3，但阻塞真机通过结论。
