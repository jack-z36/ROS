# 场景一执行约束

## 1. 执行边界

- 本场景只做 4 个相机 ROS 节点的逐个启动、逐个观察和逐个验证。
- 每次只启动一个目标相机节点，确认 topic、频率和 Octopus 可见性后，再切换到下一个节点。
- 不在本场景内追求一键启动、自动录制、自动同步或完整 FASTUMI 处理流水线。

## 2. 启动前检查

- 每次执行前先 source ROS2 和工作区环境：

```bash
source /opt/ros/jazzy/setup.bash
source /home/hit/ROS/install/setup.bash
```

- BatonMini 启动前必须确认对应 USB 网卡已 UP，并记录本机 `local_ip`。
- GoPro 启动前必须用 `v4l2-ctl --list-devices` 确认采集卡对应的 `/dev/videoX`。

## 3. 命名约束

- BatonMini right 使用 `baton_mini_right` 前缀。
- BatonMini left 使用 `baton_mini_left` 前缀。
- GoPro right 使用 `gopro_right` namespace。
- GoPro left 使用 `gopro_left` namespace。
- ROS topic / namespace 不使用空格。

## 4. 验证约束

- 每个节点启动后至少验证：
  - `ros2 topic list` 中能看到目标 topic；
  - 图像 topic 可用 `ros2 topic hz` 或 `rqt_image_view` 观察；
  - 非图像 topic 可用 `ros2 topic echo --once` 或 `ros2 topic hz` 观察；
  - Octopus 能看到并订阅目标 topic；
  - Octopus 开始录制、停止录制后能输出 `.mcap` 文件。
- 如果节点启动失败，先记录设备路径、IP、命令、错误输出和临时判断，再做修复。

## 5. 文档约束

- 每次实际启动、失败、修复或阶段性确认后，更新：
  - `/home/hit/ROS/DOCS/场景一/执行记录.md`
  - `/home/hit/ROS/DOCS/场景一/当前进度.md`
