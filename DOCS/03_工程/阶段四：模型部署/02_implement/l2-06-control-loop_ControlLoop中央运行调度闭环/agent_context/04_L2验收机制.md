# L2-06 验收机制（Agent Gate）

## 1. Gate 目标

证明真实生产对象可以组成以下 tracer bullet，并且 control tick 不等待 inference、失败不会泄漏 command、shutdown 可收敛：

```text
DeployConfig + canonical ActRuntimeResources/PolicyInputSpec
  -> L2-02 observation pipeline
  -> ObservationSnapshot
  -> L2-06 request/worker/result
  -> L2-03 ActInferenceService
  -> L2-06 active/pending/cursor/fallback
  -> L2-04 SafetyGuard
  -> L2-05 ActionPublisher
  -> L2-06 outcome reducer/metrics
```

Gate 不证明 driver 已接收或机器人已到位；`PUBLISHED` 只证明 ROS publisher 调用事实。

## 2. PASS / FAIL / BLOCKED 语义

| 状态 | 严格含义 | 例子 |
|---|---|---|
| `PASS` | 真实生产对象及稳定公共接口通过；只替换不可控外部边界 | fake policy、FakeNode、fake clock、fake permit provider |
| `FAIL` | 代码、接口、测试、脚本、fixture 或行为缺失/错误 | loader 不可用、shape 不匹配、worker 未实现、未知 skip |
| `BLOCKED` | 实现和 local Gate 已完整 PASS，但外部环境、资源、拓扑或授权当前不可用 | ROS runtime、real bundle/GPU、driver、E-stop、操作者授权 |

禁止规则：

- 缺 production file、test、fixture 或 `l2_06_verify.sh` 是 FAIL，不是 skip/BLOCKED。
- 无 ROS/GPU 不能掩盖纯 Python、config、adapter 或 loader 错误。
- pytest skip 只有匹配 allowlist 外部原因才转换为 BLOCKED；未知原因、代码/fixture 缺失一律 FAIL。
- 任一 FAIL 时脚本退出 1；仅 PASS + 有证据的 BLOCKED 时退出 0。
- BLOCKED 行必须使用：`BLOCKED_ENV`、`BLOCKED_ARTIFACT`、`BLOCKED_TOPOLOGY`、`BLOCKED_HARDWARE`、`BLOCKED_AUTHORIZATION`。
- bundle artifact 不可取得用 `BLOCKED_ARTIFACT`；ROS/GPU/torch runtime 不可用用 `BLOCKED_ENV`；join timeout 是 FAIL，不是 BLOCKED。

## 3. 必需实现切片草案（本包不创建 L3）

在生成 L2-06 L3 前必须先处理 P0 接缝，不得把上游修复塞进 ControlLoop：

| 顺序 | 切片 | owner | 完成证据 |
|---:|---|---|---|
| 0A | default config、CLI static flag、canonical resource aggregate、queue=1 | L2-01 owner | config/repo Gate PASS |
| 0B | typed observation factory、camera/image/gripper/monotonic、adapter fail-fast | L2-02 owner | OBS real-chain Gate PASS |
| 0C | L2-03 消费 canonical `PolicyInputSpec`，不再私自派生 | L2-03 owner，与 L2-01 协作 | canonical-spec Gate PASS |
| 0D | L2-05 非法输入异常、reason/failure-stage/topic provenance | L2-05 owner | publish provenance Gate PASS |
| 1 | A1/A2：channel + metrics | L2-06 runtime | C1-C2、C4-C6、C8-C12 unit PASS |
| 2 | A3：InferenceWorker | L2-06 runtime | B1-B2、C22 serial/error/stop PASS |
| 3 | A4：ControlLoop | L2-06 runtime | B3-B8、C3/C7/C13-C19/C23-C26 PASS |
| 4 | A5：process + ROS composition | L2-06 UI | B9-B12、C20-C21 atomic startup/shutdown PASS |
| 5 | 真实跨 L2 integration + verify script | L2-06 acceptance | 本文件全部 local 标签无 FAIL |

只有 0A～0D 完成后，L2-06 L3 才能以真实接口为基线；否则只能做隔离实验，不能宣称闭环实现。

## 4. 验证脚本合同

后续必须创建真实脚本和 fake fixture config：

```bash
bash src/model_deploy/act/scripts/l2_06_verify.sh \
  --scope local --policy fake \
  --config src/model_deploy/act/tests/fixtures/l2_06_fake.yaml

bash src/model_deploy/act/scripts/l2_06_verify.sh \
  --scope ros-dry-run --policy fake \
  --config src/model_deploy/act/tests/fixtures/l2_06_fake.yaml

bash src/model_deploy/act/scripts/l2_06_verify.sh \
  --scope real-policy-dry-run --policy real \
  --config "$ACT_DEPLOY_CONFIG"
```

`--scope/--policy` 只属于 verify harness，不属于 production C21。fake 模式显式构造 canonical fake `ActRuntimeResources` 并注入 A5；real 模式把 `--config` 原样传给 `python -m model_deploy.act.ui.act_deploy_node`。production main 只允许 real policy，绝不根据 bundle 缺失隐式切 fake。

当前脚本、fixture 和 L2-06 测试尚不存在，所以现状是 FAIL；上述命令在实现前不是 PASS 证据。

### 4.1 输出格式

固定分组：`types` → `config` → `repo` → `service` → `runtime` → `ui·boundary`。每个标签一行：

```text
PASS|FAIL|BLOCKED <LABEL> <一句事实>
```

FAIL 后必须紧跟：

```text
  file: <path>
  class: <class 或 无 class>
  micro-unit: <A/B/C id + 名称 + 类型；或 N/A — upstream L2 contract; consumer=B11/B7>
  pytest: <exact node id；无测试时写 MISSING 并 FAIL>
  error: <摘要>
```

最后一行固定为 `N PASS / N FAIL / N BLOCKED`。

### 4.2 脚本行为

1. 不得把多个目录拼成一个含空格的 `rg` 参数。
2. 不得只检查 `import rclpy` 就把 sensor/geometry/std message 依赖标 PASS。
3. pytest skip 必须先匹配本文件 §2 allowlist；其余转换为 FAIL。
4. local scope 不访问真硬件、不连接真实 driver；纯 FakeNode command outcome 合同测试可显式 enabled=True，但 Fake publishers 不得进入 ROS graph。
5. real-policy scope 要求 `--config`；缺参数是 FAIL。artifact/GPU blocked 前必须先证明 loader/local contract PASS。
6. validator PASS 只证明结构，不替代 `HTML_SOURCE_ALIGNMENT` 语义扫描。

## 6. 必须使用真实对象的 tracer tests

允许替换：policy forward、ROS Node/publisher、clock、permit provider、真实 bundle/GPU。

不得替换：正式 `DeployConfig` loader、canonical resource types、L2-02 production config path、`ActInferenceService`、L2-06 A1-A5、`SafetyGuard`、`ActionPublishRequest/Result`、`ActionPublisher`。否则 Dict/dataclass、HWC/CHW、错方法名等真实断口会再次被 fake 隐藏。

纯 FakeNode 的六 outcome 合同测试允许 `command_output_enabled=True`，前提是所有 publisher 都是进程内记录器且没有 ROS graph/driver；ROS dry-run 和 real-policy dry-run始终为 False。

## 8. 当前基线与放行规则

当前已知：默认 config、canonical resources、observation 接缝、L2-03 shared spec、L2-05 provenance、L2-06 runtime/node/script/test 和 HTML 语义均未全部闭合。必须由未来实现重新测量，禁止把本文件写成当前 PASS 记录。

- L3 生成：用户确认本版设计、HTML 同步、0A～0D owner/修改路径确认后才允许。
- 合并至 `model_deploy`：`--scope local` 必须 0 FAIL；ROS/real-policy 只可保留充分外部证据的 BLOCKED。
- 真机结论：另需 ROS topology、permit、E-stop、driver readiness 和操作者授权证据。
