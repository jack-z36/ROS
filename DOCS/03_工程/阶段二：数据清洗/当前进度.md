### 正常用户网页

已有能力：

- 本机网页仅监听 `127.0.0.1`，浏览器刷新或关闭不会取消任务。
- 看板、新建任务、历史记录、目录浏览、新建目录和当前层 `.mcap` 文件勾选。
- 最终 dataset 父目录可自由选择任意本机目录，不做路径限制或风险提示。
- 每个 MCAP 独立执行 cleaned、MCAP_A、aligned、Forge bridge；成功 bridge episodes 聚合为一个 LeRobot v3 dataset。
- 多批次可以并行运行，并共享默认最多 `6` 个文件处理 worker。
- 单文件失败不阻止成功 episode 发布；失败文件可以一键生成重试草稿。
- 用户取消批次时回滚本批次 dataset 与 sidecar；删除历史摘要不会删除真实产物。
- 结果页可视化展示 Forge quality 总分、各维度分数、逐 episode 分数和 flags。
- 结果页训练前技术体检已按当前 LeRobot feature contract 判断 state/action 维度；动态配置为 16/16 时不再因“不是 32 维”被误判为格式阻断。
- 结果页提供固定右手坐标系 TCP 3D 轨迹：单 episode 按原始时间戳播放，全部 episode 静态总览。
- 轨迹视图使用 `bounds.min` 作为左下角显示局部原点，只做可视化平移和等比例缩放，不改写原始坐标。
- 普通 Web 固定按左右 arm-base 生产语义展示轨迹；历史 `format-only/common_frame` 轨迹仅保留开发烟测兼容。
- 历史任务没有新版轨迹缓存时，`GET /api/jobs/{job_id}/trajectory` 会按需补齐左右 bounds、坐标系 profile 和投影提示并写回 sidecar。
- 历史任务的训练前技术体检缓存带有 LeRobot feature contract fingerprint；当前契约变化后会自动重算，避免继续展示旧 `32/16` 固定契约结论。
- 可按需启动 Forge Web Viewer，在新标签页打开最终 dataset。
- 顶部导航提供独立配置中心：夹爪只展示状态并通过 gripper-only GoPro 向导自动生成；位姿配置编辑左右 `camera_from_tcp.translation_mm` 与 `work_frames.position_mm / rotation_euler_rad`；同时可保存场景二 pose/tactile 滤波生产默认参数和 LeRobot v3 feature 段落。人工输入明确标注 `mm/rad`，Baton Mini 原始位姿、Runtime 和最终 arm-base TCP 输出的位置统一使用 `m`。
- 新建任务页不再暴露 preset、bridge mode 或单次任务覆盖；普通任务固定使用 arm-base 生产链路，并读取配置中心保存的生产默认值。
- 每个 Web job 写出 `src/data_clean/runs/web_jobs/runs/<job_id>/config_snapshot.yaml`，其中包含实际滤波参数和 LeRobot feature config。

### 场景二：MCAP_A 与信号可靠性

已有 dev check 能力：

- `runtime/scene2_signal_reliability.py`：位姿、夹爪、触觉异常检测。
- `runtime/scene2_signal_repair.py`：repair run 与三模态补全。
- `runtime/scene2_pose_filter.py`：位姿滤波和 guard 审计。
- `runtime/scene2_tactile_filter.py`：触觉滤波和 diff 审计。
- `runtime/scene2_mcap_a_writer.py`：MCAP_A 写出链路。
- Scene2 只处理生产配置显式声明的 2 路 source-frame TCP pose、2 路 gripper 和 4 路可选 pressure tactile；未声明 topic 原样复制。
- 一次 MCAP_A 任务只加载一次分析样本、检测一次并修复一次；三模态共享 run id、输入身份、stream inventory 和配置快照。
- 检测、邻居查找和滤波状态均限定在 `topic + time_domain`；不跨 topic、缺失区间或触觉 shape/contact reset 边界。
- `SignalSampleRef.message_index` 固定为源 MCAP 物理遍历中的同 topic 序号，写回时同时校验时间、sequence 和 source channel。
- 只有字段级 `AUTO_REPAIR` 处置进入计算；四种已有样本替换均要求合法前后邻居，不启用单邻居 hold fallback。
- pose/tactile 按完整 `sample_refs` segment 计算，tactile 每段重新初始化 Median/EMA；成功 gripper 修复也写回 MCAP_A。

尚未完成：

- 关节限制、速度/加速度限制和 MuJoCo 仿真验证。
- 机器人约束报告成为训练合格判据。

### 临时双臂 LeRobot v3 bridge

已有能力：

- `service/forge_bridge.py` 消费 aligned MCAP，生成 `04_forge_bridge/forge_ready.mcap`。
- bridge 按生产配置中的 LeRobot feature 白名单拼接 `observation.state` 和固定 `t+1 action`；默认配置仍输出 32 维 state 和 16 维 action。
- bridge 写出 `forge_bridge_schema.json`、`forge_bridge_report.json` 和 `forge_topic_config.yaml`。
- `runtime/forge_bridge_to_lerobot.py` 通过 Forge Python API 显式传入 topic config，生成双目 LeRobot v3 数据集。
- Forge inspect/quality 已能检查 `05_lerobot_v3_bimanual/`。

最近真实验证结论：

- 已验证网页批次：`5` 个 raw MCAP 聚合为 `5 episodes / 773 frames`。
- 对应 Forge quality 总分：`8.39/10`，`flagged=0`。
- 已验证外部输出目录：`/home/hit/下载/lerobot/20260601_15`。
- 最新外部目录任务包含 `1 episode / 273 frames`，Forge quality 总分 `8.05/10`，`flagged=0`。
- 每个 episode 的末帧因无 `t+1 action` 被丢弃。
- `observation.state`：默认 `32` 维；配置中心可在现有 aligned MCAP 字段白名单内启用/禁用非必选段落并排序。
- `action`：默认 `16` 维；固定为 `t+1` 绝对目标，左右 TCP pose 必选，夹爪段落可配置。
- 训练前技术体检的格式输入模块以当前 feature schema 的期望维度为准；动作贴边/饱和的维度标签也按当前 action schema offset 生成。

- 上述历史验证结果若来自 `format-only`，只能验证格式链路、基础质量检查和网页发布能力，不能代表正式训练可用；普通 Web 当前固定走 arm-base 生产语义。

## 风险与判断边界

- 不要把历史 `format-only` 的 LeRobot 输出当作正式训练数据。
- 不要把 Forge quality 分数单独当作数据质量最终结论；它缺少完整生产 readiness 和机器人约束前提。
- aligned MCAP 是语义中间产物，临时 Forge bridge 必须输出到独立 `04_forge_bridge/`，避免污染场景三契约。
- Forge CLI `--config` 可能不会把 MCAP topic config 传给 reader；当前正确转换入口是 `runtime/forge_bridge_to_lerobot.py`。
- 左右 TCP 分别位于各自 arm-base 坐标系；可视化不得把两条轨迹当成共享物理坐标系直接叠加。
- 网页自由输出目录只适用于最终 LeRobot dataset；sidecar、中间 MCAP、bridge、日志和缓存仍必须留在受控目录。
