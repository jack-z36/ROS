# 讲解分层范式

## 定位

本文件规定 Agent 讲解任何程序部件（函数、class、文件、模块、数据流等）时的**披露深度与节奏**。强制约束 Agent 一次只给一层，避免信息倾泻。

| 项 | 内容 |
|---|---|
| 消费对象 | Agent（讲解任何程序部件时必遵守） |
| 权威性 | 讲解节奏与披露深度的权威 |
| 读取时机 | 每次讲解类任务开始时（与 `INDEX.md` 一起加载） |
| 上游来源 | 用户在多次讲解交互中确认的偏好 |
| 配套文件 | `用户认知框架与讲解偏好.md`（讲什么）、本文件（怎么讲、讲多深） |

## 核心原则

**默认只给第 1 层，绝不擅自往下铺。** 用户明确说"下一层"或点名某个子模块，才展开下一层。每层结束必须停下来，给明确的下一步选项。

这条原则服务于"信息密度控制"——用户是小白时，一次喂太多会信息过载，反而学不会。

## 三层范式

| 层 | 内容 | 碰不碰代码 | 触发方式 |
|---|---|---|---|
| **第 1 层** | 整体比喻 + 模块拆解（每块继续用比喻） | 不碰代码、零术语 | 默认从这里开始 |
| **第 2 层** | 源码分段 + 比喻混排（代码块和比喻一一对应） | 碰代码，但只讲"这段干啥"，不逐行展开参数 | 用户说"下一层" |
| **第 3 层** | 按用户点名，结合真实编程知识讲某个子模块，让用户理解比喻对应的真实代码逻辑 | 逐行/逐参数展开，但仍然标注事实/推断 | 用户点名某个子模块 |

### 第 1 层：整体比喻 + 模块比喻

**做什么**：
1. 先用一个生活化比喻讲**整体功能**（像什么、干什么）。
2. 再把整体**拆成几个功能模块**，每个模块**继续用比喻**讲它干啥。

**浓度规范**：
- 零代码、零术语。
- 必要的体系外新词（如"线程""锁""队列"）要先翻译成大白话或类比，再标注"这是新词"。
- 模块拆分粒度：通常 3-6 个模块。太多会过载，太少等于没拆。

**反面**（禁止）：
- 一上来就贴代码。
- 整体比喻做完立刻跳到逐行讲解。
- 一次把三层全铺出来。

### 第 2 层：源码分段 + 比喻混排

**做什么**：把函数实际代码切成几段（按功能切，不按行数切），每段下面用比喻讲它干啥。代码块和比喻**一一对应**。

**浓度规范**：
- 每段代码只讲"这段在干什么"，不逐行展开每个参数的含义。
- 比喻要呼应第 1 层用过的比喻体系（同一个"工厂"比喻就一路用到底，不要中途换比喻）。
- 贯穿性规则（如"任何步骤失败都要撤回"）单独拎出来讲一次，不要每段重复。

**反面**（禁止）：
- 把每个参数的类型注解、每个语法单元都展开（那是第 3 层的事）。
- 一段代码配三段比喻（比例失调）。

### 第 3 层：比喻对应真实代码逻辑

**做什么**：用户点名某个子模块后，结合真实编程知识，讲清楚"第 1/2 层的比喻对应代码里到底是什么逻辑"。

**浓度规范**：
- **必须从函数签名开始，不能跳过**。函数签名（`def name(self, *, config: DeployConfig, ...) -> None:`）定义了"这个函数需要什么才能跑"，对小白是理解后续函数体的前提。跳过签名直接讲函数体第一行，会让参数名凭空冒出来，造成困惑。
- 可以逐行、逐参数展开。
- 但仍然遵守"思考呈现"：区分**事实**（代码确实这么写的）和**推断**（我猜它为什么这么写）。
- 体系外新词第一次出现时必须翻译 + 标注，之后可以直接用。
- 一个子模块讲完就停，不要顺便把别的子模块也铺出来。

**触发规则**：必须由用户点名（如"讲讲第 4 步的 ControlLoop 装配"）。Agent 不主动进入第 3 层。

## 配套规范（参照其他文件）

| 规范 | 出处 | 在本范式里的体现 |
|---|---|---|
| 信息密度控制 | `Agent交互质量概念体系.md` | 一次只给一层，不信息倾泻 |
| 交互闭环 | `Agent交互质量概念体系.md` | 每层结束给明确的下一步选项 |
| 思考呈现 | `Agent交互质量概念体系.md` | 第 3 层标注事实/推断 |
| 边界守持 | `Agent交互质量概念体系.md` | 不擅自深入，等用户要 |
| 体系外新词处理 | `INDEX.md` + `用户认知框架与讲解偏好.md` | 先翻译/类比，再标注"这是新词" |

## 示例（用 `_act_init` 演示三层浓度差）

### 第 1 层示例（默认给这层）

> **整体**：这个函数像工厂的"开业准备流程"。厂长按顺序把零件摆上流水线、最后按启动键。中途出错就全部撤回。
>
> **6 个工位**：①叫观测组就位 ②摆内部零件 ③开工前验货 ④拼流水线 ⑤给打工仔通电 ⑥挂闹钟。

### 第 2 层示例（用户说"下一层"才给）

```python
self._control_loop = ControlLoop(
    config=ControlLoopConfig(...),
    request_queue=self._request_queue,
    ...
)
```
> **比喻**：厂长亲手拼核心机器"控制环"，把前面造的零件当配件接到控制环上——传话筒、记事本、保安对讲机、发布窗口按钮、取画面电话。

### 第 3 层示例（用户点名才给）

> 用户："讲讲 ControlLoopConfig 每个字段什么意思"
>
> Agent 逐字段展开：`chunk_size` 是模型一次预测多少步动作、`action_dim` 是动作向量多少维……每个字段标注"这是配置项，来自 config 层"。
