# 消费对象文档形态规范

## 1. 适用范围

- 阶段：全局
- 任务模式：文档体系维护、非具体编程规划、普通代码维护、Debug / Bugfix 中涉及非代码文件输出的场景
- 适用对象：`DOCS/` 下新建或重构的非代码文件
- 不适用对象：源码注释、第三方工具自动生成文件、外部资料原文快照

Agent 在生成或重构任何 `DOCS/` 下非代码文件前，必须先判断主要消费对象，再选择文件形态和信息密度。

## 2. 消费对象判定

| 消费对象 | 典型文件 | 默认形态 | 核心目标 |
|---|---|---|---|
| 人类 | 架构理解入口、功能模块可视化、操作说明、验收体验入口 | HTML 优先 | 帮助人快速理解、判断、提出建议 |
| Agent | 权威上下文、任务定义、边界契约、设计细节、验收规则、调度上下文 | Markdown 优先 | 充当 Agent 记忆，降低幻觉和边界漂移 |
| 人类 + Agent | 同一语义既要被人理解，又要被 Agent 后续执行引用 | HTML + Agent Markdown 双轨 | 人类低密度理解，Agent 高密度引用 |
| Agent 结构化流程 | dispatch、状态机、配置片段、机器校验输入 | YAML / JSON / 表格等结构化格式 | 让 Agent 或脚本稳定解析 |

不得因为文件是“文档”就默认写 Markdown，也不得因为内容复杂就把人类入口写成高密度 Agent 上下文。

## 3. 人类消费文件规则

人类主消费文件优先使用 HTML。例外是简单清单、签字记录、短说明或纯文本命令集合，这类可以继续使用 Markdown。

人类 HTML 必须满足：

- 图形化语义优先，优先使用图、流程、分区、层级、状态面板、时间线或交互视图表达关系。
- 少文字，避免长段落堆叠。
- 排版疏松，单位面积信息量低。
- 优先保证“能理解”和“语义覆盖面完整”，可以接受字段级、函数级、实现级理解深度损失。
- 尽量覆盖当前场景中的关键语义，但覆盖方式由场景决定，不强制固定章节。
- 不作为 Agent 后续生成 L3、执行、验收或合入的权威来源。

复杂 HTML 如果省略字段、函数、完整表格、验收细则或边界细节，必须说明对应的 Agent 权威 Markdown 入口。简单 HTML 不强制逐项标注来源。

## 4. Agent 消费文件规则

Agent 主消费文件优先使用 Markdown。它的核心作用是作为 Agent 记忆，确保 Agent 能全面理解某个信息，避免猜测、幻觉和职责漂移。

Agent Markdown 必须满足：

- 信息高密度，允许表格、清单和较完整的字段描述。
- 语义完整，必须写清目标、输入、输出、边界、依赖、验收或失败条件中与任务相关的部分。
- 结构稳定，便于后续 Agent 按标题、表格和路径检索。
- 可引用，路径、ID、对象名、命令、验收项必须尽量具体。
- 低歧义，未知项必须显式写为待确认，不得让后续 Agent 自行猜测。
- 抗污染，必须区分当前权威、历史参考、只读参考和禁止继承内容。

每份 Agent Markdown 必须声明以下元信息；很小的文件可以用简短形式写在开头：

| 元信息 | 要求 |
|---|---|
| 消费对象 | 说明本文主要供哪类 Agent 或流程读取。 |
| 权威性 | 说明本文是否为权威上下文，和 HTML、旧文档或模板冲突时以谁为准。 |
| 上游来源 | 说明语义来自哪些任务文档、架构文档、设计包、代码或用户确认。 |
| 不负责范围 | 明确本文不承担什么职责，避免后续 Agent 扩权。 |
| 读取时机 | 说明什么任务开始前必须读本文。 |
| 冲突处理 | 说明发现冲突、过期或缺信息时应停止、提问、标记过期还是引用上游。 |

## 5. 双轨产物规则

同一语义同时服务人类和 Agent 时，默认拆成双轨产物：

```text
人类 HTML
Agent Markdown 目录或文件
```

双轨产物必须满足：

- HTML 是 Agent Markdown 的低密度视觉投影，不是独立权威。
- Agent Markdown 是后续生成、执行、验收和合入的权威上下文。
- 二者必须通过索引、对齐表、来源提示或目录结构说明关系。
- 语义修改顺序固定为：先更新 Agent Markdown，再同步 HTML。
- 若来不及同步 HTML，必须在 Agent Markdown 和 HTML 中标记 HTML 已过期。

阶段四 L1/L2 的 `HTML + agent_context/` 是该规则的当前标准样例，但本规范不限于阶段四。

## 6. 结构化 Agent 文件例外

YAML、JSON、TOML、CSV 或纯表格文件属于 Agent 消费大类，但可以不使用 Markdown，前提是它们主要用于调度、配置、状态机、机器校验或脚本输入。

结构化 Agent 文件必须被以下至少一种机制锚定语义：

- 上游模板说明字段含义。
- 相邻 Markdown 说明字段语义、边界和验收方式。
- 所属 skill 或约束文件说明读取、写入和校验规则。
- 校验脚本固定字段和合法值。

结构化文件不得孤立存在为隐式契约。字段语义、允许值、冲突处理和写入边界不能只靠字段名让后续 Agent 猜。

## 7. 输出前自检

Agent 生成或重构非代码文件前必须自检：

- 这个文件的主要消费对象是谁？
- 是否需要人类 HTML、Agent Markdown，还是双轨产物？
- 如果是人类文件，是否足够图形化、低密度、易理解？
- 如果是 Agent 文件，是否足够完整、结构化、可引用、低歧义？
- 如果是结构化文件，字段语义是否已被模板、规则、相邻 MD 或脚本锚定？
- 如果同一语义有 HTML 和 Markdown，是否明确了权威关系和同步规则？

无法判断消费对象或权威关系时，必须先停止并向用户确认，不得自行生成模糊文档。
