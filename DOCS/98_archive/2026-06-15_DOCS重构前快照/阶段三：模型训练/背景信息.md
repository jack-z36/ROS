# 阶段三：模型训练背景信息

## 上游输入

阶段三不直接消费 raw MCAP。更稳妥的路线是：

阶段二的 `canonical_dataset_mcap` 经 exporter 转成具体训练框架需要的格式，再由训练脚本读取。

exporter 需要读取：

- `dataset_index.parquet`
- `schema/observation_schema.json`
- `schema/action_schema.json`
- `schema/frame_schema.json`
- `schema/topic_schema.json`
- `schema/quality_schema.json`
- `episodes/*/data.mcap`
- `episodes/*/step_index.parquet`
- `episodes/*/masks.parquet`

## 可能的训练格式

训练格式可以根据目标模型生态选择：

- LeRobotDataset。
- HDF5。
- Zarr。
- 模型仓库自定义格式。

这些格式只是训练入口，不是项目内部唯一可信数据源。项目内部更核心的中间态仍然是 `data.mcap + metadata/schema/index/masks/report`。

## observation 和 action 契约

阶段三必须严格继承阶段二定义的 observation 和 action。

当前 observation 包括左右图像、左右 common frame TCP pose、左右夹爪宽度、左右触觉和语言指令。

当前 action 采用 UMI 风格 relative trajectory action。模型输出的是未来一段相对于当前 TCP 位姿的目标相对轨迹，以及夹爪宽度序列。

训练时 action 怎么定义，部署时就必须怎么解释。否则即使模型 loss 下降，也可能无法稳定驱动机械臂。

## 与部署阶段的关系

阶段三输出的 checkpoint 不是最终机械臂命令生成器。它输出的是 candidate action。

阶段四还需要 action decoder、post-processor、robot adapter、安全限制和真实机械臂接口，才能把 candidate action 变成可执行命令。
