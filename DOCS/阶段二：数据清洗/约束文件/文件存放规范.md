# 阶段二文件存放规范

本文件是阶段二开发过程中的**强制性文件存放约束**。任何 Agent 在阶段二开发中创建、写入或输出文件时，必须遵守本规范的每一条规定。

## 适用范围

本规范仅适用于阶段二 `data_clean` 相关开发。阶段一的 ROS 包、Octopus、硬件驱动等不适用本规范。

## 核心原则

```
源码进 src，配置进 config，测试进 tests；
中间产物进 asset/dev，最终产物进 asset/prod；
运行记录进 runs，缓存进 .cache；
除源码和配置模板外，其余全部不进 Git。
```

## 一、源码文件

**位置**：`src/data_clean/`

分层结构，严格遵守单向依赖 `Schemas → Config → Repo → Service → Runtime → UI`：

| 子包 | 职责 | 可依赖 |
|---|---|---|
| `schemas/` | 类型定义、schema 常量 | 无 |
| `config/` | 配置加载、dataclass | schemas |
| `repo/` | 数据访问、编解码 | schemas, config |
| `service/` | 业务逻辑（清洗、验证、变换） | schemas, config, repo |
| `runtime/` | 流程编排、入口调度 | schemas, config, repo, service |
| `ui/` | 用户界面、交互工具 | schemas, config, repo, service |

**规则**：
- 新增 Python 模块必须放入对应层级子包，不得在 `src/data_clean/` 根目录创建 `.py` 文件。
- 后层可调前层，前层不得反向依赖后层。同层内互相引用合法。
- 每个新模块创建时，必须在 `data_clean_architecture.md` 中更新目录结构表。

## 二、配置文件

**位置**：`config/data_clean/`

| 类别 | 位置 | 进 Git |
|---|---|---|
| 配置模板 | `config/data_clean/templates/` | 进 |
| 正式配置 | `config/data_clean/` 根 | 视内容 |
| 运行时配置快照 | `src/data_clean/runs/{run_id}/config_snapshot.yaml` | 不进 |

**规则**：
- 阶段二配置文件必须放在 `config/data_clean/` 下，不得放在 `config/` 根目录（根目录属于阶段一）。
- 新配置模板（`.example.yaml`）放入 `templates/`。
- Runtime 每次运行时必须把当时生效的配置快照写入 `runs/{run_id}/config_snapshot.yaml`，不得遗漏。
- 不得在 `src/data_clean/` 内部散落配置文件。

## 三、测试文件

**位置**：`src/data_clean/tests/`

| 类别 | 位置 | 进 Git |
|---|---|---|
| 测试代码（.py） | `tests/{service,runtime,contract,smoke}/` | 不进 |
| 测试 fixture | `tests/fixtures/` | 不进 |
| 测试运行输出 | `tests/outputs/` | 不进 |

子目录含义：

- `service/`：service 层单元测试
- `runtime/`：runtime 层集成测试
- `contract/`：数据契约测试（验证 MCAP 输入输出格式）
- `smoke/`：端到端冒烟测试
- `fixtures/`：测试用 MCAP 样本等小数据
- `outputs/`：测试运行产生的临时输出

**规则**：
- 所有测试相关文件（代码、fixture、输出）统一放在 `src/data_clean/tests/` 下。
- 测试代码不得与源码混放在 `service/`、`runtime/` 等子包中。
- 大型 MCAP fixture（>10MB）应放入 `asset/阶段二：数据清洗/dev/mcap_raw/` 而非 `tests/fixtures/`，测试中通过路径引用。
- `tests/` 整个目录不进 Git。

## 四、运行记录文件

**位置**：`src/data_clean/runs/`

每次运行生成一个独立目录：

```
runs/
└── {YYYY-MM-DD_HHMMSS}_{scene_tag}/
    ├── run_log.json              # 结构化运行日志
    ├── config_snapshot.yaml      # 本次运行配置快照
    ├── error_summary.json        # 错误摘要（如有）
    ├── run_result.json           # 运行结果索引
    └── outputs/                  # 调试产物
```

**规则**：
- 每次 Runtime 运行必须创建独立 run 目录，不得复用旧目录。
- `run_log.json` 和 `config_snapshot.yaml` 是必须产出，不得省略。
- 调试产物（中间 MCAP、调试图表等）放入 `outputs/`，不得散落到项目其他位置。
- `runs/` 不进 Git。

## 五、数据产物文件

**位置**：`asset/阶段二：数据清洗/`

### dev/（中间产物，不进 Git）

| 子目录 | 内容 |
|---|---|
| `dev/mcap_raw/` | 原始 MCAP 文件 |
| `dev/mcap_cleaned/` | 场景一清洗后的 MCAP |
| `dev/mcap_validated/` | 场景二验证后的 MCAP |
| `dev/mcap_aligned/` | 场景三对齐后的 MCAP |
| `dev/debug/` | 开发调试临时输出 |

### prod/（最终产物，不进 Git）

| 子目录 | 内容 |
|---|---|
| `prod/canonical_dataset_mcap/` | 场景四 canonical dataset |
| `prod/canonical_dataset_mcap/schema/` | 实际生成的 schema |
| `prod/canonical_dataset_mcap/manifest/` | 实际生成的 manifest |
| `prod/canonical_dataset_mcap/episodes/` | episode 数据 |
| `prod/exports/hdf5/` | 场景五 HDF5 导出 |
| `prod/exports/lerobot/` | 场景五 LeRobot 导出 |
| `prod/exports/zarr/` | 场景五 Zarr 导出 |

**规则**：
- 数据产物只能在 `asset/阶段二：数据清洗/` 的 `dev/` 或 `prod/` 下生成，不得在工作空间根目录、`src/`、`config/` 或其他位置生成 MCAP、parquet、HDF5、Zarr 等数据文件。
- 中间产物（cleaned、validated、aligned）放入 `dev/`，只有通过全部验证的最终 canonical dataset 和 exports 才能放入 `prod/`。
- 不得覆盖 `dev/mcap_raw/` 中的原始 MCAP。
- 阶段二主数据流严格遵循：`raw → cleaned → validated → aligned → canonical dataset → exports`，不得跳步或混放。

## 六、Win 端规划记录与历史执行记录

**位置**：`DOCS/阶段二：数据清洗/执行记录/`

本类文件只承载 Win 主机的阶段二规划记录、文档整理记录和旧流程历史记录，不是 Ubuntu 主机执行 L3 时的输出目录，也不是 Runtime 程序运行生成的 `run_log.json`。

| 类别 | 位置 | 进 Git |
|---|---|---|
| Win 端规划记录 | `DOCS/阶段二：数据清洗/执行记录/MMDDHH_<简短主题>.md` | 进 |
| 历史执行记录 | `DOCS/阶段二：数据清洗/执行记录/<旧记录文件>.md` | 进 |

**规则**：
- Win 文档规划端可在需要沉淀阶段规划、模板调整或任务生成记录时写入本目录。
- Ubuntu L3 执行端禁止写入本目录；L3 执行结果只追加到当前 L3 任务文件末尾。
- 明确 L3 微元任务完成后，当前任务文件从 `03_tasks/task/active/<功能组>/` 移到 `03_tasks/task/completed/<L1归档目录>/<功能组>/`，执行摘要随任务文件一起归档；如果原 active 功能组目录为空，删除该空目录。
- 旧的 `执行记录.md`、`当前进度.md` 和本目录历史记录暂时保留为历史索引，不再作为 Ubuntu L3 执行输出。
- 该目录记录的是 Win 端文档层历史，不能替代 `src/data_clean/runs/{run_id}/` 中的程序运行日志。

## 七、Schema / Manifest / 报告文件

| 类别 | 位置 | 进 Git |
|---|---|---|
| Schema 模板定义 | `src/data_clean/schemas/` | 进 |
| 运行时生成的 schema | `asset/.../prod/canonical_dataset_mcap/schema/` | 不进 |
| 运行时生成的 manifest | `asset/.../prod/canonical_dataset_mcap/manifest/` | 不进 |
| 各类报告（alignment/quality） | 跟随数据产物，在 episode 或 run 目录内 | 不进 |

**规则**：
- Schema 的**定义模板**（如 `observation_schema.json` 的结构定义）随源码维护在 `src/data_clean/schemas/`，进 Git。
- 运行时生成的**实际 schema 实例**（包含真实字段和统计信息）必须跟随数据产物存放在 `asset/` 下，不进 Git。
- 各类 report 文件（alignment_report、quality_report、robot_constraint_report）必须与对应数据放在一起，不得单独建目录。

## 八、环境依赖文件

**位置**：已有的 `.conda-envs/` 和 `.miniconda3/`

**规则**：
- Conda 环境只在 `.conda-envs/` 下创建，不得在 `src/data_clean/` 或其他位置创建虚拟环境。
- 依赖变更必须记录在 `requirements.txt` 或 `environment.yml` 中（如有），不得仅存在于本地环境中。
- 环境目录不进 Git。

## 九、缓存文件

**位置**：`src/data_clean/.cache/`

**规则**：
- 阶段二开发过程中产生的所有缓存（pip 缓存、模型缓存、中间计算缓存等）集中存放在 `.cache/`。
- `__pycache__/` 和 `.pytest_cache/` 由工具自动生成，保留原位即可，但不得手动在此类目录中创建文件。
- `.cache/` 不进 Git。

## 十、禁止事项

以下行为严格禁止：

1. **禁止在 `src/data_clean/` 根目录创建 `.py` 文件**——必须放入对应子包。
2. **禁止在 `config/` 根目录创建阶段二配置**——必须放入 `config/data_clean/`。
3. **禁止在工作空间根目录生成数据产物**（MCAP、parquet、HDF5、Zarr 等）——必须放入 `asset/阶段二：数据清洗/`。
4. **禁止覆盖原始 MCAP**——`dev/mcap_raw/` 中的文件只读。
5. **禁止把真实数据放进 Git**——数据产物、Runtime 运行记录、测试输出全部 gitignore；Win 端规划记录按本规范写入 `DOCS/阶段二：数据清洗/执行记录/` 并进入 Git，Ubuntu L3 执行摘要随当前 L3 任务文件归档。
6. **禁止跳步输出**——未经过前置场景验证的数据不得进入下一阶段目录。
7. **禁止在源码目录散落运行输出**——日志、调试文件、临时文件必须在 `runs/` 或 `tests/` 中。
8. **禁止创建本规范未列出的顶层目录**——如需新目录，先更新本规范并获得确认。

## 十一、文件创建检查清单

Agent 在创建任何文件前，必须按以下清单自查：

```
□ 这是源码吗？           → src/data_clean/{对应子包}/
□ 这是配置模板吗？       → config/data_clean/templates/
□ 这是正式配置吗？       → config/data_clean/
□ 这是测试代码/结果吗？  → src/data_clean/tests/
□ 这是 Runtime 运行记录吗？ → src/data_clean/runs/{run_id}/
□ 这是 Win 端规划记录/历史记录吗？ → DOCS/阶段二：数据清洗/执行记录/
□ 这是 Ubuntu L3 执行摘要吗？ → 当前 L3 任务文件末尾
□ 这是中间数据产物吗？   → asset/阶段二：数据清洗/dev/
□ 这是最终数据产物吗？   → asset/阶段二：数据清洗/prod/
□ 这是 schema 模板吗？   → src/data_clean/schemas/
□ 这是缓存吗？           → src/data_clean/.cache/
□ 以上都不是？           → 先更新本规范，再创建文件。
```

如果目标位置不在本规范列出的路径中，Agent 必须暂停并向用户确认，不得自行决定存放位置。
