# L2 功能边界：l2-04-safety-guard

## 1. 文档契约

| 元信息 | 内容 |
|---|---|
| 消费对象 | 实现、集成、L3 生成与验收 Agent |
| 权威性 | L2-04 整体边界权威；详细编号见 `03a_功能微元总览与组织结构.md` |
| 上游来源 | L1 任务文档、L1 边界、L1 协作、`04_L2-04绝对位姿单步变化检查边界.md`、用户确认 |
| 不负责 | 不定义 L2-06 fallback、L2-05 硬件适配或 L2-01 配置文件值 |
| 读取时机 | 设计、实现或集成 L2-04 前 |

## 2. Runtime 边界

```text
L2: l2-04-safety-guard
Runtime responsibility:
  把已经解归一化、处于部署 ActionDomain 的 16D 绝对目标动作，
  相对可信比较基准投影为单步安全动作，或明确拒绝。

Inputs:
  candidate_action: ndarray shape (16,)
  previous_safe_action: ActionSpec | None
  latest_observation: ObservationSnapshot | None（L2-06 已验证新鲜）
  SafetyConfig / ActionDomain（构造 A1 时注入）

Output:
  SafetyResult(status=PASS|ADJUSTED|REJECTED, action=ActionSpec|None, findings=...)
```

`candidate_action` 已离开模型归一化空间：L2-04 不 normalize/unnormalize，不做单位转换，不把夹爪转换为 F100 寄存器值。

16D 语义固定为：

```text
[ left xyz(3), left quat_xyzw(4), right xyz(3), right quat_xyzw(4), left grip, right grip ]
```

## 3. 两类比较基准

| 基准 | 表达的事实 | L2-04 用途 | 不代表 |
|---|---|---|---|
| `previous_safe_action` | 上一拍成功交给 L2-05 的安全目标 | 检查连续命令是否跳变 | 机器人实际到位反馈 |
| `latest_observation` | 当前实测 TCP pose 与夹爪状态 | 启动/重置时建立实测基准 | 上一拍命令 |

选择规则已确认：`previous_safe_action → fresh ObservationSnapshot → REJECTED(NO_REFERENCE)`。

L2-04 不同时对两个基准做双重裁剪；否则会把单步安全检查错误扩展为反馈跟踪控制器。

## 4. 负责内容

- 严格检查候选 Action 为 `(16,)`、有限数和合法内部 `xyzw` quaternion。
- 选择语义明确的比较基准，并在没有基准时拒绝。
- 分别对左右臂执行平移欧氏距离限制、四元数旋转角限制。
- 分别对左右夹爪执行同域绝对范围限制和单步变化限制。
- 组装同一 ActionDomain 的 `ActionSpec`，输出带稳定原因码的 `SafetyResult`。

## 5. 不负责内容

- 不产生 action，不选择 ActionChunk 行，也不管理 cursor。
- 不保存或更新 `previous_safe_action`、observation、metrics、queue 或 timer。
- 不决定 hold、safe-stop、重试或 fallback；仅报告 `REJECTED`。
- 不发布 topic，不转 `xyzw → wxyz`，不映射 F100 `0~100` 寄存器。
- 不做 workspace、IK、碰撞、急停、deadman、硬件 gate 等 L2-05 硬件级检查。

## 6. 上下游与完成判据

| 方向 | 合作对象 | 边界 |
|---|---|---|
| 上游 | L2-01 | ActionSpec/ActionDomain/SafetyConfig 静态契约 |
| 上游 | L2-02 | ObservationSnapshot 数据契约 |
| 调用方 | L2-06 | 选择单步 action、提供基准、消费结果、更新状态和 fallback |
| 下游 | L2-05 | 仅消费 `SafetyResult.action`；负责外部协议与硬件 gate |

完成条件：可在无 ROS、无硬件环境下，用 mock 验证 PASS、ADJUSTED、REJECTED 三条路径；L2-06 能仅凭 `SafetyResult.status` 做发布或 fallback 决策。

## 7. 明确阻断项

进入实现前，L2-01 的 `SafetyConfig` 必须补齐并校验：平移米制阈值、旋转弧度阈值、夹爪范围/步长（同 ActionDomain）、四元数容差。没有这些静态契约，L2-04 不得猜测单位或硬件值域。
