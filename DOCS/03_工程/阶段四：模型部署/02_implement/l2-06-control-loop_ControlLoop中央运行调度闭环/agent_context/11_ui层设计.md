# ui 层设计：L2-06

## 1. 目标源码与层职责

```text
src/model_deploy/act/ui/act_deploy_node.py
src/model_deploy/act/ui/__init__.py
```

UI 是 process/ROS composition root：读取 CLI 与外部事实、调用 L2-01 public loader、装配 L2-02～05 与 L2-06 runtime、创建 timer、发布 runtime metrics、管理 shutdown。它不实现图像处理、policy forward、安全算法、chunk 选择或 ROS action message 适配。

`ui/__init__.py` 只增量导出 `ActDeployNode`，必须保留 L2-05 已有 `ActionPublisher`、`ActionPublishIoError`、`build_ros_messages` 以及 L2-02 submodule 导入路径；import facade 不得初始化 ROS、启动 worker 或创建 timer。`act_deploy_node.py` 对同 package L2-02/05 实现使用 `.observation_pipeline`/`.action_publisher` 明确 sibling import，不从正在初始化的 `model_deploy.act.ui` facade 反向导入；Gate 必须实测任意 import 顺序都无 circular/partial module。

覆盖微元：A5、B9-B12、C20-C21。

## 2. C21/B11 process entry

### C21 `build_arg_parser`

```text
--config PATH                    required
--enable-command-output          startup-only，default false
```

不再使用旧 `--mode shadow` 作为 command gate。`RuntimeConfig.mode` 最多用于兼容日志，不能替代 L2-05 static switch 或每 tick CommandPermit。

production C21/B11 只运行 real policy，不提供 `--policy` 或 `--bundle-dir`。`--policy fake|real` 仅属于 `l2_06_verify.sh` harness：fake 时直接向 A5 注入测试用 `ActRuntimeResources/ActInferenceService`，real 时把脚本的 `--config PATH` 原样转交 production B11；该 flag 绝不转发给 C21。

### B11 `main`

签名冻结为 `main(argv: Sequence[str] | None = None) -> int`。

```text
parse CLI
  -> load_deploy_config(path,
                        command_output_enabled=explicit_flag)
  -> load_act_runtime_resources(config)
  -> build L2-03 ActInferenceService(...,
                                     input_spec=resources.policy_input_spec)
  -> rclpy.init
  -> construct A5 ActDeployNode
  -> spin
  -> finally B10 shutdown + destroy node + rclpy.shutdown
```

canonical resource function、L2-03 input-spec injection 与 L2-02 public factory 当前并未全部存在，属于 `01_L2功能边界.md §8` 的代码 FAIL。B11 不允许绕过它们读取私有字段或猜配置。

可执行入口冻结为：

```bash
python -m model_deploy.act.ui.act_deploy_node --config <deploy.yaml>
```

模块必须包含 `if __name__ == "__main__": raise SystemExit(main())`；`ui/__init__.py` 公开 `ActDeployNode`，但不在 import 时初始化 ROS 或启动线程。B11 用 `node: ActDeployNode | None` 和 `rclpy_initialized: bool` 跟踪部分启动：startup/runtime exception 返回 1；正常 spin/KeyboardInterrupt 且 B10 返回 True 才返回 0；join timeout 返回 1；finally 仅销毁已创建 node并仅在已 init 时 shutdown ROS。argparse 自身保留标准 exit code 2。

## 3. A5 `ActDeployNode` class

A5 是 `rclpy.node.Node` 子类。B11 在 `rclpy.init()` 后调用构造；`super().__init__` 一旦成功，A5 必须先建立 lifecycle lock/全部 None handle/部分构造标志，再进入任何可失败的 subscription/publisher/runtime 装配。

### 3.1 构造输入

```text
DeployConfig
canonical ActRuntimeResources + 已构造 ActInferenceService
CommandPermitSource: Callable[[], CommandPermit]
monotonic_clock: Callable[[], float] = time.monotonic
optional hardware safe-stop port（只有外部合同明确后）
```

无 permit source 时：command output disabled 可注入固定 `CommandPermit(allowed=False, reason_code="COMMAND_OUTPUT_DISABLED")` 用于 local/dry-run；command output enabled 时不得启动真实 command 路径，状态为 `BLOCKED_HARDWARE/TOPOLOGY`，不能自动允许。provider 抛异常或返回错类型时，本 tick 使用 `CommandPermit(False, "PERMIT_SOURCE_ERROR")` 并记录原异常，绝不 fail-open。

### 3.3 原子启动顺序

L2-02 上游修复后的唯一 composition seam 冻结为：

```python
@dataclass(frozen=True)
class ObservationPipeline:
    collector: ObservationCollector
    buffer: ObservationBuffer
    adapter: ObservationRosAdapter
    input_spec: PolicyInputSpec
    monotonic_clock: Callable[[], float]

def build_observation_pipeline(
    *,
    node: object,
    config: DeployConfig,
    input_spec: PolicyInputSpec,
    monotonic_clock: Callable[[], float],
) -> ObservationPipeline:
    ...
```

owner/目标文件固定为 L2-02 `src/model_deploy/act/ui/observation_pipeline.py`，并由 `model_deploy.act.ui` facade 重导出 `ObservationPipeline/build_observation_pipeline`；函数名、参数和返回结构不得另设备选。`ObservationPipeline.input_spec` 必须就是 `resources.policy_input_spec`，`pipeline.monotonic_clock is A5._monotonic_clock`；collector/buffer/A2/A3 直接使用该 callable，B9 从同一 callable 采样并把值传给 A4，不让 A4 再隐式读第二个时钟。生成 snapshot 时深复制 images/state/encoded arrays，禁止与 callback cache 别名。factory 内创建 subscriptions，只有 ROS package/runtime 确实缺失才抛稳定 environment-unavailable 异常；配置、camera mapping、message type、decoder 或 node API 错误必须原样分类为代码 FAIL。

1. 调 L2-02 canonical public factory，以 `DeployConfig + resources.policy_input_spec + node/clock` 创建 `ObservationCollector/Buffer/Adapter`；factory 必须在创建第一个 subscription 前完成 config/spec/message-class 的全部纯 RAM 校验。只有 allowlist ROS package/graph 缺失可报告环境 BLOCKED，配置/类型/代码异常必须传播并让构造 FAIL。
2. 创建 `SafetyGuard(config.safety)` 单一实例、两个 A1、A2 与尚未 start 的 A3。
3. B12 对 config、canonical resources、L2-02 pipeline metadata、L2-03 service、queue capacity 和 permit topology 做无 I/O 交叉校验。
4. 校验通过后才创建 L2-05 `ActionPublisher(node, config.command_output, config.topics)` 与 C20 metrics publisher，再创建 A4；A4 必须显式接收同一 `config.command_output.command_output_enabled` 作为只读 result 交叉校验事实，并绑定：

```python
observation_provider = observation_buffer.latest_observation
publish_action = action_publisher.publish
```

5. start daemon worker；`start()` 成功返回后立即置 `_worker_started=True`。
6. 最后创建 control timer 和 metrics timer；两个 timer 都创建成功后才置 `_started=True`。
7. A5 用单一 `except BaseException` cleanup guard 包住步骤 1～6；该 guard 只回收后 re-raise，绝不把 `KeyboardInterrupt/SystemExit` 转成业务成功。任一步失败不得留下 timer，已启动 worker必须立即调用可处理 None/未 start handle 的 B10 回收。由于 Python 构造失败时 B11 尚拿不到 `node` 引用，A5 except 还必须在 B10 后对已成功初始化的 ROS Node 调用 `self.destroy_node()` 再 re-raise；cleanup 异常只追加诊断，不覆盖原 startup exception。B11 finally 只销毁成功返回的 node 并 shutdown ROS。

### 3.4 B12 `run_startup_preflight`

B12 签名返回 `None`；输入均为已加载 RAM 对象，不读取 YAML/bundle/GPU，也不创建 subscription/publisher。任一代码合同失败抛 `StartupContractError` 并携带稳定 code。首先检查 `pipeline.input_spec is resources.policy_input_spec`、`inference_service.input_spec is resources.policy_input_spec`、`pipeline.monotonic_clock is A5._monotonic_clock`，随后证明 16D/chunk/camera/image 合同一致、`LatestQueue.CAPACITY == config.runtime.max_inference_requests == config.runtime.max_pending_chunks == 1`、command enabled 时 permit source 存在。A5 必须用同一局部 `monotonic_clock` 构造 pipeline/A2/A3，并仅由 B9 采样后传入 A4；fake-clock Gate 验证其行为。B12 不反射读取这些对象的私有字段，也不以测试 fake 反推业务合同。

稳定 code 集合：`SPEC_IDENTITY_MISMATCH`、`STATE_DIM_MISMATCH`、`ACTION_DIM_MISMATCH`、`CHUNK_SIZE_MISMATCH`、`CAMERA_KEYS_MISMATCH`、`IMAGE_CONTRACT_MISMATCH`、`QUEUE_CAPACITY_MISMATCH`、`CLOCK_DOMAIN_MISMATCH`、`PERMIT_SOURCE_MISSING`。

## 4. B9 `_control_tick`

```text
ROS timer fires
  -> with lifecycle_lock
     -> 若 shutdown/stopping，直接返回
     -> 若 worker_fatal_reason 存在：C25 锁存该稳定 reason，返回
     -> 否则若已 start 的 worker 非预期死亡：C25 WORKER_TERMINATED，返回
     -> monotonic_s = self._monotonic_clock()
     -> ros_time_s = node clock 转 seconds
     -> command_permit = permit_source()
        - provider exception/invalid type -> deny permit + runtime error
     -> control_loop.tick(monotonic_s, ros_time_s, command_permit)
```

B9 不读取 raw gate/deadman/E-stop 字段；provider 已把它们汇总为 L2-05 `CommandPermit`。B9 先读 A2 frozen snapshot 中的 worker fatal 事实，仅允许映射到 C3 已定义 reason，不读 A3 私有字段。B9 不直接 publish action/status，不捕获错误后继续假装成功。

双时钟必须为 finite 且非负；invalid clock 不调用 B3，而以 C25 `CLOCK_INVALID` 锁存 runtime fault。permit provider 异常是可诊断的逐 tick deny，不等价于 clock/invariant 代码错误。

## 5. C20 `_publish_runtime_metrics`

外部边界：`config.topics.command.metrics`，默认 `/act/metrics`。

读入/写出：C20 也在 `_lifecycle_lock` 内先检查 `_shutdown`；活动时由 C12 返回 `RuntimeMetricsSnapshot`，再以 `json.dumps(..., sort_keys=True, separators=(",", ":"), allow_nan=False)` 转成 `std_msgs/msg/String` 后 publish。JSON 顶层固定含 `schema_version: 1`、`l2_id: "l2-06-control-loop"`，并覆盖 C4 的 runtime status、request/cursor、latency、last/deferred fallback reason、publish outcome counters、两个 fault latch、provenance 和 last error；tuple/mapping 转为 JSON list/object，不发布 repr。

`/act/command/status` 已由 L2-05 按每 action 真实发布事实写出；A5 禁止再次写该 topic。安全 findings/fallback 原因若 L2-05 status 丢失，以 `/act/metrics` 的 orchestration reason 为权威。

## 6. B10 `_shutdown_runtime`

签名冻结为 `def _shutdown_runtime(self) -> bool`；返回值只表示 worker 是否在 bounded timeout 内终结。

```text
idempotent shutdown
  -> with lifecycle_lock（覆盖整个 bounded shutdown，串行多个调用者）
     -> 若 _shutdown 已为 True，返回 bool(_shutdown_succeeded)
     -> 先置 _shutdown=True
     -> C23 control_loop.begin_stopping()
     -> cancel control timer / metrics timer
     -> worker handle 存在时 C22 worker.stop()（先设置 stop event）
     -> C10 request_queue.close（清 pending request 并唤醒 worker，返回数只记 shutdown_queue_cleared_count）
     -> 仅 `_worker_started=True` 时 worker.join(bounded timeout)；未 start 的 Thread 绝不调 join
     -> C10 result_queue.close（清 timer 取消后的未消费 result，返回数只记 shutdown_queue_cleared_count）
     -> join 成功：runtime_status=STOPPED，_shutdown_succeeded=True
     -> join timeout：runtime_status=SHUTDOWN_TIMEOUT，保留 last_error，_shutdown_succeeded=False
     -> 返回 _shutdown_succeeded
  -> ROS handles 随 node 销毁
```

join timeout 是 `WORKER_SHUTDOWN` Gate FAIL，不是 BLOCKED；不得声称正常停止。policy 调用不可强杀，A3 固定 `daemon=True` 使进程仍可有界退出；result queue 关闭后晚到结果被丢弃。shutdown 后没有新 request、candidate 或 publish。

为支持构造失败回收，B10 对尚为 None 的 timer/queue/worker/control-loop handle 逐项跳过；worker 存在但 `_worker_started=False` 时可 stop/close 但不 join，否则 Python 会抛 `cannot join thread before it is started`。任何已 start 的 worker 都必须执行 stop→close→join，不能因“部分构造”省略。

## 7. observation 与 policy 装配边界

A5 必须消费 L2-02 public typed pipeline，不能：

- 把 `DeployConfig` 强塞给当前 Dict-only adapter；
- 自己硬编码六个 required state fields；
- 猜 logical camera key；
- 在 ControlLoop 前转 HWC→CHW 或缩放图像；
- 用 `Pose` 占位 gripper message；
- 读取 L2-03 私有 `_input_spec`。

这些接缝未修时 `OBS_TYPED_CONFIG_SEAM/OBS_IMAGE_POLICY_CONTRACT/OBS_GRIPPER_WIRE_CONTRACT/OBS_TO_INFERENCE_REAL_CHAIN` 必须 FAIL，node 不启动。

## 8. side effects 与依赖方向

- 外部读取：CLI argv、L2-01 repo functions、ROS clock、permit provider。
- 外部写入：L2-02 subscriptions、L2-05 publishers、L2-06 `/act/metrics`、ROS lifecycle。
- UI 可依赖 config/repo/service/runtime/types；runtime 不能 import UI。
- 文件/GPU I/O 只发生在 B11 startup，不发生在 B9/tick。
