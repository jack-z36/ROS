## 测试输入

- 合法 16D action：左右 TCP pose + 左右 gripper width。
- 非法 action：NaN、Inf、非单位四元数、越界 width、超出 workspace 的 TCP。
- dry-run 或 shadow-run 配置。
- 可观察 `/pi05/policy_action` 和 metrics 的 ROS 环境或等价 mock。

## 观察点

- safety_guard 单测中非法 action 均被拒绝，合法 action 通过。
- dry-run 日志中能看到 16D action 和 safety result。
- shadow-run 中 `/pi05/policy_action` 为 16D `Float32MultiArray`。
- metrics 或 status 中 `sent_to_driver=false`。
- 未启动 rm65 driver、gripper driver 或任何真实硬件发送节点。

## 通过现象

- 非法 action 不会进入发布或驱动路径。
- 合法 action 能被解码、检查并形成可观察的 16D policy action。
- shadow-run 能发布观测 topic，但 status 明确显示未发送到 driver。
- metrics 能解释每轮 action 是否通过、为什么失败、是否发送。
- 验收过程中硬件链路保持阻断。

## 失败现象与排查入口

- 非法 action 被放过：优先检查 safety_guard。
- `/pi05/policy_action` 不是 16D：优先检查 action_codec 和 publish 入口。
- `sent_to_driver=true`：立即停止，检查 mode gate 和 L2-05 bridge 是否被误接入。
- metrics 缺字段：优先检查 publish_metrics。
