L2-04 · 单步 Action 安全检查闭环

对准备发布的单步 raw action（解归一化后的真实运动控制指令）做部署侧通用安全检查：shape / NaN / quaternion 模长 / TCP xyz 步长 / 夹爪值域。通过则输出 safe action，非法则返回拒绝原因交 L2-06 fallback。它是动作离开 ACT 部署程序前的最后一道 policy-action 通用过滤。本页用 4 个维度交互呈现：功能边界、Pi0.5 对应部分如何运作、开发蓝图、人类验收标准。

本页只是人类快速浏览入口，不作为 L3 生成依据。
权威细节见 agent_context/00_INDEX.md 及其路由的 Markdown。HTML 与 MD 冲突时，以 MD 为准。

图② reject vs clamp：两类处理语义墙

✗ reject（accepted=False, action=None）→ 交 L2-06 fallback

· shape 非 16D — 动作非法，不可修正

· 含 NaN / Inf — 动作非法

· quaternion 模长偏离 1（左/右分别可定位）— 姿态非法

✓ clamp 修正（accepted=True, action 已修正）→ 仍是合法 safe action

· TCP xyz 步长超 max_tcp_delta_per_step — clamp 到限值（米制）

· gripper 越出 [hand_min, hand_max] — clamp 到边界（依夹爪设备）

关键：reject 和 clamp 是两种不同处理。动作本身非法（shape/NaN/quat）必须拒绝；数值越界（步长/夹爪）可修正，clamp 后仍是合法 action。fallback 策略选择（hold/continue/safe_stop）归 L2-06，L2-04 只产 SafetyResult。

图③ 负责 / 不负责（边界墙）

✓ 负责（policy-action 通用安全）

shape 校验（16D，复用 L2-01 ensure_action_vector）· NaN/Inf 检查 · quaternion 模长归一化校验（wxyz，左/右分别定位）· TCP xyz 单步平动位移 delta clamp（anchor：previous 优先，observation 兜底）· gripper 值域 clamp（值域由 SafetyConfig 决定）· 构造 safe action 或带原因的拒绝结果

✗ 不负责（归其他 L2）

产生 raw action（→ L2-06 cursor 直取）· chunk 生命周期 / chunk 级 NaN/age 校验（→ L2-06）· fallback 策略选择 hold/continue/safe_stop（→ L2-06）· action 平滑 / smoothstep / 跨 chunk 融合（后续优化）· 发布 topic / 硬件命令 / SDK（→ L2-05）· workspace / IK / 急停 / deadman / 碰撞 / 奇异点（→ L2-05 硬件级）

accepted → L2-05 发布 safe action；rejected → L2-06 fallback 决策。L2-04 是动作离开程序前的最后一道 policy-action 过滤。

维度 2 · Pi0.5 这部分是如何运作的

📖 阅读路径：先懂 Pi0.5 安全检查结构可复用（骨架）→ 看检查链四步 → 看一个 action 怎么走 → 看 Pi0.5 关节空间与 ACT TCP 空间的根本差异 → ACT 怎么改见维度3

这一维度只回答：Pi0.5 部署代码里，负责单步 action 安全检查的那部分是怎么跑的。不涉及 ACT 怎么改。关键认知——Pi0.5 是关节空间 14D，ACT 是 TCP 空间 16D，数值必须重写。

这一节用白话讲。Pi0.5 的安全检查核心是一个叫 SafetyGuard 的对象，每来一个动作就过一遍它的 filter_action。
📖 术语词典（点开随时查）
SafetyGuard
（安全守卫）		一个"检查员"对象。每来一个准备发送的动作，它按固定顺序检查：形状对不对、有没有坏值、超不超步长、夹爪值合不合法。通过了放行（可能先修一下），不通过就拦下并写明原因。
filter_action
（过滤动作）		SafetyGuard 的主方法。输入一个动作 + 上一个动作 + 当前观测，输出一个 SafetyResult（通过带修正动作 / 拒绝带原因）。
anchor
（锚点/基准）		算"这一步走多远"时的起点。Pi0.5 优先用上一个通过的动作，没有就用当前观测到的关节角。ACT 改为 TCP 位姿。
delta clamp
（步长钳制）		如果"目标位 − 锚点位"超过单步最大允许距离，就把超出部分砍掉，限制在 ±limit 内。是修正不是拒绝。
关节空间 vs TCP 空间Pi0.5 动作是 6 个关节角（度/弧度）；ACT 动作是末端 TCP 的 xyz 坐标（米）+ 四元数姿态。这是两者最根本的差异。

Pi0.5 安全检查四步流程

1

形状 + 坏值检查

先用 ensure_action_vector 验动作是 14D，不是就拒绝；再查有没有 NaN/Inf，有就拒绝。
这两步 ACT 直接复用（改成 16D）。
→
2

拆分 + 关节绝对限位

拆成 BimanualAction（左右各 6 关节 + 手部标量）。若开了 joint_limits，把每个关节角 clamp 到硬件允许范围。
ACT 不复用（TCP 空间无关节限位）。
→
3

单步 delta 钳制

选 anchor（上一动作优先，否则当前关节角），把"目标−anchor"clamp 到 ±max_joint_delta_rad。
ACT 结构复用，改为 TCP xyz 三维。
→
4

手部值域 + 返回

手部标量 clamp 到 [hand_min, hand_max]（Pi0.5 是 300-1000）。返回 SafetyResult(action=修正后动作, accepted=True)。
ACT 值域按 F100 改 0-100。

跟一个动作走全流程（Pi0.5）

1# ControlLoop.tick() 每 step 调一次 2raw_action = self._next_raw_action(now) # 从 chunk 取单步 3result = self.safety_guard.filter_action( 4 raw_action, 5 observation=latest_observation, 6 previous_action=self.last_command) # anchor 主来源 7if not result.accepted: 8 return self._fallback(result.reason) # 拒绝 → L2-06 fallback 9self.last_command = result.action # 记下，下步当 anchor 10return ControlCommand(action=result.action) # 通过 → 发布

注意：last_command 由 ControlLoop（L2-06）持有，不是 SafetyGuard 持有。SafetyGuard 无可变状态。

图① 运行时协作调用链（filter_action 每 tick 调用方向）

协作关键事实：驱动方是 L2-06 ControlLoop（runtime 层），每 tick 同步调 filter_action。SafetyGuard（service）有编排函数（filter_action 编排检查链），但无可变运行时状态（config frozen）。失败在 ②③ 即停，不进入 clamp ④。SafetyResult（types）是跨层冻结契约，L2-05/L2-06 只读消费。last_command 由 L2-06 持有，不归 SafetyGuard。

图② A/B/C 三层功能模块总览

L2-04 的 21 个功能模块按 A/B/C 三层编号（A = 打包成 class 的行为单元，B = 组织 C 的同步编排函数，C = 不再拆分的原子数据/计算微元）。下表是总览，每个模块的逐函数契约见图③ 六层落点。

A 层（3.25 · class）— 1 个功能模块：把 B/C 打包成可调用对象
编号名称类型基础介绍
A1SafetyGuardclass整个 L2-04 的对外句柄。构造时一次注入 immutable SafetyConfig/ActionDomain（L2-01 提供），之后被 L2-06 每 tick 同步调用。无运行时可变状态——previous_safe_action、observation、metrics、fallback 都通过方法参数传入或留在 L2-06。结构复用 Pi0.5 SafetyGuard，去掉关节限位。
B 层（3.375 · 编排函数）— 5 个功能模块：把 C 层原子微元组织成检查链
编号名称类型基础介绍
B1filter_action编排函数（公开方法）A1 唯一公开方法，对外总入口。步骤：① 调 B2（输入 candidate/previous/snapshot → 输出 canonical ActionSpec）；② 调 C9（输入 previous+snapshot → 输出 C4 基准）；③ 调 B5（输入 candidate+C4 → 输出 safe ActionSpec+findings）；④ 构造 C5（输入 status/action/findings → 输出 SafetyResult）。契约失败→C5(REJECTED)；越界→C5(ADJUSTED)。
B2_validate_candidate_action编排函数（私有方法）B1 第一步。步骤：① 调 C6（输入 candidate → 输出 (16,) ndarray）；② 调 C7（输入 (16,) → 输出 finite (16,)）；③ 调 L2-01 split_action（输入 (16,) → 输出 左右 pose+gripper）；④ 调 C8 左右各一次（输入 quat → 输出 unit quat）。任一失败即终止上抛给 B1。
B3_project_arm_pose编排函数（私有方法）单侧 TCP pose 投影，左右各调一次。步骤：① 调 C10（输入 target_xyz+ref_xyz+limit_m → 输出 投影 xyz+finding）；② 调 C11（输入 target_quat+ref_quat+limit_rad → 输出 投影 quat+finding）。不拒绝，超限即投影。
B4_project_gripper编排函数（私有方法）单侧夹爪投影，左右各调一次。步骤：① 调 C12（输入 scalar+min+max → 输出 [min,max] scalar+finding）；② 调 C13（输入 scalar+ref_scalar+max_step → 输出 投影 scalar+finding）。不拒绝，超限即投影。
B5_project_bimanual_action编排函数（私有方法）双臂双夹爪投影总装。步骤：① 调 B3×2（输入 左右 target/ref pose → 输出 左右 safe pose+findings）；② 调 B4×2（输入 左右 target/ref scalar → 输出 左右 safe scalar+findings）；③ 调 C14（输入 左右投影字段 → 输出 16D ActionSpec）；④ 调 C15（输入 ActionSpec+domain → 输出 校验后 ActionSpec）。C15 失败由 B1 转 REJECTED。

编号名称类型基础介绍
C1SafetyStatus数据（types）Enum：PASS / ADJUSTED / REJECTED。

这一层只定义"安全检查结果长什么样"。作为跨 L2 公共 RAM 契约，供 L2-05/L2-06 只读消费，避免它们依赖 service 实现。不读配置、不依赖 ROS、不做计算。

safety_result.py（types/safety_result.py）— C1/C2/C3/C5 四个数据微元

安全检查的冻结输出契约，跨模块 RAM 对象。结构复用 Pi0.5 safety_guard.py::SafetyResult，把 action/accepted/reason 三字段重写为 status + findings，使 ADJUSTED 的调整原因不丢失。

config/ · 本 L2 不新增产物（复用 L2-01 SafetyConfig）

原因：L2-04 的安全检查参数（TCP delta 限值 max_tcp_delta_per_step、夹爪值域 hand_min/hand_max、quaternion 开关 quaternion_check、容差 quat_tol）全部复用 L2-01 已落地的 config/schema.py::SafetyConfig，本 L2 不新增 config 文件。

使用的上游对象：service 层在 __init__ 接收 SafetyConfig 实例，一次构建 frozen 限值。
验收确认：L2-04 不产生 config/*.py 产物；rg 检查 service 层无 schema 新增。
⚠ 协调点：当前默认 hand_min=300/hand_max=1000（RM65 残留），对大象 F100（0-100）是 no-op 安全漏洞，进 L3 前须修正 deploy.yaml。

repo/ · 本 L2 不新增产物

原因：repo 层负责外部资源读取（文件/topic/硬件）。L2-04 的安全检查是纯 RAM 计算——输入 raw action 已由 L2-03 解归一化进内存，检查过程中不读任何外部文件、不订阅 topic、不访问硬件。

使用的上游对象：raw action（L2-06 cursor 直取）+ ObservationSnapshot（L2-02，兜底 anchor）。均已在 RAM。
验收确认：L2-04 不产生 repo/*.py 产物。

service/ · 业务计算层 — SafetyGuard 核心（L2-04 主实现）

新增文件 src/model_deploy/act/service/safety_guard.py。接收已解归一化的 16D 绝对目标动作（RAM 对象），相对可信基准投影为单步安全动作或明确拒绝，输出 C5 SafetyResult。文件按业界 Python 工程规范组织：模块顶部定义私有 dataclass（C4）→ 模块级无状态纯函数（C6-C15）→ 主 class SafetyGuard（A1，含实例属性 + 公开/私有方法 B1-B5）。每个微元前置 A/B/C 编号。

safety_guard.py（service/safety_guard.py）

L2-04 主实现文件。纯 RAM 业务计算，无 ROS/timer/queue/文件 IO。模块级放无状态工具（纯函数 + 一个私有 dataclass），有状态的依赖与对外契约集中在 SafetyGuard class。结构复用 Pi0.5 SafetyGuard，去掉关节限位、改为绝对 TCP 目标几何投影。

失败：不拒绝——超限即投影，产生 C3 finding。

runtime/ · 本 L2 不新增产物（fallback 归 L2-06）

原因：runtime 层负责时间/线程/队列/调度/状态机。L2-04 的 SafetyGuard 是无状态同步计算——不创建 timer/thread/queue，不维护 chunk cursor 或 fallback 策略。tick 调用与 fallback 决策都归 L2-06 ControlLoop。

使用的上游对象：被 L2-06 ControlLoop.tick 每 step 同步调用；last_command（anchor 主来源）由 L2-06 持有。
验收确认：L2-04 不产生 runtime/*.py 产物。

ui/ · 本 L2 不新增产物

原因：ui 层负责 ROS 边界（node/subscriber/publisher/message converter）。L2-04 不发布 topic、不订阅、不创建 node——它只产 SafetyResult 交 L2-06，发布 safe action 归 L2-05。

使用的上游对象：无。SafetyResult 经 L2-06 → L2-05 发布。
验收确认：L2-04 不产生 ui/*.py 或 launch 产物。

边界不变量：L2-04 只产 C5 SafetyResult，不做 fallback 策略选择（归 L2-06）。B1-B5 全部是同步编排，不创建 timer/queue；C4-C15 全部是 RAM 内纯计算。Pi0.5 的 hold 路径会把 last action 再过一遍 filter_action（即 B1）复检——这个模式 L2-06 可沿用，但策略选择（hold/continue/safe_stop）是 L2-06 的编排决策。L2-04 不持有 previous_safe_action（由 L2-06 持有，在 L2-05 接受输出后更新）。
