# 阶段一：数据采集背景信息

## 为什么需要阶段一

FastUMI 改造的第一步是获得真实、完整、可追溯的示教日志。后续数据清洗、模型训练和部署都依赖这些 raw MCAP。如果采集阶段 topic 不稳定、设备名漂移、Octopus 录制缺 topic，后面的 canonical dataset 和 VLA 训练都会建立在不可靠的数据源上。

## 当前关注的数据模态

项目当前重点关注双臂/双手数据，每一侧可能包含：

- 左侧：`image_left`、`left_baton_pose_raw`、`left_gripper_width_raw`、`left_tactile`、`left_timestamp`。
- 右侧：`image_right`、`right_baton_pose_raw`、`right_gripper_width_raw`、`right_tactile`、`right_timestamp`。
- 其他：`language_instruction`、`episode_start`、`episode_end`、机械臂状态、夹爪状态、设备状态、采集质量状态。

这些名字是训练语义层面的目标字段，不等同于 raw MCAP 中已经固定存在的 topic 名。raw topic 到训练语义字段的映射由阶段二的 schema 和 metadata 进一步明确。

## raw MCAP 的定位

raw MCAP 是阶段一的核心产物。它是原始采集日志，不是最终训练数据。

raw MCAP 的价值是：

- 可回放。
- 可追溯。
- 可重新清洗。
- 可检查原始 topic。
- 可排查传感器问题。
- 可作为 canonical dataset 的原始来源。

模型训练不应该直接依赖原始 topic 名称，而应该依赖阶段二生成的 observation schema、action schema、step index、masks 和质量报告。

## 与其他阶段的关系

阶段一输出 raw MCAP，阶段二把 raw MCAP 从 topic 世界转换成 episode/step/observation/action 世界，阶段三使用导出的训练格式训练 VLA，阶段四用实时 observation 和训练时一致的 action 语义驱动机械臂。

阶段一的关键边界是：只保证原始数据完整记录，不在本阶段强行完成时间同步、坐标系统一、action chunk 生成或训练格式导出。
