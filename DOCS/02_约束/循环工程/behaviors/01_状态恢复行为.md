# 状态恢复行为

## 消费 Agent

- 主 Agent

## 本文职责

本文只约束主 Agent 在每轮循环开始时如何恢复阶段四真实状态。

## 不负责

本文不决定目标 L2、不派发任务、不修改状态、不执行 Git。

## 旧流程残留检查

状态恢复时必须检查当前状态摘要、dispatch 和 acceptance 路径是否仍引用旧 layer-based L2：

```text
l2-01-types
l2-02-config
l2-03-assembly
l2-04-publish
l2-05-hardware
```

这些 ID 只能出现在 `_legacy_layer_based_act/`、`_archived_pi05/` 或明确废弃说明中。若出现在当前状态、active dispatch、目标 L2 或 acceptance 权威路径中，必须停止恢复并报告“旧流程残留”。

## 输出

必须先输出当前状态摘要，至少包含：

- L2 Gate 状态。
- 当前可推进 L2 候选。
- 已知 blocked 项。
- Git pending push 项。
- 下一步需要进入的行为文件。

## 禁止事项

- 禁止凭记忆恢复进度。
- 禁止把 `00_status` 摘要当作唯一权威来源。
- 禁止在状态冲突时继续执行；必须指出冲突并以 dispatch、验收结果和 Git 实际状态为准。
