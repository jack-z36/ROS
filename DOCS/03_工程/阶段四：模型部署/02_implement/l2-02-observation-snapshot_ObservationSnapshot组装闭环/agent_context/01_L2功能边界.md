## 2. L2 功能边界

```text
L2: l2-02-observation-snapshot
Runtime responsibility: 从外部 observation topics 接收图像、TCP pose 和 gripper state，生成完整、合法、新鲜的 ObservationSnapshot。
Inputs: DeployConfig 中的 observation topic / image config、外部 observation ROS messages、L2-01 的 16D state codec / topic 契约。
Outputs: ObservationSnapshot、latest-only observation buffer、observation_ready / missing_fields / stale_observation_count 观察信号。
Owns: ObservationSnapshot 创建、字段齐全性检查、新鲜度检查、图像预处理入口、latest observation 写入。
Does not own: ACT batch、模型推理、ActionChunk、ControlLoop 推理节奏、SafetyGuard、硬件命令发送。
Upstream L2: l2-01-external-contract。
Downstream L2: l2-03-act-inference、l2-06-control-loop。
```

一句话责任：L2-02 是外部 observation 世界进入 ACT 部署程序 RAM 的入口，它把零散传感器消息冻结成可被推理和调度稳定消费的 `ObservationSnapshot`。

## 3. 输入输出契约

### 输入

```text
/act/observation/image/left_gripper_fisheye
/act/observation/image/right_gripper_fisheye
/act/observation/arm/left_tcp_pose
/act/observation/arm/right_tcp_pose
/act/observation/gripper/left_state
/act/observation/gripper/right_state
```

这些 topic 名来自 L2-01 的 `DeployConfig.topics.observation`，L2-02 不硬编码最终配置值。

### 输出

```text
ObservationSnapshot(
  images=Mapping[str, image tensor],
  state=structured ACT state,
  encoded_state=np.ndarray shape (16,),
  captured_at_s=<monotonic seconds>,
)

ObservationBuffer.latest_observation
```

`ObservationSnapshot` 是跨 L2 公共 RAM 契约，设计落点为 `src/model_deploy/act/types/observation.py`。L2-03 只消费 snapshot，不依赖 ROS callback；L2-06 只读取 latest observation，不管理单个传感器字段。

## 4. 负责内容

- 创建 observation topic 的订阅入口设计。
- 将 ROS image 消息转换为 ACT 需要的 RAM 内图像对象。
- 接收左右臂 TCP pose。
- 接收左右夹爪 gripper width / state。
- 维护各字段最新值和采集时间。
- 检查必需字段是否齐全。
- 检查字段是否在 `max_age_s` 内新鲜。
- 调用 L2-01 state codec 生成 16D `encoded_state`。
- 将合法 snapshot 写入 latest-only buffer。
- 暴露缺字段、过期和 decode 失败的可观察诊断。

## 5. 不负责内容

- 不调用 ACT 模型。
- 不构造 ACT batch。
- 不生成、消费或选择 `ActionChunk`。
- 不决定是否发起下一次推理。
- 不维护 ControlLoop tick 状态。
- 不执行 action safety check。
- 不发布硬件命令。
- 不声明真实 ROS / real-robot 行为已通过；无 ROS 环境只能记录为 `env-blocked` 或 mock 通过。

## 6. 完成判据

- 给定 mock 图像、左右 TCP pose 和左右 gripper state，能生成 `encoded_state.shape == (16,)` 的 `ObservationSnapshot`。
- 任一必需字段缺失时不生成 snapshot，并能报告 missing fields。
- 任一字段超过 `max_age_s` 时不生成 snapshot，并能报告 stale。
- 连续写入 snapshot 时 latest buffer 只保留最新一帧。
- 无 ROS 环境下 service / runtime / types 层可 import 和测试；ui 层 ROS adapter 的真实订阅验收记录为 `env-blocked`。

## 7. 仍需用户确认的问题

当前计划已锁定本轮只生成 L2 设计内容，不生成 L3。后续进入代码实现前仍需确认：

- L2-01 的 `StateSpec` / `DeployConfig` / topic schema 是否已落地到当前开发分支。
- 图像 RAM 形态最终是 `np.ndarray`、torch tensor，还是 adapter 层保持二者兼容。
- TCP pose 的 16D state 编码中 quaternion / position / gripper width 的最终段序是否与 L2-01 实现一致。
