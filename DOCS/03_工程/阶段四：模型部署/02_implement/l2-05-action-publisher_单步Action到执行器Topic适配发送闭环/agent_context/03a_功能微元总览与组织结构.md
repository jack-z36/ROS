## 2. 总量与分层

```text
A 层（3.25 Class）      1 个：A1
B 层（3.375 编排函数）  3 个：B1-B3
C 层（3.5 原子微元）   21 个：C1-C21
```

“24 个业务功能微元”指 `B1-B3 + C1-C21`；A1 是把有状态 UI 微元打包为长生命周期对象的 class，不重复计入业务功能总数。

### 2.1 A 层：3.25 Class

| 编号 | 名称 | 父级 | 落点层 | 职责 |
|---|---|---|---|---|
| A1 | `ActionPublisher` | 无 | ui | 唯一 ROS 输出 class；持有六 publisher、只读 config、夹爪防刷状态和最近 result；对外暴露 B3。 |

### 2.2 B 层：3.375 编排函数

| 编号 | 名称 | 父级 | 落点层 | 职责 |
|---|---|---|---|---|
| B1 | `build_topic_payloads` | B3 调用，模块级 | service | `SafetyResult + CommandOutputConfig -> TopicPayloadBundle`；组织 safe action 复核、16D 拆分、arm target 和 gripper 映射。 |
| B2 | `build_ros_messages` | B3 调用，模块级 | ui | `TopicPayloadBundle + ros_time_s -> _RosMessageBundle`；组织 policy、两臂、两爪候选 ROS message 构造，不构造最终 status。 |
| B3 | `ActionPublisher.publish` | A1 | ui | 唯一公共入口；按 B1 → B2 → CLI/permit 决策 → ROS 写出 → result → status 顺序完成闭环。 |

### 2.3 C 层：3.5 原子微元

| 编号 | 3.5 类型 | 名称 | 父级/所有者 | 落点层 | 职责 |
|---|---|---|---|---|---|
| C1 | 数据 | `CommandPermit` | L2-06 创建，B3 消费 | types | 每 tick 动态许可：`allowed`、`reason_code`。 |
| C2 | 数据 | `ActionPublishRequest` | L2-06 创建，B3 消费 | types | action_id、SafetyResult、CommandPermit、ROS/单调时间。 |
| C3 | 数据 | `ArmPoseTarget` | B1 创建，B2 消费 | types | transport-neutral 单臂目标：统一 frame、xyz、xyzw。 |
| C4 | 数据 | `TopicPayloadBundle` | B1 创建，B2 消费 | types | policy 16D + 两臂 ArmPoseTarget + 两爪 0..100。 |
| C5 | 数据 | `PublishOutcome` | C19 选择，C6 携带 | types | `REJECTED/OBSERVED/BLOCKED/PUBLISHED/PARTIAL/FAILED`。 |
| C6 | 数据 | `ActionPublishResult` | C19 创建，L2-06/C20 消费 | types | 一次调用的真实发布事实。 |
| C7 | 数据 | `CommandOutputConfig` | 启动装配创建，A1/B1/B3 消费 | config | CLI enable、统一 frame、夹爪映射、deadband、间隔、QoS。 |
| C8 | 数据 | `_RosMessageBundle` | B2 创建，B3 消费 | ui | 模块私有五消息引用；不含 status。 |
| C9 | 计算函数 | `require_publishable_action` | B1 | service | `SafetyResult -> ActionSpec`；只接受 PASS/ADJUSTED 并复核 16D/finite/爪域。 |
| C10 | 计算函数 | `build_arm_pose_target` | B1 | service | `TCP7 + pose_frame_id -> ArmPoseTarget`；不做 TF。 |
| C11 | 计算函数 | `map_gripper_command` | B1 | service | `[0,1] + config -> 0..100`；越域失败。 |
| C12 | 计算函数 | `_build_policy_msg` | B2 | ui | `tuple[16] -> Float32MultiArray`。 |
| C13 | 计算函数 | `_build_arm_msg` | B2 | ui | `ArmPoseTarget + ros_time_s -> PoseStamped`。 |
| C14 | 计算函数 | `_build_gripper_msg` | B2 | ui | `0..100 -> Float64`。 |
| C15 | 计算函数 | `_decide_command_publish` | B3 | ui | `command_output_enabled + CommandPermit -> allow/reason`。 |
| C16 | 计算函数 | `_should_publish_gripper` | B3/A1 | ui | 读取单侧 cache，判断 deadband/最小间隔。 |
| C17 | 数据读写函数 | `_try_publish` | B3/A1 | ui | 调用一个 ROS publisher；返回成功事实或抛出带 label 的错误。 |
| C18 | 内部状态更新函数 | `_record_gripper_success` | B3/A1 | ui | 仅在对应夹爪 publish 成功后替换 target/time。 |
| C19 | 计算函数 | `_build_publish_result` | B3 | ui | 调用事实、permit、计数、错误 -> frozen `ActionPublishResult`。 |
| C20 | 计算函数 | `_build_status_msg` | B3 | ui | `ActionPublishResult -> String(JSON)`；保留 unknown=null。 |
| C21 | 内部状态更新函数 | `_record_last_result` | B3/A1 | ui | 用当前 frozen result 替换 `_last_result`。 |

## 3. 权威调用树

```text
L2-06 ControlLoop.tick()                         编排函数 · 驱动方
└── A1 ActionPublisher
    └── B3 publish(request)                      编排函数 · 唯一公共入口
        ├── B1 build_topic_payloads(...)         编排函数 · service 纯 RAM
        │   ├── C9 require_publishable_action
        │   ├── C10 build_arm_pose_target ×2
        │   ├── C11 map_gripper_command ×2
        │   └── 创建 C4 TopicPayloadBundle
        │
        ├── B2 build_ros_messages(...)           编排函数 · ui 纯消息构造
        │   ├── C12 _build_policy_msg
        │   ├── C13 _build_arm_msg ×2
        │   ├── C14 _build_gripper_msg ×2
        │   └── 创建 C8 _RosMessageBundle
        │
        ├── C15 _decide_command_publish
        ├── C17 _try_publish(policy)
        ├── [若 command 允许]
        │   ├── C17 _try_publish(left_arm)
        │   ├── C17 _try_publish(right_arm)
        │   ├── C16 _should_publish_gripper ×2
        │   ├── C17 _try_publish(gripper) ×0..2
        │   └── C18 _record_gripper_success ×0..2
        ├── C19 _build_publish_result
        ├── C20 _build_status_msg
        ├── C17 _try_publish(status)              best effort
        └── C21 _record_last_result
            ↓
        C6 ActionPublishResult -> L2-06
```

实际调用方向是 `L2-06 -> B3`；B1/B2 是 B3 的内部顺序调用，不允许 L2-06 绕过 B3 分别调用三步。

## 4. 整体协作逻辑

```text
启动期：
显式 CLI --enable-command-output
  -> C7.command_output_enabled（默认 False）
  -> 构造 A1，创建六 publisher

每 tick：
C2 ActionPublishRequest + immutable C7
  -> B1 生成 C4 TopicPayloadBundle
  -> B2 生成 C8 _RosMessageBundle（不含 status）
  -> B3 总开关/permit 决策并写 policy/可选 command
  -> C19 汇总真实事实为 C6
  -> C20 根据 C6 构造 status
  -> status best effort + C6 返回 L2-06
```

关键不变量：

- B1/B2 完全成功前，policy/command publisher 调用数必须为 0。
- CLI 关闭仍运行 B1/B2，只关闭四路 command 写出。
- status 是 C6 的外部投影，不是 B2 的候选输入消息。
- ROS 多 Topic 不具备事务性；C6 必须保留部分成功事实。

## 5. 上游复用对象（不编号）

| 对象 | 所属 | 在本体系中的作用 |
|---|---|---|
| `ActionSpec`、`ensure_action_vector`、`split_action` | L2-01 types | 16D 固定布局与结构化 action。 |
| `SafetyStatus`、`SafetyResult` | L2-04 types | C9 的来源契约；PASS/ADJUSTED 可发布，REJECTED 停止。 |
| `DeployConfig`、`TopicsConfig` | L2-01 config | topics 和最终 `CommandOutputConfig` 容器。 |
| node-like publisher factory | L2-06/UI 装配 | A1 构造六 publisher 的工厂。 |
| `action_id`、`ros_time_s`、`monotonic_s` | L2-06 | C2 的标识与时间来源。 |
| CLI parser / launch argument | 启动 UI/装配 | 将显式 `--enable-command-output` 转成 C7.enabled；不由 L2-05 解析。 |

这些对象不重新编号，也不在本 L2 重复实现；通过 RAM 注入或 request 字段进入 L2-05。

## 6. 状态所有权边界

```text
A1 ActionPublisher owns:
  六 publisher handles
  immutable C7 CommandOutputConfig
  左/右最近成功 gripper target + monotonic time
  最近一次 C6 ActionPublishResult

B1/B2 own:
  无跨调用状态

L2-06 owns:
  action_id / 时间 / CommandPermit 构造
  原始 gate/deadman/estop/driver readiness
  active chunk / cursor / fallback / retry
  全局 RuntimeMetrics
```

## 7. L3/验收/HTML 使用规则

- L3 切片、测试 label、HTML 图②/图③引用编号前必须先读取本文件。
- B 层只能有 B1-B3；deadband、state record、status write 均为 C 层原子微元，不得重新升级成第四/第五个编排函数。
- C1-C21 只允许一份实现；左右重复调用不新增编号。
- HTML 未同步前，本文件与其他 Agent Markdown 是唯一权威。
