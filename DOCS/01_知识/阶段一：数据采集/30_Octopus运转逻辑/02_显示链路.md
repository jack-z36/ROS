# 显示链路

本页描述 Octopus 显示链路（`octopus` 节点）的内部机理：从 ROS topic 到 Qt 面板更新的完整路径。

## 定位

本页回答：显示节点收到消息后，内部怎么处理才变成屏幕上的画面/数值/热力图？

本页不涉及录制（见 `03_录制链路.md`），不涉及各传感器的消息字段（见 `20_传感器模态语义/`）。

## 建立订阅

`MainWindow` 构造时：

1. 创建 Qt dock 布局（6 个业务 dock：左/右 GoPro、左/右 Pose、左/右 Tactile）。
2. 创建显示节点 `rclcpp::Node("octopus")`。
3. 创建显示链路自己的 `SingleThreadedExecutor`，放在 `std::jthread` 中持续 `spin()`——这让 ROS 回调不阻塞 Qt 主线程。
4. `subscribeTopics()` 内部定义三个 lambda：`subscribe_image`、`subscribe_odometry`、`subscribe_pressure`，分别绑定三类面板。

固定订阅的 8 个 topic 见 `20_传感器模态语义/04_核心topic清单.md`。所有显示订阅保存在 `subscriptions_` map 中，key 是 topic 字符串，生命周期跟随 `MainWindow`。

## 图像处理路径

```text
/gopro_*/image_raw (sensor_msgs/Image)
  → image 回调
  → to_ffmpeg_frame()  按 img.step 逐行复制 img.data，根据 encoding 选 FFmpeg pixfmt（非零拷贝）
  → Resampler::scale()  转换为面板固定需要的 RGBA frame
  → ImageDockWidget::preset()  交给纹理显示链路
  → Qt 主显示区
```

### ImageSubscriptionState 缓存

每个图像订阅维护一个 `ImageSubscriptionState`，缓存 `Resampler`、宽和高：

- 图像尺寸变化时，重建 `Resampler`。
- 尺寸不变时，复用缓存的 `Resampler`，避免每帧重新分配转换器。

### 排障

- 某个图像面板不更新：先确认上游 topic 是否存在且类型正确，再看 `subscribeTopics()` 是否订阅了该固定 topic。
- 图像黑屏但 topic 有消息：重点看 `encoding` 是否被 `to_ffmpeg_pixfmt()` 支持。

## 位姿处理路径

```text
/baton_mini_*/fast_odom (nav_msgs/Odometry)
  → odometry 回调
  → OdometryDockWidget::preset()  把消息压入队列
  → 面板 100ms timer refresh()  drain 队列，一次性更新
  → 数值标签 + 10 秒 xyz 曲线
```

`OdometryDockWidget` 每次刷新时：

- 更新 frame、stamp、position、orientation、linear、angular 数值标签。
- 把 position xyz 追加到时间窗，`refresh_chart()` 只保留最近 10 秒数据。

## 触觉处理路径

```text
/pressure/* (PressureFrame)
  → pressure 回调
  → PressureDockWidget::preset()  把消息压入队列
  → 面板 100ms timer refresh()  drain 队列
  → 按 gripper 字段路由 + 热力图更新
```

`PressureDockWidget` 的关键逻辑：

- 依靠 `PressureFrame.gripper` 判断是 `gripper_1` 还是 `gripper_2`，路由到对应热力图。
- 两个 gripper 使用**同一个当前最大压力值**做颜色缩放，避免同手两块热力图颜色尺度不一致。
- 显示内容：热力图、max/avg、矩阵尺寸（rows×cols）、更新时间。

### 排障

- 触觉热力图空白：重点看 `PressureFrame.rows/cols/data` 是否有效，以及 `gripper` 是否是 `gripper_1` 或 `gripper_2`。

## 队列 + Timer 模式

位姿和触觉面板采用统一的"队列 + 100ms timer drain"模式：

- 回调不直接更新 UI（避免高频回调阻塞 Qt 线程），而是调用面板 `preset()` 把消息压入队列。
- 面板自己的 100ms timer 调用 `refresh()`，一次性 drain 队列并更新标签/图表/热力图。

这是显示链路处理非图像高频数据的核心模式。
