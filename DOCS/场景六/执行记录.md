### 3. 发现和修复运行链路问题

为了让脚本实际处理 MCAP，逐步发现并处理以下问题：

1. **zstandard 压缩依赖缺失**
   - 真实 MCAP 使用 zstandard 压缩。
   - 当前 Python 环境缺少 `zstandard` 时，读取 MCAP 报：

     ```text
     unsupported compression type zstandard
     ```

   - 曾临时安装到 `/tmp/data_clean_pydeps` 做验证，后续改为 conda 环境。

2. **Octopus 写入的 ROS2 schema 有缩进**
   - `mcap_ros2` 动态解析 `nav_msgs/msg/Odometry` schema 时，因 schema 文本存在统一缩进导致解析失败。
   - 在 `core/ros2_codec.py` 中加入 schema 规范化逻辑。
   - 在 `core/mcap_io.py` 中输出原始 channel/schema 时也使用规范化后的 schema。

3. **系统 OpenCV ArUco 模块 segfault**
   - 系统自带 `cv2.aruco.detectMarkers` 对空白图也会段错误。
   - 初步加过图像连续内存修复：
     - 在 `core/gripper_width.py` 中将图像转为连续 `uint8` 灰度数组。
   - 最终通过独立 conda 环境安装可用的 `opencv-contrib-python-headless` 解决。

4. **缺少配置文件**
   - 当时仓库没有找到现成的 `data_clean` YAML 示例。
   - 新增了 `/home/hit/ROS/config/data_clean_smoke_test.yaml` 作为清洗配置。
