# 阶段二场景四：背景信息

## 场景定位

aligned MCAP 已经解决了多 topic 时间对齐问题，但它仍然更接近 topic 日志。模型训练需要的是 episode、step、observation、action 和 masks。

本场景的职责是把 aligned MCAP 转换为 `canonical_dataset_mcap/`，使数据从 topic 世界进入 dataset 世界。

## canonical dataset 的定位

canonical dataset 是 raw/cleaned/validated/aligned MCAP 和训练格式之间的稳定中间层。它保留 MCAP 数据本体，同时用 schema、index、masks、reports 和 manifest 明确训练语义。

它的作用是：

- 让后续 exporter 不需要猜 topic 语义。
- 让不可训练 step 可以通过 masks 被过滤。
- 让质量问题和机器人约束检查结果可以追溯。
- 让不同训练格式都能从同一个标准中间态导出。

## 四层信息

- 数据本体层：episode 内的 MCAP 数据，可回放、可追溯。
- 语义契约层：schema 定义 observation、action、frame、topic 和 quality 规则。
- step 映射层：step index 把数据本体映射到 step。
- 质量和追溯层：masks、reports、manifest 说明数据是否可用以及如何生成。

## observation 和 action

observation 应表达每个 step 的多模态状态，例如图像、位姿、夹爪宽度、触觉和语言指令。

action 使用 UMI 风格 relative trajectory action：在当前推理起点 t，预测未来 K 步目标相对轨迹，并包含夹爪相关信息。关键约束是：action chunk 必须相对于同一个当前起点，而不是逐步 delta。

## masks 和 reports

masks 用来回答“这个 step 或字段能不能用于训练”。它不能只有布尔值，还必须能说明 invalid reason。

reports 用来回答“为什么这个 episode 质量如此”。它应汇总：

- 时间对齐质量。
- 数据质量。
- 机器人约束检查结果。
- 处理过程和输入来源。

## 与后续场景的关系

场景五应只读取 canonical dataset，而不是绕过 schema、step index 和 masks 直接读取上游 MCAP。这样才能保证训练格式导出可复现、可扩展、可过滤。

## 风险与未知

- schema 第一版如果频繁变动，会影响后续 step index、masks 和 exporter。
- action horizon 需要与训练需求匹配。
- masks 的粒度需要足够表达无效原因，但不能复杂到难以使用。
- 质量阈值需要根据真实数据逐步校准。
