# ui 层设计：L2-05

> [!info] 元信息
> - 消费对象：ROS UI 实现/验收 Agent。
> - 权威性：本文定义 L2-05 唯一外部副作用与有状态 class。
> - 上游来源：ActionPublishPlan、DeployConfig、用户确认的两通道/模式边界。
> - 不负责范围：不订阅、不拥有 node 生命周期/timer、不调用硬件 API。
> - 读取时机：实现或审查 ROS publisher 前。
> - 冲突处理：出现 bridge subscription、raw gate 信号或硬件 SDK 时直接判越界。

## 1. 目标源码路径

```text
src/model_deploy/act/ui/action_publisher.py
src/model_deploy/act/ui/__init__.py       # 仅导出 ActionPublisher
```

不新增独立 ROS Node 或 launch。本组件由 L2-06 的 node/装配入口创建。

## 2. 层职责与文件职责

ui 层把 transport-neutral plan 转为 ROS messages，实际调用六个 publisher，执行 mode/最终授权二次门控、夹爪 deadband 和逐调用 status。它是 ACT 内部唯一 command publish 边界。

不做：subscription、timer、thread、queue、SafetyGuard、workspace/IK、driver SDK、fallback。

## 3. ROS transport 决策

| Topic | 类型 | 构造规则 |
|---|---|---|
| `/act/policy_action` | `Float32MultiArray` | 16D float32 原样；不拆成硬件单位。 |
| 两路 arm target | `PoseStamped` | request ROS stamp；对应 base frame；xyz + quaternion xyzw。 |
| 两路 gripper target | `Float64` | service 已映射的 0..100。 |
| `/act/command/status` | `String` JSON | 稳定 key 顺序；null 保留 unknown。 |

模块使用 lazy ROS import：无 rclpy 时仍可 import，创建真实 publishers 时标记/抛出明确 `BLOCKED_ENV`；mock node 测试不需要 ROS graph。

## 4. `ActionPublisher` class 设计

### 4.1 class 封装微元

| 3.5 微元 | 内容 |
|---|---|
| 数据 | config、六 publisher handles、每侧 last gripper target/time、last result、env status。 |
| 计算函数 | ROS message builders、deadband 判断、status JSON。 |
| 内部状态更新 | 只在对应 gripper publish 成功后记录 target/time；每次调用记录 last result。 |
| 数据读写 | 六个 ROS publisher `.publish()`。 |
| 编排函数 | `publish(request)` 按本地构造 -> mode/gate -> policy -> command -> status -> result 顺序执行。 |

### 4.2 constructor

```text
ActionPublisher(node, deploy_config)
```

- 使用 `node.create_publisher` 创建恰好六个 publisher，QoS depth 来自 CommandOutputConfig。
- 不调用 `create_subscription`、`create_timer`。
- 不从 node clock 取时间；时间必须来自 request。
- publisher 创建失败立即阻止可用状态，不能半初始化后接受 publish。

### 4.3 public method

```text
publish(request: ActionPublishRequest) -> ActionPublishResult
```

只有这一个业务入口。禁止暴露“直接发左臂/右臂”的 public bypass method，避免 raw/未授权调用绕过整体构造门。

## 5. 消息构造与发布顺序

```text
1. service.build_publish_plan(request, config)
2. 在 RAM 中构造 policy + status draft + PoseStamped×2 + Float64×2
3. command 任一构造失败 -> 四路 command publish 0
4. dry-run -> 返回本地 result
5. shadow/safe -> publish policy
6. safe + allowed -> publish 两臂，再发布 deadband 允许的两爪
7. 每次成功立即增加局部 count；gripper 成功后才更新 cache
8. 捕获异常并形成 partial_ros_publish:n/4
9. 尽力 publish status；同步返回同一 result
```

policy 与 command 是并行语义，不是 topic 串行依赖。policy 发布失败不自动授权/禁止 command；为了保守可观测性，第一版设计选择 policy publish 失败时不进入四路 command，并返回 `policy_publish_failed`，由 L2-06 决定后续行为。

## 6. deadband 与最小间隔

每侧独立：

```text
publish gripper iff:
  no previous successful target
  OR (abs(target-last_target) >= deadband
      AND monotonic_s-last_time >= min_interval)
```

- 目标相同永远跳过，除非未来明确设计 keepalive。
- 目标改变但时间不足时本 tick 跳过，后续 tick 重新判断。
- 跳过原因进入 `gripper_skipped`，不等于 failure。
- publish 抛异常时不得更新 cache。
- 两臂不受 gripper deadband 影响；但四路 message 仍需在任何 command publish 前完成本地构造。

## 7. status JSON

最低 payload：

```json
{
  "action_id": "...",
  "safety_ok": true,
  "mode": "shadow-run",
  "policy_action_published": true,
  "command_publish_count": 0,
  "gripper_skipped": [],
  "sent_to_driver": false,
  "failure_reason": "shadow_only",
  "driver_accepted": null,
  "hardware_reached": null
}
```

`sent_to_driver` 只表示候选命令已经调用 driver topic publisher；`driver_accepted` 与 `hardware_reached` 必须保持 null，除非外部 driver 反馈由 L2-06 汇总。L2-05 不订阅反馈来填值。

## 8. 输入输出与副作用

| 输入 | 输出 | 副作用 |
|---|---|---|
| node-like factory、DeployConfig、ActionPublishRequest | ActionPublishResult | 最多六个 ROS publish；最小 RAM state 更新 |

## 9. 依赖关系

允许：types、config、service、ROS message packages、标准库。

禁止：runtime（UI 不反向依赖调度实现）、repo、SafetyGuard 实现、RM65/F100 SDK、MoveIt/IK、Modbus/serial。`ActionPublisher` 只读取 `SafetyResult` 数据契约，不 import L2-04 service。

## 10. Pi0.5 参考

- `Pi05VlaDeployNode._create_publishers`：结构复用 publisher handle 生命周期。
- `_control_tick`：仅参考 publish API，拒绝逐路边构造边发和 shadow command。
- `Pi05BridgeNode`/`CommandMuxNode`：订阅、deadman、mode state 均不复用。
- JSON status transport可参考 mux，但 status 改为逐 action 且语义更严格。

## 11. 验收覆盖

- constructor 恰好创建六 publisher，0 subscription，0 timer。
- dry/shadow/safe+授权矩阵 mock 调用数准确。
- 四路构造全部发生在第一次 command publish 之前。
- policy failure 时 command=0；第 n 路 command failure 返回 partial count/sent=false。
- deadband/min interval 每侧独立，失败不更新 cache。
- Pose frame/stamp/xyzw 与 gripper 0..100 正确。
- status 不伪造 driver/hardware success。
- 无 ROS import测试与 ROS shadow 测试分层。

## 12. 边界继承声明

本文件继承当前 L2-05 唯一 ROS 出口边界，不从旧 layer-based publish/hardware 卡片或 Pi0.5 bridge/mux 继承。ROS UI 只做外部消息适配与 publish，不能吞并调度、安全或硬件驱动。
