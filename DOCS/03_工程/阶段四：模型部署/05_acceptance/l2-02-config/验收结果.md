## 测试输入

- 合法部署配置：包含 observation topics、command topics、runtime mode、action_dim=16、state_dim=16 和 SafetyConfig。
- tactile 关闭或缺省的配置。
- 非法配置：缺 topic、mode 非法、维度仍为 14 或 26、SafetyConfig 缺关键阈值。

## 观察点

- pytest stdout 中 Config 层测试为 passed。
- 合法配置对象中 topic 名、维度、mode 和 SafetyConfig 字段值与 TO-BE Contract 一致。
- 非法配置测试必须显示预期异常，不得用默认值掩盖错误。
- 测试日志保存到 `logs/` 时，文件名建议使用 `YYYYMMDD_l2-02_config.log`。

## 通过现象

- `deploy.yaml` 或等价测试配置可以被完整加载。
- `action_dim` 和 `state_dim` 均为 16。
- 运行模式至少能区分 dry-run、shadow-run 和 safe/real-robot 相关模式边界。
- 旧 BridgeMux 语义不再作为当前命令配置的必需字段。
- 非法配置会在启动前失败，不会进入 ROS 节点或真机链路。

## 失败现象与排查入口

- 仍读取旧字段或 BridgeMux 字段：优先检查 config schema 和 deploy.yaml。
- 维度仍为旧值：优先检查 RuntimeConfig 默认值和 L2-01 常量引用。
- 非法配置没有失败：优先检查 `__post_init__` 或配置校验函数。
- 测试无法导入：优先检查测试路径和包路径。
