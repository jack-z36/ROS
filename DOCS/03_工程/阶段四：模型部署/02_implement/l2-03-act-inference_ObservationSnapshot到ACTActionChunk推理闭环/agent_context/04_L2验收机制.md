# L2-03 验收机制

## 1. Gate 目标

L2-03 Gate 要证明两件事同时成立：

1. 一次合法同步调用确实完成 `ObservationSnapshot -> ActionChunk`，且输出严格满足 `(chunk_size,16)`、`float32`、有限值和 16D 物理语义。
2. 实现没有把 L2-01 的资源加载、L2-02 的像素处理、L2-04 的安全、L2-05 的 ROS 输出或 L2-06 的运行调度带入本 L2。

本 Gate 的基础环境是 CPU + stub policy + stub normalizer；不需要 ROS、GPU、真实 bundle 或生产 fake-policy 分支。

## 3. Gate 场景

### 3.1 类型契约

| 场景 | 输入 | 通过现象 | 失败现象 |
|---|---|---|---|
| 合法 ActionChunk | `(N,16)` float32 finite array | 仅保存 actions 的 chunk 被构造 | 缺字段或多运行元数据字段 |
| 非二维输出 | `(16,)` 或 rank 3 array | 抛异常 | 静默接受 |
| 非 16D 输出 | `(N,15)` / `(N,17)` | 抛异常 | 仅检查 rank |
| 非 float32 | float64/int array | 拒绝或在明确转换点统一为 float32 后验证 | 向下游泄漏非 float32 |
| 非有限值 | 含 NaN/Inf | 抛异常 | 替换为零或 clamp |

### 3.2 阶段一：Observation 批次准备

| 标签 | 微元 | 关键输入 | 通过现象 |
|---|---|---|---|
| `service.batch.compatibility` | 模型输入兼容性检查 | 合法/缺相机/错 shape snapshot | 合法通过；缺失或不兼容明确失败 |
| `service.batch.tensorize_state` | State tensor 表达转换 | 16D physical ndarray | CPU float32 `(16,)` tensor；数值不改变 |
| `service.batch.normalize_state` | State 数值归一化 | recording normalizer | 只调用 state `normalize()` 一次，输出仍为 `(16,)` |
| `service.batch.bind_images` | Image tensor 绑定 | 多相机 sentinel 图像 | 按完整 policy key 精确绑定；不按 dict 顺序猜测 |
| `service.batch.add_dimension` | Batch 维度添加 | state/image single sample tensors | `(1,16)` 与 `(1,C,H,W)` |
| `service.batch.assemble` | ACT batch 组装 | 已批次化 state/images | 只含 `observation.state` 与必需 `observation.images.*` |
| `service.batch.device` | Device 对齐 | CPU policy fixture | 所有 tensor 位于 policy device；测试不硬编码 CUDA |

输入兼容性 Gate 不测试 ROS freshness，也不允许测试代码借此要求 L2-03 重新 resize、换色或缩放图像。

### 3.3 阶段二：ACT 前向推理

| 标签 | 微元 | 输入 | 通过现象 |
|---|---|---|---|
| `service.policy.predict_chunk` | ACT chunk API 调用 | recording stub policy + batch | 只调用一次 `predict_action_chunk(batch)` |
| `service.policy.no_select_action` | API 边界 | stub policy 的 `select_action` 设为失败 | 总入口仍通过，证明未调用 `select_action` |
| `service.policy.error_propagation` | 前向失败传播 | 抛异常的 stub policy | 原异常或带阶段上下文的异常返回调用方；不返回 None/旧 chunk |

### 3.4 阶段三：ActionChunk 后处理

| 标签 | 微元 | 输入 | 通过现象 |
|---|---|---|---|
| `service.output.raw_shape` | raw 输出结构检查 | `(1,N,16)`、`(N,16)`、`(2,N,16)`、`(1,N,14)`、`(1,N+1,16)` | 只有严格 `(1,chunk_size,16)` 通过 |
| `service.output.unbatch` | Batch 维移除 | 合法 raw tensor | 只移除已验证 B=1 维 |
| `service.output.unnormalize` | Action 反归一化 | recording action normalizer | 只调用一次 `unnormalize()`，输入是 `(N,16)` |
| `service.output.float32_cpu` | CPU float32 转换 | 合法 physical tensor | 得到 CPU numpy float32 `(N,16)` |
| `service.output.final_contract` | 最终输出契约检查 | NaN/Inf、错 dtype/shape | 失败不创建 ActionChunk |
| `service.output.no_repair` | 禁止修补 | 超范围 sentinel、过长/过短 raw | 值不被 clamp；维度错误不 crop/pad；段序不重排 |

### 3.5 三阶段闭环与边界

| 标签 | 场景 | 通过现象 |
|---|---|---|
| `service.full_chain` | 合法 snapshot + recording normalizer + deterministic stub policy | 返回只含 actions 的 `ActionChunk`；两个 normalizer 各调用一次 |
| `service.error_stops_chain` | 阶段一/二/三分别失败 | 后续阶段不执行；无部分输出 |
| `boundary.no_resource_io` | 静态扫描 service/types | 无 bundle/checkpoint/path/json/yaml loader 调用 |
| `boundary.no_runtime_state` | 静态扫描 service/types | 无 Thread/queue/timer/request/cursor/metrics/fallback |
| `boundary.no_ros_or_hardware` | 静态扫描 service/types | 无 ROS import、publisher/subscriber、SDK/Modbus/serial |
| `boundary.no_safety_or_smoothing` | 静态扫描 service/types | 无 clamp、delta/IK/collision、安全检查、blend/smooth/RTC |
| `boundary.only_allowed_layers` | 文件列表检查 | L2-03 新增实现只在 `types/`、`service/`、tests |

后续 L3 可以创建 `src/model_deploy/act/scripts/l2_03_verify.sh`。脚本本身不是本设计包中的实现产物，但必须按下列规范输出。

### 4.1 命令骨架

```bash

```

脚本应顺序运行类型、service、集成和静态边界测试，并用统一格式汇总。建议对应 pytest 命令：

```bash

  src/model_deploy/act/tests/types/test_action_chunk.py \

```

### 4.3 标签到微元映射

| 标签 | 层 | 完整定位链 | PASS 含义 |
|---|---|---|---|
| `types.action_chunk_contract` | types | `types/action_chunk.py -> ActionChunk -> 数据/actions` | 只存在合法 actions 值对象 |
| `service.batch.tensorize_state` | service | `service/observation_batch.py -> 无 class -> State tensor 表达转换（计算函数）` | physical ndarray 正确变为 CPU float32 tensor |
| `service.batch.normalize_state` | service | `service/observation_batch.py -> 无 class -> State 数值归一化（计算函数）` | 正确 normalizer 恰好调用一次 |
| `service.batch.bind_images` | service | `service/observation_batch.py -> 无 class -> Image tensor 绑定（计算函数）` | 相机 key 与 policy feature 精确对应 |
| `service.policy.predict_chunk` | service | `service/act_inference.py -> ActInferenceService -> ACT 前向推理（计算函数）` | 只调用 `policy.predict_action_chunk` |
| `service.output.unnormalize` | service | `service/action_chunk_postprocess.py -> 无 class -> Action 反归一化（计算函数）` | action normalizer 恰好调用一次 |
| `service.output.no_repair` | service | `service/action_chunk_postprocess.py -> 无 class -> Raw/最终输出检查（计算函数）` | 未发生 clamp/crop/pad/reorder |
| `service.full_chain` | service | `service/act_inference.py -> ActInferenceService -> 总编排入口（编排函数）` | 三阶段完整闭环 |
| `boundary.reuse_only` | boundary | `config/repo/runtime/ui -> 无 class -> 无新增产物（边界）` | 层职责未越界 |
| `boundary.no_runtime_state` | boundary | `service/ -> ActInferenceService -> 禁止运行状态（边界）` | 无线程、queue、cursor、metrics、fallback |
| `boundary.no_ros_or_hardware` | boundary | `types/service -> 无 class -> 无数据读写微元（边界）` | 无 ROS/硬件读写 |

### 4.4 退出码与 BLOCKED

- 任一必须项 FAIL：退出码 `1`。
- 所有必须项 PASS：退出码 `0`。
- 真实 policy 的补充 dry-run 不是本地 Gate 必须项；无真实 L2-01 资源时标 `BLOCKED`，不影响本地 Gate。
- `BLOCKED` 只能表示外部环境缺失，不能掩盖 stub policy、normalizer、shape 或边界测试失败。

## 5. 可选真实 policy 补验

真实 policy 已由 L2-01 加载并注入时，可额外运行一次不连接 ROS/硬件的 dry-run：

```text
已加载 real ACT policy + 真实图像/normalizer 契约
-> L2-03 同步调用
-> 仅观察 ActionChunk 契约或明确异常
```

此项验证真实模型兼容性，不改变 L2-03 的边界：

- 不从 L2-03 读取 bundle。
- 不在 L2-03 选择 real/fake policy。
- 不因为缺 GPU/bundle 把 stub Gate 标为失败。
- 不得据此声称机械臂已经安全执行；安全和 publish 仍需后续 L2。

## 6. 放行条件

满足以下条件才允许 L2-06 集成该 service：

- 三个一级阶段和总入口的单测全部 PASS。
- strict raw/final shape 测试 PASS。
- 两个 normalizer 的调用方向与调用次数测试 PASS。
- `select_action` 未被调用。
- `ActionChunk` 无运行元数据。
- 静态边界测试 PASS。

不允许合入：资源加载、fake-policy 生产分支、thread/queue/cursor/metrics、safety/clamp/smoothing 或 ROS/hardware 代码。
