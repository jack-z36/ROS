# 阶段二场景一：提取夹爪开合以及位姿转换

## 一句话总结

从 raw MCAP 生成 cleaned MCAP，补齐夹爪宽度语义，并把左右 Baton Mini raw pose 转换为机械臂基坐标系下的 TCP pose（arm-base），raw pose 保留为附加大字段，为后续可靠性验证提供具备基础训练语义的数据。

## 核心目标

本场景负责阶段二的第一步：把阶段一采集得到的 raw MCAP，从“硬件原始 topic 日志”推进为可继续处理的 cleaned MCAP。

cleaned MCAP 至少应具备三类能力：

- 保留原始图像、位姿、触觉等多模态数据。
- 补齐左右夹爪宽度语义。
- 将左右 Baton Mini 每帧动态 raw camera pose 结合 `camera_from_tcp.translation_mm` 和 `work_frames.position_mm / rotation_euler_rad`，转换为左右机械臂基坐标系下的 TCP pose（arm-base），raw pose 保留为附加大字段。

主位姿 topic 固定为 `/left_arm_base_tcp_pose`、`/right_arm_base_tcp_pose`（frame_id = `left_arm_base` / `right_arm_base`），由动态 TCP 中间位姿经 `Algo.rm_algo_workframe2base` 转换得到。Baton Mini raw pose 的位置单位为 `m`；人工配置的相机 TCP 平移和 work frame 平移单位为 `mm`，进入 Runtime 后统一换算为 `m`。raw pose 保留为附加大字段，不替换原始 topic 内容。

## 软件能力产出

本场景应形成以下中粒度软件能力：

- raw MCAP 批处理入口：用户可以对一批 raw MCAP 发起清洗。
- 配置加载能力：读取输入输出位置、目标 topic、夹爪标定参数和左右位姿转换参数。
- 夹爪宽度提取能力：从视觉标定或图像信息中生成左右夹爪宽度语义。
- arm-base 位姿转换能力：将左右 TCP in camera 位姿转换为机械臂基坐标系下的 TCP pose。
- 标定能力：支持生成或更新夹爪宽度和 arm-base 转换相关参数。
- 基础校验能力：检查输入 topic、输出文件、配置完整性和失败原因。

已经形成的具体脚本、模块和配置文件名，以本场景 `输出程序与文件.md` 和包内架构文档为准；本目标描述不再约束后续代码拆分方式。

## 自动化处理目标

用户运行本场景入口后，理想情况下应自动完成：

1. 扫描 raw MCAP 输入。
2. 校验必需 topic 和配置。
3. 提取或写入左右夹爪宽度语义。
4. 转换左右 TCP in camera 位姿为 arm-base TCP pose。
5. 写出 cleaned MCAP。
6. 记录清洗结果、失败原因和配置来源。

## 数据输出

| 输出 | 用途 |
| --- | --- |
| cleaned MCAP | 场景二的输入。 |
| 清洗报告 | 人工复查和后续问题定位。 |
| 标定结果/位姿转换参数 | 后续批量清洗复用。 |

## 成功标准

- 用户能批量处理 raw MCAP。
- cleaned MCAP 中能定位图像、触觉、夹爪宽度和左右 arm-base TCP pose。
- 左右位姿转换参数分别维护，不能误用同一套参数。
- 清洗失败时有明确失败原因。
- 本场景输出能被场景二作为可靠性验证输入。

## 与上下游关系

上游是阶段一通过 Octopus 录制得到的 raw MCAP。下游是场景二硬件数据可靠性验证。

本场景只补齐基础语义和统一位姿表达，不负责滤波、异常值修复、IK、MuJoCo 验证或多 topic 时间对齐。
