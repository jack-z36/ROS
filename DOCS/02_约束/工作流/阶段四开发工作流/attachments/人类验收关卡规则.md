# 人类验收关卡规则

## 1. 适用范围

- 阶段：阶段四：模型部署
- 适用对象：每个 L2 功能模块完成 L2 Gate 后、合入 `model_deploy` 前的人类确认环节
- 不适用对象：单个 L3 的局部验收、纯文档讨论、知识查询

## 2. 核心规则

每个 L2 必须先通过 AI 侧 L2 Gate，再由人类亲自运行验收清单并签字。没有人类签字，不允许合入 `model_deploy`。

```text
L3 完成
-> L2 Gate
-> 人类验收清单
-> 人类签字
-> Git 合入 model_deploy
```

## 3. 人类验收清单

每个 L2 必须生成：

```text
DOCS/03_工程/阶段四：模型部署/05_acceptance/<l2>/人类验收清单.md
```

清单必含：

| 字段       | 要求                                               |
| ---------- | -------------------------------------------------- |
| 验收项编号 | 可逐项勾选。                                       |
| 运行目录   | 明确 cwd。                                         |
| 运行命令   | 可复制执行。                                       |
| 测试输入   | mock 数据、配置、bundle、topic 或硬件条件。        |
| 观察点     | stdout、日志、topic、metrics、生成文件或人工现象。 |
| 通过现象   | 明确到 shape、字段、状态、topic、动作现象。        |
| 失败现象   | 写明常见失败和排查入口。                           |
| 验收性质   | `机械` 或 `人工`。                             |

## 4. 签字位置

人类验收结论写入：

```text
DOCS/03_工程/阶段四：模型部署/05_acceptance/<l2>/验收结果.md
```

签字格式：（注意：不要是代码块）

```markdown
## 人类验收

- 验收人：<用户名>
- 验收日期：YYYY-MM-DD
- 验收结论：[ ] 已通过  [ ] 不通过
- 逐项结果：
  - 验收项 1：<命令> -> <通过现象> -> [ ] 通过
  - 验收项 2：<命令> -> <通过现象> -> [ ] 通过
- 备注：
```

缺少验收人、日期或通过勾选时，视为未通过。

## 5. 真机验收边界

涉及真机的验收项必须是人工验收，且必须满足：

- 用户明确授权。
- 急停可用。
- 人在现场。
- 动作幅度保守。
- shadow-run 已通过。
- failure/status topic 可观察。

无硬件环境下，真机验收只能记录为 `hardware-blocked`，不得写成通过。

## 6. 与 Git 合入关系

AI 执行阶段四 Git 合入前必须检查：

```text
L2 Gate 通过
验收结果.md 存在
人类验收段存在
验收结论勾选已通过
验收人和日期存在
真机风险记录完整
```

不满足任一条件，停止合入并报告用户。
