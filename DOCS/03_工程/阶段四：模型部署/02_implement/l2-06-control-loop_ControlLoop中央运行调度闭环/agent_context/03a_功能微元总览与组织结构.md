# L2-06 功能微元总览与组织结构

本文件是 L2-06 A/B/C 编号、总量、父子关系、运行时调用树和上游复用对象的唯一权威。实现、L3、验证和 HTML 蓝图只要引用微元编号，都必须先读本文件；其他文件不得自行增删或重编号。

## 1. 编号与总量

| 层级 | 总量 | 编号 | 含义 |
|---|---:|---|---|
| A（3.25 class） | 5 | A1-A5 | 跨调用状态、线程或 ROS 生命周期的打包单元 |
| B（3.375 编排） | 12 | B1-B12 | worker、tick、fallback、publish、startup preflight、process 与生命周期的有序协作 |
| C（3.5 原子） | 26 | C1-C26 | 数据、纯计算、状态更新和外部读写原子 |

## 2. 唯一编号总表

| ID | 名称 | 类型 | 父级 | 责任 |
|---|---|---|---|---|
| A1 | `LatestQueue[T]` | 3.25 class | — | 打包 bounded deque、Condition、closed 与 latest-only 并发不变量 |
| A2 | `RuntimeMetrics` | 3.25 class | — | 打包 worker/loop 线程安全指标和 immutable snapshot |
| A3 | `InferenceWorker` | 3.25 class | — | 一个 policy/service 的单线程同步调用和 stop 生命周期 |
| A4 | `ControlLoop` | 3.25 class | — | 唯一拥有 active/pending/cursor/in-flight/discard/previous/fallback/fault，并核验 startup switch/result echo 的中央状态机 |
| A5 | `ActDeployNode` | 3.25 class | — | ROS composition root、timer、permit/clock、metrics 与 shutdown |
| B1 | `InferenceWorker.run` | 编排函数 | A3 | 阻塞取 request、stop-aware 限频、执行 B2、写 result |
| B2 | `InferenceWorker._execute_request` | 编排函数 | A3 | 调 L2-03；成功或异常都形成 C2 |
| B3 | `ControlLoop.tick` | 编排函数 | A4 | 一拍总顺序：收结果、激活、提交、选 action、安全、发布、归约 |
| B4 | `ControlLoop._collect_latest_result` | 编排函数 | A4 | 非阻塞收 C2、终结匹配 request、校验并放 pending或返回 tick-local reason |
| B5 | `ControlLoop._maybe_submit_inference` | 编排函数 | A4 | 根据 fresh observation、prefetch 与 in-flight 创建 C1 |
| B6 | `ControlLoop._choose_candidate` | 编排函数 | A4 | 只在 normal execute horizon 内选择候选；不读取 fallback policy |
| B7 | `ControlLoop._safety_and_publish` | 编排函数 | A4 | 真实调用 L2-04，构造 L2-05 request，调用 publish port |
| B8 | `ControlLoop._apply_fallback` | 编排函数 | A4 | 唯一解释 fallback policy，返回 hold/continue candidate 或逐 tick status-only |
| B9 | `ActDeployNode._control_tick` | 编排函数 | A5 | 每拍读取双时钟与 CommandPermit，再调用 B3 |
| B10 | `ActDeployNode._shutdown_runtime` | 编排函数 | A5 | 与 tick 串行地 stopping/cancel、stop/close/join，并区分 STOPPED/SHUTDOWN_TIMEOUT |

| B12 | `run_startup_preflight` | 编排函数 | A5/UI module | 对 canonical resources、L2-02/03 合同、queue 与 permit topology 做无 I/O 原子放行；失败抛稳定 code |
| C1 | `InferenceRequest` | 数据 | A3/A4 | request id、ObservationSnapshot、submit monotonic time、trigger cursor |
| C2 | `InferenceResult` | 数据 | A3/A4 | request id、四类时间、ActionChunk XOR error |
| C3 | `FallbackReason` | 数据 | A4 | 稳定运行失败枚举，供 metrics/Gate 使用 |
| C4 | `RuntimeMetricsSnapshot` | 数据 | A2/A5 | frozen counters/gauges/last + deferred reason/outcome/status |
| C5 | queue state | 数据 | A1 | deque、Condition、closed、maxsize=1 |
| C6 | metrics state | 数据 | A2 | guarded mutable counters、latency、last/deferred fallback、last error/outcome |
| C7 | ControlLoop state | 数据 | A4 | active/pending/cursor/in-flight/discard-in-flight/ids/last tick time/previous+source time/deferred fallback/output/runtime fault/stopping/tick sequence |
| C8 | `LatestQueue.put_latest` | 内部状态更新函数 | A1 | 满时淘汰旧项、追加最新项并唤醒 waiter |
| C9 | `LatestQueue.take_latest` | 内部状态更新函数 | A1 | 取最新、清旧；worker 可阻塞，tick 非阻塞 |
| C10 | `LatestQueue.close` | 内部状态更新函数 | A1 | 清待处理项并返回清除数，closed=True，唤醒 waiter，禁止后续 put |
| C11 | `RuntimeMetrics.record_event` | 内部状态更新函数 | A2 | 在 lock 下累计/替换指标字段 |

| C15 | `ControlLoop._activate_pending` | 内部状态更新函数 | A4 | 以当前时间复验 pending；合法则 pending→active/cursor=0，否则返回 expired reason |

## 3. 运行时调用树

```text
UI/B11 main
├─ C21 build_arg_parser / parse CLI
├─ 调 L2-01 config/resource public functions
├─ 构造 L2-03 service（消费 canonical PolicyInputSpec）
└─ 创建 A5 ActDeployNode

A5 construction
├─ 创建 L2-02 pipeline（消费同一 PolicyInputSpec）
├─ 创建 L2-04 SafetyGuard
├─ 创建 A1 request_queue / result_queue
├─ 创建 A2 RuntimeMetrics
├─ 创建尚未 start 的 A3 InferenceWorker
├─ B12 run_startup_preflight
├─ 创建 L2-05 ActionPublisher / metrics publisher
├─ 创建 A4 ControlLoop
├─ start A3
├─ 最后创建 control/metrics timers
└─ 任一失败：B10 回收 + A5 自销毁半构造 ROS Node

A3 InferenceWorker
└─ B1 run
   ├─ C9 take_latest(blocking)
   ├─ B2 _execute_request
   │  ├─ L2-03 ActInferenceService.predict_action_chunk
   │  └─ C2 InferenceResult(success OR error)
   ├─ C8 result_queue.put_latest
   └─ C11 metrics.record_event

A5 ActDeployNode timer
└─ B9 _control_tick
   ├─ worker/clock invariant -> C25 latch_runtime_fault + return
   ├─ 读取 ros_time_s / monotonic_s
   ├─ 读取 CommandPermitSource
   └─ A4/B3 ControlLoop.tick
      ├─ B4 _collect_latest_result
      │  ├─ C9 result_queue.take_latest(non-blocking)
      │  └─ C13 validate_inference_result / terminal id 归约
      ├─ C15 _activate_pending（active 缺失或到 horizon）
      ├─ C14 should_submit_inference
      ├─ B5 _maybe_submit_inference
      │  └─ C8 request_queue.put_latest(C1)
      ├─ B6 _choose_candidate（normal only）
      │  ├─ candidate：C17 + C26，limit=execute_horizon
      │  └─ reason：B8 _apply_fallback
      │     ├─ hold candidate：previous-safe + original source time → C26
      │     ├─ continue candidate：C17 + active capture time → C26，limit=chunk_size
      │     └─ safe-stop/status-only：None
      └─ B7 _safety_and_publish（B6/B8 返回 candidate 时）
         ├─ C24 _next_action_id
         ├─ L2-04 SafetyGuard.filter_action
         ├─ C18 build_action_publish_request
         ├─ L2-05 ActionPublisher.publish
         └─ C19 _apply_publish_outcome
      [observation/safety/queue/id invariant] -> C25 latch_runtime_fault

A5 metrics timer
└─ C12 RuntimeMetrics.snapshot
   └─ C20 _publish_runtime_metrics -> /act/metrics

A5 shutdown
└─ B10 _shutdown_runtime
   ├─ lifecycle/tick lock 内 C23 begin_stopping + cancel timers
   ├─ C22 worker.stop event
   ├─ C10 request_queue.close/clear/wake
   ├─ bounded join
   └─ C10 result_queue.close + STOPPED 或 SHUTDOWN_TIMEOUT
```

## 4. 总体协作轨迹

```text
L2-02 ObservationSnapshot
  -> C1 InferenceRequest
  -> A3 worker
  -> L2-03 synchronous predict_action_chunk
  -> C2 InferenceResult(ActionChunk | error)
  -> A4 active/pending/cursor
  -> raw action (16,)
  -> L2-04 SafetyResult
  -> L2-05 ActionPublishRequest/ActionPublishResult
  -> C19 runtime state reducer
  -> C4 /act/metrics
```

失败轨迹：

```text
startup contract FAIL
  -> 不启动 worker/timer

policy Exception
  -> C2 error result
  -> 终结匹配 in-flight、推进 last-completed
  -> active 仍合法/未到 horizon：B6 normal
  -> 无 normal candidate：B8 fallback/status-only

SafetyResult.REJECTED
  -> L2-05 rejected status（同 tick 不再发第二动作）
  -> chunk 失效
  -> C19 保存一次性 SAFETY_REJECTED
  -> 下一个无 normal candidate 的 fresh tick 交 B8

ActionPublishResult.PARTIAL/FAILED
  -> C16 清状态
  -> output fault latch
  -> 后续 tick 禁止 command
```

## 5. 上游复用对象（不新编号）

| 来源 | 复用对象 / port | 精确用途 | 禁止误写 |
|---|---|---|---|
| L2-01 | `DeployConfig.runtime`、`command_output`、topics | scheduling、gate 静态开关、metrics topic | 不在 tick 解析 YAML；不把 `mode` 当 CommandPermit |
| L2-01/repo | 已加载 policy、state/action normalizer、启动 contract results | 创建 L2-03 service 前注入 | 当前 public loader 缺失是前置 FAIL，不归 A3/A4 文件读取 |
| L2-02 | `ObservationSnapshot` | C1 payload、安全 fallback reference | 不修改/转置 images，不添加 runtime metadata |
| L2-02 | `ObservationBuffer.latest_observation(max_age_s)` | 绑定 observation provider；A4 用 tick time 二次检查 type/age/clock skew | 不复制 latest observation slot；小幅并发 future capture 延后到下一 tick |
| L2-03 | `ActInferenceService.predict_action_chunk` | A3 唯一 policy 调用 | 不把 worker/queue/metrics 归 L2-03 |
| L2-03 | `ActionChunk` | C2 success payload | 只读 actions，不添加 id/time/cursor |
| L2-04 | `SafetyGuard`、`SafetyResult`、`SafetyStatus` | B7 safety call/result | 不读 `.accepted`，不调用 `.filter()` |
| L2-05 | `CommandPermit` | B9 每 tick 注入 B3 | 原始 gate/deadman/E-stop 不直接塞给 L2-05 |
| L2-05 | `ActionPublishRequest/Result`、`PublishOutcome` | B7/C18/C19 | 核验 id/safety/switch/permit/outcome/provenance；不调用不存在的 publish_safe/emit_fallback |
| 外部 driver/UI port | `CommandPermitSource` | B9 读取最终许可 | 无 provider 时默认 deny；真机 BLOCKED |
| 外部 driver port | 可选 hardware safe-stop | 主动 stop（若项目确认需要） | 当前不存在时只能 status-only，不能声称物理 stop |

## 6. 六层落点摘要

| layer | 状态 | 目标 |
|---|---|---|
| types | 无新增 | 复用 L2-02～05 公共业务类型；L2-06 内部记录不升级为跨 L2 language |
| config | 无新增 | 复用 L2-01；上游缺失字段/loader 修复是启动前置 |
| repo | 无新增 | 资源加载由 L2-01 repo/startup factory 提供，L2-06 只消费 RAM |
| service | 无新增 | 只调用 L2-03/04 与 L2-05 publish port |
| runtime | 有产物 | A1-A4、B1-B8、C1-C19、C22-C26 |
| ui | 有产物 | A5、B9-B12、C20-C21 |

## 7. 版本冻结声明

- 第一版不新增 action smoothing、blend、aligned cursor、RTC 或跨 chunk 融合。
- `InferenceRequest/Result/RuntimeMetrics` 均由 L2-06 拥有；任何文档再次把它们归给 L2-03 都是污染。
- 任何实现若绕过真实 L2-04/L2-05 public API，Gate 直接 FAIL。
- 本表如需增删编号，必须同时更新 `03_ACT微元设计与协作.md`、`04_L2验收机制.md`、六层文件和 HTML 投影，并重新获得用户确认。
