# L2 能力模块说明：夹爪宽度提取

## 1. 能力名称

```text
夹爪宽度提取
```

## 2. 所属位置

阶段：阶段二：数据清洗
L1：service_s1
场景：场景一：提取夹爪开合以及位姿转换
模块类别：数据计算类
来源功能模块清单：`DOCS/阶段二：数据清洗/02_service/场景一/功能模块清单.md`

## 3. 一句话目标

```text
从左右 GoPro 图像中检测 ArUco marker，生成 cleaned MCAP 中的左右 GripperWidthSample。
```

## 4. 能力角色

本能力负责把 raw MCAP 中缺失的夹爪宽度语义补齐为 [[GripperWidthSample]]，使场景二和后续 canonical dataset 能读取夹爪开合信息。其标定输入必须来自 [[GripperCalibrationConfig]]，不得把浏览器配置生成逻辑混入 MCAP 清洗主流程。

## 5. 上游关系

- raw MCAP 必须包含左右 GoPro image topic。
- [[Scene1Config]] 必须提供 [[GripperCalibrationConfig]] 归一后的 ArUco 字典、marker id、marker 像素范围和 `gripper_max`。

## 6. 下游关系

- [[CleanedMcap]] 中新增的 gripper topic 被场景二异常检测和后续 observation/action 构建依赖。
- [[Scene1CleanReport]] 应记录图像帧数、直接检测帧数、缺失帧和插值帧。

## 7. 上游接口对齐检查

| 上游功能 | 上游接口 / 产物 | 本能力如何依赖 | 对齐状态 | 处理方式 |
|---|---|---|---|---|
| raw MCAP | `/gopro_left/image_raw`、`/gopro_right/image_raw` | 读取图像并逐帧生成 gripper width | 已对齐 | 复用现有配置 |
| [[GripperCalibrationConfig]] | `gripper_streams` | 提供 marker 和输出 topic 配置 | 待正式化 | service_s1_002 |
| [[CleanedMcap]] | gripper output topic | 写出 `std_msgs/msg/Float32` | 已对齐 | 保持现有写出方式 |

## 8. 职责边界

本能力负责：

1. 从图像生成归一化 [[GripperWidthSample]]。
2. 对缺失 marker 帧做现有插值补齐，并记录统计。

本能力不负责：

1. 判断夹爪数据是否物理可靠。
2. 生成 mask 或 invalid reason。
3. 输出物理单位宽度替代归一化值。

## 9. 计算职责

| 计算项 | 输入 | 输出 | 影响下游 |
|---|---|---|---|
| marker 检测 | image frame、marker id | 直接检测距离 | 决定 gripper 原始样本 |
| 单 marker 估计 | 单个 marker center、图像中心线 | 估计距离 | 降低单帧检测缺失 |
| 宽度映射 | marker 像素距离、`marker_min/max`、`gripper_max` | 归一化 [[GripperWidthSample]] | 场景二读取夹爪宽度 |
| 缺失帧插值 | 已检测样本序列 | 每帧 gripper width | 保证 gripper 消息数等于图像帧数 |

## 10. 计算规则

| 规则 | 触发条件 | 计算 / 判断方式 | 结果表达 |
|---|---|---|---|
| 双 marker 直接计算 | 两个 marker 都检测到 | 两中心点欧氏距离 | direct marker sample |
| 单 marker 估计 | 只检测到一个 marker | marker 到图像中心线水平距离乘 2 | single marker estimate |
| 无 marker 缺失 | 未检测到目标 marker | 该帧先留空，最终插值 | interpolated sample |
| 全流无有效 marker | 整条 image stream 无有效样本 | gripper stream 失败 | failure_reason |

## 11. 输出结果结构

| 字段 | 类型 | 含义 | 有效性要求 | 下游使用方式 |
|---|---|---|---|---|
| `value` | float | 归一化夹爪宽度 | `[0, 1]` | 场景二异常检测 |
| `output_topic` | string | gripper width topic | 不与输入 topic 冲突 | 场景二 topic 消费 |
| `frame_count` | integer | 图像帧数 | `> 0` | 报告统计 |
| `interpolated_frames` | integer | 插值帧数 | `>= 0` | 报告统计和质量判断 |

## 12. 异常与边界输入

| 边界情况 | 预期结果 | reason / error 表达 | 是否阻塞下游 |
|---|---|---|---|
| image topic 缺失 | 清洗失败 | missing configured image topic | 是 |
| image schema 不支持 | 清洗失败 | unsupported image message type/encoding | 是 |
| 全流无 marker | 清洗失败 | could not detect any valid markers | 是 |
| 部分帧无 marker | 插值补齐 | interpolated_frames 统计 | 否，但应进入报告 |

## 13. 可验证样例

| 样例 | 输入特征 | 预期输出 | 验证方式 |
|---|---|---|---|
| 合法输入 | 图像中有目标 marker | gripper 消息数等于图像帧数 | 最小 MCAP 契约测试 |
| 缺失输入 | 缺少 GoPro image topic | 清洗失败 | validator 测试 |
| 边界输入 | 部分帧缺 marker | 插值帧数进入报告 | gripper accumulator 单元测试 |

## 14. 整体完成标准

- [ ] gripper 输出 topic 和值域在 [[CleanedMcap]] 中明确。
- [ ] [[Scene1CleanReport]] 能承载检测/插值统计。
- [ ] 后续 L3 验收覆盖 gripper 数量等于图像帧数。

## 17. 给 L3 任务生成的约束

1. 不得改变 `std_msgs/msg/Float32` 输出类型。
2. 不得把归一化值改成物理宽度，除非同步更新 [[GripperWidthSample]]。

## 18. 开发者功能检验契约

本能力在 `./start_data_clean.sh --dev -> 场景一` 下对应的功能检验项：

```text
scene1_gripper_width_extract
```

检验目标：

- 读取生产配置或本次临时 [[GripperCalibrationConfig]]。
- 使用小样本 GoPro 图像或 MCAP image stream 生成左右 gripper width。
- 输出每帧归一化 [[GripperWidthSample]] 和检测/插值统计。

测试产物：

- [[Scene1DevArtifact]]：`artifacts/gripper_width_samples.json`
- [[Scene1DevArtifact]]：`artifacts/gripper_width_stats.json`
- 可选 [[Scene1DevArtifact]]：`artifacts/debug_gripper_width.mcap`
- [[Scene1DevRunLog]]：`logs/run_log.json`

临时覆盖：

- 允许覆盖小样本输入、输出目录、marker 参数。
- 默认不写回正式配置。

输出隔离：

- 调试 MCAP 和统计文件只写入本次 [[Scene1DevRun]]。
