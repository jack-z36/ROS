# L3 任务文件身份校验约束

本文约束 Ubuntu L3 执行端在执行微元任务前，必须确认实际读取的任务文件与用户指定的任务文件是同一个文件，避免误执行同目录下相邻任务。

## 一、适用范围

只要用户要求执行某个 L3 微元任务文件，例如：

```text
DOCS/03_工程/阶段二：数据清洗/03_tasks/task/active/runtime-g7/runtime_mvp_021_fake_service_result_generator.md
```

执行 Agent 必须先按本文完成身份校验，再读取其他上下文、修改代码或运行测试。

## 二、必须校验的四个信息

执行前必须同时确认：

1. 用户输入的 L3 路径。
2. 实际读取成功的 L3 文件路径。
3. 文件名中的 L3 编号和任务短名。
4. 文件正文中的标题、`L3 编号` 和任务定位信息。

用户输入路径和文件正文中的 `当前任务文件路径` 都必须使用相对仓库根目录路径，不得使用 Windows 盘符路径、Linux 绝对路径或开发者本机工作区路径。

四项必须指向同一个任务。示例：用户要求执行 `runtime_mvp_021_...md` 时，实际读取文件、文件名编号和正文 `L3 编号` 都必须是 `021`，不得读取或执行 `020`、`022` 或同目录其他任务。

## 三、执行前固定动作

执行 Agent 必须按顺序执行：

1. 原样记录用户给出的任务路径，不得先自行改写成同目录其他路径。
2. 只打开用户给出的任务路径。
3. 如果该路径读取失败，立即停止，不得在同目录搜索替代任务。
4. 读取成功后，从实际文件路径提取文件名编号，例如 `runtime_mvp_021`。
5. 从文件正文读取标题和“任务定位”中的 `L3 编号`。
6. 对比用户路径、实际路径、文件名编号和正文编号。
7. 校验通过后，才能继续读取该 L3 文件列出的其他上下文并执行任务。

## 四、失败时必须停止

出现以下任一情况，必须停止执行并汇报问题：

- 用户给出的路径不存在或无法读取。
- 实际读取的路径与用户给出的路径不同。
- 文件名编号与用户指定路径中的编号不同。
- 文件正文标题或 `L3 编号` 与文件名编号不一致。
- 用户只给出模糊任务名，无法唯一定位一个 L3 文件。

停止时只汇报：

1. 用户给出的路径。
2. 实际尝试读取的路径。
3. 失败原因。
4. 需要用户重新提供的精确 L3 文件路径。

不得自行选择同目录下“看起来相关”的其他 L3 文件继续执行。

## 五、执行摘要要求

L3 完成后，当前 L3 文件末尾的执行摘要必须包含“任务文件身份校验”小节，写明：

```text
用户指定路径：
实际读取路径：
文件名编号：
正文 L3 编号：
校验结论：通过 / 未通过
```

只有校验结论为“通过”时，才允许继续执行、勾选成功标准并归档到 `task/completed/<L1归档目录>/<功能组>/`。
