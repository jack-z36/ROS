# 阶段二场景一：背景信息

## 场景定位

raw MCAP 是阶段一采集链路的原始产物，主要保存硬件 topic 日志。它包含图像、Baton Mini odometry、触觉等数据，但还没有完全具备后续训练数据所需的语义表达。

本场景存在的原因是：在进入滤波、异常值处理、IK 验证和时间对齐之前，必须先把 raw MCAP 转换为 cleaned MCAP，使数据具备统一的基础语义。

## 输入数据形态

raw MCAP 中主要包含：

- 左右图像数据。
- 左右 Baton Mini 原始位姿数据。
- 左右触觉数据。

这些数据仍处在 topic 世界中，不直接区分 observation、action、episode 或 step。

## 关键语义补齐

### 夹爪宽度

当前硬件采集链路中，夹爪宽度不是直接由独立传感器写入 MCAP 的训练字段。需要通过视觉标定或图像信息，生成左右夹爪宽度语义。

该语义后续会进入 observation，并在 action 或 mask 生成时作为重要字段参与判断。

### arm-base TCP 位姿

左右 Baton Mini 的 raw pose 分别处在各自局部坐标系中。为了让后续双臂数据能在同一空间下理解，必须将左右 raw pose 转换为机械臂基坐标系下一致的 TCP pose。

数据链路：

```text
raw pose → TCP in camera（固定外参叠加）→ arm-base TCP pose（Algo.rm_algo_workframe2base）
```

本场景输出 arm-base TCP pose 作为主位姿字段（`arm_base_tcp_pose`），frame_id = `<hand>_arm_base_link`。raw pose 保留为附加大字段，不替换原始 topic 内容。

## 软件能力边界

本场景需要形成 raw MCAP 清洗、夹爪宽度提取、arm-base 位姿转换、标定和基础校验等能力。

具体脚本、模块、配置文件和代码路径属于实现细节，应记录在本场景 `输出程序与文件.md` 和包内架构文档中。背景信息只描述为什么需要这些能力，以及它们在阶段二数据流中的位置。

## 输出数据形态

cleaned MCAP 应保留原始多模态数据，并补齐后续场景依赖的基础语义字段：

- 图像字段。
- 触觉字段。
- 左右夹爪宽度。
- 左右 arm-base TCP pose。

同时应产生清洗报告和标定/转换参数，使后续处理能够复现 cleaned MCAP 的生成过程。

## 与后续场景的关系

场景二会基于 cleaned MCAP 做滤波、异常值检测、补全、IK 和仿真验证。因此场景一输出不要求数据已经平滑或物理可执行，但必须保证基础字段可读、左右空间表达清楚、失败原因可追溯。

## 风险与未知

- 夹爪宽度提取依赖视觉标定质量，真实硬件条件会影响稳定性。
- arm-base TCP pose 的 frame_id 需要与 hand 一致（left_arm_base / right_arm_base），否则左右空间关系会失真。
- Baton Mini 可能存在漂移，场景一只负责转换表达，不负责判断长期可靠性。
- TCP 外参尚未在本场景固化，后续涉及机器人执行时需要继续明确。
