# 坐标系、单位与时间域

## 坐标系

阶段二当前生产语义以左右 arm-base TCP pose 为主：

- 左手 TCP pose 属于 `left_arm_base`。
- 右手 TCP pose 属于 `right_arm_base`。

左右 arm-base 是两个不同物理坐标系。除非有明确转换关系，否则不得把左右轨迹当成同一世界坐标直接叠加解释。

## 位姿链路

需要区分这些位姿语义：

- Baton Mini raw pose：采集侧原始位姿。
- TCP in camera：由每帧动态 pose 与固定 TCP 外参组合得到的中间位姿。
- arm-base TCP pose：阶段二生产主位姿语义。
- common_frame：历史兼容语义，不作为当前生产主链路。

## 单位

阶段二必须区分人工配置单位和 Runtime 计算单位：

- Web 人工输入的 `camera_from_tcp.translation_mm` 使用 `mm`。
- Web 人工输入的 `work_frames.position_mm` 使用 `mm`。
- `work_frames.rotation_euler_rad` 使用 `rad`。
- Runtime 进入计算后位置统一为 `m`。
- cleaned MCAP、MCAP_A、aligned MCAP 和 LeRobotDataset v3 中的 TCP position 使用 `m`。

## 时间域

处理 MCAP 时需要区分：

- `header.stamp`：消息内部采样时间。
- `publish_time`：MCAP 消息发布或写入时间。
- `log_time`：日志记录时间，常作为兜底。

当前宏观原则是：图像和触觉优先使用传感器消息时间；位姿在设备时钟不同步时更依赖 publish_time；缺失时再回退 log_time。
