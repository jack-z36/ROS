# 预处理后数据详解

## 总览

预处理阶段将原始传感器数据转换为模型可消费的格式，输出 **3 路图像 tensor + 1 个归一化后的 26D 状态向量**。

---

## 预处理总表

| # | 数据名称 | 输入格式 | 输出格式 | 维度 | 值范围 | 说明 |
|---|----------|----------|----------|------|--------|------|
| 1 | 顶部图像 | CompressedImage → RGB uint8 | torch.Tensor | (3, 224, 224) | [0, 1] | CHW float32 |
| 2 | 左腕图像 | CompressedImage → RGB uint8 | torch.Tensor | (3, 224, 224) | [0, 1] | CHW float32 |
| 3 | 右腕图像 | CompressedImage → RGB uint8 | torch.Tensor | (3, 224, 224) | [0, 1] | CHW float32 |
| 4 | 状态向量 | JointState + Point + Vector3 | torch.Tensor | (26,) | [-1, 1] | 归一化 float32 |

---

## 图像预处理流程

```
CompressedImage
    ↓ cv2.imdecode
RGB numpy (H, W, 3) uint8
    ↓ preprocess_rgb_image()
torch.Tensor (3, 224, 224) float32  # 值范围 [0, 1]
```

### 预处理步骤

1. **解码**: JPEG/PNG 字节 → RGB numpy 数组
2. **缩放**: 保持宽高比缩放到 224×224 内
3. **填充**: 用零值填充到 224×224 正方形
4. **归一化**: uint8 [0, 255] → float32 [0, 1]

### 配置参数

```python
ImagePreprocessConfig:
    image_size: 224          # 输出尺寸
    mode: "resize_pad"       # 缩放填充模式
```

---

## 状态编码流程

```
JointState (12D) + Point (3D) + Vector3 (3D) + JointState (1D) × 2
    ↓ encode_bimanual_state()
np.ndarray (26,) float32           # 编码后
    ↓ state_normalizer.normalize()
torch.Tensor (26,) float32         # 归一化到 [-1, 1]
```

### 编码布局

| Index | 字段 | 维度 | 来源 | 原始单位 | 归一化后范围 |
|-------|------|------|------|----------|-------------|
| 0-5 | `left_arm_q` | 6D | proprioception | rad | [-1, 1] |
| 6-11 | `right_arm_q` | 6D | proprioception | rad | [-1, 1] |
| 12 | `left_hand_q` | 1D | left_hand_state | 300-1000 | [-1, 1] |
| 13 | `right_hand_q` | 1D | right_hand_state | 300-1000 | [-1, 1] |
| 14-16 | `left_ee_pos` | 3D | left_ee_position | m | [-1, 1] |
| 17-19 | `left_ee_rpy` | 3D | left_ee_rpy | rad | [-1, 1] |
| 20-22 | `right_ee_pos` | 3D | right_ee_position | m | [-1, 1] |
| 23-25 | `right_ee_rpy` | 3D | right_ee_rpy | rad | [-1, 1] |

### 归一化公式

$$y = 2 \times \frac{x - \min}{\max - \min} - 1$$

- 归一化参数 (`min_vals`, `max_vals`) 从训练数据集中统计，保存在 `normalizers.json`
- 对于 `identity_indices` 指定的维度，跳过归一化，保持原值

## ObservationSnapshot 结构

预处理后的数据最终组装为 `ObservationSnapshot`：

```python
@dataclass(frozen=True)
class ObservationSnapshot:
    images: Mapping[str, torch.Tensor]   # {"top": (3,224,224), "left_wrist": ..., "right_wrist": ...}
    state: BimanualState                 # 结构化状态（原始值）
    encoded_state: np.ndarray            # (26,) 编码向量（原始值）
    captured_at_s: float                 # 采集时间戳
```

### 内存布局

```
ObservationSnapshot
├── images
│   ├── "top":         torch.Tensor (3, 224, 224) float32
│   ├── "left_wrist":  torch.Tensor (3, 224, 224) float32
│   └── "right_wrist": torch.Tensor (3, 224, 224) float32
├── state
│   ├── left_arm_q:    np.ndarray (6,) float32
│   ├── right_arm_q:   np.ndarray (6,) float32
│   ├── left_hand_q:   float
│   ├── right_hand_q:  float
│   ├── left_ee_pos:   np.ndarray (3,) float32
│   ├── left_ee_rpy:   np.ndarray (3,) float32
│   ├── right_ee_pos:  np.ndarray (3,) float32
│   └── right_ee_rpy:  np.ndarray (3,) float32
├── encoded_state:     np.ndarray (26,) float32
└── captured_at_s:     float
```

> [!note] 归一化时机
> 归一化在 `_build_batch()` 中执行，而非在 `ObservationSnapshot` 创建时。
> `encoded_state` 保持原始值，归一化后的 tensor 仅用于模型输入。

## State 完整变换链

> [!question] 核心问题
> 送入推理的 state 到底是什么？是一个每维都有明确定义的巨大矩阵吗？

**是的**——26D 向量每一维都有固定物理含义，index 0 就是左臂 joint1，index 6 就是右臂 joint1，以此类推。但模型最终消费它的方式**不是数值矩阵运算，而是当作文本 token**。

### 变换全景

```
原始 ROS 消息 (10 路 topic)
    ↓ snapshot() 采集
ObservationSnapshot.encoded_state    # (26,) float32 原始值
    ↓ normalize()                    # min-max → [-1, 1]
(26,) float32 归一化                 # 仍是数值向量
    ↓ np.digitize() 离散化           # 256 个 bin
(26,) int [0, 255]                   # 每个维度变成一个整数
    ↓ 拼接成字符串
"128 45 200 180 90 110 130 46 201 179 91 109 60 55 150 130 100 70 80 90 150 130 100 70 80 90"
    ↓ 嵌入 prompt
"Task: bimanual manipulation, State: 128 45 200 ...;\nAction: "
    ↓ PaliGemma tokenizer
(1, max_length) int64 token ids
    ↓ 送入 VLA 模型
```

### 各阶段详解

#### 1. 编码：ROS 消息 → 26D float32

```python
# state_codec.py — encode_bimanual_state()
vector = np.concatenate([
    left_arm_q,      # index 0-5   左臂 6 关节角 (rad)
    right_arm_q,     # index 6-11  右臂 6 关节角 (rad)
    left_hand_q,     # index 12    左手 (300-1000)
    right_hand_q,    # index 13    右手 (300-1000)
    left_ee_pos,     # index 14-16 左臂末端位置 xyz (m)
    left_ee_rpy,     # index 17-19 左臂末端姿态 rpy (rad)
    right_ee_pos,    # index 20-22 右臂末端位置 xyz (m)
    right_ee_rpy,    # index 23-25 右臂末端姿态 rpy (rad)
])  # → shape (26,) float32
```

#### 2. 归一化：原始值 → [-1, 1]

```python
# normalization.py — ActionStateNormalizer.normalize()
y = 2 * (x - min_vals) / (max_vals - min_vals) - 1
```

- 参数来自 `normalizers.json`（训练时从数据集统计）
- `identity_indices` 指定的维度跳过归一化

#### 3. 离散化：float32 → int [0, 255]

```python
# processor_pi05.py — Pi05PrepareStateTokenizerProcessorStep
bins = np.linspace(-1, 1, 256 + 1)[:-1]  # 256 个 bin 边界
discretized = np.digitize(state_np, bins=bins) - 1  # → [0, 255]
```

将连续的归一化值量化为 256 个离散级别。

#### 4. 文本化：int 向量 → 字符串

```python
state_str = " ".join(map(str, discretized))
# "128 45 200 180 90 110 130 46 201 179 91 109 60 55 150 130 100 70 80 90 150 130 100 70 80 90"
```

#### 5. 嵌入 prompt：字符串 → 完整指令

```python
full_prompt = f"Task: {task_description}, State: {state_str};\nAction: "
# "Task: bimanual manipulation, State: 128 45 200 ...;\nAction: "
```

#### 6. Token化：字符串 → token ids

PaliGemma tokenizer 将整个 prompt（含 task + state + action 前缀）编码为 token id 序列，送入 VLA 模型。

### 关键洞察

| 层次 | 形态 | 消费方式 |
|------|------|----------|
| 编码后 | `(26,)` float32 | 数值向量（物理含义明确） |
| 归一化后 | `(26,)` float32 [-1,1] | 数值向量（统一量纲） |
| 离散化后 | `(26,)` int [0,255] | 整数序列（量化） |
| **文本化后** | **字符串** | **当作文本 token，不是数值矩阵** |
| tokenizer 后 | `(1, max_length)` int64 | 模型输入 |

> [!important] 核心结论
> 虽然 26D state 每一维有明确的物理定义（joint1、joint2、...），但 VLA 模型**不做数值矩阵乘法**，而是把这些数字当作**文本 token** 喂给 PaliGemma 的语言建模头。这是 VLA（Vision-Language-Action）架构的核心设计——将动作状态编码为语言序列的一部分。
