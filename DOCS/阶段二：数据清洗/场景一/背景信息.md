## 程序三：坐标系统一的软件需求

程序三的目标是把左右 Baton Mini 的原始局部位姿统一转换到同一个 `common_frame` 下，并最终为双臂 observation 生成 `left_tcp_pose_common` 和 `right_tcp_pose_common`。

### 物理方案前提

程序三基于一个 3D 打印刚性定位底座系统：

- `left_base`：左手 UMI 装置初始放置点。
- `origin_base`：公共坐标系原点。
- `right_base`：右手 UMI 装置初始放置点。

公共坐标系定义为：

- x 轴：从 `left_base` 指向 `right_base`。
- z 轴：垂直桌面向上。
- y 轴：由右手系确定。

这套坐标系在软件中称为 `common_frame` 或 `origin_frame`。

底座必须固定左右 UMI 装置的完整 6D 初始位姿，而不是只固定平面位置。每次采集前，左 UMI 装置放入 `left_base`，右 UMI 装置放入 `right_base`，其位置、高度、朝向、俯仰角和横滚角都应由机械结构重复固定。

### 配置需求

程序三必须支持保存左右手两套独立 6D 外参：

- `T_common_left_start`：左 Baton Mini 初始坐标系到公共坐标系的变换。
- `T_common_right_start`：右 Baton Mini 初始坐标系到公共坐标系的变换。

配置中不能只保存原点位置，必须保存完整位置和姿态：

- translation：`x`、`y`、`z`。
- rotation：`qx`、`qy`、`qz`、`qw`。

建议在配置语义中使用：

- `common_from_left_start`
- `common_from_right_start`

如果沿用当前左右拆分文件，则左手配置写入 `/home/hit/ROS/config/data_clean_left_transform.yaml`，右手配置写入 `/home/hit/ROS/config/data_clean_right_transform.yaml`。无论最终文件布局如何，都必须保证左右手参数分开维护，不再共用同一套 transform。

程序三还必须支持相机到 TCP/夹爪中心的固定外参：

- `T_left_camera_tcp`
- `T_right_camera_tcp`

这两个外参用于把 Baton Mini 相机/设备位姿继续转换到真正进入 observation 的 TCP 位姿。

### 转换计算需求

Baton Mini 原始输出可理解为各自初始局部坐标系下的设备位姿：

- `T_left_start_left_camera(t)`
- `T_right_start_right_camera(t)`

程序三应按以下链路转换到公共坐标系：

- `T_common_left_camera(t) = T_common_left_start * T_left_start_left_camera(t)`
- `T_common_right_camera(t) = T_common_right_start * T_right_start_right_camera(t)`

如果要得到 TCP/夹爪中心位姿，则继续乘以相机到 TCP 的固定外参：

- `T_common_left_tcp(t) = T_common_left_camera(t) * T_left_camera_tcp`
- `T_common_right_tcp(t) = T_common_right_camera(t) * T_right_camera_tcp`

最终输出的训练语义字段为：

- `left_tcp_pose_common`
- `right_tcp_pose_common`

这两个字段都必须处在同一个 `common_frame` 下，格式应与阶段二 observation/schema 约定一致，当前推荐为 `[x, y, z, qx, qy, qz, qw]`。

### observation 需求

程序三输出的位姿字段进入最终双臂 observation：

- `image_left`
- `image_right`
- `left_tcp_pose_common`
- `right_tcp_pose_common`
- `left_gripper_width`
- `right_gripper_width`
- `left_tactile`
- `right_tactile`
- `language_instruction`

最终 observation 不应直接使用 `left_baton_pose_raw` 或 `right_baton_pose_raw` 作为训练位姿字段。raw pose 只能作为生成 `left_tcp_pose_common` 和 `right_tcp_pose_common` 的输入材料。

### 软件校验需求

程序三在读取或生成配置时应尽量检查：

- 左右 transform 是否分别存在，不能把左右手误用为同一套参数。
- translation 单位是否明确，避免 `m` 和 `mm` 混用。
- 四元数顺序是否明确为 `qx qy qz qw`。
- 四元数是否接近单位四元数。
- `common_frame` 的原点和轴向是否写入 metadata 或 schema。
- `T_left_camera_tcp` 和 `T_right_camera_tcp` 是否真实标定，未标定时必须显示警告。
- 输出 `left_tcp_pose_common` 和 `right_tcp_pose_common` 后，应能抽样检查数值量级和左右空间关系是否符合底座定义。

### 风险与边界

该方案是第一版工程可落地方案，优点是低成本、可重复、实现难度较低，适合先把双臂 observation 坐标系统一跑通。

主要风险包括：

- 3D 打印底座加工误差。
- 底座安装误差。
- UMI 装置在底座中存在晃动。
- Baton Mini 自身漂移。
- 左右数据时间同步误差。
- 相机中心到 TCP 的 offset 仍需真实标定。

因此该方案可作为第一版双臂 observation 坐标系统一方案，但后续如果追求更高精度，应考虑增加 ArUco、AprilTag 或机器人本体标定校验。

## 已发现并处理的问题

- 直接运行 `python3 src/data_clean/core/mcap_clean_batch.py` 会找不到 `core` 包，现通过 `start_data_clean.sh` 设置 `PYTHONPATH`。
- 当前系统 Python 环境缺少可直接使用的 `mcap`、`mcap_ros2`、`zstandard`，已建立独立 conda 环境。
- Octopus 写入的 ROS2 schema 存在缩进，`mcap_ros2` 动态解析前需要规范化 schema。
- 系统自带 OpenCV ArUco 检测曾出现 segfault，conda 环境中使用可用的 `opencv-contrib-python-headless`。
- `file_glob` 已从单个测试文件改为 `*.mcap`，实际清洗数量由交互式 launcher 控制。
- 已将配置/标定向导升级为浏览器版实时 GoPro 标定中心：
  - 不再要求用户选择夹爪完全闭合/完全张开的 MCAP。
  - 自动检查并在必要时启动左右 GoPro-only 节点，只订阅 `/gopro_left/image_raw` 和 `/gopro_right/image_raw`。
  - 由于 conda 环境中的 OpenCV 是 `opencv-contrib-python-headless`，`cv2.getBuildInformation()` 显示 `GUI: NONE`，标定中心不再使用 `cv2.imshow()`，而是通过 `http://127.0.0.1:<port>` 浏览器页面显示画面。
  - 夹爪标定按左闭合、左张开、右闭合、右张开的顺序实时采样，每步 2 秒，要求至少 30 帧、成对 marker 检测率 >= 90%、距离波动 <= 3 px。
  - 浏览器不可用时，夹爪标定可在终端输入 `g` 进入数字反馈兜底；TCP 点选必须使用浏览器页面。
  - TCP 标定作为浏览器独立页面，通过 GoPro 截图点选四个点：Baton Mini 参考点、夹爪 TCP 点、比例尺点 A、比例尺点 B，再按毫米比例尺计算 `tcp_offset.x/z`。
  - TCP 写入前会从最近 MCAP 抽样判断每个 pose stream 单位是 `m` 还是 `mm`，再将网页测得的毫米偏移转换为该 stream 的配置单位。
  - 输出新配置 `config/data_clean_calibrated.yaml`，并在覆盖前自动备份旧配置。
  - GoPro-only 子进程日志写入 `/home/hit/ROS/log/data_clean_gopro_only_*.log`，不刷标定终端。
- 清洗配置优先级为：命令行 `--config` 或 `DATA_CLEAN_CONFIG` > `config/data_clean_calibrated.yaml` > `config/data_clean_smoke_test.yaml`。
