# L2 能力模块说明：配置预检查模块

## 1. 能力名称

```text
Runtime MVP / 配置预检查模块
```

## 2. 所属位置

阶段：阶段二：数据清洗  
L1：`runtime_mvp`  
场景：Runtime MVP，不归入 `02_service` 的具体业务场景  
模块类别：数据计算类  
来源功能模块清单：[[功能模块清单]]

## 3. 一句话目标

```text
在执行输入产物预检查和 Service 调度前，判断本次生效配置是否满足 Runtime 继续执行的最低结构、场景和可追溯性要求。
```

## 4. 能力角色

```text
本能力是 Runtime MVP 的配置放行闸门，负责把“配置已读取”进一步判断为“配置足以进入后续 Runtime 流程”。
```

它消费功能三产出的 [[EffectiveRuntimeConfig]] 与 [[ConfigSnapshot]]，结合 [[RunContext]] 中的目标 [[SceneName]] 和 [[SceneConfigRequirement]]，产出 [[ConfigPrecheckResult]]。它不负责检查真实 Service 算法参数是否业务正确。

## 5. 上游关系

- 来自 [[RunContext]] 的目标场景、运行模式、配置路径和运行事实。
- 来自 [[03_配置加载与配置快照模块]] 的 [[EffectiveRuntimeConfig]]。
- 来自 [[03_配置加载与配置快照模块]] 的 [[ConfigSnapshot]] 路径和可追溯性事实。
- 来自 [[SceneName]] 的受控场景枚举和全流程顺序。
- 来自用户确认的设计结论：功能四只做 Runtime 级配置结构与可追溯性预检查，不提前承担 Service 业务参数校验。

## 6. 下游关系

- 输入产物预检查模块消费 [[ConfigPrecheckResult]]，只在 `passed = true` 时继续检查上游产物。
- 场景注册与 Service 调度模块依赖 [[ConfigPrecheckResult]] 的放行结论。
- 结构化日志模块记录 [[ConfigPrecheckIssue]] 和配置预检查结果。
- Manifest 与错误摘要模块可将阻塞型 [[ConfigPrecheckIssue]] 映射为 [[RuntimeErrorRef]] 或失败摘要。
- Runtime smoke test 模块验证合法配置、缺字段、缺场景配置和快照不可追溯等路径。

| 上游功能 | 上游接口 / 产物 | 本能力如何依赖 | 对齐状态 | 处理方式 |
| --- | --- | --- | --- | --- |

## 8. 职责边界

本能力负责：

1. 检查 [[EffectiveRuntimeConfig]] 是否存在、可消费且保留配置来源与覆盖项。
2. 检查 [[ConfigSnapshot]] 是否存在语义引用，并能追溯到本次 [[RunDirectory]]。
3. 检查 [[RunContext]] 中的每个目标 [[SceneName]] 在生效配置中存在对应 Runtime 级配置块。
4. 检查全局 Runtime 必需字段和 [[SceneConfigRequirement]] 是否满足最小结构要求。
5. 产出 [[ConfigPrecheckResult]] 和必要的 [[ConfigPrecheckIssue]]。

本能力不负责：

1. 读取配置文件或写入 `config_snapshot.yaml`。
2. 检查输入 MCAP、cleaned、validated、aligned 或 canonical dataset 文件是否存在。
3. 判断 MCAP topic、滤波、异常值、IK、MuJoCo、canonical dataset schema 或 exporter 参数是否业务正确。
4. 调用 fake service 或真实 service。
5. 写入 `run_log.json`、`processing_manifest.json`、`error_summary.json` 或 `run_result.json`。

## 9. 计算职责

本能力负责的判断或计算：

| 计算项 | 输入 | 输出 | 影响下游 |
| --- | --- | --- | --- |
| 生效配置存在性检查 | [[EffectiveRuntimeConfig]] | [[ConfigPrecheckIssue]] 或通过 | 缺失时阻止输入产物预检查 |
| 配置来源与覆盖项可追溯性检查 | [[EffectiveRuntimeConfig]] 中的 [[RuntimeConfigSource]] 和 [[ConfigOverrideSet]] | [[ConfigPrecheckIssue]] 或通过 | 不可追溯时阻止调度 |
| 配置快照可追溯性检查 | [[ConfigSnapshot]]、[[RunContext]]、[[RunDirectory]] | [[ConfigPrecheckIssue]] 或通过 | 快照缺失或路径逃逸时阻止调度 |
| 目标场景配置块检查 | [[RunContext]] 的目标 [[SceneName]]、[[EffectiveRuntimeConfig]]、[[SceneConfigRequirement]] | 按场景生成 [[ConfigPrecheckIssue]] 或通过 | 缺少 Runtime 级目标场景配置时阻止该次运行 |
| 最小全局配置结构检查 | [[EffectiveRuntimeConfig]] | [[ConfigPrecheckIssue]] 或通过 | 全局结构缺失时阻止后续 Runtime 流程 |
| 汇总放行结果 | 规则检查结果、[[ConfigPrecheckIssue]] | [[ConfigPrecheckResult]] | 决定是否进入输入产物预检查和调度 |

## 10. 计算规则

| 规则 | 触发条件 | 计算 / 判断方式 | 结果表达 |
| --- | --- | --- | --- |
| 生效配置必须存在 | 配置加载完成后进入预检查 | [[EffectiveRuntimeConfig]] 非空，且 `effective_data` 为可消费 mapping | 失败生成 `effective_config_missing` |
| 配置来源必须可追溯 | [[EffectiveRuntimeConfig]] 存在 | 必须能定位 [[RuntimeConfigSource]]，并保留来源类型和配置路径 | 失败生成 `config_source_untraceable` |
| 覆盖项必须显式记录 | [[EffectiveRuntimeConfig]] 存在 | 必须包含 [[ConfigOverrideSet]]；无覆盖时也应表达为空覆盖集合 | 失败生成 `override_set_missing` |
| 配置快照必须指向本次 run | [[ConfigSnapshot]] 已由上游产出 | 快照路径必须位于 [[RunDirectory]] 内，且语义上对应 `config_snapshot.yaml` | 失败生成 `snapshot_untraceable` |
| 目标场景必须满足最小 Runtime 配置要求 | [[RunContext]] 中存在目标 [[SceneName]] | 按 [[SceneConfigRequirement]] 对每个目标场景检查生效配置中是否存在 Runtime 级配置入口 | 失败生成 `missing_scene_config` |
| 全流程场景顺序必须受控 | [[RunContext]] 为全流程目标 | 目标场景顺序应与 [[SceneName]] 约束一致 | 失败生成 `invalid_scene_sequence` |
| Runtime 最小全局字段必须存在 | 任意运行模式 | 检查配置中是否存在 Runtime 继续执行所需的全局根字段，例如输入根、输出根或模式相关入口；具体字段由 L3 结合现有配置确定 | 失败生成 `missing_global_runtime_config` |

## 11. 输出结果结构

| 字段 | 类型 | 含义 | 有效性要求 | 下游使用方式 |
| --- | --- | --- | --- | --- |
| `passed` | boolean | 是否允许继续执行 | 有 `severity = error` 的 issue 时必须为 false | 输入产物预检查和调度的放行条件 |
| `checked_scenes` | list of [[SceneName]] | 被检查的目标场景 | 必须与 [[RunContext]] 一致 | 日志、错误摘要、smoke test |
| `issues` | list of [[ConfigPrecheckIssue]] | 发现的问题 | 无问题时为空列表 | 日志、错误摘要、用户排错 |
| `checked_rules` | list of [[ConfigPrecheckRule]] 或 rule id | 实际执行规则 | 至少覆盖本 L2 固定的 Runtime 级规则 | smoke test 和回归测试 |
| `effective_config_ref` | [[EffectiveRuntimeConfig]] | 被检查配置引用 | 必须来自功能三，不重新读取配置 | 下游确认配置来源 |
| `config_snapshot_ref` | [[ConfigSnapshot]] 或空 | 配置快照引用 | 快照缺失时必须产生阻塞 issue | manifest、日志、错误摘要 |

## 12. 异常与边界输入

| 边界情况 | 预期结果 | reason / error 表达 | 是否阻塞下游 |
| --- | --- | --- | --- |
| [[EffectiveRuntimeConfig]] 缺失 | 预检查失败 | `effective_config_missing` | 是 |
| `effective_data` 不是 mapping | 预检查失败 | `effective_config_not_mapping` | 是 |
| [[RuntimeConfigSource]] 缺失或路径为空 | 预检查失败 | `config_source_untraceable` | 是 |
| [[ConfigOverrideSet]] 未显式记录 | 预检查失败 | `override_set_missing` | 是 |
| [[ConfigSnapshot]] 路径为空或逃逸 [[RunDirectory]] | 预检查失败 | `snapshot_untraceable` | 是 |
| 目标 [[SceneName]] 不在受控枚举内 | 预检查失败 | `unknown_scene_name` | 是 |
| 目标场景缺少 Runtime 级配置块 | 预检查失败 | `missing_scene_config` | 是 |
| Service 业务参数存在但数值可能不合理 | Runtime 预检查通过或最多 warning | `service_business_config_not_checked` | 否，交给对应 Service |

## 13. 可验证样例

| 样例 | 输入特征 | 预期输出 | 验证方式 |
| --- | --- | --- | --- |
| 合法输入 | 有 [[EffectiveRuntimeConfig]]、[[ConfigSnapshot]]，目标场景配置块存在 | [[ConfigPrecheckResult]] 的 `passed = true`，`issues = []` | 单元测试构造最小有效配置 |
| 缺失输入 | [[EffectiveRuntimeConfig]] 缺失或不是 mapping | `passed = false`，包含阻塞型 [[ConfigPrecheckIssue]] | 单元测试断言 issue code |
| 边界输入 | 全流程目标场景顺序错误 | `passed = false`，包含 `invalid_scene_sequence` | 单元测试传入乱序目标场景 |
| 业务参数边界 | Service 内部参数缺失但 Runtime 场景块存在 | 不在功能四中判死，必要时 warning | 单元测试确认不提前执行 Service 业务校验 |

## 17. 给 L3 任务生成的约束

后续从本 L2 生成 L3 任务时，必须遵守：

1. 每个 L3 只能解决一个核心目标。
2. 每个 L3 必须先判断任务类别，并使用对应 L3 类别模板。
3. 每个 L3 必须有明确输入、输出、修改边界、验收命令和成功标准。
4. 每个 L3 必须写明“本次不做什么”。
5. 每个 L3 不能跨越本 L2 的能力边界。
6. 如果需要修改本 L2 之外的模块，必须在 L3 文档中显式说明原因。
