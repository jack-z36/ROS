# 01 删除位姿转换配置生成模块

## 问题定位

旧模块“位姿转换配置生成”围绕 `FrameAlignmentConfig` / `common_anchor` 生成统一 `common_frame` 配置。这个模块服务的是旧链路：

```text
左右 raw pose -> common_frame -> common-frame TCP pose
```

新最终定义不再需要统一 `common_frame`。左右手位姿应分别进入各自机械臂基坐标系：

- 左手 TCP pose -> 左手机械臂基坐标系。
- 右手 TCP pose -> 右手机械臂基坐标系。

因此该配置生成模块不再改造，直接删除出当前主链路。

## 修改方法

后续真正修改功能模块时：

1. 不再为 `FrameAlignmentConfig.common_anchor` 设计新生成流程。
2. 不再生成 `common_from_left_start`、`common_from_right_start` 作为主链路配置。
3. 不再把“左右 pose 统一到 common frame”作为场景一必需产物。
4. 用户后续直接输入“工作坐标系在机械臂基坐标系下的位姿”。
5. 配置层只保留后续官方函数调用所需的输入引用，不再承担工作坐标系标定生成责任。

## 后续影响

需要从当前主链路移除或降级为历史兼容的概念：

- `FrameAlignmentConfig`
- `common_anchor`
- `CommonFrameCameraPose`
- `CommonFrameTcpPose`
- `common_from_*_start`

这些概念可以保留在历史文档或调试说明中，但不得作为最终数据集主位姿定义。

## 验收标准

后续完成代码与文档改造后，应满足：

- 主链路不再要求执行“位姿转换配置生成”功能。
- 开发者入口不再把 common frame 配置生成作为新路线必经步骤。
- 最终数据说明中不再把 common frame 位姿作为主位姿。
- 用户输入的“工作坐标系在机械臂基坐标系下的位姿”成为官方函数调用输入之一。
