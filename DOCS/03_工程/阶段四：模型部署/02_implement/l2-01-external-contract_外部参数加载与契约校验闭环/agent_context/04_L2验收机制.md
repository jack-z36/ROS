# L2-01 L2 验收机制（AI 侧 L2 Gate）

> [!info] 产物归属
> - 类型：L2 设计包内的 AI 侧 L2 Gate 验收机制（阶段四：模型部署）。
> - `l2_id`：`l2-01-external-contract`
> - 本文职责：定义本 L2 的 L2 Gate 目标、必需 L3 清单草稿、校验层级、通过/失败现象、blocked 项、是否允许下游 L2 开始、是否允许合入 model_deploy。
> - 人类侧验收见 `05_人类验收机制.md`。

## 1. L2 Gate 目标

证明：合法外部参数能载入 RAM 形成 `DeployConfig` + `StateSpec`/`ActionSpec`（16D）+ bundle/normalizer contract 结果；非法参数在入口处失败并阻止启动；下游 L2 可直接 import 这些对象，无需猜测。

## 2. 必需 L3 清单草稿

> L3 在 L2 设计经用户确认后由 `stage4-l3-orchestrator` 生成。本清单是草稿，用于 L2 Gate 规划。

| 建议 L3 | 目标层 | 落点 | 一句话目标 | 建议验收模式 |
|---|---|---|---|---|
| L3-a：types 层 action/state 规格 + codec | types | `types/action_spec.py`、`types/state_spec.py` | 16D 维度常量、段序、codec、维度校验 | direct-local（单测） |
| L3-b：types 层 contract result 对象 | types | `types/contract_result.py` | BundleContractResult/NormalizerContractResult | direct-local（单测） |
| L3-c：repo 层 bundle/manifest/normalizer/experiment_config 读取 | repo | `repo/*.py` | 进程外资源读取 + 存在性检查 | direct-local（单测，用临时 fixture 文件） |
| L3-d：config 层 DeployConfig schema + 校验器 + 装配 | config | `config/schema.py` | frozen dataclass 群 + 校验器 + from_mapping | direct-local（单测，合法/非法配置） |
| L3-e：config 层 bundle/normalizer contract 元数据校验 | config | `config/schema.py` | 三处 dim 交叉校验 + normalizer dim 校验 | direct-local（单测） |
| L3-f：config_files/deploy.yaml 配置实例 | config_files | `config_files/deploy.yaml` | 一份合法示例配置 | static-review |
| L3-g：load_deploy_config 端到端入口 + 集成测试 | config + tests/integration | `config/schema.py` + `tests/integration/` | 端到端：合法 bundle → DeployConfig；非法 → 抛错 | direct-local（集成测试） |

## 3. 校验层级

| 层级 | 是否适用 | 说明 |
|---|---|---|
| unit | 是（主） | types/repo/config 各层单测 |
| import | 是 | 下游能 `from ... import DeployConfig, StateSpec, ActionSpec` |
| mock | 是 | 用临时 fixture 文件模拟 bundle/deploy.yaml |
| dry-run | 否 | dry-run 属 L2-06/L2-07 范围（需 ROS） |
| shadow-run | 否 | 本 L2 不发 topic |
| real-robot | 否 | 本 L2 不碰硬件 |
| env-blocked | 可能 | 若无真实 ACT bundle，用 fake bundle 走通；真实 bundle 校验标 env-blocked |

## 5. 测试输入

- **合法 fixture**：字段齐全的 `deploy.yaml`（dims=16、合法 hz/chunk/mode）+ 合法 bundle（manifest/normalizers/experiment_config 维度一致=16）。
- **非法 fixture 群**：缺字段、dim 非 16、hz≤0、`execute_horizon>chunk_size`、bundle 缺文件、三处 dim 不一致、normalizer dim≠16。

## 6. 观察点

- 单测 stdout（通过/失败计数）。
- 异常类型与 message（配置非法应抛 ACT 配置异常，bundle 缺文件应抛 FileNotFoundError）。
- `ContractResult.passed` / `reason` 字段。

## 7. 通过现象

- 全部单测 + 集成测试 PASS。
- 合法 fixture 构造出 `DeployConfig`，`runtime.action_dim==16`、`state_dim==16`。
- 各类非法 fixture 抛出对应异常，不构造出半初始化对象。
- bundle contract 校验：三处 dim 一致 → passed=True；不一致 → passed=False + reason。
- 下游 `import DeployConfig, StateSpec, ActionSpec` 成功。

## 8. 失败现象与排查入口

| 失败现象 | 可能原因 | 排查入口 |
|---|---|---|
| 合法配置构造失败 | 校验器过严 / 段序定义错 | `config/schema.py` 校验器 + types 段序 |
| 非法配置未抛错 | 校验器缺失 / 关系校验漏 | 对应 `_positive_*`/`__post_init__` |
| bundle contract 误判 | manifest 路径错 / dim 读取错 | `repo/manifest_parser.py` + `config` contract 校验 |
| normalizer dim 校验漏 | 未调 contract 校验 | `config/schema.py:check_normalizer_contract` |
| import 失败 | 路径/命名不一致 | 检查 `__init__.py` 导出 |

## 9. Blocked 项

| 项 | 原因 | 处理 |
|---|---|---|
| 真实 ACT bundle 校验 | 当前可能无真实 ACT bundle | 用 fake/fixture bundle 走通；真实 bundle 标 env-blocked，留待 L2-03 有真 bundle 时复验 |
| TCP/quaternion safety 字段 | 具体字段待 L2-05 或用户 | 本 L2 占位，L2-05 细化 |

## 10. 是否允许下游 L2 开始

**否**（在 L2 Gate 通过前）。本 L2 是全部下游 L2 的静态契约地基。L2 Gate 通过 + 人类验收签字后，L2-02 及之后方可开始。

## 11. 是否允许合入 model_deploy

仅当**全部满足**：
- L2 Gate 通过（本表第 7 节现象全部观察到了）。
- 人类验收签字通过（`05_acceptance/l2-01-external-contract/验收结果.md` 已填已通过）。
- 无 env-blocked/hardware-blocked 未解释项（或已明确标注由哪个下游 L2 Gate 覆盖）。
- Git 状态符合阶段四 Git 操作规则。
