# 大象夹爪Ubuntu上位机控制行动框架

## 目标
使用Ubuntu上位机，通过USB转RS485模块，控制Elephant Robotics myCobot Pro力控夹爪（myGripper-F100）实现开合动作。

## 通信原理（小白必读）

> [!note] 先理解原理，再动手操作
> 这部分帮助你理解"为什么这样做"，而不只是"怎么做"。

### 硬件连接：像"寄信"一样

```
电脑USB口 ←→ USB转RS485模块 ←→ 夹爪的RS485接口
   ↑              ↑                    ↑
  你            翻译官               对方
```

- **USB口**：电脑的"嘴巴"，能说USB语言
- **USB转RS485模块**：翻译官，把USB语言翻译成RS485语言
- **RS485接口**：夹爪的"耳朵"，只懂RS485语言

### 数据格式：消息的"信封"

夹爪只认一种固定格式的消息（协议帧）：

```
帧头(2B) + 长度(1B) + ID(1B) + 功能码(1B) + 寄存器地址(2B) + 数据(2B) + CRC校验(2B)
```

**示例：读取固件版本号的"信"**
```python
cmd = bytes.fromhex('FEFE080E03000100007251')
#  FE FE  → 帧头（表示"我要开始说话了"）
#  08     → 长度（后面还有8个字节）
#  0E     → ID（夹爪的地址，默认0x0E）
#  03     → 功能码（03=读取）
#  00 01  → 寄存器地址（固件版本号存在这里）
#  00 00  → 数据（读取时填0）
#  72 51  → CRC校验（防错用的"暗号"）
```

### Python代码：你的"嘴巴"和"耳朵"

```python
import serial  # 串口通信库

# 1. 打开"电话线"
ser = serial.Serial('/dev/ttyACM0', 115200, timeout=1)
#                设备路径        波特率      等待响应时间

# 2. 写信（发送指令）
cmd = bytes.fromhex('FEFE080E03000100007251')
ser.write(cmd)  # 把字节数据写入串口

# 3. 听回信（读取响应）
resp = ser.read(64)  # 最多读64个字节
print('夹爪说:', resp.hex())

# 4. 挂电话
ser.close()
```

### 关键参数说明

| 参数 | 值 | 为什么 |
|------|-----|--------|
| **设备路径** | `/dev/ttyACM0` | 你夹爪的"门牌号" |
| **波特率** | `115200` | 通话速度（必须和夹爪一致） |
| **超时** | `1` 秒 | 等多久没回应就放弃 |

### 设备路径说明

> [!tip]+ 为什么我的设备是 `/dev/ttyACM0` 而不是 `/dev/ttyUSB0`？
> 你的USB转串口芯片（沁恒CH340N/CH343）使用Linux内核自带的 `cdc_acm` 驱动，该驱动创建的设备节点是 `/dev/ttyACM*`。
> 
> `/dev/ttyUSB*` 是由老款芯片的专有驱动创建的。
> 
> **推荐使用稳定路径**（插拔不变）：
> ```bash
> /dev/serial/by-id/usb-1a86_USB_Single_Serial_5AF5010881-if00
> ```

### 协议是什么？（字段详解）

> [!note] 协议 = 双方约定的通信规则
> 协议不是字典，不是把文字翻译成十六进制。协议是**格式约定**——双方都必须遵守的消息结构。

**消息格式：像"填表格"**

```
┌────────┬────────┬────────┬────────┬────────┬────────┬────────┐
│ FE FE  │   08   │   0E   │   03   │ 00 01  │ 00 00  │ 72 51  │
├────────┼────────┼────────┼────────┼────────┼────────┼────────┤
│  帧头  │  长度  │   ID   │ 功能码 │寄存器  │  数据  │  校验  │
│        │        │        │        │  地址  │        │        │
└────────┴────────┴────────┴────────┴────────┴────────┴────────┘
```

**逐字段解释**

| 字段 | 示例 | 作用 | 生活类比 |
|------|------|------|----------|
| **帧头** | `FE FE` | 标记消息开始 | 打电话先说"喂？" |
| **长度** | `08` | 后续字节数量 | 快递包裹写的"内含8件" |
| **ID** | `0E` | 目标设备地址 | 门牌号（默认14） |
| **功能码** | `03` | 操作类型 | 点菜时说"看菜单"还是"点菜" |
| **寄存器地址** | `00 01` | 存储位置 | 文件柜的抽屉编号 |
| **数据** | `00 00` | 要写入的值 | 抽屉里的东西（读取时填0） |
| **CRC校验** | `72 51` | 错误检测 | 快递单号核对 |

**功能码说明**

| 功能码 | 含义 | 示例 |
|--------|------|------|
| `03` | 读取 | 问夹爪"你现在角度是多少？" |
| `06` | 写入 | 告诉夹爪"把角度设置为50" |

**常用寄存器地址**

| 寄存器 | 地址 | 说明 |
|--------|------|------|
| 固件版本号 | `00 01` | 固件主版本 |
| 使能状态 | `00 0A` | 0=断使能，1=使能 |
| 夹爪角度 | `00 0B` | 0-100（全闭到全开） |
| 当前角度 | `00 0C` | 读取当前角度值 |
| 速度 | `00 20` | 1-100 |

**完整通信流程**

```
你的电脑                          夹爪
   │                               │
   │  "喂！我要问你问题！"          │
   │  FE FE（帧头）───────────────→│
   │                               │
   │  "我后面有8个字节"            │
   │  08（长度）──────────────────→│
   │                               │
   │  "我要问14号夹爪"             │
   │  0E（ID）────────────────────→│
   │                               │
   │  "我要读取"                   │
   │  03（功能码）────────────────→│
   │                               │
   │  "读固件版本号那个抽屉"        │
   │  00 01（寄存器地址）─────────→│
   │                               │
   │  "（占位）"                   │
   │  00 00（数据）───────────────→│
   │                               │
   │  "这是验证码"                 │
   │  72 51（CRC）────────────────→│
   │                               │
   │                               │ 夹爪查抽屉，找到版本号
   │                               │
   │  "版本号是 00 0D（=13）"      │
   │←──────────────────────────────│
```

## 阶段一：Ubuntu软件环境搭建

> [!info] 核心思路
> 我们需要一个“翻译官”来帮我们和夹爪说话。这个翻译官就是Python的 `pyserial` 库，它能直接操作串口，发送十六进制指令。

### 1.1 安装Python和pip
打开Ubuntu终端（快捷键：`Ctrl`+`Alt`+`T`），执行：
```bash
sudo apt update
sudo apt install python3 python3-pip -y
```

### 1.2 安装串口通信库
```bash
pip3 install pyserial
```

## 阶段二：验证基本通信

> [!info] 核心思路
> 在正式控制开合前，先试试“对话”是否通畅。我们将使用minicom串口调试工具，直接发送十六进制指令验证通信。

### 2.1 识别串口设备
在终端执行：
```bash
ls /dev/ttyUSB*
```
- 如果看到类似 `/dev/ttyUSB0` 的输出，说明模块已被识别。
- 如果没有，请检查驱动是否安装正确，或尝试更换USB口。

### 2.2 确认串口权限
为了能正常读写串口，可能需要将当前用户加入 `dialout` 组：
```bash
sudo usermod -a -G dialout $USER
```
执行后，**需要注销并重新登录Ubuntu**才能生效。

### 2.3 安装并配置minicom
minicom是Ubuntu下常用的串口调试工具，用于发送和接收串口数据。

1. **安装minicom**
   ```bash
   sudo apt update
   sudo apt install minicom -y
   ```

2. **启动minicom并配置串口**
   ```bash
   sudo minicom -s
   ```
   进入配置菜单后，按以下步骤操作：

   **步骤1**：选择 **Serial port setup** → 回车

   **步骤2**：按 **A** 修改 **Serial Device**：输入你的串口设备路径（如 `/dev/ttyUSB0`）

   > [!tip]+ 为什么要这样做？
   > 告诉minicom要操作哪个串口设备，就像告诉它"我要和哪个口说话"

   **步骤3**：按 **E** 修改 **Bps/Par/Bits**：选择 **115200 8N1**

   > [!tip]+ 为什么要这样做？
   > 设置通信参数：波特率115200（传输速度）、8位数据位、无校验、1位停止位。这些参数必须和夹爪一致，否则双方"语言不通"

   **步骤4**：按 **F** 修改 **Hardware Flow Control**：改为 **No**

   > [!tip]+ 为什么要这样做？
   > 关闭硬件流控制。流控制是协调数据传输速度的机制，对于简单的串口通信，关闭它可以避免不必要的等待

   **步骤5**：按 **G** 修改 **Software Flow Control**：改为 **No**

   > [!tip]+ 为什么要这样做？
   > 关闭软件流控制。同上，简化通信过程，避免数据被意外暂停

   **步骤6**：回车确认，选择 **Save setup as dfl** 保存为默认配置

   > [!tip]+ 为什么要这样做？
   > 这样下次启动minicom时，就不用重新配置了

   **步骤7**：选择 **Exit** 进入minicom主界面

### 2.4 使用Python测试通信（推荐）

> [!tip]+ 为什么用Python而不是minicom？
> minicom没有内置的十六进制发送功能，需要配合 `printf` 等外部工具，操作繁琐。Python的 `pyserial` 库可以直接发送字节数据，一步到位。

1. **测试指令：读取固件主版本号**
   ```python
   python3 -c "
   import serial
   ser = serial.Serial('/dev/ttyACM0', 115200, timeout=1)
   cmd = bytes.fromhex('FEFE080E03000100007251')
   ser.write(cmd)
   print('已发送:', cmd.hex())
   resp = ser.read(64)
   print('响应:', resp.hex() if resp else '无响应（检查夹爪是否上电）')
   ser.close()
   "
   ```

2. **预期输出**
   ```
   已发送: fefe080e03000100007251
   响应: fefe080e030001000db790
   ```

3. **响应格式解读**

| 帧头    | 长度  | ID  | 功能码 | 寄存器地址 | 数据    | CRC校验 |
| ----- | --- | --- | --- | ----- | ----- | ----- |
| FE FE | 08  | 0E  | 03  | 00 01 | 00 0D | B7 90 |
   

   > [!tip]+ 寄存器0001返回的数据是什么意思？
   > 寄存器 `00 01` 存储固件主版本号，返回数据 `00 0D` 表示版本号为 13。

### 2.5 验证通信成功

> [!success] 通信成功的标志
> - 串口路径正确（如 `/dev/ttyACM0`）
> - 波特率正确（默认115200）
> - 夹爪上电正常
> - 响应数据以 `FE FE` 开头

**如果通信失败**：
1. 检查串口号是否正确：`ls /dev/ttyUSB*` 或 `ls /dev/ttyACM*`
2. 检查波特率是否匹配（默认115200）
3. 检查接线：A-A，B-B，不要反接
4. 检查电源：夹爪必须用24V外部电源供电
5. 检查权限：当前用户是否在 `dialout` 组

### 2.5 验证通信成功
**预期结果**：
- 发送指令后，立即收到响应
- 响应数据以 `FE FE` 开头
- 响应数据长度符合协议格式（通常为11字节）
- CRC校验正确

**如果通信失败**：
1. 检查串口号是否正确
2. 检查波特率是否匹配（默认115200）
3. 检查接线：A-A，B-B，不要反接
4. 检查电源：夹爪必须用24V外部电源供电
5. 检查权限：当前用户是否在 `dialout` 组

## 阶段三：控制夹爪开合

> [!info] 核心思路
> 通信成功后，我们就可以发送“开”和“合”的指令了。角度范围是0（全闭）到100（全开）。

### 3.1 控制原理
控制夹爪开合的过程，本质上是上位机通过串口向夹爪发送一系列**写指令**。
每个指令都包含：帧头、设备ID、功能码（写操作0x06）、目标寄存器地址、以及要写入的数据（如角度值）。
夹爪收到指令后，会执行相应动作并返回一个确认帧。

### 3.2 控制流程
1. **建立连接**：打开串口，设置波特率（默认115200）。
2. **发送使能指令**：向寄存器 `0x000A` 写入 `1`，夹爪进入工作状态。
3. **发送角度指令**：向寄存器 `0x000B` 写入目标角度值（0-100），夹爪开始运动。
4. **等待与确认**：等待足够时间让夹爪运动到位，可通过读取指令确认当前位置。
5. **发送断使能指令**：向寄存器 `0x000A` 写入 `0`，夹爪进入休眠状态。

### 3.3 核心寄存器
| 功能 | 寄存器地址 | 写入值范围 | 说明 |
|------|------------|------------|------|
| **使能控制** | `0x000A` | 0 或 1 | 0=断使能（休眠），1=使能（工作） |
| **角度设置** | `0x000B` | 0 - 100 | 0=全闭，100=全开 |
| **速度设置** | `0x0020` | 1 - 100 | 运动速度，数值越大越快 |

## 阶段四：常见问题与调试

> [!question] 遇到问题？
> 别慌，按照以下步骤排查。

1.  **通信失败**：
    - 检查串口号：`ls /dev/ttyUSB*`
    - 检查权限：`ls -l /dev/ttyUSB0`，看是否属于 `dialout` 组
    - 检查接线：A-A，B-B，不要反接
    - 检查电源：夹爪必须用24V外部电源供电

2.  **夹爪不动**：
    - 确认已执行使能指令（寄存器0x000A写入1）
    - 检查速度设置是否为0
    - 检查扭矩设置是否过小

3.  **运动抖动**：
    - 尝试调整PID参数（D值），适当增大D值可减少抖动
    - 参考[[自定义协议控制]]中的PID设置指令
