# 阶段二：数据清洗阶段产出

## 文档定位

本文件记录阶段二当前已经形成或依赖的软件资产，并把“数据清洗全流程的步骤”映射到对应代码模块。阶段最终目标写在 `阶段目标描述.md`；概念和边界写在 `背景信息.md`；详细代码结构见 `src/data_clean/data_clean_architecture.md`。

## 入口与运行层

| 软件资产 | 路径 | 功能 |
| --- | --- | --- |
| 统一启动脚本 | `start_data_clean.sh` | 设置 Python、ROS 环境和 `PYTHONPATH`，分流到网页 UI、legacy CLI 或 dev menu。 |
| 正常用户网页入口 | `src/data_clean/ui/web_launcher.py` | 本地 Web UI，看板、新建任务、目录浏览、文件勾选、启动确认、全链路进度、评测报告、3D TCP 轨迹和历史记录。 |
| 开发者检验菜单 | `src/data_clean/ui/dev_menu.py` | `./start_data_clean.sh --dev` 的场景/功能检验入口，分发到场景一、二、三和 Forge bridge check。 |
| legacy CLI 清洗入口 | `src/data_clean/runtime/mcap_clean_launcher.py` | 终端批量清洗入口，支持 latest/all/dry-run/workers/calibrate 等参数。 |
| Runtime 调度基础设施 | `src/data_clean/runtime/` | run 目录、配置预检查、输入产物预检查、结构化日志、manifest、pipeline dispatcher 等。 |
| 代码级架构说明 | `src/data_clean/data_clean_architecture.md` | 后续 Codex 理解源码分层、模块职责和数据流的首选入口。 |

## 场景一：raw MCAP -> cleaned MCAP

| 软件资产 | 路径 | 功能 |
| --- | --- | --- |
| 配置加载 | `src/data_clean/config/mcap_process_config.py` | 解析清洗配置、pose streams、gripper streams、transform 配置。 |
| MCAP 单文件处理 | `src/data_clean/service/mcap_io.py` | 读取 raw MCAP，保留原始消息，生成转换后的位姿 payload 和夹爪宽度 topic。 |
| 输入/输出校验 | `src/data_clean/service/validator.py` | 校验 topic/schema、输出 topic 数、消息数量和配置一致性。 |
| 位姿转换 | `src/data_clean/service/tcp_transform.py`、`src/data_clean/service/arm_base_transform.py` | common/arm-base 相关 SE(3) 位姿转换。 |
| 夹爪宽度提取 | `src/data_clean/service/gripper_width.py` | 从 GoPro 图像检测 ArUco marker，估计并归一化夹爪宽度。 |
| 标定向导 | `src/data_clean/ui/mcap_calibration_wizard.py` | 浏览器/交互式标定入口，辅助生成正式配置。 |
| 场景一 dev checks | `src/data_clean/ui/scene1_dev_checks.py` | 场景一开发者检验项和隔离运行目录。 |

## 正常网页批次构建

`./start_data_clean.sh` 无参数时启动仅监听 `127.0.0.1` 的网页入口。正常用户勾选多个 raw MCAP 后，网页 Runtime 会为每个文件依次执行：

```text
raw MCAP
  -> cleaned MCAP
  -> MCAP_A
  -> aligned MCAP
  -> Forge bridge
  -> 成功 episode 聚合
  -> 单个 LeRobot v3 dataset
  -> Forge inspect / quality
```

已形成的网页能力：

| 能力 | 行为 |
| --- | --- |
| 目录与文件选择 | 浏览整个本机文件系统；输入目录只扫描当前层 `.mcap`；支持全选、全不选、反选和搜索。 |
| 最终输出目录 | 默认建议 `asset/阶段二：数据清洗/prod/exports/lerobot/`，但用户可自由选择任意本机父目录；网页不限制路径，也不显示路径风险提示。 |
| 批次容错 | 单文件失败不阻止其他文件继续；至少一个 MCAP 成功时仍发布包含成功 episode 的 dataset。 |
| staging 与回滚 | 先在 `src/data_clean/runs/web_jobs/outputs/staging/<job_id>/` 构建；用户取消或批次失败时回滚本批次发布产物。 |
| worker 调度 | 多批次可并行运行，共享默认最多 `6` 个文件处理 worker。 |
| 历史摘要 | 页面刷新、浏览器关闭不取消任务；历史摘要持久化，删除历史不删除真实产物。 |
| 失败重试 | 结果页可使用失败 MCAP 自动创建新的任务草稿。 |
| Forge Viewer | 结果页按需启动外部 Forge Web Viewer，新标签页打开最终 dataset。 |
| 配置工作台 | 默认读取 `config/data_clean/data_clean_calibrated.yaml`，可叠加本机 preset 和当前任务覆盖；夹爪、坐标系转换、检测滤波、对齐、bridge 与 LeRobot fps 均按真实接口适配。 |
| 配置快照 | 每个 Web job 写出 `src/data_clean/runs/web_jobs/runs/<job_id>/config_snapshot.yaml`；sidecar 摘要只引用 snapshot 路径。 |

网页任务 sidecar 固定写入：

```text
asset/阶段二：数据清洗/dev/debug/web_jobs/<dataset_name>_data_clean_sidecar/
├── 01_cleaned/<stem>/
├── 02_mcap_a/<stem>/
├── 03_aligned/<stem>/
├── 04_forge_bridge/<stem>/
├── logs/<stem>/
└── reports/
```

用户自由选择目录只影响最终 LeRobot dataset：

```text
<用户选择的本机父目录>/<dataset_name>/
```

中间 MCAP、bridge、日志和报告仍留在受控 sidecar 中。

## 网页结果页

任务结果页已经提供三个视图：

| 视图 | 功能 |
| --- | --- |
| 评测报告 | 可视化展示 Forge quality 总分、各维度分数条、逐 episode 分数、flags 和报告文件位置。 |
| 3D 轨迹 | 从最终 dataset 的 `observation.state` 读取左右 TCP pose，使用固定右手坐标系工程视角；左下角显示局部原点取当前 `bounds.min`，不改写原始坐标；单个 episode 可按真实时间戳播放。 |
| 逐文件状态 | 展示每个 MCAP 是否纳入最终 dataset、episode 数量、当前阶段、阶段产物和失败原因。 |

3D 轨迹坐标系策略：

- `format-only`：旧 `common_frame` 双手轨迹可叠加在一个画布。
- `formal`：左右 TCP 分别属于 `left_arm_base` 与 `right_arm_base`，采用双画布同步播放，不比较双手绝对空间位置。
- `全部 episode`：只展示静态总览；选择单个 episode 后可播放、暂停、拖动进度条、回到起点和切换倍速。

结果页缓存：

| 文件 | 功能 |
| --- | --- |
| `reports/forge_inspect.json` | Forge inspect 原始报告。 |
| `reports/forge_quality.json` | Forge quality 原始报告。 |
| `reports/forge_quality_flagged.json` | flagged episode 列表。 |
| `reports/quality_visual_summary.json` | 评测页可视化摘要。 |
| `reports/trajectory_summary.json` | 3D 轨迹、bounds 与坐标系 profile 摘要。 |

轨迹接口：

| 接口 | 功能 |
| --- | --- |
| `GET /api/jobs/{job_id}/trajectory` | 从最终 dataset parquet 按需读取左右 TCP pose；返回 episode、时间戳、全局 bounds、左右 hand bounds、坐标系 profile 和固定右手投影提示。旧缓存缺字段时自动补齐并写回 sidecar。 |
| `GET /api/config/default` | 读取默认配置摘要。 |
| `GET /api/config/presets` | 列出本机 Web preset。 |
| `POST /api/config/presets` | 保存仅包含覆盖值的 preset。 |
| `DELETE /api/config/presets/{name}` | 删除用户 preset，不修改正式配置。 |
| `POST /api/config/preview` | 预览有效配置、覆盖 diff、警告和字段校验错误。 |
