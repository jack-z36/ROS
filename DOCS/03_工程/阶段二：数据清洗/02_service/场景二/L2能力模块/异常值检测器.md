# L2 能力模块说明：异常值检测器

> ⚠️ 当前不在主路径；保留以备未来。

## 1. 能力名称

```text
异常值检测器
```

## 2. 所属位置

阶段：阶段二：数据清洗
L1：service_s2
场景：场景二：硬件数据可靠性验证
模块类别：数据计算类
来源功能模块清单：`DOCS/03_工程/阶段二：数据清洗/02_service/场景二/功能模块清单.md`

## 3. 一句话目标

```text
在 cleaned MCAP 原始序列上识别位姿、触觉和夹爪的样本级异常与无样本缺失区间，并输出可被数据补全器、滤波器和报告生成器共同消费的可靠性检测结果。
```

## 4. 能力角色

本能力是场景二 P0 预处理链路的第一步。它先于数据补全器、位姿滤波器和触觉滤波器运行，负责把 cleaned MCAP 中的坏点、非法值、跳变、异常变化和缺失区间表达为统一检测结果。

已按 `grill-me` 约束完成意图澄清：异常检测的主接口从时间段级改为样本级；已有消息异常使用 [[SampleReliabilityIssue]] 和 [[SignalSampleRef]]，无样本缺失使用 [[MissingIntervalIssue]]，连续问题摘要使用 [[ReliabilityIssueGroup]]。[[IssueTimeSegment]] 不再作为通用必填接口。

## 5. 上游关系

- 场景一 [[CleanedMcap]] 必须可用。
- 位姿优先消费 [[CommonFrameTcpPose]]，必要时通过 [[CommonFrameCameraPose]] 和 raw pose 追溯。
- 夹爪宽度消费 cleaned MCAP 中的 [[GripperWidthSample]] topic。
- 触觉消费 4 路 [[TactilePressureFrame]] topic。
- 检测阈值和规则来自 [[ReliabilityCheckRuleConfig]]。

## 6. 下游关系

- 数据补全器消费 [[SignalReliabilityDetectionResult]] 中的 `sample_issues` 和 `missing_interval_issues`。
- 位姿滤波器和触觉滤波器在补全后运行，并参考不可修复或未处理问题。
- [[McapA|MCAP_A]] 生成器不直接消费异常检测器的点级证据，但需要继承补全/滤波后的追溯信息。
- Parquet 标注与验证报告生成器汇总样本级问题、缺失区间和聚合摘要，生成统一问题标注和验证报告。

## 8. 职责边界

本能力负责：

1. 在 cleaned MCAP 原始序列上检测位姿、触觉和夹爪的信号可靠性问题。
2. 对已有样本异常输出 [[SampleReliabilityIssue]]。
3. 对无样本缺失区间输出 [[MissingIntervalIssue]]。
4. 可选输出 [[ReliabilityIssueGroup]] 作为展示和报告摘要。
5. 聚合输出 [[SignalReliabilityDetectionResult]]。

本能力不负责：

1. 不修改 cleaned MCAP 或任何序列值。
2. 不执行插值、邻近保持、滤波或 [[McapA|MCAP_A]] 写出。
3. 不决定最终 episode 丢弃、训练 mask 或场景四质量报告。
4. 不把 [[ReliabilityIssueGroup]] 作为补全器的权威处理单元。

## 9. 计算职责

| 计算项 | 输入 | 输出 | 影响下游 |
|---|---|---|---|
| 通用时间检查 | 各输入 topic 时间戳 | [[MissingIntervalIssue]]，重复时间/倒退时间类 [[SampleReliabilityIssue]] | 数据补全器不跨缺失区间寻找邻居 |
| 通用非法值检查 | 位姿、触觉、夹爪样本 | NaN/Inf、空矩阵、长度不匹配、越界类 [[SampleReliabilityIssue]] | 阻止非法值进入补全/滤波 |
| 位姿异常检查 | [[CommonFrameTcpPose]] | 位置跳变、四元数非法、速度/加速度异常样本 | 数据补全器和位姿滤波器 |
| 触觉异常检查 | [[TactilePressureFrame]] | 尖峰、突变、shape 不一致、饱和、全零可疑样本 | 数据补全器和触觉滤波器 |
| 夹爪异常检查 | [[GripperWidthSample]] | 值域越界、宽度跳变、长时间卡死样本 | 数据补全器和后续标注 |
| 问题聚合摘要 | [[SampleReliabilityIssue]] | [[ReliabilityIssueGroup]] | 开发者验收和报告展示 |
| 检测结果聚合 | 所有检测记录、[[ReliabilityCheckRuleConfig]] | [[SignalReliabilityDetectionResult]] | 下游统一消费 |

## 10. 计算规则

| 规则 | 触发条件 | 计算 / 判断方式 | 结果表达 |
|---|---|---|---|
| 缺失区间 | topic 采样间隔超过配置阈值 | 比较相邻消息时间差 | [[MissingIntervalIssue]]，`issue_type=missing_segment` |
| 时间异常 | 时间戳倒退或重复 | 检查单 topic 时间序列单调性 | [[SampleReliabilityIssue]]，`issue_type=timestamp_anomaly` |
| 位姿跳变 | 位置或姿态变化超过配置阈值 | 比较相邻 [[CommonFrameTcpPose]] 差异 | [[SampleReliabilityIssue]]，`issue_type=pose_jump` |
| 位姿速度/加速度异常 | 推导速度或加速度超过配置阈值 | 按相邻样本时间差计算一阶/二阶变化 | [[SampleReliabilityIssue]]，`issue_type=pose_velocity_anomaly` / `pose_accel_anomaly` |
| 四元数非法 | 四元数非有限或范数偏离 1 | 检查 `qx/qy/qz/qw` | [[SampleReliabilityIssue]]，`issue_type=invalid_orientation`，`field_path=pose.orientation` |
| 触觉 shape 不一致 | `rows * cols != len(data)` 或 rows/cols 异常 | 检查 [[TactilePressureFrame]] 结构 | [[SampleReliabilityIssue]]，`issue_type=tactile_shape_mismatch` |
| 触觉尖峰/突变 | 单帧或短段变化超过阈值 | 比较矩阵统计量或相邻矩阵差异 | [[SampleReliabilityIssue]]，`issue_type=tactile_spike` |
| 触觉饱和/全零 | 矩阵中饱和或零值比例超过阈值 | 计算比例和持续时间 | [[SampleReliabilityIssue]]，`issue_type=tactile_saturation` / `tactile_zero_suspicious` |
| 夹爪越界 | value 超出 `[0, 1]` 或配置范围 | 检查 [[GripperWidthSample]] | [[SampleReliabilityIssue]]，`issue_type=gripper_out_of_range` |
| 夹爪跳变/卡死 | 相邻差值过大或长时间不变化 | 比较相邻 value 和持续时间 | [[SampleReliabilityIssue]] 或 [[ReliabilityIssueGroup]] 摘要 |

## 11. 输出结果结构

| 字段 | 类型 | 含义 | 有效性要求 | 下游使用方式 |
|---|---|---|---|---|
| `sample_issues` | list[[SampleReliabilityIssue]] | 已有样本点异常列表 | 可为空但字段必须存在 | 数据补全器主输入 |
| `missing_interval_issues` | list[[MissingIntervalIssue]] | 无样本缺失区间列表 | 可为空但字段必须存在 | 数据补全器记录未处理缺失，滤波器避开 |
| `issue_groups` | list[[ReliabilityIssueGroup]] | 可选展示/报告摘要 | 只能引用已有 sample issue | 报告和人工复查 |
| `rule_config_ref` | [[ReliabilityCheckRuleConfig]] | 本次使用的规则配置引用 | 必须可追溯 | 复现实验和调参 |
| `summary_by_modality` | object | 三模态问题统计 | 必须区分 pose/tactile/gripper | 开发者入口摘要 |

## 12. 异常与边界输入

| 边界情况 | 预期结果 | reason / error 表达 | 是否阻塞下游 |
|---|---|---|---|
| cleaned MCAP 缺失 | 功能检验失败 | `missing_cleaned_mcap` | 是 |
| 位姿、触觉或夹爪某类 topic 缺失 | 生成 [[MissingIntervalIssue]] 或按配置失败 | `missing_topic` | 取决于配置和必需程度 |
| 触觉 `rows * cols` 与 `data` 长度不一致 | 生成 `tactile_shape_mismatch` 样本级问题 | evidence 记录 rows/cols/data_len | 默认不自动补全 |
| 阈值配置缺失 | 功能检验失败或生成 `inspect_required` | `missing_rule_config` | 是，除非该规则显式关闭 |
| 严重长段缺失 | 生成 [[MissingIntervalIssue]]，建议 `drop_or_mask_candidate` | reason 记录缺失持续时间 | 不允许 v1 自动插样本 |

## 13. 可验证样例

| 样例 | 输入特征 | 预期输出 | 验证方式 |
|---|---|---|---|
| 合法输入 | 位姿连续、触觉 shape 正常、夹爪在 `[0, 1]` | `sample_issues=[]`、`missing_interval_issues=[]` | 最小 cleaned MCAP fixture |
| 缺失输入 | 某 topic 中间存在超长采样间隔 | [[MissingIntervalIssue]] | 合成 topic 序列单元测试 |
| 边界输入 | 触觉单帧矩阵突增或 shape 不一致 | [[SampleReliabilityIssue]]，`field_path=tactile.frame` | 触觉 fixture 测试 |
| 位姿跳变 | TCP 位置相邻帧突变 | [[SampleReliabilityIssue]]，建议 `mark_only` 或 `inspect_required` | 位姿序列规则测试 |
| 夹爪异常 | 归一化值越界或长期不变 | [[SampleReliabilityIssue]] 和可选 [[ReliabilityIssueGroup]] | 夹爪序列规则测试 |

## 18. 给 L3 任务生成的约束

1. 每个 L3 只能解决一个核心目标。
2. 异常检测 L3 不得修改 MCAP 或补全任何值。
3. 异常检测必须运行在补全和滤波之前。
4. 已有样本问题必须输出 [[SampleReliabilityIssue]]，不得退回时间段主接口。
5. 无样本缺失必须输出 [[MissingIntervalIssue]]，不得由 v1 补全器插入新消息。
6. 触觉首版必须纳入正式范围，不得降级为仅未知问题。
7. 自动化验收至少覆盖一个位姿异常、一个触觉异常和一个夹爪异常。
8. 每个 Service 场景 L3 必须写明它对应或影响 `./start_data_clean.sh --dev` 下的场景二功能检验项或场景完整 smoke test。
9. L3 自动化验收只证明局部实现正确；场景最终验收必须由用户本人运行 `./start_data_clean.sh --dev` 后确认。
