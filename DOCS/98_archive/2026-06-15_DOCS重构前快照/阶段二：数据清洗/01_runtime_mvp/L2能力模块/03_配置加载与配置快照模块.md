# L2 能力模块说明：配置加载与配置快照模块

## 1. 能力名称

```text
Runtime MVP / 配置加载与配置快照模块
```

## 2. 所属位置

阶段：阶段二：数据清洗  
L1：`runtime_mvp`  
场景：Runtime MVP，不归入 `02_service` 的具体业务场景  
模块类别：数据读写类  
来源功能模块清单：[[功能模块清单]]

## 3. 一句话目标

```text
读取本次 Runtime 运行配置，应用临时覆盖项，生成最终生效配置，并把它写入 run 目录中的 config_snapshot.yaml。
```

## 4. 能力角色

```text
本能力是 Runtime MVP 的配置取证能力，负责让后续预检查、调度、日志和 manifest 共享同一份已落盘的生效配置。
```

它承接 [[RunContext]] 与 [[RunDirectoryLayout]]，产出 [[EffectiveRuntimeConfig]] 和 [[ConfigSnapshot]]。它不负责深度校验配置是否满足某个场景的业务必需字段。

## 5. 上游关系

- 来自 [[RunContext]] 的配置路径、运行模式、目标场景和后续可选入口参数。
- 来自 [[RunDirectoryLayout]] 的 `config_snapshot.yaml` 目标路径。
- 来自现有阶段二配置文件的配置内容，例如 `config/data_clean/data_clean_calibrated.yaml` 和 `config/data_clean/data_clean_smoke_test.yaml`。
- 来自用户确认的设计结论：配置快照保存“最终生效配置”，即默认配置、用户指定配置和本次临时覆盖参数合并后的结果，同时记录原始配置来源和覆盖项来源。

## 6. 下游关系

- 配置预检查模块消费 [[EffectiveRuntimeConfig]]，检查全局配置和场景配置是否完整、合法、可追溯。
- 输入产物预检查模块消费 [[EffectiveRuntimeConfig]] 中的输入路径和场景相关路径。
- 场景注册与 Service 调度模块消费 [[EffectiveRuntimeConfig]] 中对 Service 调用有影响的配置。
- 结构化日志模块记录 [[RuntimeConfigSource]]、[[ConfigOverrideSet]] 和 [[ConfigSnapshot]] 路径。
- Manifest 与错误摘要模块消费 [[ConfigSnapshot]]，追溯本次运行到底使用了什么配置。
- Runtime smoke test 模块验证配置加载成功路径、缺配置失败路径和快照写入路径。

## 8. 职责边界

本能力负责：

1. 确定本次运行的 [[RuntimeConfigSource]]。
2. 读取配置文件并应用 [[ConfigOverrideSet]]。
3. 生成 [[EffectiveRuntimeConfig]]。
4. 将最终生效配置写入 [[ConfigSnapshot]]。
5. 在 [[RunContext]] 或等价运行事实中登记 `config_snapshot_path`。

本能力不负责：

1. 判断配置字段是否满足所有场景业务要求。
2. 检查输入 MCAP、cleaned、validated、aligned 或 canonical dataset 是否存在。
3. 创建 [[RunDirectory]] 或 `outputs/` 子目录。
4. 调用 fake service 或真实 service。
5. 写入 `run_log.json`、`processing_manifest.json`、`error_summary.json` 或 `run_result.json`。

## 9. 读写职责

本能力负责的读写动作：

| 动作 | 读取来源 | 写入目标 | 格式 | 下游消费者 |
| --- | --- | --- | --- | --- |
| 选择配置来源 | [[RunContext]]、入口参数、默认配置规则 | [[RuntimeConfigSource]] | 内存对象 / 后续 Types | 配置加载、本模块失败处理、日志 |
| 读取配置文件 | [[RuntimeConfigSource]] 指向的配置文件 | [[EffectiveRuntimeConfig]] 的原始配置部分 | YAML | 配置预检查、输入预检查、调度 |
| 应用临时覆盖项 | [[ConfigOverrideSet]] | [[EffectiveRuntimeConfig]] | 内存对象 / map | 配置预检查、日志、manifest |
| 写入配置快照 | [[EffectiveRuntimeConfig]]、[[RunDirectoryLayout]] | [[ConfigSnapshot]] / `config_snapshot.yaml` | YAML | 配置预检查、日志、manifest、smoke test |
| 回填快照路径 | [[ConfigSnapshot]] | [[RunContext]] 的 `config_snapshot_path` 或等价运行事实 | 路径语义 | 后续 Runtime 横切模块 |

## 10. 路径与命名规则

| 文件 / 目录 | 路径来源 | 命名规则 | 是否允许覆盖 | 创建时机 |
| --- | --- | --- | --- | --- |
| 原始配置文件 | [[RuntimeConfigSource]] | 用户显式路径、环境变量路径或默认配置路径 | 不允许本模块覆盖 | [[RunDirectory]] 创建后读取 |
| 配置快照文件 | [[RunDirectoryLayout]] | `config_snapshot.yaml` | 仅允许在本次新建 [[RunDirectory]] 内首次写入 | 配置读取和覆盖项应用成功后 |
| run 目录 | [[RunDirectory]] | 由 [[02_Run目录管理模块]] 定义 | 本模块不创建、不覆盖 | 本能力执行前必须已存在 |

## 11. 文件格式与内容契约

| 文件 | 格式 | 必填内容 | 可选内容 | 校验方式 |
| --- | --- | --- | --- | --- |
| 原始配置文件 | YAML | 可被解析为 mapping | 业务配置字段由后续模块解释 | 文件存在、可读、YAML 顶层为 mapping |
| `config_snapshot.yaml` | YAML | [[EffectiveRuntimeConfig]] 的最终生效配置、[[RuntimeConfigSource]]、[[ConfigOverrideSet]] | 内容 hash、写入时间、工具版本 | 文件写入成功、可重新读取为 mapping、路径位于 [[RunDirectory]] 内 |

## 12. 覆盖策略与幂等性

- 重复运行时如何处理：不同运行必须进入不同 [[RunDirectory]]；同一 run 目录内不重复初始化配置快照。
- 是否允许覆盖已有文件：不允许覆盖旧 run 的 `config_snapshot.yaml`；如果本次新 run 中快照文件已存在，应视为初始化冲突。
- 如何避免污染旧 run：配置快照只能写入 [[RunDirectoryLayout]] 提供的本次运行路径。
- 临时文件或半成品如何处理：第一版可以直接写目标文件；如果后续实现引入临时文件，临时文件必须位于同一 [[RunDirectory]] 内。

## 13. 失败处理

| 失败情况 | 判断方式 | 处理策略 | 错误信息要求 | 是否写入报告 |
| --- | --- | --- | --- | --- |
| 未找到配置文件 | [[RuntimeConfigSource]] 的 `config_path` 不存在 | 阻止后续预检查和调度 | 包含配置路径、来源类型和建议下一步 | 后续错误摘要模块若可用则写入 |
| 配置文件不可读 | 文件系统异常或权限不足 | 阻止后续预检查和调度 | 包含配置路径和底层错误摘要 | 后续错误摘要模块若可用则写入 |
| 配置文件不是 YAML mapping | 解析结果不是 mapping | 阻止生成 [[EffectiveRuntimeConfig]] | 包含配置路径和格式要求 | 后续错误摘要模块若可用则写入 |
| 覆盖项无法应用 | 覆盖路径冲突或覆盖结构不可表达 | 阻止写入 [[ConfigSnapshot]] | 包含覆盖项来源和冲突位置 | 后续错误摘要模块若可用则写入 |
| 快照路径逃逸 run 目录 | 路径规范化后不在 [[RunDirectory]] 内 | 阻止写入 | 包含非法路径和期望 run 目录 | 是 |
| 快照写入失败 | 文件系统异常或写后不可读 | 阻止后续预检查和调度 | 包含快照目标路径和失败原因 | 后续错误摘要模块若可用则写入 |

## 14. 整体完成标准

- [ ] 已建立 [[RuntimeConfigSource]]、[[ConfigOverrideSet]]、[[EffectiveRuntimeConfig]] 和 [[ConfigSnapshot]] 的原子数据定义。
- [ ] 本 L2 能力模块说明中出现的数据概念均使用 Obsidian 双向链接。
- [ ] 能从 [[RunContext]] 和入口默认规则确定本次 [[RuntimeConfigSource]]。
- [ ] 能应用空或非空 [[ConfigOverrideSet]]，生成 [[EffectiveRuntimeConfig]]。
- [ ] 能把最终生效配置写入 [[RunDirectory]] 内的 `config_snapshot.yaml`。
- [ ] 本 L2 没有混入配置预检查、输入产物预检查或 Service 调度职责。

## 17. 给 L3 任务生成的约束

后续从本 L2 生成 L3 任务时，必须遵守：

1. 每个 L3 只能解决一个核心目标。
2. 每个 L3 必须先判断任务类别，并使用对应 L3 类别模板。
3. 每个 L3 必须有明确输入、输出、修改边界、验收命令和成功标准。
4. 每个 L3 必须写明“本次不做什么”。
5. 每个 L3 不能跨越本 L2 的能力边界。
6. 如果需要修改本 L2 之外的模块，必须在 L3 文档中显式说明原因。
