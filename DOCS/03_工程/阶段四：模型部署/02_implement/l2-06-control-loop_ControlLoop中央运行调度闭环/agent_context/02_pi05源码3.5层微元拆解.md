# Pi0.5 源码 3.5 层微元拆解：L2-06

## 1. 参考范围与使用原则

Pi0.5 只提供 runtime 结构参考，不提供当前 ACT 的 L2 ownership 或数据契约。当前 ACT 必须保持 16D、L2-03 同步 service、L2-04 `SafetyResult`、L2-05 `ActionPublishRequest/Result` 和第一版无 smoothing 的边界。

| Pi0.5 源码 | 关键对象 | ACT 复用判定 |
|---|---|---|
| `deploy/src/pi05/deploy/runtime/shared_buffer.py:62-102` | `InferenceRequest`、`LatestQueue` | 结构复用；由 L2-06 自己实现并补 close/阻塞唤醒/淘汰计数 |
| `.../shared_buffer.py:106-153` | `RuntimeMetrics` | 结构复用；改成线程安全 mutable owner + immutable snapshot |
| `.../shared_buffer.py:156-242` | `SharedBuffer` | 不复用 class；ACT 已有 L2-02 `ObservationBuffer`，L2-06 只新增推理 channel 与 metrics，禁止复制 observation slot |
| `.../inference_worker.py:15-91` | `InferenceWorker` | 结构复用；当前 ACT ownership 为 L2-06，不是 L2-03 |
| `.../control_loop.py:37-56` | `is_action_chunk_usable()` | 结构复用；age 改从 L2-06 `InferenceResult` 读取，不能要求 L2-03 `ActionChunk` 带时间 |

## 2. Pi0.5 实际运行链

```text
ROS callback
  -> SharedBuffer.latest_observation

ControlLoop.tick
  -> 收 result queue
  -> 必要时投 InferenceRequest
  -> active/pending/blend 选择 action
  -> SafetyGuard
  -> 返回 ControlCommand

InferenceWorker thread
  -> 取 latest request
  -> policy_runtime.predict_action_chunk
  -> 构造带 request/time/cursor 的 ActionChunk
  -> 写 result queue

Pi05VlaDeployNode._control_tick
  -> ControlLoop.tick
  -> node 直接发布四路硬件 topic
```

这一结构解释了“timer 不等待 GPU”以及为何 worker/queue/cursor 必须与 ControlLoop 属于同一个运行调度 L2；但 Pi0.5 的数据字段和直接硬件输出不能照搬。

## 4. class 打包表

| class | state | 打包微元 | 生命周期 / 并发 | 为什么是 class | ACT 建议 |
|---|---|---|---|---|---|
| Pi0.5 `LatestQueue` | deque、lock | put/take/len | callback/worker/tick 共享 | 共享可变状态 | 保留为 L2-06 `LatestQueue[T]`；增加 close/Condition |
| Pi0.5 `RuntimeMetrics` | counters/gauges | record/snapshot | worker + tick 并发 | 指标需原子更新 | 保留为 L2-06 class，并返回 frozen snapshot |
| Pi0.5 `SharedBuffer` | observation、queues、metrics | 多种共享状态 | callback/worker/tick | 旧代码聚合过多 | 拆分：observation 复用 L2-02；queue/metrics 归 L2-06 |
| Pi0.5 `InferenceWorker` | thread/event/period | request→inference→result | 后台线程 | 隔离阻塞 policy call | L2-06 新增；一个 service 一个串行 worker |
| Pi0.5 `ControlLoop` | active/pending/cursor/request/fallback | tick 状态机 | ROS timer 单线程调用 | 状态跨 tick | L2-06 新增；删除 blend/alignment，加入 publish reducer/fault latch |
| Pi0.5 deploy node | ROS handles/timers/worker | composition、I/O、shutdown | ROS node 生命周期 | 外部世界入口 | ACT `ActDeployNode`；只装配，不吞并 L2-02～05 算法 |

## 5. Pi0.5 不能直接复用的缺陷

1. Pi0.5 worker 捕获 policy 异常后只记 metrics，不写 result；ControlLoop 的 `request_pending` 可能永远无法清除。ACT 必须产出 error `InferenceResult`。
2. Pi0.5 把 request/time/cursor 写进 `ActionChunk`；当前 L2-03 明确禁止这些字段。ACT 必须用 L2-06 envelope。
3. Pi0.5 `SharedBuffer` 同时拥有 observation、queue 和 metrics；会吞并当前 L2-02 `ObservationBuffer` ownership。
4. Pi0.5 age 使用 monotonic observation time；当前 ACT `ObservationSnapshot.captured_at_s` 实现仍是 wall clock。这是进入 L2-06 前必须修复的代码 FAIL。
5. Pi0.5 node 直接发布硬件 topic；ACT 必须构造 `ActionPublishRequest` 并只调用 L2-05。
6. Pi0.5 使用旧 `accepted/reason` safety 语义；ACT 使用 `PASS/ADJUSTED/REJECTED + findings`。
7. Pi0.5 safe-stop 只是返回 `None`，并不代表驱动器已停止。ACT 也不能把“没有新 command”写成“物理 stop 已执行”。

## 6. ACT 复用结论

- **直接复用的思想**：timer/worker 解耦、latest-only channel、active/pending、cursor、metrics、显式 shutdown。
- **结构复用后重写**：request/result、chunk age 校验、fallback、node composition。
- **仅参考理解**：SharedBuffer 聚合、直接 ROS publish、旧 ControlCommand。
- **明确不复用**：smoothstep、blend、RTC/aligned cursor、旧 action/state 维度和旧 safety accepted 字段。
