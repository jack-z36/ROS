# L2-05 · 硬件执行栈（独立子系统）

> [!info] 归属
> - 对应分层：**独立新子系统**（自含 Types/Config/Repo/Service/Runtime/UI）。
> - 上游：[[00_L2改造工作包总览]]；通过 `/pi05/policy_action` topic（UI 契约）连接 L2-04。
> - 关联 Delta：D1（拓扑）、D2（launch）、D5（RM65）、D6（夹爪）、D14（bridge）、D15（arm msg）、D16（gripper msg）、D19（失败语义）。

> [!danger] 真机风险最高
> 本工作包直接接触 RM65 机械臂和大象夹爪硬件。必须最后实现，且在 L2-01~04 全部 dry-run/shadow-run 验证通过后才进入。任何改造必须有可回滚路径（节点不启动即回滚）。

## 一句话定位

新建 `command_bridge_sender_node`（policy action → 硬件指令的桥梁，含安全门控）+ RM65/夹爪适配节点 + 新 launch，把整套拓扑从 picotele 切换到 RM65+大象夹爪。这是真机执行的核心，也是风险最高的一层。

## 对应分层

本工作包是一个**独立子系统**，内部自含完整分层：

| 子系统层 | 内容 |
|---|---|
| Config | launch 参数（arm_ip、夹爪串口、gate 配置） |
| Repo | 订阅 `/pi05/policy_action` + arm/gripper 状态 topic |
| Service | 16D 解析、IK 预检、width→angle 转换、workspace 检查 |
| Runtime | 节点生命周期、RM65 SDK 连接管理 |
| UI | 发布 `/pi05/command/*` + `/pi05/command/status` |

与 L2-01~04 **无代码依赖**，只通过 `/pi05/policy_action` topic 解耦。

## 真实改造边界

### 新建 `command_bridge_sender_node`

职责：收 `/pi05/policy_action`(16D) → 安全检查 → 拆成 PoseStamped + Float64 → 发硬件命令 → 写 status。

**输入**（订阅）：
- `/pi05/policy_action`（Float32MultiArray 16D）
- `/pi05/observation/arm/left_tcp_pose`、`/right_tcp_pose`（PoseStamped，用于 IK 预检的 q_in + workspace 锚点）
- `/pi05/observation/gripper/left_state`、`/right_state`（Float32，width，用于步长限制）
- 急停/enable/deadman 物理开关（topic 或服务）

**输出**（发布）：
- `/pi05/command/arm/left_target`、`/right_target`（PoseStamped，quaternion）
- `/pi05/command/gripper/left_target`、`/right_target`（Float64，angle[0,100]）
- `/pi05/command/status`（String JSON：action_id/safety_ok/sent_to_driver/failure_reason）

**发送前检查**（Q5 七步，按序）：
1. action 维度 = 16D
2. 全部 finite
3. quaternion 归一化
4. workspace 几何检查
5. `rm_inverse_kinematics` 预检（flag=0 四元数，不执行只查）
6. gripper_width ∈ [0,1] → 映射 angle ∈ [0,100]
7. enable/急停/deadman gate

**mode/gate 逻辑**（Q4）：
- shadow-run：gate 关，不发硬件命令，但 `/pi05/command/status` 记录 `safety_ok=true, sent_to_driver=false`。
- safe-run：gate 开，发硬件命令。
- 急停/deadman 物理开关在任何 mode 下可即时切断。

### 新建 `rm65_driver_node`（适配层）

**状态发布角色**：把厂商 `rm_pose_t`/UDP 推送的 `waypoint.quaternion` 转成 `/pi05/observation/arm/*_tcp_pose`（PoseStamped，quaternion xyzw 归一化，position 单位 m）。若厂商只给 euler 则 driver 内 euler→quaternion。

**命令执行角色**：收 `/pi05/command/arm/*_target`（PoseStamped）→ 调 `movep_canfd` 的 `pose_quat` 模式（quaternion ×1e6 定点数）→ 驱动机械臂。记录 SDK 返回码。

> [!note] 复用厂商 rm_driver
> 不重写 RM65 底层驱动。本节点是「适配层」：把厂商 topic/API 包装成 Pi05 约定的 topic 语义。状态发布和命令执行可耦合在同一节点（TO-BE Contract 已说明）。

### 新建 `elephant_gripper_node`（适配层）

**状态发布角色**：读大象夹爪寄存器值 angle[0,100] → 映射成 width[0,1] → 发 `/pi05/observation/gripper/*_state`（Float32）。

**命令执行角色**：收 `/pi05/command/gripper/*_target`（Float64，angle[0,100]）→ 调大象夹爪 modbus/SDK → 驱动夹爪。

> [!warning] width↔angle 映射需硬件标定
> 理论 `width=angle/100`，但闭合点/全开点的真实寄存器值需用大象夹爪实物实测标定。标定完成前不接真机（Contract Delta D16 已标注）。

### 新建 launch

`pi05_rm65_deploy.launch.py`：拉起 fisheye_camera_node + tactile_sensor_node（第一版可选）+ rm65_driver_node + elephant_gripper_node + Pi05VlaDeployNode + command_bridge_sender_node。旧 launch 保留作回滚。

## adapter 优先策略

本 L2 全是**新建节点**，无「改造旧代码」问题。command_bridge_sender_node 是核心抽象（深 L2），对外只暴露 `/pi05/command/*` 和 `/pi05/command/status`。

厂商驱动用**适配层包装**（rm65_driver_node / elephant_gripper_node），不修改厂商 SDK 源码。

## 真机风险

**最高**。直接驱动 RM65 机械臂和大象夹爪。

**强制保护**：
- 进入本 L2 前，L2-01~04 必须 dry-run + shadow-run 通过。
- shadow-run 下 bridge gate 关闭，验证整条链路（policy_action → bridge 检查 → status）但机械臂不动。
- safe-run 前必须完成 width↔angle 硬件标定。
- 急停/deadman 物理开关必须优先于一切软件 gate。

## 验收路径

1. **dry-run（bridge 独立）**：启动 bridge，喂构造的 policy_action，看 `/pi05/command/*` 输出 + status。不启动 rm65/gripper 执行节点。
2. **shadow-run（全链路，机械臂不动）**：mode=shadow-run，policy_action → bridge 检查 → status 显示 `sent_to_driver=false`，机械臂纹丝不动。
3. **IK 预检测试**：构造不可达 TCP 目标，断言 bridge 拒绝并写 failure_reason。
4. **width→angle 映射测试**：width=0→angle=0，width=1→angle=100，中间值线性。
5. **real-robot smoke test（safe-run）**：mode=safe-run，给一个安全的保守 action（如「保持当前位姿」），看机械臂是否按预期运动；急停测试。

## 回滚方式

- bridge/适配节点不启动 → policy_action 仍可独立 dry-run（L2-04 不受影响）。
- 切回旧 launch（pi05_picotele_mux）+ 旧 config + 旧 bundle（Q7 三件套）。
- 厂商 rm_driver / 夹爪 SDK 不受本 L2 影响（适配层删除即可）。
