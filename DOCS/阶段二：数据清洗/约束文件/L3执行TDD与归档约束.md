# L3 执行 TDD 与归档约束

本文约束阶段二 L3 微元任务的实际执行方式。只要 L3 涉及代码新增、代码修改、bug 修复或行为变更，执行 Agent 必须按本文执行。

执行阶段二 L3 前必须先确认当前分支是该 L3 所属 L1 feature 分支。Runtime MVP 使用 `runtime-mvp`；Service 使用 `feature/stage2-service`。如果当前分支是 `main` 或其他不匹配分支，必须停止并提示切换，不得继续执行。

## 一、必须使用 TDD 技能

执行代码类 L3 前，必须读取并使用 Codex 环境中可用的 `$tdd` 技能：

```text
$tdd
```

执行方式采用垂直切片 TDD：

1. 先为一个可观察行为写测试或最小复现。
2. 确认测试失败，或说明当前环境无法运行失败验证的具体原因。
3. 写最少代码让该行为通过。
4. 运行对应测试。
5. 只在测试为 green 后做必要整理。
6. 再进入下一个行为。

不得一次性写完大量测试后再整体实现；不得绕过公共接口直接测试内部实现细节；不得借 TDD 名义扩大 L3 范围。

## 二、Python 命令统一使用 python3

代码执行环境不保证存在 `python` 指令。阶段二 L3 中所有 Python 执行命令、验收命令、示例命令和交接记录必须使用：

```bash
python3
```

不得写成：

```bash
python
```

如果某个工具链只能通过 `python` 调用，必须先在交接中说明原因，并优先寻找等价的 `python3` 调用方式。

## 三、项目文件路径统一使用相对路径

阶段二 L3 文档、执行记录和交接摘要中，凡是引用仓库内文件或目录，都必须使用相对仓库根目录的路径，例如：

```text
DOCS/阶段二：数据清洗/03_tasks/task/active/<功能组>/
DOCS/阶段二：数据清洗/03_tasks/task/completed/<功能组>/
src/data_clean/
```

不得写入开发者本机的绝对路径、Windows 盘符路径或某台机器特有的工作区路径。

外部 Agent 技能只写技能名，例如 `$tdd`，不写技能在某台机器上的安装路径。

## 四、执行前必须读取相关微元任务记录

执行 L3 前，除当前 L3 文件列出的必读文档外，还必须读取与当前任务直接相关的历史记录：

1. `DOCS/阶段二：数据清洗/03_tasks/README.md`
2. 当前 L3 所属 L2 能力模块说明。
3. 当前 L3 直接依赖的上游 L3 文件，优先同时检查 `task/active/<上游功能组>/` 与 `task/completed/<上游功能组>/`。
4. 同一功能组下已经完成的 L3 任务文件。
5. 当前 L3 文件明确列出的其他必读历史记录。

如果找不到相关记录，必须在执行摘要中写明“未找到相关 L3 历史记录”，不能假装已经对齐。

## 五、完成后必须更新任务文件

L3 完成后，必须先更新当前 L3 任务文件，再移动归档：

1. 在“成功标准”中，把已经实际验证通过的条目从 `- [ ]` 改为 `- [x]`。
2. 未验证或未完成的条目保持 `- [ ]`，并在执行摘要中说明原因。
3. 在任务文件末尾追加“执行摘要”，写明实际修改文件、测试/验收命令、结论和遗留风险。
4. 只有成功标准已经处理完毕后，才能把任务文件从 `DOCS/阶段二：数据清洗/03_tasks/task/active/<功能组>/` 移到 `DOCS/阶段二：数据清洗/03_tasks/task/completed/<功能组>/`。

不得完成代码后只口头交接；不得让已完成 L3 长期停留在 `task/active/<功能组>/`；不得移动到 `task/completed/<功能组>/` 后仍留下未解释的空成功标准。

Ubuntu L3 执行端禁止写入 `DOCS/阶段二：数据清洗/执行记录/`、阶段/场景 `当前进度.md`、共享 `执行记录.md` 或 `DOCS/总执行日志.md`。如需阶段汇总，只能在当前 L3 执行摘要中建议 Win 端后续整理。

## 六、交接摘要最低要求

交接摘要必须包含：

1. 本次读取了哪些相关 L3 任务文件或执行记录。
2. 本次使用 TDD 的 red / green / refactor 过程；如果无法完整执行，说明具体阻塞。
3. 实际修改了哪些文件。
4. 新增或修改了哪些函数、类、配置或测试。
5. 运行了哪些验收命令，命令必须使用 `python3`。
6. 哪些成功标准已勾选，哪些未勾选以及原因。
7. 是否已从 `task/active/<功能组>/` 移动到 `task/completed/<功能组>/`。
