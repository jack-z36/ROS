# 阶段二：数据清洗背景信息

## 给后续 Codex 的一句话

阶段二的核心不是“把 MCAP 另存一次”，而是把 raw topic 日志逐步变成 step 级 observation/action 数据。当前已经跑通到临时双臂 LeRobot v3 格式；正式 canonical dataset 和 UMI 相对 action 仍是后续目标。

## 核心概念

### topic 世界

raw/cleaned/MCAP_A/aligned MCAP 都仍然是 MCAP 文件。MCAP 内部按 ROS2 topic 存放消息，每个 topic 有自己的频率、时间戳和 schema。图像、位姿、触觉、夹爪宽度在 raw topic 世界中不天然对齐。

### step 世界

训练数据需要按统一 step 组织：

```text
step_t = observation_t + action_t
```

场景三会生成统一 step 时间轴，并把多个 topic 的消息或派生值对齐到每个 step。

### MCAP_A

MCAP_A 是场景二之后、场景三之前的主数据中间产物。它的目标是承载经过可靠性检测、修复和滤波后的主数据，使场景三可以基于更稳定的输入做时间对齐。

相关 runtime 入口包括：

- `runtime/scene2_signal_reliability.py`
- `runtime/scene2_signal_repair.py`
- `runtime/scene2_pose_filter.py`
- `runtime/scene2_tactile_filter.py`
- `runtime/scene2_mcap_a_writer.py`

### aligned MCAP

aligned MCAP 是场景三输出。它不直接等同于训练格式，而是一个语义清晰、按 step 对齐后的 MCAP bundle。当前语义字段包括：

- 双目图像：`/gopro_left/image_raw`、`/gopro_right/image_raw`
- 双臂 TCP pose：`/aligned/left_tcp_pose`、`/aligned/right_tcp_pose`
- 双夹爪宽度：`/aligned/left_gripper_width`、`/aligned/right_gripper_width`
- 四路触觉统计：`/aligned/tactile_left_gripper_1`、`/aligned/tactile_left_gripper_2`、`/aligned/tactile_right_gripper_1`、`/aligned/tactile_right_gripper_2`

相关代码入口：

- `runtime/scene3_full_flow_check.py`
- `service/field_aligner.py`
- `service/pose_field_aligner.py`
- `service/tactile_field_aligner.py`
- `repo/aligned_mcap_writer.py`

### Forge bridge

Forge bridge 是当前临时训练格式桥接层。它消费 aligned MCAP，生成单独的 Forge-ready MCAP 和 sidecar：

```text
04_forge_bridge/
├── forge_ready.mcap
├── forge_topic_config.yaml
├── forge_bridge_schema.json
└── forge_bridge_report.json
```

它的职责是把 aligned MCAP 中的语义字段拼成 LeRobot v3 需要的 `observation.state` 和 `action`，并保留双目图像。

相关代码入口：

- `service/forge_bridge.py`
- `runtime/forge_bridge_check.py`
- `runtime/forge_bridge_to_lerobot.py`

### 网页批次 dataset 构建

正常网页入口不是单文件清洗器，而是批次 LeRobot v3 dataset 构建器。用户勾选多个 raw MCAP 后，每个文件独立执行：

```text
raw -> cleaned -> MCAP_A -> aligned -> Forge bridge
```

所有成功 bridge episode 再聚合为一个最终 dataset。普通单文件失败只记录错误摘要，不阻止其他成功文件发布；批次取消则回滚本批次已发布产物。

最终 dataset 与中间产物分开存放：

```text
<用户选择的本机父目录>/<dataset_name>/                 # 最终 LeRobot dataset
asset/阶段二：数据清洗/dev/debug/web_jobs/
  <dataset_name>_data_clean_sidecar/                   # 中间产物、日志和报告
```

网页默认建议 `asset/阶段二：数据清洗/prod/exports/lerobot/`，但允许用户自由选择任意本机最终输出父目录，不做路径限制或风险提示。该自由选择是 `约束文件/文件存放规范.md` 中的受控例外，只适用于最终 dataset；sidecar、cleaned、MCAP_A、aligned、bridge、日志和缓存仍留在受控目录。

### 网页结果可视化

网页结果页从最终发布 dataset 和 sidecar 报告读取数据，提供：

- Forge quality 总分、维度分数条、逐 episode 分数和 flags。
- 左右 TCP 3D 轨迹。
- 每个 MCAP 是否纳入最终 dataset、episode 数量、阶段产物和失败原因。
- 按需启动 Forge Web Viewer 的入口。

3D 轨迹采用固定右手坐标系工程视角，显示局部原点固定在左下角。显示局部原点取当前视图 `bounds.min`，不是物理坐标 `(0, 0, 0)`；原始坐标仍保留在摘要和轨迹样本中。单个 episode 可按原始时间戳播放；全部 episode 只展示静态总览。

坐标系必须区分：

- `format-only`：旧 `common_frame` 双手轨迹可以叠加展示。
- `formal`：左右 TCP 分别属于 `left_arm_base` 和 `right_arm_base`，必须分屏同步播放，不能假设双手处于同一个世界坐标系。

轨迹数据来自最终发布 dataset 的 `data/chunk-*/file-*.parquet`。网页通过 `GET /api/jobs/{job_id}/trajectory` 按需生成或读取 `reports/trajectory_summary.json`；旧历史缓存缺少新版字段时，会补齐左右 bounds、坐标系 profile 和投影提示。

## 时间域规则

阶段二处理 MCAP 时必须区分三个常见时间来源：

- `header.stamp`：ROS 消息内部时间，通常表示传感器采样时刻。
- `publish_time`：MCAP 消息发布/写入时刻，更接近采集管线实际接收时刻。
- `log_time`：MCAP 日志记录时间，通常作为最后兜底。

当前实现规则：

- 图像优先使用 `header.stamp`，因为左右相机帧在该时间域更稳定。
- 触觉优先使用 `header.stamp`，因为 PressureFrame 的采样时间应以传感器时间为准。
- 位姿优先使用 `publish_time`，因为设备时钟可能不同步，直接使用 pose 的 `header.stamp` 可能造成跨设备时间域错位。
- 缺失可用时间时再回退到 `log_time`。

相关实现集中在：

- `repo/ros2_codec.py`
- `repo/mcap_topic_catalog.py`
- `runtime/scene3_full_flow_check.py`

## 双臂数据语义

当前临时 LeRobot bridge 的最小语义单元是：

```text
observation.images.left/right
observation.state: 32 维
action: 16 维
```

`observation.state` 包含双臂绝对 TCP pose、双夹爪宽度和四路触觉统计。触觉每路来自 PressureFrame 的 `6 x 15` 矩阵，在 half-step 时间窗内聚合为：

```text
mean, std, min, max
```

`action` 从同一组 pose/gripper 序列取下一 step 的绝对目标：

```text
action_t = left/right tcp pose 与 gripper width at t+1
```

因此输出 step 数等于完整 aligned step 数减 1。

## format-only 与 formal

当前桥接有两种模式：

- `format-only`：允许用旧 common pose 做格式烟测，固定 `training_eligible=false`。它只能证明链路和格式能跑通。
- `formal`：只接受 arm-base pose 与已完成标定的配置；缺少标定、字段缺失、非有限值、夹爪超出 `[0,1]`、位姿超过默认 `10m` 等情况会阻止导出。

已验证的真实样例属于 `format-only`，所以 Forge quality 分数只能作为格式和数据粗检参考，不能作为正式训练可用结论。
