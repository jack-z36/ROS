# 优化程序加载规则

## 适用范围

优化已有程序的性能、代码结构、实现方式或行为。用户可能要求改变原有行为边界，此时用户新意图的优先级高于开发阶段的原有目标。不包括：新增功能模块（走 04 L3 微元任务执行）或单纯解释原理（走 02 知识查询）。

## 触发信号

- "优化""改进""重构""提升性能""简化""改造""换一种实现方式"。
- 用户要求改变已有程序的行为或实现，但没有指定 L3 文件，也不是明显 debug。

## 上下文加载顺序

1. 明确用户的优化目标和允许修改范围。
2. 读取涉及阶段的必要知识页，仅作为理解当前实现的参考，不作为优化方向的依据。
3. 读取 `DOCS/02_约束/编程执行/Agent编程执行原则.md`，确认修改边界和验收闭环。
4. 如果涉及架构边界、跨层依赖、公共 type / schema / provider / adapter，读取 `DOCS/02_约束/编程执行/架构边界与机械约束原则.md`。
5. 如果涉及文件落点变更，读取对应文件存放约束。
6. 读取当前代码实现并实施优化。

## 意图隔离规则（本规则特有）

优化任务中，用户的优化意图是唯一行为权威。阶段知识页、原有开发目标、历史设计文档中的"阶段目标""设计意图""契约约定"只作为理解当前实现的技术参考，不得作为阻止优化或限定优化方向的依据。

当用户的优化目标与现有文档中的阶段目标冲突时：

- 以用户当前指明的优化目标为准，不被旧阶段文档的既定目标牵引。
- 在实现中明确标注行为变更点和原因。
- 优化完成后，如有必要，提醒用户更新对应知识文档以反映新行为。

## 必读入口

- `DOCS/02_约束/编程执行/Agent编程执行原则.md`
- 涉及阶段的 `DOCS/01_知识/<阶段>/` 相关主题页（仅作实现参考）
- 相关约束文件（文件存放、架构边界等）

## 禁止默认读取

- `DOCS/98_archive/`
- `DOCS/99_learning/`
- 与优化目标不直接相关的阶段工程记录

## 阻断条件

- 用户未指明优化目标和允许修改范围。
- 优化需要新增功能模块但未提供 L3 路径。
- 目标文件落点违反文件存放规范。
- 用户意图存在自相矛盾或无法执行的约束。

## 输出要求

说明优化前后的行为差异、修改范围、验证结果和仍待同步的知识文档。
