# L2 能力模块说明：触觉滤波器

## 1. 能力名称

```text
触觉滤波器
```

## 2. 所属位置

阶段：阶段二：数据清洗
L1：service_s2
场景：场景二：硬件数据可靠性验证
模块类别：数据计算类
来源功能模块清单：`DOCS/阶段二：数据清洗/02_service/场景二/功能模块清单.md`

## 3. 一句话目标

```text
对数据补全器输出的触觉压力矩阵序列做逐 cell 时间平滑，降低噪声并保留真实接触变化，同时保持 topic、时间戳、排序和样本数量不变。
```

## 4. 能力角色

本能力是场景二 P0 预处理链路中“数据补全器”和 [[McapA|MCAP_A]] 生成器之间的 tactile 平滑层。它只处理补全后的 [[TactilePressureFrame]] 序列，输出 [[TactileFilterResult]] 和滤波后触觉序列引用，供 [[McapA|MCAP_A]] 生成器写入主数据 MCAP。

已按 `grill-me` 约束完成意图澄清：触觉滤波器 v1 采用逐 cell 时间滤波；默认使用短窗口中值 + EMA；真实接触突变处重置 EMA；主审计记录只保存摘要，完整矩阵 diff 只在开发者调试产物中输出。

## 5. 上游关系

- 直接上游是 [[数据补全器]]。
- 输入修复结果为 [[SignalRepairResult]]。
- 补全后 tactile 序列通过 [[TactileFilterInputSequence]] 表达。
- 触觉样本语义来自 [[TactilePressureFrame]]。
- 样本定位复用 [[SignalSampleRef]]。
- 无样本缺失区间复用 [[MissingIntervalIssue]]，滤波不得跨越。
- tactile 相关 `unrepaired` / `skipped` 样本来自 [[SignalRepairRun]] 和 [[SignalRepairSampleRecord]]，必须作为分段边界。

## 6. 下游关系

- [[McapA|MCAP_A]] 生成器消费滤波后触觉序列和 [[TactileFilterResult]]。
- Parquet 标注与验证报告生成器消费 [[TactileFilterSampleRecord]]、[[TactileFilterSegmentSummary]] 和 reset / skipped 记录。
- 开发者入口 `scene2_tactile_filter` 展示滤波前后差异、接触变化 reset、跳过样本和运行日志。

## 7. 上游接口对齐检查

| 上游功能 | 上游接口 / 产物 | 本能力如何依赖 | 对齐状态 | 处理方式 |
|---|---|---|---|---|
| 异常值检测器 | [[MissingIntervalIssue]] | 作为触觉滤波硬边界，不跨缺失区间平滑 | 已对齐 | 复用 |
| 数据补全器 | [[SignalRepairResult]] | 读取 `output_sequence_refs`、`repair_runs`、`unhandled_missing_interval_records` 和 `timestamp_policy` | 部分对齐 | 通过 [[TactileFilterInputSequence]] 定义语义接口；具体 artifact 格式由数据补全器 L3 固化 |
| 补全样本记录 | [[SignalRepairRun]]、[[SignalRepairSampleRecord]]、[[RepairDecisionStatus]] | 将 tactile 相关 `unrepaired` / `skipped` 样本作为分段边界 | 已对齐 | 复用 |
| 场景一 cleaned MCAP 触觉 topic | [[TactilePressureFrame]] | 作为触觉矩阵字段、shape 和 topic 来源 | 已对齐 | 复用 |

## 8. 职责边界

本能力负责：

1. 将 [[SignalRepairResult]] 的 tactile 输出解释为 [[TactileFilterInputSequence]]。
2. 基于 [[MissingIntervalIssue]]、tactile 相关未修复样本和 shape 有效性切分连续可靠片段。
3. 对每个触觉矩阵 cell 沿时间执行短窗口中值滤波和 EMA。
4. 在真实接触变化处重置 EMA，避免跨接触起止边缘平滑。
5. 输出 [[TactileFilterResult]]、[[TactileFilterSegmentSummary]] 和 [[TactileFilterSampleRecord]]。
6. 在开发者调试模式下可输出完整矩阵 diff artifact。

本能力不负责：

1. 不重新做异常检测。
2. 不补全、插入、删除或重采样消息。
3. 不修改 topic 名称、时间戳结构、排序、shape 或样本数量。
4. 不做空间卷积或接触语义分类。
5. 不处理位姿或夹爪滤波。
6. 不写 [[McapA|MCAP_A]]。
7. 不决定最终 episode 丢弃或训练 mask。

## 9. 计算职责

| 计算项 | 输入 | 输出 | 影响下游 |
|---|---|---|---|
| 输入语义对齐 | [[SignalRepairResult]]、[[TactileFilterInputSequence]] | 可滤波 tactile topic 序列 | 避免直接猜测补全 artifact 格式 |
| shape 有效性检查 | [[TactilePressureFrame]] | 可滤波序列或错误记录 | 防止错误矩阵进入滤波 |
| 分段边界构建 | [[MissingIntervalIssue]]、tactile `unrepaired` / `skipped` 样本 | 连续可靠片段 | 防止滤波跨坏段扩散 |
| 接触变化边界 | 相邻触觉帧、[[TactileFilterConfig]] | EMA reset 点 | 保留真实接触起止变化 |
| 逐 cell 中值滤波 | 片段内触觉矩阵 | 去孤立尖峰候选序列 | 降低单帧尖峰 |
| 逐 cell EMA | 中值输出、reset 点 | 滤波后矩阵序列 | 降低连续高频噪声 |
| 样本级审计 | 原始矩阵、滤波矩阵 | [[TactileFilterSampleRecord]] | 报告和开发者复查 |
| 结果聚合 | 样本记录、片段摘要、序列引用 | [[TactileFilterResult]] | MCAP_A 和报告生成器消费 |

## 10. 计算规则

| 规则 | 触发条件 | 计算 / 判断方式 | 结果表达 |
|---|---|---|---|
| 只消费补全后 tactile | [[SignalRepairResult]] 已存在 | 通过 [[TactileFilterInputSequence]] 读取补全后触觉序列 | 输入接口记录 |
| 保持时间结构 | 任意输入 topic | 不新增、不删除、不重采样、不改时间戳 | `timestamp_policy=preserve_original` |
| shape 检查 | 每帧触觉矩阵 | 检查 `rows * cols == len(data)` 且同一序列 shape 一致 | `invalid_shape` |
| 缺失区间分段 | 出现 [[MissingIntervalIssue]] | 缺失区间两侧分别滤波 | [[TactileFilterSegmentSummary]] |
| 未修复样本分段 | tactile 相关 `unrepaired` / `skipped` | 该样本不进入滤波窗口，左右两侧分段 | `status=skipped_boundary` |
| 接触变化 reset | 相邻帧变化超过 `contact_reset_threshold` | 重置 EMA 状态，不跨边缘延续平滑 | `status=ema_reset` |
| 中值窗口 | 片段样本足够 | 对每个 cell 使用 `median_window=3` 的短窗口中值 | 候选去尖峰矩阵 |
| EMA 平滑 | 中值候选序列 | 对每个 cell 使用 `ema_alpha=0.35` 平滑 | 滤波后矩阵 |
| 审计摘要 | 每个触觉样本 | 记录 shape、min、max、mean、changed_cell_count、mean/max abs delta | [[TactileFilterSampleRecord]] |
| 调试全量 diff | 开发者调试模式开启 | 输出完整矩阵前后差异到调试 artifact | `debug_artifact_ref` |

## 11. 输出结果结构

| 字段 | 类型 | 含义 | 有效性要求 | 下游使用方式 |
|---|---|---|---|---|
| `input_repair_result_ref` | [[SignalRepairResult]] | 来源补全结果引用 | 必须可追溯 | 报告和复现 |
| `tactile_filter_config_ref` | [[TactileFilterConfig]] | 本次滤波配置引用 | 必须可追溯 | 调参和复现 |
| `input_sequence_refs` | list[[TactileFilterInputSequence]] | 输入触觉序列引用 | 与补全结果对齐 | 复现输入 |
| `output_sequence_refs` | object/list | 滤波后触觉序列引用 | 不塞完整 MCAP | MCAP_A 生成器 |
| `segment_summaries` | list[[TactileFilterSegmentSummary]] | 分段和 reset 摘要 | 覆盖所有连续可靠片段 | 调试和报告 |
| `sample_records` | list[[TactileFilterSampleRecord]] | 样本级审计 | 覆盖每个处理样本 | 审计和报告 |
| `timestamp_policy` | enum string | 固定 `preserve_original` | 必填 | 验收不重采样 |
| `sample_count_before` / `sample_count_after` | object | 各 tactile topic 样本数 | 必须相等 | 验收长度不变 |
| `summary_by_topic` | object | 按 topic 汇总 filtered/kept/reset/skipped | 必须区分 reset 和 skipped | 开发者入口摘要 |

## 12. 异常与边界输入

| 边界情况 | 预期结果 | reason / error 表达 | 是否阻塞下游 |
|---|---|---|---|
| 缺少 [[SignalRepairResult]] | 功能检验失败 | `missing_signal_repair_result` | 是 |
| `timestamp_policy` 不是 `preserve_original` | 功能检验失败 | `unsupported_timestamp_policy` | 是 |
| `output_sequence_refs` 无法映射为 [[TactileFilterInputSequence]] | 功能检验失败 | `invalid_tactile_filter_input_sequence` | 是 |
| 触觉帧 shape 不一致 | 当前序列或片段拒绝滤波 | `tactile_shape_mismatch` | 否，进入报告 |
| 片段过短 | 当前片段原样保留或只执行可用窗口 | `short_segment_kept_original` | 否 |
| 接触变化超过 reset 阈值 | 重置 EMA，不跨越平滑 | `contact_reset` | 否 |
| 完整 diff 输出关闭 | 主记录仍保存摘要 | `full_diff_disabled` | 否 |

## 13. 可验证样例

| 样例 | 输入特征 | 预期输出 | 验证方式 |
|---|---|---|---|
| 合法输入 | 连续 tactile 序列，无缺失和未修复样本 | 生成滤波后序列，样本数、时间戳和 shape 不变 | 单元测试 |
| 缺失区间 | 中间存在 [[MissingIntervalIssue]] | 左右分段独立滤波，不跨段 | 分段测试 |
| 未修复样本 | 某 tactile 样本 `unrepaired` 或 `skipped` | 该样本作为边界，左右分段 | 上游接口兼容测试 |
| 接触变化 | 相邻帧均值变化超过 reset 阈值 | 当前样本触发 EMA reset | reset 边界测试 |
| 孤立尖峰 | 单 cell 单帧明显突增 | 中值窗口抑制尖峰，输出 diff 摘要 | 滤波计算测试 |
| 调试全量 diff | 开发者模式开启 | 主记录引用完整矩阵 diff artifact | 开发者产物测试 |

## 18. 给 L3 任务生成的约束

1. 每个 L3 只能解决一个核心目标。
2. 触觉滤波器 L3 不得重新做异常检测。
3. 触觉滤波器 L3 不得补全、插入、删除或重采样消息。
4. 滤波不得跨越 [[MissingIntervalIssue]]。
5. tactile 相关 `unrepaired` / `skipped` 样本必须作为分段边界。
6. 触觉滤波必须逐 cell 沿时间执行，不得做空间卷积。
7. 接触变化超过 reset 阈值时必须重置 EMA，不得跨接触边缘延续平滑。
8. 主审计记录不得保存完整矩阵 diff；完整 diff 只允许作为开发者调试 artifact。
9. 每个 Service 场景 L3 必须写明它对应或影响 `./start_data_clean.sh --dev` 下的场景二功能检验项或场景完整 smoke test。
10. L3 自动化验收只证明局部实现正确；场景最终验收必须由用户本人运行 `./start_data_clean.sh --dev` 后确认。
