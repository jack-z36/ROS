# L2 能力模块说明：对齐契约与配置定义

## 1. 能力名称

```text
对齐契约与配置定义
```

## 2. 所属位置

阶段：阶段二：数据清洗  
L1：service_s3  
场景：场景三：MCAP 多 topic 时间轴对齐  
模块类别：数据定义类  
来源功能模块清单：`DOCS/阶段二：数据清洗/02_service/场景三/功能模块清单.md`

## 3. 一句话目标

```text
定义场景三输入、输出、step 时间轴、topic 对齐策略、阈值、alignment index 和 report 的统一契约，避免后续模块自行猜字段。
```

## 4. 能力角色

本能力是场景三 P0 主链路的契约层。它先固化 [[Scene3AlignmentConfig]]、[[TargetFieldMapping]]、[[StepTimeline]]、[[FieldAlignmentStrategy]]、[[FieldAlignmentStatus]]、[[AlignmentIndex]]、[[AlignmentReport]]、[[AlignedMcap]] 和 [[AlignedMcapWriteSummary]]，供后续输入盘点、时间轴生成、字段对齐、报告生成和写出模块复用。

已按 `grill-me` 约束完成意图澄清：首版以双目图像为时间轴核心，默认 `target_step_hz=15`；左右图像参与有效时间范围交集裁剪，位姿、触觉和夹爪不参与裁剪；aligned MCAP 是场景三输出，MCAP_A 只读不改；逐 step-field 对齐事实写入必需的 `alignment_index.parquet`。

## 5. 上游关系

- 直接上游是场景二 MCAP_A 生成器输出的 [[McapA]] 和 [[McapAWriteSummary]]。
- [[McapA]] 保留 cleaned MCAP topic 名称、消息类型、时间戳排序和样本数，是场景三输入。
- 左右图像 topic 已按阶段一和场景一契约稳定为 `/gopro_left/image_raw`、`/gopro_right/image_raw`，消息类型为 `sensor_msgs/msg/Image`。
- 左右夹爪宽度 topic 为 `/gopro_left/gripper_width`、`/gopro_right/gripper_width`，来源于对应图像帧。

## 6. 下游关系

- MCAP_A 输入盘点与校验器读取 [[Scene3AlignmentConfig]] 和 [[TargetFieldMapping]] 判断上游产物是否可消费。
- 统一 Step 时间轴生成器按 [[StepTimeline]] 契约生成统一 step。
- 多策略字段对齐器按 [[FieldAlignmentStrategy]] 和 [[FieldAlignmentStatus]] 写出逐字段对齐结果。
- 对齐索引与报告数据生成器生成 [[AlignmentIndex]] 和 [[AlignmentReport]]。
- aligned MCAP 与 sidecar 写出器写出 [[AlignedMcap]]、[[AlignmentIndex]]、[[AlignmentReport]] 和 [[AlignedMcapWriteSummary]]。

## 7. 上游接口对齐检查

| 上游功能 | 上游接口 / 产物 | 本能力如何依赖 | 对齐状态 | 处理方式 |
|---|---|---|---|---|
| 场景二 MCAP_A 生成器 | [[McapA]] | 作为场景三唯一主输入 MCAP，读取其 topic、时间戳和主数据 | 已对齐 | 复用 |
| 场景二 MCAP_A 生成器 | [[McapAWriteSummary]] | 追溯 MCAP_A 来源、写出状态和上游处理摘要 | 已对齐 | 复用 |
| 场景一 cleaned MCAP 契约 | 图像 topic、pose topic、gripper topic | 复用图像和夹爪 topic 语义，避免重定义输入字段 | 已对齐 | 复用 |
| 场景三功能模块清单 | 第 1 个功能模块 | 作为本能力范围、上下游和优先级来源 | 已对齐 | 复用并细化 |

## 8. 职责边界

本能力负责：

1. 定义场景三对齐配置、目标字段映射、时间轴、对齐策略、状态枚举和输出产物契约。
2. 固化首版默认值：`target_step_hz=15`、双目图像交集、图像最近邻、pose 插值+slerp、触觉窗口聚合、夹爪跟随图像。
3. 明确 `alignment_index.parquet` 是逐 step-field 对齐事实的必需 sidecar，`alignment_report.json` 只保存统计摘要。
4. 明确 aligned MCAP 是按统一 step 时间轴整理后的主数据输出，MCAP_A 只读不改。

本能力不负责：

1. 不读取 MCAP_A。
2. 不生成 step 时间轴。
3. 不实现最近邻、插值、slerp 或窗口聚合算法。
4. 不写出 aligned MCAP、Parquet 或 JSON 文件。
5. 不决定训练 mask、episode 构建或 canonical dataset schema。

## 10. 字段表

| 字段 | 类型 | 现实含义 | 是否必需 | 默认值 | 合法值 / 范围 | 无效时如何表达 |
|---|---|---|---|---|---|---|
| `target_step_hz` | number | 统一 step 目标频率 | 是 | `15` | `> 0` | 配置校验失败 |
| `baseline_image_topics` | list[string] | 双目图像基准 topic | 是 | `/gopro_left/image_raw`, `/gopro_right/image_raw` | 首版必须左右同时存在 | 输入不可消费 |
| `required_timeline_fields` | list[string] | 参与时间范围裁剪的字段 | 是 | 左右图像 | 首版不含 pose/tactile/gripper | 配置校验失败 |
| `image_max_dt_ms` | number/null | 图像最近邻超时阈值 | 否 | `1000 / target_step_hz / 2` | `> 0` | 使用默认或配置失败 |
| `pose_strategy` | enum | 位姿默认策略 | 是 | `interpolation_slerp` | `interpolation_slerp` / `nearest_neighbor` | 配置校验失败 |
| `pose_fallback_strategy` | enum | 位姿插值不足时 fallback | 是 | `nearest_neighbor` | `nearest_neighbor` | 记录 `fallback_reason` |
| `tactile_strategy` | enum | 触觉默认策略 | 是 | `window_aggregate` | `window_aggregate` / `nearest_neighbor` | 配置校验失败 |
| `gripper_strategy` | enum | 夹爪默认策略 | 是 | `follow_image_nearest` | `follow_image_nearest` / `nearest_neighbor` / `linear_interpolate` | 配置校验失败 |
| `alignment_index_format` | enum | 对齐索引格式 | 是 | `parquet` | 首版固定 `parquet` | 写出失败 |
| `aligned_mcap_output_dir` | string | aligned 产物目录 | 是 | `asset/阶段二：数据清洗/dev/mcap_aligned/` | 阶段二文件存放规范允许路径 | 配置校验失败 |

## 11. 序列化与兼容性要求

- 是否需要序列化：需要，配置应可序列化为 YAML / JSON，报告为 JSON，alignment index 为 Parquet。
- 序列化格式：`Scene3AlignmentConfig` 可由配置文件和 CLI 临时覆盖生成；`AlignmentIndex` 固定 Parquet；`AlignmentReport` 和 `AlignedMcapWriteSummary` 固定 JSON。
- 字段命名风格：首版使用 snake_case。
- 版本兼容要求：下游必须按数据定义读取，不得自行定义相似字段名。
- 缺失字段处理：必需配置缺失时失败；可推导字段按默认值填充并写入运行日志。

## 12. 有效性规则

| 规则 | 判断方式 | 失败表达 | 是否阻塞下游 |
|---|---|---|---|
| MCAP_A 输入必须引用 [[McapA]] | 路径和上游摘要检查 | 输入不可消费 | 是 |
| 左右图像 topic 必须存在 | topic catalog 检查 | 无法生成时间轴 | 是 |
| 统一 step 时间轴只由左右图像共同有效区间裁剪 | 检查 `required_timeline_fields` | 配置校验失败 | 是 |
| 可选字段不裁剪时间轴 | 检查字段配置 | 配置校验失败 | 是 |
| 图像超时不删除 step | step-field 状态检查 | [[AlignmentIndex]] 记录 `timeout` | 否 |
| 位姿插值不足可 fallback | 邻居检查 | `fallback_nearest` + `fallback_reason` | 否 |
| 触觉窗口无样本 | 窗口样本数检查 | `missing_time` | 否 |

## 13. 使用边界

本数据定义只表达：

- 场景三对齐链路的配置、schema、枚举、默认策略和输出产物语义。
- 后续模块必须共同遵守的字段名、默认值、状态和 sidecar 格式。
- 与场景二 [[McapA]] / [[McapAWriteSummary]] 的接口对齐关系。

本数据定义不表达：

- 最近邻、插值、slerp、窗口聚合的具体实现。
- aligned MCAP 的实际写出流程和失败清理。
- 场景四 episode、mask、quality report 或 LeRobotDataset v3 schema。

## 18. 给 L3 任务生成的约束

后续从本 L2 生成 L3 任务时，必须遵守：

1. 每个 L3 只能解决一个核心目标。
2. 每个 L3 必须先判断任务类别，并使用对应 L3 类别模板。
3. 本能力拆出的 L3 只负责数据定义、schema、配置默认值和序列化测试，不实现 MCAP 读取或对齐算法。
4. 所有 L3 必须复用场景二 [[McapA]] 和 [[McapAWriteSummary]]，不得新增相似输入对象。
5. `target_step_hz` 默认值必须为 `15`，但配置文件和开发者 CLI 本次运行临时覆盖必须可表达。
6. `alignment_index.parquet` 是必需 sidecar；`alignment_report.json` 只保存统计摘要。
7. aligned MCAP 是按 step 时间轴整理后的场景三输出，不得修改 MCAP_A。
8. 每个 Service 场景 L3 必须写明它对应或影响 `./start_data_clean.sh --dev` 下的场景三完整 smoke test。
9. L3 自动化验收只证明局部实现正确；场景最终验收必须由用户本人运行 `./start_data_clean.sh --dev` 后确认。
