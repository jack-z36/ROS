# 阶段四：模型部署背景信息

## 部署包组成

部署阶段至少需要：

- 模型权重 checkpoint。
- 模型配置。
- tokenizer 或 language processor。
- 图像预处理代码。
- Observation Builder。
- VLA Policy Server。
- Action Decoder。
- Action Post-processor。
- Robot Adapter。
- 机械臂控制接口。
- 安全限制。
- 日志与回放工具。

## Observation Builder

Observation Builder 从实时 ROS2 topic 构造模型需要的 `observation_t`。

它需要读取左右图像、左右 TCP pose、左右 gripper width、左右 tactile 和 language instruction，并进行时间同步、图像 resize/normalize、状态归一化，最后按 `observation_schema.json` 拼成模型输入。

## VLA Policy Server

VLA Policy Server 输入 observation 和语言指令，输出 candidate action。

如果训练时采用 UMI 风格 relative trajectory action，那么推理输出也必须被解释为相对于当前 TCP 位姿的未来相对轨迹。

## Action Post-processor

Action Post-processor 把 candidate action 转成更安全、更稳定、更可执行的 safe action。

它需要做动作选择、过时动作丢弃、最大平移量限制、最大旋转量限制、夹爪变化速度限制、轨迹平滑、workspace 检查、机械臂能力检查、碰撞风险检查和异常跳变检查。

## Robot Adapter

Robot Adapter 把 safe action 转成机械臂控制接口能接受的命令。

如果 safe action 是相对 TCP 轨迹，则需要用当前真实 TCP pose 将 relative TCP action 还原成 target TCP pose。随后根据机械臂接口选择直接末端位姿控制、IK 后关节角控制，或轨迹规划后发送轨迹命令。

夹爪部分需要把左右 gripper target 映射到对应夹爪控制命令。

## 关键原则

部署阶段必须保证：

训练时 action 的定义，等于推理时 action 的解释，等于后处理时 action 的转换逻辑。

如果训练时 action 表示相对于当前 TCP 的未来目标轨迹，部署时就不能把它当成 robot_base 下的绝对坐标直接发给机械臂。
