## 1. 白话运行机制

Pi0.5 没有独立、窄边界的 `ActionPublisher`。旧输出职责散落在三个 ROS node：

```text
ControlLoop.tick() 产出旧 14D BimanualAction
  -> Pi05VlaDeployNode：逐路构造并发布 joint/hand command
  -> Pi05BridgeNode：订阅四路 command，转换并转发
  -> CommandMuxNode：订阅 VLA/teleop/deadman/enable，按 mode/timeout 仲裁
  -> picotele driver
```

这条链能说明“publisher handle 应由长生命周期对象持有”“输出前应先形成可解释的动作对象”“外部 driver 仍需最终 gate”，但不能直接成为当前 ACT L2-05：旧链是 14D joint、串行 subscription、mode 状态机和 shadow command；新边界是 16D TCP、三编排函数、无 subscription/timer、CLI command 总开关和 L2-06 `CommandPermit`。

## 5. 复用结论

| 等级 | 结论 |
|---|---|
| 直接复用 | 无；Pi0.5 位于只读参考目录且核心契约不相容。 |
| 结构复用 | frozen/强类型数据对象；topic/config 注入；长生命周期对象持有 publisher；消息先在 RAM 构造。 |
| 参考理解 | bridge/mux 说明外部 driver 仍需 gate、timeout、manual takeover 和 status；当前由 L2-06/driver 承担。 |
| 不复用 | 14D codec、JointState 臂输出、旧 hand 映射、bridge/mux subscription、raw deadman、mode 状态机、joint delta clamp、全局 metrics、硬件 launch、smoothstep/blend。 |

## 6. 对 ACT 设计的强制约束

1. 只保留三编排函数：B1 Topic 载荷、B2 ROS message、B3 选择并发布。
2. 不创建兼容 Pi0.5 的串行 bridge；policy 与 command 从同一 safe action 派生。
3. 不复用旧 `publishes_command_topics` 或任何运行 mode 枚举。
4. CLI `--enable-command-output` 缺省必须关闭；动态许可只由 L2-06 `CommandPermit` 提供。
5. 不在 B2 构造最终 status；status 必须根据 B3 的真实发布事实形成。
6. 不在 publish 成功前累计“已发送”，不把 ROS publish 等同硬件执行。
7. 不使用旧 14D gripper 量纲；当前唯一映射为 `[0,1] -> [0,100]`。
8. 不把 driver launch、workspace/IK/TF 或厂商接口纳入本 L2。
