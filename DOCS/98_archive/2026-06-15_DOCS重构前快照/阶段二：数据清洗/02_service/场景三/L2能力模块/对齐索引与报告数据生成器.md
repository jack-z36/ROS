# L2 能力模块说明：对齐索引与报告数据生成器

## 1. 能力名称

```text
对齐索引与报告数据生成器
```

## 2. 所属位置

阶段：阶段二：数据清洗  
L1：service_s3  
场景：场景三：MCAP 多 topic 时间轴对齐  
模块类别：数据计算类  
来源功能模块清单：`DOCS/阶段二：数据清洗/02_service/场景三/功能模块清单.md`

## 3. 一句话目标

```text
汇总逐 step-field 对齐事实，生成 AlignmentIndex 数据和 AlignmentReport 草稿统计对象。
```

## 4. 能力角色

本能力是场景三 P0 主链路的对齐事实汇总层。它位于 [[多策略字段对齐器]] 之后、[[aligned MCAP 与 sidecar 写出器]] 之前，负责把 [[FieldAlignmentResult]] 规范化为 [[AlignmentIndex]] 数据，并生成 [[AlignmentReport]] draft。  

已按 `grill-me` 约束完成意图澄清：本能力是纯计算模块，不写 Parquet、JSON 或 MCAP；[[AlignmentIndex]] 只保留逐 step-field 对齐事实，不保存 `derived_value` 或主数据 payload；字段缺失、超时、fallback 和 unavailable 属于质量统计，不代表本能力整体 failed。

## 5. 上游关系

- 直接上游是 [[多策略字段对齐器]] 生成的 [[FieldAlignmentResult]]。
- 时间轴上游是 [[统一Step时间轴生成器]] 生成的 [[StepTimeline]] 和 [[StepTimelineGenerationSummary]]。
- 输入守门上游是 [[MCAP_A输入盘点与校验器]] 生成的 [[SourceTopicCatalog]] 和 [[McapAInputValidationSummary]]。
- 契约上游是 [[对齐契约与配置定义]] 产出的 [[Scene3AlignmentConfig]]、[[TargetFieldMapping]]、[[FieldAlignmentStatus]]、[[AlignmentIndex]] 和 [[AlignmentReport]]。

## 6. 下游关系

- [[aligned MCAP 与 sidecar 写出器]] 读取本能力输出的 [[AlignmentIndex]] 数据和 [[AlignmentReport]] draft，完成 sidecar 与最终报告写出。
- 场景四 LeRobotDataset v3 构建、masks 和 quality report 读取最终落盘的 [[AlignmentIndex]] 与 [[AlignmentReport]]。
- 开发者入口 `scene3_alignment_report_check` 通过本能力输出检查对齐事实和统计是否正确。
- 场景三完整 smoke test 间接依赖本能力，确认字段对齐结果能被汇总为可追溯的机器可读报告数据。

## 7. 上游接口对齐检查

| 上游功能 | 上游接口 / 产物 | 本能力如何依赖 | 对齐状态 | 处理方式 |
|---|---|---|---|---|
| 多策略字段对齐器 | [[FieldAlignmentResult]] | 读取逐 step-field 对齐结果，抽取可持久化事实和统计基础 | 已对齐 | 复用 |
| 统一 Step 时间轴生成器 | [[StepTimeline]] / [[StepTimelineGenerationSummary]] | 汇总 step 数、起止时间、频率和时间轴生成状态 | 已对齐 | 复用 |
| MCAP_A 输入盘点与校验器 | [[SourceTopicCatalog]] / [[McapAInputValidationSummary]] | 引用输入 catalog、可消费结论和 warning，写入 report draft | 已对齐 | 复用 |
| 对齐契约与配置定义 | [[AlignmentIndex]] / [[AlignmentReport]] | 作为本能力输出契约；report 只生成 draft 阶段字段 | 已对齐 | 复用并细化 draft/final 边界 |
| 场景三功能模块清单 | 第 5 个功能模块 | 作为本能力范围、上下游和优先级来源 | 已对齐 | 复用并细化 |

## 8. 职责边界

本能力负责：

1. 将 [[FieldAlignmentResult]] 规范化为 [[AlignmentIndex]] 数据对象。
2. 按字段、状态、方法和时间误差生成统计摘要。
3. 生成 [[AlignmentReport]] draft，表达输入引用、配置引用、timeline 摘要、质量降级和失败摘要。
4. 为开发者功能检验项 `scene3_alignment_report_check` 提供可机器读取的调试产物。

本能力不负责：

1. 不写 `alignment_index.parquet`。
2. 不写 `alignment_report.json`。
3. 不写 aligned MCAP 或写出摘要。
4. 不保存 `derived_value`、图像 payload、pose 值、夹爪值或触觉聚合主数据。
5. 不决定训练 mask、episode 构建或 canonical dataset 可用性。

## 9. 计算职责

| 计算项 | 输入 | 输出 | 影响下游 |
|---|---|---|---|
| 对齐事实规范化 | [[FieldAlignmentResult]] | [[AlignmentIndex]] 数据对象 | 第 6 模块写出 Parquet sidecar |
| 唯一性检查 | `step_index + field_name` | 重复记录错误或 warning | 防止下游 step-field 事实不确定 |
| 状态计数 | [[FieldAlignmentStatus]] | `status_counts` | 报告和人工复查 |
| 字段级统计 | field / method / status / `dt_ms` / window fields | `field_stats` | 场景四 quality report 和 smoke test |
| 质量降级摘要 | missing、timeout、fallback、unavailable、aggregation coverage | degraded summary | 表达质量事实但不做训练裁决 |
| report draft 组装 | 输入引用、配置引用、timeline 摘要、统计结果 | [[AlignmentReport]] draft | 第 6 模块补齐最终路径后写出 JSON |

## 10. 计算规则

| 规则 | 触发条件 | 计算 / 判断方式 | 结果表达 |
|---|---|---|---|
| 只保留事实字段 | 处理 [[FieldAlignmentResult]] | 抽取来源、时间、方法、状态、误差、邻居、窗口、样本数、覆盖率、fallback reason、message_ref | [[AlignmentIndex]] |
| 不保存派生主数据 | `derived_value` 非空 | 不写入 [[AlignmentIndex]]，只允许第 6 模块用于写 aligned MCAP | report draft 可统计其状态，不保存其值 |
| 每个 step-field 最多一条主记录 | 发现重复 `step_index + field_name` | 标记输入冲突 | `failure_reason=duplicate_step_field_record` |
| 降级不等于失败 | 存在 `missing_time`、`timeout`、`fallback_nearest` 或 `unavailable` | 进入质量统计和 degraded summary | report draft `status=completed` 或 `degraded` |
| 流程错误才失败 | 输入缺失、重复记录、状态非法或必要引用缺失 | 停止或生成 failed draft | `failure_reason` 明确错误 |
| report draft 不要求输出路径 | 第 6 模块尚未写出文件 | `output_aligned_mcap`、`alignment_index` 可为空或标记待写出 | 第 6 模块 final 阶段补齐 |

## 11. 输出结果结构

| 字段 | 类型 | 含义 | 有效性要求 | 下游使用方式 |
|---|---|---|---|---|
| [[AlignmentIndex]] | table-like data / Parquet-ready records | 逐 step-field 对齐事实 | 每个 `step_index + field_name` 最多一条主记录 | 第 6 模块写出 `alignment_index.parquet` |
| [[AlignmentReport]] draft | report object / JSON-ready object | 对齐统计草稿 | draft 阶段不要求最终输出路径 | 第 6 模块补齐 final 字段后写出 |
| `field_stats` | object | 每个字段的误差、缺失、超时、fallback 和聚合统计 | 必须可机器读取 | 人工复查、场景四质量统计 |
| `status_counts` | object | 各 [[FieldAlignmentStatus]] 计数 | 必须覆盖所有出现过的状态 | smoke test 和质量摘要 |
| `degradation_summary` | object | 降级事实摘要 | 不得表达训练可用性裁决 | 场景四进一步判定 |
| `failure_reason` | string/null | 本汇总流程失败原因 | 失败时必填 | 开发者入口定位问题 |

## 12. 异常与边界输入

| 边界情况 | 预期结果 | reason / error 表达 | 是否阻塞下游 |
|---|---|---|---|
| [[FieldAlignmentResult]] 缺失或为空 | 生成 failed draft 或停止 | `missing_field_alignment_result` | 是 |
| 重复 `step_index + field_name` | 判定输入冲突 | `duplicate_step_field_record` | 是 |
| 存在 unknown status | 判定输入非法 | `invalid_field_alignment_status` | 是 |
| 大量 `timeout` | report draft completed/degraded，统计 timeout rate | `timeout_count` / `timeout_rate` | 否 |
| 可选字段 `unavailable` | report draft completed/degraded，统计 unavailable | `unavailable_count` | 否 |
| 触觉窗口无样本 | 统计 `missing_time` 和 coverage | `missing_time_count` | 否 |
| pose fallback | 统计 fallback ratio 和原因 | `fallback_nearest_count` / `fallback_reason_counts` | 否 |

## 13. 可验证样例

| 样例 | 输入特征 | 预期输出 | 验证方式 |
|---|---|---|---|
| 合法输入 | 每个 step-field 一条结果，含 aligned / interpolated / aggregated | 生成 [[AlignmentIndex]] 和 completed report draft | service / contract test |
| 缺失输入 | 无 [[FieldAlignmentResult]] | failed draft，原因 `missing_field_alignment_result` | failure test |
| 重复记录 | 同一 `step_index + field_name` 两条主结果 | failed draft，原因 `duplicate_step_field_record` | uniqueness test |
| 降级输入 | 存在 missing / timeout / fallback / unavailable | report draft 为 completed/degraded，统计降级比例 | degradation test |
| 触觉聚合 | 存在 window、sample_count、coverage_ratio | field stats 包含聚合样本数和覆盖率统计 | aggregation stats test |

- [ ] [[AlignmentReport]] draft 与第 6 模块 final 阶段字段边界已明确。
- [ ] 字段缺失、超时、fallback 和 unavailable 已作为质量统计表达，不被误判为训练可用性裁决。

## 18. 给 L3 任务生成的约束

后续从本 L2 生成 L3 任务时，必须遵守：

1. 每个 L3 只能解决一个核心目标。
2. 每个 L3 必须先判断任务类别，并使用对应 L3 类别模板。
3. 本能力拆出的 L3 必须写入功能组 `service-s3-g5`，不得混入其他功能组。
4. 每个 L3 必须复用 [[FieldAlignmentResult]]、[[AlignmentIndex]] 和 [[AlignmentReport]]，不得新增相似统计对象。
5. 第 5 模块不得写 Parquet、JSON report、aligned MCAP 或写出摘要。
6. [[AlignmentIndex]] 不得保存 `derived_value`、图像 payload、pose 值、夹爪值或触觉聚合主数据。
7. 字段缺失、超时、fallback 和 unavailable 必须作为质量统计表达，不得在本模块中变成训练 mask 或 episode 丢弃决策。
8. 每个 Service 场景 L3 必须写明它对应或影响 `./start_data_clean.sh --dev` 下的 `scene3_alignment_report_check` 或场景三完整 smoke test。
9. L3 自动化验收只证明局部实现正确；场景最终验收必须由用户本人运行 `./start_data_clean.sh --dev` 后确认。
