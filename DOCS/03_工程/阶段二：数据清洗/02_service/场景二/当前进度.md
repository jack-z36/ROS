# 阶段二场景二：当前进度

> 消费对象：Scene2 开发、验收与维护 Agent。权威性：当前实现状态。上游来源：代码与自动化合同测试。不负责：IK/MuJoCo 方案设计。读取时机：进入 Scene2 工作前。冲突处理：以代码、数据定义和本进度文档的当前契约为准。

## 当前状态

Scene2 P0 信号可靠性与 MCAP_A 写出链路已完成边界收口：按显式白名单读取一次 cleaned MCAP 分析样本，在 RAM 内依次完成 topic 隔离检测、字段级处置、严格双邻居修复、精确 segment 滤波，并按稳定消息引用流式写回 MCAP_A。

当前主位姿是 `/baton_mini_left/tcp_pose` 与 `/baton_mini_right/tcp_pose`，保持各自 Baton source frame，不在 Scene2 做坐标转换。

## 已完成

- [x] 固化 2 路必需 pose、2 路必需 gripper、4 路默认可选 tactile 的显式 stream inventory。
- [x] Repo 按 `log_time_order=False` 建立源 MCAP 同 topic 物理序号和完整稳定消息引用。
- [x] 必需流缺失、重复声明、白名单流 schema 不支持时 fail-closed；未声明 topic 原样复制。
- [x] 三模态检测器按 `topic + time_domain` 独立排序和计算，issue id 包含 topic、物理序号和 field path。
- [x] 检测建议与字段级处置分离；只有 `AUTO_REPAIR` 能进入数值修复。
- [x] position、orientation、gripper、tactile 四种 replacement unit 分别形成 repair run；无双邻居或约束失败时保留原值，不降级 hold。
- [x] pose 与 tactile segment 保存完整成员引用和边界原因，滤波只消费精确成员。
- [x] tactile 按 topic、缺失、未修复异常、time domain、shape、contact reset 分段，每段重新初始化 Median/EMA。
- [x] MCAP_A runtime 使用唯一 run directory/run id/config snapshot，分析加载、检测、修复各执行一次。
- [x] 写出器按稳定引用精确写回 pose/tactile 滤波值和成功 gripper 修复值；每项必须命中一次，并做 topic/schema/count/time/sequence 写后合同校验。
- [x] topic 隔离、稳定身份、处置状态机、四种修复、segment/config、统一 runtime 和 gripper 写回已有自动化合同测试。
