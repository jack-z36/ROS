# Runtime MVP 背景信息

阶段二将从 raw MCAP 逐级生成 cleaned、validated、aligned、canonical dataset 和 exports。为了避免每个场景各自实现入口、日志、错误处理和目录管理，需要先建立统一 Runtime。

Runtime 位于架构分层中的 Runtime 层：

```text
Types -> Config -> Repo -> Service -> Runtime -> UI
```

Runtime 的职责是编排，不是算法。它应调用 Service 层提供的能力，并统一处理横切关注点：

- 运行目录。
- 结构化日志。
- processing manifest。
- 错误摘要。
- 场景选择。
- 配置和输入检查。

Runtime MVP 阶段可以先使用 fake service 验证流程闭环，避免在真实清洗算法尚未完成时阻塞工作环境搭建。

## Runtime 与支撑层关系

Types、Config、Repo 会随着 Runtime MVP 和 Service 开发按需扩展，但它们不是 Service 的附属品，而是整个阶段二 pipeline 的支撑层。

依赖方向必须保持：

```text
UI -> Runtime -> Service -> Repo -> Config -> Types
```

- Runtime 可以调用 Service，并使用 Repo/Config/Types 提供的能力。
- Service 可以调用 Repo、Config 和 Types。
- Repo、Config、Types 不能反向依赖 Service、Runtime 或 UI。
