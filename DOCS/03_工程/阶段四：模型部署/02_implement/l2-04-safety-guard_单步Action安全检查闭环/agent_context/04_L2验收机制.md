# L2-04 验收机制

## 1. Gate 目标与范围

L2 Gate 要证明：A1/B1-B5/C1-C15 能在 mock RAM 环境中，把 16D 绝对候选动作稳定分为 PASS、ADJUSTED、REJECTED；不访问 ROS、文件或硬件。

Gate 不证明真实机械臂可达、IK、碰撞、急停或 F100 寄存器行为；这些分别属于 L2-05 与 real-robot 验收。

## 2. 所需 L3 切片（设计草案，未生成任务）

| 切片 | 目标 | 覆盖编号 |
|---|---|---|
| types result contract | 实现并测试 C1-C3/C5 | C1-C3、C5 |

## 4. 统一验收脚本设计需求

后续 L3 创建：

```text
DOCS/03_工程/阶段四：模型部署/05_acceptance/l2-04-safety-guard/scripts/l2_04_verify.sh
```

脚本按 `types / config / repo / service / runtime / ui / boundary` 分组输出每个标签：

```text
PASS|FAIL|BLOCKED  LABEL  简短说明
  file: ... / class: ... / micro-unit: B? or C? / pytest: ... / error: ...
SUMMARY: N PASS / N FAIL / N BLOCKED
```

任一 FAIL 退出非零；环境或 bundle 缺失只能标 BLOCKED，不能伪装 PASS。L2-04 核心 mock Gate 不依赖 ROS/hardware，因此核心 C/B 测试不应 BLOCKED。

## 5. 验收层级与放行

| 层级 | 必须性 | 通过条件 |
|---|---|---|
| unit/import/mock | 必须 | §3 全部核心标签 PASS |
| dry-run | 可选 | L2-06 mock 调 B1 并理解 status |
| shadow-run | 下游补验 | L2-05 消费 safe action，不触发硬件 |
| real-robot | hardware-blocked | 人工授权、急停、L2-05 gate 后才可执行 |

只有全部 required L3 和本地 mock Gate PASS，才允许 L2-05/L2-06 进入集成设计；Git 合入仍需人类验收与后续工作流 Gate。
