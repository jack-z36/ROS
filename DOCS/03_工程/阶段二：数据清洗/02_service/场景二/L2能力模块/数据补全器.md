# L2 能力模块说明：数据补全器

> 消费对象：Scene2 修复链路开发与验收 Agent。权威性：当前字段级处置与修复契约。上游来源：`schemas/repair.py`、`service/repair_run.py`、`service/repair_compute.py`。不负责：异常检测和滤波。读取时机：修改 Scene2 修复逻辑前。冲突处理：以类型化处置和严格双邻居规则为准，历史 hold/fallback 描述无效。

```text
数据补全器
```

## 3. 一句话目标

```text
只消费异常值检测器输出的点级异常与缺失区间，对可自动修复的位姿、触觉和夹爪已有样本执行可追溯补全，并输出修复结果与修复后序列引用。
```

## 4. 能力角色

本能力是场景二 P0 预处理链路中“发现异常”和“滤波平滑”之间的修复层。它不重新发现异常，而是先把检测事实转换为字段级 [[RepairDecisionStatus|RepairDisposition]]，再只对 `AUTO_REPAIR` 处置执行预定数值方法。

补全器覆盖 `pose` / `tactile` / `gripper` 三模态；只修改存在合法前后邻居的已有异常样本，不新增、不删除、不重采样消息，不启用单邻居 hold/fallback。`SuggestedRepairAction` 只保留为检测建议，不能授权改值。

## 5. 上游关系

- 直接上游是 [[异常值检测器]]。
- 输入检测结果为 [[SignalReliabilityDetectionResult]]。
- 样本级主输入为 [[SampleReliabilityIssue]]，定位对象为 [[SignalSampleRef]]。
- 无样本缺失区间为 [[MissingIntervalIssue]]，v1 不自动插入消息。
- 修复策略来自 [[SignalRepairPolicyConfig]]。
- 原始三模态序列来自 [[CleanedMcap]]。

## 6. 下游关系

- 位姿滤波器消费补全后的 pose 序列和不可修复记录。
- 触觉滤波器消费补全后的 tactile 序列和不可修复记录。
- [[McapA|MCAP_A]] 生成器消费补全/滤波后的主数据序列。
- Parquet 标注与验证报告生成器消费 [[SignalRepairResult]]，记录修复、拒绝、跳过和未处理缺失。
- 开发者入口 `scene2_signal_repair` 展示修复结果、修复后序列引用和运行日志。

| 上游功能 | 上游接口 / 产物 | 本能力如何依赖 | 对齐状态 | 处理方式 |

## 8. 职责边界

本能力负责：

1. 按 `topic + modality + time_domain + replacement_unit` 聚合 [[SignalRepairRun]]，同一 pose 样本的 position/orientation 独立处置。
2. 对 `AUTO_REPAIR + pending` run 执行线性插值或 SLERP。
3. 对不可自动修复、跳过和缺失区间输出可追溯记录。
4. 输出 [[SignalRepairResult]] 和修复后序列引用。

本能力不负责：

1. 不重新做异常发现。
2. 不新增、不删除、不重采样消息。
3. 不跨 topic、跨左右臂、跨模态查找邻居。
4. 不做滤波、IK、MuJoCo 或 [[McapA|MCAP_A]] 写出。
5. 不决定最终 episode 丢弃或训练 mask。

## 9. 计算职责

| 计算项 | 输入 | 输出 | 影响下游 |
|---|---|---|---|
| 字段级问题聚合 | [[SampleReliabilityIssue]] | 同一 replacement unit 问题组 | 避免 position/orientation 状态互相覆盖 |
| repair run 聚合 | 样本问题组、[[MissingIntervalIssue]] | [[SignalRepairRun]] | 连续异常统一补全，避免串联漂移 |
| 类型化处置 | 检测事实、策略 | `AUTO_REPAIR` / `MASK_ONLY` / `MANUAL_REVIEW` / `UNRECOVERABLE` / `NO_ACTION` | 决定是否允许进入计算 |
| 合法邻居查找 | 原始同 topic 序列、点级问题、缺失区间 | run 外侧合法前后邻居 | 插值输入 |
| 三模态补全 | pose/tactile/gripper run | [[SignalRepairSampleRecord]] 和修复后序列引用 | 滤波器和 MCAP_A 生成器 |
| 结果聚合 | 所有 run、缺失区间、序列引用 | [[SignalRepairResult]] | 报告生成器和开发者入口 |

## 10. 计算规则

| 规则 | 触发条件 | 计算 / 判断方式 | 结果表达 |
|---|---|---|---|
| 只消费上游输出 | 检测结果已存在 | 读取 [[SignalReliabilityDetectionResult]]，不新增异常检测规则 | 输入接口记录 |
| run 聚合 | 同一 `topic + modality + time_domain + replacement_unit` | `field_path` 必须进入主分组键 | [[SignalRepairRun]] |
| 计算权限 | `disposition=AUTO_REPAIR` 且 `status=pending` | 核对预定方法后才调用数值修复 | repaired/unrepairable |
| 合法邻居 | 同 topic、同模态、同时间域、同 replacement unit 干净、不跨缺失区间 | 同时找到前后合法样本 | 邻居引用 |
| position 插值 | `pose.position` 可插值 | 按 timestamp 比例线性插值三元组 | `repair_method=linear_interpolate` |
| orientation 插值 | `pose.orientation` 可插值 | 固定使用 SLERP 并归一化 | `repair_method=slerp_interpolate` |
| gripper 插值 | `gripper.value` 可插值 | 按 timestamp 比例线性插值，修复后 clamp 到 `[0, 1]` | 记录 `clamped` |
| tactile 插值 | `tactile.frame` 可插值 | 整帧矩阵逐元素线性插值，shape 不一致则拒绝 | 主记录保存摘要 |
| 缺失区间处理 | [[MissingIntervalIssue]] | v1 不插入消息 | `unhandled_missing_interval_records` |

## 11. 输出结果结构

| 字段 | 类型 | 含义 | 有效性要求 | 下游使用方式 |
|---|---|---|---|---|
| `input_detection_result_ref` | [[SignalReliabilityDetectionResult]] | 输入检测结果引用 | 必须可追溯 | 报告和复现 |
| `repair_policy_config_ref` | [[SignalRepairPolicyConfig]] | 修复策略配置引用 | 必须可追溯 | 调参和复现 |
| `repair_runs` | list[[SignalRepairRun]] | run 级决策记录 | 每个 run 有状态和 reason | 报告、审计 |
| `unhandled_missing_interval_records` | list | v1 未处理的缺失区间 | 必须覆盖所有 [[MissingIntervalIssue]] | 下游 mask 候选 |
| `output_sequence_refs` | object/list | 修复后序列引用 | 不塞完整序列 | 滤波器和调试产物 |
| `timestamp_policy` | enum string | 固定 `preserve_original` | 必填 | 验收不重采样 |
| `sample_count_before` / `sample_count_after` | object | 各 topic 样本数 | 必须相等 | 验收长度不变 |
| `summary_by_modality` | object | 三模态修复统计 | 区分 repaired/unrepaired/skipped | 开发者入口摘要 |

## 12. 异常与边界输入

| 边界情况 | 预期结果 | reason / error 表达 | 是否阻塞下游 |
|---|---|---|---|
| 检测结果缺失 | 功能检验失败 | `missing_detection_result` | 是 |
| 样本定位找不到原始消息 | 当前样本拒绝修复 | `sample_ref_not_found` | 否，进入报告 |
| 非 `AUTO_REPAIR` 处置 | 不调用数值修复函数 | `status=skipped/unrepairable` | 否 |
| 插值缺少前后合法邻居 | 保留原值并成为滤波 segment 边界 | `missing_previous_neighbor` / `missing_next_neighbor` | 否 |
| 跨缺失区间查找邻居 | 禁止跨越，拒绝修复 | `cross_missing_interval` | 否 |
| tactile shape 不一致 | 拒绝自动补全 | `tactile_shape_mismatch` | 否 |
| pose position 可修但 orientation 不可修 | 两个字段独立记录，position 可成功而 orientation 保留原值 | 各自 run status | 否 |

## 13. 可验证样例

| 样例 | 输入特征 | 预期输出 | 验证方式 |
|---|---|---|---|
| 合法输入 | detection result 无 sample issue | 无修复 run，序列引用保持原样 | 单元测试 |
| 夹爪连续异常 | 5 个连续 gripper 样本获 `AUTO_REPAIR`，前后邻居合法 | 1 个 run，5 条 repaired sample record | 夹爪序列测试 |
| 姿态异常 | orientation 异常，前后合法四元数 | 使用 SLERP，输出归一化四元数 | pose 单元测试 |
| 触觉整帧异常 | 触觉帧可插值且前后 shape 一致 | 整帧逐元素插值，主记录保存摘要 | 触觉 fixture 测试 |
| 未获批准 | run 处置为 `MANUAL_REVIEW` | 不进入计算，保持原值 | 状态机测试 |
| 缺失区间 | detection result 含 MissingIntervalIssue | 不插消息，记录未处理缺失 | 缺失区间测试 |

## 18. 给 L3 任务生成的约束

1. 每个 L3 只能解决一个核心目标。
2. 数据补全器 L3 不得重新做异常检测。
3. 数据补全器不得新增、删除、重采样消息。
4. 数据补全器不得跨 topic、跨左右臂、跨模态查找邻居。
5. `SuggestedRepairAction` 不得直接授权数值修复。
6. `pose.orientation` 插值必须使用 SLERP。
7. 触觉 v1 只做整帧矩阵逐元素插值，不做单 cell 修复。
8. 同一 pose 样本的 position/orientation 必须分别处置和记录。
9. 每个 Service 场景 L3 必须写明它对应或影响 `./start_data_clean.sh --dev` 下的场景二功能检验项或场景完整 smoke test。
10. L3 自动化验收只证明局部实现正确；场景最终验收必须由用户本人运行 `./start_data_clean.sh --dev` 后确认。
