# ui 层设计：L2-02

## 1. 目标源码路径

```text
src/model_deploy/act/ui/observation_ros_adapter.py
```

## 2. 层职责

`ui/` 是外部交互边界。L2-02 的 ui 层负责把 ROS observation messages 转成 service 层可消费的 RAM 值，并在 callback 后尝试把 ready snapshot 写入 runtime buffer。

ui 层不得实现核心 snapshot 业务规则，不得调用 ACT 模型，不得发布硬件命令。

## 3. 文件设计

### `ObservationRosAdapter`（typed，deploy_057）

文件职责（不再消费 raw Dict）：

- 只消费冻结的 `DeployConfig` 与 `PolicyInputSpec`，无 Dict fallback。
- 根据 `DeployConfig.topics.observation` 创建 subscription；camera keys 必须与
  `PolicyInputSpec.camera_keys` 精确一致（不一致 → `ValueError` fail-fast）。
- 将 ROS message decode 成 RAM 值，并把图像预处理为 **owned float32 CHW、
  范围 [0,1]、shape 精确等于 `spec.image_shapes`** 后写入 collector。
- 调用 `ObservationCollector.update_*`；调用 `ObservationCollector.snapshot(max_age_s)`
  并在 ready 时写入 `ObservationBuffer`。
- 在缺字段或 decode 失败时记录 diagnostics；decode 失败不更新缓存。
- gripper：订阅消息类型（占位 `Pose`）与 `decode_gripper_width` 标量解码器保持一致；
  真实 gripper ROS topology **未知**，置 `gripper_topology_unknown=True` 单独记录，
  解码失败如实记录为 local error，不掩盖为成功。
- 订阅创建失败：已创建 handles 统一 rollback（destroy）后向上传播异常；
  仅当 ROS packages 缺失时记 `env_blocked`，配置 / decoder 错误一律传播，不降级为环境。

class 设计：

| class | 封装微元 | 内部状态 | 生命周期 / 并发 | 为什么是 class |
|---|---|---|---|---|
| `ObservationRosAdapter` | subscription 创建、callback、message decode、try snapshot | ROS node handle、collector、buffer、config、input_spec、monotonic_clock、last log time | 随 ROS node 生命周期存在，callback 事件驱动 | 需要持有 node 和 callback 依赖 |

函数设计：

| 函数 | 输入 | 输出 | 副作用 | 错误行为 |
|---|---|---|---|---|
| `create_subscriptions(node)` | ROS node | subscription handles | 注册 ROS subscriptions；部分失败 rollback | 非 ROS 缺失 → 抛错；ROS 缺失 → `env_blocked` |
| `decode_image_message(msg)` | Image / CompressedImage | RGB RAM image | 读取 message payload | unsupported encoding 抛错 |
| `handle_image(name, msg)` | camera name、message | 无 | decode→预处理→CHW 校验→更新 collector→可能写 buffer | decode/preprocess/shape/range 失败记录 warning |
| `handle_tcp_pose(side, msg)` | side、pose msg | 无 | 更新 collector，可能写 buffer | shape / quaternion 非法记录 warning |
| `handle_gripper_state(side, msg)` | side、state msg | 无 | 更新 collector，可能写 buffer | 缺标量 width 记录 warning |
| `try_publish_observation()` | 无 | bool | ready 时写 buffer | missing fields 时只记录 diagnostics |

### `observation_pipeline.py`（typed factory，deploy_057）

文件职责：

- 暴露冻结 public seam：`@dataclass(frozen=True) class ObservationPipeline`
  （`collector` / `buffer` / `adapter` / `input_spec` / `monotonic_clock`）。
- `build_observation_pipeline(*, node, config, input_spec, monotonic_clock)`
  在**创建任何 subscription 之前**完成 config / spec / camera / image / message class
  的纯 RAM 校验（camera keys 对齐、PolicyInputSpec 已保证 CHW/float32/[0,1]）；
  通过后创建 collector / buffer / adapter 并建订阅；订阅中途失败由 adapter rollback。
- `pipeline.input_spec` 与传入对象 identity 相同；`pipeline.monotonic_clock` 也保留同一 callable。
- 整个采集链（collector / buffer / adapter / factory）共用注入的 monotonic clock，
  `captured_at_s` 与 buffer freshness 同域；`ObservationSnapshot` 在构造时对
  images / state / encoded_state 做深复制，已发布的 snapshot 不受源缓存后续修改影响。

class / 函数设计：

| 符号 | 封装微元 | 不变量 |
|---|---|---|
| `ObservationPipeline` | 冻结 facade，聚合 collector/buffer/adapter/spec/clock | frozen；spec/clock identity 保留 |
| `build_observation_pipeline` | 校验 → 装配 → 建订阅 | 订阅前纯 RAM 校验；部分订阅失败 rollback 并传播 |


## 4. ROS import 策略

真实 ROS packages 应延迟 import 或封装在 adapter 初始化路径中，保证以下模块在无 ROS 环境下仍可 import：

- `types/observation.py`
- `service/observation_collector.py`
- `runtime/observation_buffer.py`

如果当前环境缺 ROS，ui 层真实 subscription 验收记录为 `BLOCKED_ENV`，但 mock message decode 和静态检查仍应执行。

## 5. 输入输出

| 输入 | 输出 |
|---|---|
| ROS Image / CompressedImage / Pose / gripper state messages | service update 调用、runtime buffer 写入 |

## 6. 副作用

- 创建 ROS subscription。
- callback 写入 collector / buffer。
- 记录 warning 或 diagnostics。

不发布 command topic，不触发硬件动作。

## 7. 依赖关系

允许依赖：

- `types/observation.py`
- `config` 公开配置对象
- `service/observation_collector.py`
- `service/image_preprocess.py`
- `runtime/observation_buffer.py`
- ROS packages（仅 ui 层）

禁止依赖：

- L2-03 ACT policy runtime
- L2-04 SafetyGuard
- L2-05 command publisher / hardware driver
- L2-06 ControlLoop internals

## 8. Pi0.5 参考

- `Pi05VlaDeployNode._create_subscriptions`
- `Pi05VlaDeployNode._image_cb`
- `Pi05VlaDeployNode._point_cb`
- `Pi05VlaDeployNode._hand_cb`
- `Pi05VlaDeployNode._publish_observation_if_ready`
- `_decode_image`

ACT 必须把这些能力拆成 adapter，而不是把整套 Pi0.5 deploy node 照搬为 L2-02。

## 9. 验收覆盖

- 无 ROS 环境下核心模块 import 不失败。
- mock image / pose / gripper callbacks 能调用 collector。
- decode 失败不更新缓存。
- ready snapshot 写入 buffer。
- 本 L2 不发布硬件命令。

## 10. 边界继承声明

本文件服务当前 L1/L2 功能边界，不从旧 layer-based L2 卡片继承任务边界。
