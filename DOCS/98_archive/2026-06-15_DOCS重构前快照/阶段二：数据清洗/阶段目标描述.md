# 阶段二：数据清洗目标描述

## 阶段定位

阶段二负责把阶段一/Octopus 采集得到的 raw MCAP，从“多 topic 原始日志”整理成后续训练可以稳定消费的数据集。当前工程已经不只是做单个 MCAP 清洗，而是围绕 Runtime 编排、Service 场景处理、对齐产物和训练格式桥接形成了一条可验证链路。

给没有上下文的 Codex 接手时，应把阶段二理解为两层：

- `Runtime`：负责入口、配置、run 目录、日志、manifest、dev check 和场景调度。
- `Service`：负责具体数据处理算法，例如夹爪提取、位姿转换、可靠性检测、字段对齐、Forge bridge。

代码级详细入口是 `src/data_clean/data_clean_architecture.md`。

## 当前真实主链路

当前已验证的主链路是：

```text
raw MCAP
  -> [场景一] cleaned MCAP
  -> [场景二] MCAP_A
  -> [场景三] aligned MCAP
  -> [临时桥接] 04_forge_bridge/forge_ready.mcap
  -> [Forge Python fallback] 05_lerobot_v3_bimanual/
```

其中：

- `raw MCAP` 是 Octopus 录制的原始 topic 日志。
- `cleaned MCAP` 增加夹爪宽度，主位姿输出在机械臂基坐标系（per RM65 base，即 arm-base），并保留 common frame 作为历史兼容说明。
- `MCAP_A` 是场景二可靠性检测、补全、滤波后的主数据中间产物。
- `aligned MCAP` 是场景三按 step 时间轴对齐后的语义 MCAP。
- `04_forge_bridge/forge_ready.mcap` 是临时 Forge 桥接产物，不污染正式 aligned MCAP 契约。
- `05_lerobot_v3_bimanual/` 是当前已跑通的双臂 LeRobot v3 格式验证产物。

已验证样例产物位于：

```text
asset/阶段二：数据清洗/dev/full_flow_random_bimanual/
```

正常用户不需要逐段手工调用 Runtime。`./start_data_clean.sh` 无参数时启动本机网页，用户勾选一批 raw MCAP 后，网页会执行上述全链路，并把所有成功文件聚合为一个 LeRobot v3 dataset。单文件失败不会阻断其他成功 episode 发布。

网页最终 dataset 写入：

```text
<用户选择的本机父目录>/<dataset_name>/
```

默认建议父目录是 `asset/阶段二：数据清洗/prod/exports/lerobot/`，但用户可以选择任意本机目录，网页不做路径限制或风险提示。该自由选择只适用于最终 dataset；中间产物、报告和日志仍固定写入受控 sidecar。

## 正式目标与临时桥接

阶段二的正式目标仍是生成 MCAP-centric canonical dataset。阶段二 action 保存左右 arm-base 下的绝对 TCP 目标位姿；训练侧 LeRobot 框架根据训练策略负责转换为差分或相对表示。canonical dataset 仍应包含 dataset/episode/step 层级的 schema、index、masks、quality report、processing manifest 和可复现的导出能力。

当前已经额外实现一条临时双臂 LeRobot v3 桥接路径，用于验证数据能否进入训练格式生态：

```text
aligned MCAP
  -> service.forge_bridge.write_forge_bridge()
  -> forge_ready.mcap + forge_bridge_schema.json + forge_bridge_report.json
  -> runtime.forge_bridge_to_lerobot.convert_forge_bridge_to_lerobot()
  -> LeRobot v3 dataset
```

这条桥接的 action 是下一时刻的双臂绝对目标，符合阶段二输出职责。差分或相对化属于训练侧职责。

## 临时 LeRobot Step 语义

当前临时 LeRobot v3 每个 step 的语义为：

```text
step_t = {
  observation_t,
  action_t
}
```

`observation_t` 包含：

```text
observation.images.left_t
observation.images.right_t
observation.state_t
```

`observation.state_t` 固定为 32 维：

```text
[0:7]   left_tcp_pose_t        = xyz + qx qy qz qw
[7:14]  right_tcp_pose_t
[14]    left_gripper_width_t
[15]    right_gripper_width_t
[16:20] tactile_left_gripper_1_t   = mean std min max
[20:24] tactile_left_gripper_2_t
[24:28] tactile_right_gripper_1_t
[28:32] tactile_right_gripper_2_t
```

`action_t` 固定为 16 维：

```text
[0:7]   left_tcp_pose_t+1
[7]     left_gripper_width_t+1
[8:15]  right_tcp_pose_t+1
[15]    right_gripper_width_t+1
```

最后一帧因为没有 `t+1` action，会在桥接时丢弃。

## 成功标准

阶段二当前可分为“已跑通格式链路”和“正式训练可用”两级成功标准。

已跑通格式链路需要满足：

- `./start_data_clean.sh` 能启动仅监听 `127.0.0.1` 的正常用户网页。
- 网页允许浏览本机目录、勾选当前层 MCAP、自由选择最终 dataset 输出父目录，并展示全链路进度。
- 网页配置中心只编辑正式生产配置中的左右 `camera_from_tcp.translation_mm` 与 `work_frames.position_mm / rotation_euler_rad`，夹爪配置通过 GoPro 向导自动生成；每个任务 snapshot 同时记录人工输入 `mm/rad` 与 Runtime 规范化后的 `m/rad`。
- 普通 Web 不暴露 preset、`format-only/formal` 切换或 frame alignment 外参表单；启动任务前服务端再次执行生产 readiness 校验，缺少夹爪标定、arm-base topic、work frame 或 RealMan SDK 时 fail-closed。
- 多个成功 MCAP 能聚合成一个 LeRobot v3 dataset；单文件失败时成功 episode 仍能发布。
- 结果页能可视化展示 Forge quality 各维度分数、逐 episode 分数和 flags。
- 结果页能从最终 dataset 展示左右 TCP 3D 轨迹；固定右手工程视角使用左下角显示局部原点，单 episode 可按原始时间戳播放。
- 普通 Web 轨迹固定按左右 arm-base 生产语义展示；历史 `format-only/common_frame` 轨迹只作为开发烟测兼容。
- `./start_data_clean.sh --dev` 能进入开发者菜单并运行场景检验项。
- 场景二能生成 MCAP_A 或对应 dev check 结果。
- 场景三能从 MCAP_A 生成 aligned MCAP、alignment index 和 alignment report。
- 临时 Forge bridge 能从 aligned MCAP 生成 `forge_ready.mcap`。
- LeRobot v3 输出包含双目视频、32 维 state、16 维 action，并能被 Forge inspect/quality 检查。

正式训练可用还需要满足：

- 左右 arm-base TCP pose、夹爪宽度、触觉字段完整可靠，且生产 readiness 全部通过。
- 标定已完成，包括真实相机到 TCP 外参和左右 work frames。
- quality report、alignment report 和后续 robot/constraint 检查均支持训练结论。
- 训练侧 LeRobot 框架能从阶段二绝对 action 按训练策略生成差分或相对表示。
