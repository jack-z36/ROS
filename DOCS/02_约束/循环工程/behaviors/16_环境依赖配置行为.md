# 环境依赖配置行为

## 消费 Agent

- 主 Agent
- 执行 sub-agent

## 本文职责

本文只约束阶段四模型部署循环中环境依赖配置、依赖安装和验证命令的运行环境。

## 不负责

本文不承载当前环境状态、依赖安装日志、具体依赖版本清单、L3 任务正文、验收结论或 Git 操作规则。

## 固定环境

- 阶段四模型部署开发必须使用 Conda 管理 Python 环境。
- Conda 环境名称固定为 `model_deploy`。
- Agent 不得自行改名、另建替代环境或退回系统全局环境继续开发。

## 必须行为

- 执行阶段四代码开发、依赖安装、局部验证、测试或 Python 命令前，必须确认当前环境是 Conda 环境 `model_deploy`。
- 环境确认至少应覆盖：
  - `conda info --envs` 或等价命令能看到 `model_deploy`。
  - 当前 Python / pip 路径指向 `model_deploy` 环境。
  - 运行命令前已通过 `conda activate model_deploy` 或等价方式进入该环境。
- 需要安装依赖时，只能安装到 `model_deploy` 环境内。
- 若 `model_deploy` 环境不存在，主 Agent 必须将其记录为环境阻塞，或在任务允许范围内创建该环境。
- 执行 sub-agent 的交接摘要必须写明：
  - 使用的 Conda 环境名称。
  - 执行过的关键验证命令。
  - 若验证未执行，说明是否因 `model_deploy` 环境缺失或依赖缺失而阻塞。

## 禁止事项

- 禁止直接在本机 Linux 全局 Python 环境中开发、安装依赖或运行验证。
- 禁止使用全局 `pip install` 污染系统 `site-packages`。
- 禁止因 Conda 环境缺失而绕过环境要求继续开发。
- 禁止把当前机器的环境状态、安装日志或临时路径写入循环工程约束文档。
