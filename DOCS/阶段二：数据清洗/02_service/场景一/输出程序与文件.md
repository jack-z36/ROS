# 场景一：输出程序与文件

## 配置文件

| 类型 | 路径 | 说明 |
|---|---|---|
| 场景一主配置 | `config/data_clean/data_clean_calibrated.yaml` | 现有浏览器标定向导写回的主配置，后续需迁移到 [[Scene1Config]] 契约。 |
| 夹爪配置 | `gripper_streams` / [[GripperCalibrationConfig]] | 由浏览器 GoPro 标定程序生成，包含 marker、像素范围和 `gripper_max`。 |
| 位姿转换配置 | `frame_alignment` / [[FrameAlignmentConfig]] | 目标契约，默认 `common_anchor: left`。 |
| 旧位姿配置 | `config/data_clean/data_clean_left_transform.yaml`、`config/data_clean/data_clean_right_transform.yaml` | 旧 `start_from_common` 文件，只作为迁移输入或兼容对象。 |

## 程序入口

| 程序 / 模块 | 路径 | 说明 |
|---|---|---|
| 浏览器标定向导 | `src/data_clean/ui/mcap_calibration_wizard.py` | 已有实现。负责启动浏览器、显示左右 GoPro 画面、采样/点击并写回配置。 |
| MCAP 批处理入口 | `src/data_clean/cli/process_mcap.py` | 现有场景一批处理命令入口。 |
| 配置加载 | `src/data_clean/config/mcap_process_config.py` | 后续需支持 [[GripperCalibrationConfig]] 和 [[FrameAlignmentConfig]]。 |
| 夹爪宽度提取 | `src/data_clean/service/gripper_extractor.py` | 根据夹爪配置生成 gripper width。 |
| 位姿转换 | `src/data_clean/service/tcp_transform.py` | 当前基于旧 transform；后续改造为 [[FrameAlignmentConfig]]。 |
| MCAP 写出 | `src/data_clean/service/mcap_io.py` | 后续需保留 raw pose 并写出 common camera/TCP pose。 |

## 输出数据

| 输出 | 路径 / topic | 契约 |
|---|---|---|
| cleaned MCAP | `asset/阶段二：数据清洗/dev/mcap_cleaned/*.mcap` | [[CleanedMcap]] |
| raw pose | `/baton_mini_left/fast_odom`、`/baton_mini_right/fast_odom` | 必须保留或可追溯。 |
| common camera pose | 配置中的 `output_camera_pose_common` | [[CommonFrameCameraPose]] |
| common TCP pose | 配置中的 `output_tcp_pose_common` | [[CommonFrameTcpPose]] |
| gripper width | `/gopro_left/gripper_width`、`/gopro_right/gripper_width` | [[GripperWidthSample]]，`std_msgs/msg/Float32`，归一化 `[0, 1]`。 |

## 需要改造的现实差异

- 当前代码和旧文档仍存在 `start_from_common` 和替换 pose payload 的历史语义。
- 新契约要求 raw pose 保留，common frame pose 和 TCP pose 有明确输出语义。
- 新位姿配置默认 `common_frame = left_umi_start_frame`，不再额外定义桌面 `origin_frame`。
- 浏览器配置生成器已经存在，后续 L3 只做接口对接和输出字段收敛。
