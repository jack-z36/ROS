场景一：提取夹爪开合以及位姿转换

从 raw MCAP 生成 cleaned MCAP，补齐夹爪宽度语义，并把左右 Baton Mini raw pose 转换到 common frame 下的相机 pose，为后续可靠性验证提供具备基础训练语义的数据。

核心目标

把阶段一采集得到的 raw MCAP，从"硬件原始 topic 日志"推进为可继续处理的 cleaned MCAP。cleaned MCAP 至少应具备三类能力：保留原始多模态数据、补齐左右夹爪宽度语义、将左右 Baton Mini 局部坐标系下的 raw pose 统一到 common frame 下的相机 pose。

背景信息

场景定位

raw MCAP 是阶段一采集链路的原始产物，主要保存硬件 topic 日志。它包含图像、Baton Mini odometry、触觉等数据，但还没有完全具备后续训练数据所需的语义表达。

本场景存在的原因是：在进入滤波、异常值处理、IK 验证和时间对齐之前，必须先把 raw MCAP 转换为 cleaned MCAP，使数据具备统一的基础语义。

输入数据形态

raw MCAP 中主要包含：

  • 左右图像数据（/gopro_left/image_raw、/gopro_right/image_raw）
  • 左右 Baton Mini 原始位姿数据（/baton_mini_left/fast_odom、/baton_mini_right/fast_odom）
  • 左右触觉数据（/pressure/left_hand/gripper_1 等 4 个 topic）

这些数据仍处在 topic 世界中，不直接区分 observation、action、episode 或 step。

关键语义补齐

夹爪宽度

夹爪宽度不是直接由独立传感器写入 MCAP 的训练字段。需要通过视觉标定或图像信息，生成左右夹爪宽度语义。该语义后续会进入 observation，并在 action 或 mask 生成时作为重要字段参与判断。

common frame 相机位姿

左右 Baton Mini 的 raw pose 分别处在各自局部坐标系中。为了让后续双臂数据能在同一空间下理解，必须将左右 raw pose 转换到统一的 common_frame 下。首版默认：

common_frame = left_umi_start_frametext

TCP pose 可在后续由 common-frame 相机 pose 叠加相机到 TCP 的固定外参得到，不在本场景强行绑定。

输出数据形态

cleaned MCAP 应保留原始多模态数据，并补齐后续场景依赖的基础语义字段：图像字段、触觉字段、左右夹爪宽度、左右 common frame 相机 pose。同时应产生清洗报告和标定/转换参数。

风险与未知
  • 夹爪宽度提取依赖视觉标定质量，真实硬件条件会影响稳定性。
  • common frame 的定义需要保持一致，否则左右空间关系会失真。
  • Baton Mini 可能存在漂移，场景一只负责转换表达，不负责判断长期可靠性。
  • TCP 外参尚未在本场景固化，后续涉及机器人执行时需要继续明确。

01 · cleaned MCAP 契约稳定 P0

数据定义类 · 来源：功能模块清单

一句话目标：稳定场景一对场景二公开的 CleanedMcap、Scene1Config 和 Scene1CleanReport 契约。

能力角色：把场景一从"已有脚本和局部实现"收敛成阶段二 Service 的稳定接口。只定义契约和任务边界，不直接改源码。

当前修正：raw pose 必须保留或可追溯；common frame camera pose 和 common frame TCP pose 必须有独立、明确的输出语义。

上游：raw MCAP 来自阶段一采集；GripperCalibrationConfig 来自浏览器 GoPro 标定程序；FrameAlignmentConfig 来自位姿转换配置生成模块。

下游：场景二读取 CleanedMcap、Scene1Config、Scene1CleanReport；场景二优先消费 CommonFrameTcpPose。

02 · 夹爪开合配置生成 P0

工具对接类 · 现实代码入口：src/data_clean/ui/mcap_calibration_wizard.py

一句话目标：对接已有浏览器 GoPro 标定程序，生成夹爪宽度提取所需的 GripperCalibrationConfig。

上游：终端启动脚本、左右 GoPro live image topic、用户在网页中点击两个点或完成 ArUco 采样流程。

L3 约束

必须先确认现有网页是否支持"点击两个点"生成配置。如果现有实现只支持 ArUco 采样，应补齐最小点位采集接口，而不是重写整套 UI。

03 · 夹爪宽度提取 P0

数据计算类

一句话目标：从左右 GoPro 图像中检测 ArUco marker，生成 cleaned MCAP 中的左右 GripperWidthSample。

上游：raw MCAP 中的 /gopro_left/image_raw、/gopro_right/image_raw 和 GripperCalibrationConfig。

下游：CleanedMcap 中新增的 gripper topic 被场景二异常检测和后续 observation/action 构建依赖。

04 · 位姿转换配置生成 P0

工具对接类

一句话目标：生成以单侧 UMI 初始坐标系作为 common_frame 的 FrameAlignmentConfig。

核心方案：首版不再额外定义桌面 origin_frame。默认 common_anchor = left，即 common_frame = left_umi_start_frame。

当 common_anchor: left 时：
T_common_left_camera(t) = T_left_start_left_camera(t)
T_common_right_camera(t) = T_common_right_start * T_right_start_right_camera(t)
T_common_tcp(t) = T_common_camera(t) * T_camera_tcptext

上游：固定底座给出 left_start_frame 和 right_start_frame 的相对外参；需要左右 camera 到 TCP 的 CameraFromTcpExtrinsic。

下游：common frame 位姿转换使用 FrameAlignmentConfig；CommonFrameCameraPose 和 CommonFrameTcpPose 被写入 cleaned/canonical 数据产物。

05 · common frame 位姿转换 P0

数据计算类

一句话目标：将左右 Baton Mini start frame 下的 raw pose 转换为 common frame 下的 camera pose 和 TCP pose。

上游：raw MCAP 中的 /baton_mini_left/fast_odom、/baton_mini_right/fast_odom 和 FrameAlignmentConfig。

下游：场景二优先按 CommonFrameTcpPose 消费位姿；CommonFrameCameraPose 用于调试和排查；raw pose 必须保留。

计算规则（common_anchor: left）

hand计算
left cameraT_common_left_camera(t) = T_left_start_left_camera(t)
right cameraT_common_right_camera(t) = T_common_right_start * T_right_start_right_camera(t)

L2 数据定义详解

CleanedMcap

场景一从 raw MCAP 生成的 cleaned MCAP 数据产物，保留原始多模态 topic，并补齐夹爪宽度、common frame camera pose 和 common frame TCP pose。它是场景二可靠性验证的直接输入，仍是 MCAP topic 世界，不是 episode/step/observation/action 世界。

内容契约
文件位置asset/阶段二：数据清洗/dev/mcap_cleaned/*.mcap
原始 topic默认保留 raw MCAP 中的原始 topic 和消息顺序
raw pose topic/baton_mini_left/fast_odom、/baton_mini_right/fast_odom 必须可追溯保留
camera common poseCommonFrameCameraPose，由 FrameAlignmentConfig 转换得到
TCP common poseCommonFrameTcpPose，由 camera common pose 叠加 CameraFromTcpExtrinsic 得到
左右 gripper topic/gopro_left/gripper_width、/gopro_right/gripper_width
gripper payload每帧图像对应一个归一化 GripperWidthSample
有效性规则
  • raw MCAP 不得被原地覆盖。
  • raw pose 必须保留或在报告中有可追溯来源，不能只留下转换后 pose。
  • camera common pose 和 TCP common pose 消息数量必须与输入 pose topic 数量一致。
  • gripper topic 消息数量必须等于对应 image topic 图像帧数。

Scene1Config

场景一清洗所需配置的总契约，覆盖 batch 输入输出、gripper 标定、frame alignment、pose stream 和标定状态。

配置块字段现实含义
batchinput_dirraw MCAP 输入目录
output_dircleaned MCAP 输出目录
gripper_streamsimage_topic, output_topic, marker_*, gripper_maxGripperCalibrationConfig 字段
frame_alignmentcommon_anchor默认 left，即 common_frame = left_umi_start_frame
pose_streamsraw pose 输入和 common pose 输出 topic
extrinsicscommon_from_*_start, camera_from_*_tcp
calibrationgripper, frame_alignment左右夹爪和位姿转换配置状态

GripperCalibrationConfig

夹爪开合提取所需的标定配置，来源于浏览器 GoPro 标定工具，用于把图像中的 marker 几何关系映射为归一化夹爪宽度。

字段类型现实含义
handenumleft 或 right
image_topicstringGoPro 图像输入 topic
output_topicstringgripper width 输出 topic
aruco_dictstringArUco 字典
marker_id_0, marker_id_1integer夹爪两侧 marker id
marker_min, marker_maxfloat关闭/张开状态对应的 marker 像素距离
gripper_maxfloat物理最大开合宽度

FrameAlignmentConfig

场景一位姿转换配置契约，用于把左右 Baton Mini raw pose 转换到同一个 common frame。首版 common frame 直接选择单侧 UMI 的初始坐标系，默认是 left_umi_start_frame。

frame_alignment:
  common_anchor: left
  pose_streams:
    left:
      input_topic: /baton_mini_left/fast_odom
      output_camera_pose_common: /baton_mini_left/camera_pose_common
      output_tcp_pose_common: /baton_mini_left/tcp_pose_common
    right:
      input_topic: /baton_mini_right/fast_odom
      output_camera_pose_common: /baton_mini_right/camera_pose_common
      output_tcp_pose_common: /baton_mini_right/tcp_pose_common
  extrinsics:
    common_from_left_start:
      translation_m: [0.0, 0.0, 0.0]
      rotation_quat_xyzw: [0.0, 0.0, 0.0, 1.0]
    common_from_right_start:
      translation_m: [0.0, 0.0, 0.0]
      rotation_quat_xyzw: [0.0, 0.0, 0.0, 1.0]
    camera_from_left_tcp:
      translation_m: [0.0, 0.0, 0.0]
      rotation_quat_xyzw: [0.0, 0.0, 0.0, 1.0]
    camera_from_right_tcp:
      translation_m: [0.0, 0.0, 0.0]
      rotation_quat_xyzw: [0.0, 0.0, 0.0, 1.0]yaml

CameraFromTcpExtrinsic

TCP 坐标系在 Baton Mini 相机坐标系下的固定外参，用于把 common frame 下的 camera pose 转换为 common frame 下的 TCP pose。

T_common_tcp(t) = T_common_camera(t) * T_camera_tcptext

配置字段统一使用 camera_from_left_tcp、camera_from_right_tcp。四元数必须是单位四元数，单位必须是 m。左右 TCP 外参必须分别配置。

CommonFrameCameraPose

左右 Baton Mini 相机在 common frame 下的位姿表达。由 raw MCAP 中 Baton Mini start frame 下的相机 pose 经过 FrameAlignmentConfig 转换得到。

字段类型现实含义
x, y, zfloatcommon frame 下相机位置
qx, qy, qz, qwfloatcommon frame 下相机姿态四元数，顺序为 xyzw
source_topicstring原 pose topic，如 /baton_mini_left/fast_odom
output_topicstring配置中的 camera common pose 输出 topic
common_anchorstringleft 或 right

CommonFrameTcpPose

左右夹爪 TCP 在 common frame 下的位姿表达，是场景二位姿滤波、异常检测和后续 IK 的优先输入。

T_common_tcp(t) = T_common_camera(t) * T_camera_tcptext
字段类型现实含义
x, y, zfloatcommon frame 下 TCP 位置
qx, qy, qz, qwfloatcommon frame 下 TCP 姿态四元数，xyzw
source_camera_posestring来源 camera common pose topic 或字段
tcp_extrinsic_sourcestringTCP 外参来源

字段类型现实含义

source_image_topicstring来源图像 topic
output_topicstring输出夹爪宽度 topic
source_methodenumdirect_marker / single_marker_estimate / interpolated

TcpFromCameraExtrinsic（已废弃）

已废弃

该名称容易被误解为 T_tcp_camera，与场景一实际计算需要的 T_camera_tcp 相反。后续配置和 L3 必须使用 CameraFromTcpExtrinsic，字段名为 camera_from_left_tcp、camera_from_right_tcp。本文件仅保留为旧链接兼容。

执行约束

环境约束

  • 默认使用 .conda-envs/data-clean/bin/python。
  • 不应依赖系统 Python 里的 OpenCV、MCAP 或 ROS2 Python 包状态。
  • 不应要求用户手工设置长 PYTHONPATH，应通过 ./start_data_clean.sh 完成。

配置边界

  • 启动配置优先级：命令行 --config 或 DATA_CLEAN_CONFIG > data_clean_calibrated.yaml > data_clean_smoke_test.yaml。
  • batch.input_dir 默认指向 mcap；batch.output_dir 默认指向 mcap_cleaned。
  • 不应把左右手 Baton Mini 的正式 transform 写成同一套顶层 transform；必须通过 pose_streams[].transform_file 分别引用左右手配置文件。

清洗行为约束

  • 默认清洗最近 1 个文件。"最近 N 个"按 MCAP 文件名中的时间从新到旧选择。
  • 如果某个文件失败，应删除该文件对应的半成品输出。
  • DATA_CLEAN_RAW_JSON=1 应只输出原始 JSON，不能混入中文提示。
  • config_is_calibrated 只有在 gripper.left/right 和 common_frame.left/right 四项均完成时才能返回 true。
  • 标定中心不得依赖 OpenCV GUI 窗口；画面预览、夹爪标定和 common frame 标定应通过本地浏览器页面完成。
  • common frame 标定必须订阅对应 pose stream 的实时 Baton Mini odometry，并把稳定采样结果写入对应手的 start_from_common。

验收边界

不能算作最终完成的情况
  • 只跑通 --dry-run，但没有跑通过真实清洗。
  • 只清洗一个测试 MCAP，却声称全部数据已完成清洗。
  • 终端输出可读，但输出 MCAP 没有验证 topic 数或新增 topic。
  • 使用测试 common frame/ArUco 参数，却没有明确提醒用户这些参数未真实标定。
  • 仅用普通采集 MCAP 估算闭合/张开范围，而没有使用实时 GoPro 标定中心采集真实完全闭合/完全张开状态。
