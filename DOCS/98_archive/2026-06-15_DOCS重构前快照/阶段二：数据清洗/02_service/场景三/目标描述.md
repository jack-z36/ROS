# 阶段二场景三：MCAP 多 topic 时间轴对齐

## 一句话总结

从 validated MCAP 生成 aligned MCAP，把图像、位姿、触觉、夹爪宽度等不同频率 topic 对齐到统一 step 时间轴。

当前 formal/生产对齐链路使用左右 arm-base pose source：`/left_arm_base_tcp_pose` 与 `/right_arm_base_tcp_pose`。旧 `format-only/common-frame` 输入只保留为开发烟测兼容，不作为普通 Web 生产链路。

## 核心目标

本场景负责阶段二的第三步：解决多 topic 异步采集导致的时间不一致问题，为场景四构建 episode/step 索引提供时间基础。

aligned MCAP 应让后续处理能够按 step 读取同一时刻附近的多模态 observation，并知道每个字段来自哪里、使用了什么对齐方式、对齐误差是多少。

## 软件能力产出

本场景应形成以下中粒度软件能力：

- 时间对齐入口：用户可以对 validated MCAP 执行时间对齐。
- 统一时间轴生成能力：根据目标频率和起止策略生成 step 时间戳。
- topic 对齐能力：为每个 step 找到各字段的最近邻、插值结果或聚合结果。
- 位姿插值能力：处理位置和四元数插值，避免错误的姿态插值方式。
- 高频数据聚合能力：对触觉等高频数据做窗口聚合或降采样。
- 缺失和超时标记能力：标记无法可靠对齐的字段或 step。
- 对齐报告能力：统计频率、误差、缺失率、插值比例和丢弃情况。

具体脚本名、模块名、配置名和代码结构在实现时决定，不在本目标描述中提前固定。

## 自动化处理目标

用户运行本场景入口后，理想情况下应自动完成：

1. 读取 validated MCAP 的目标 topic 时间戳。
2. 生成统一 step 时间轴。
3. 对齐每个 step 的图像、位姿、触觉和夹爪字段。
4. 记录每个字段的来源、对齐方式和时间误差。
5. 标记缺失、复用、插值、超时和丢弃情况。
6. 写出 aligned MCAP 和 alignment report。

## 数据输出

| 输出 | 用途 |
| --- | --- |
| aligned MCAP | 场景四的输入。 |
| alignment report | 场景四 masks、quality report 和人工验收依据。 |
| 对齐索引中间产物（可选） | 可辅助生成 `step_index.parquet`，但不是必须固定格式。 |

## 成功标准

- 每个 step 都有统一时间戳。
- 每个 observation 字段都能追溯来源或明确标记无效。
- 对齐方式和对齐误差可追溯。
- 对齐质量有机器可读报告。
- 本场景输出能被场景四用于构建 canonical dataset。
