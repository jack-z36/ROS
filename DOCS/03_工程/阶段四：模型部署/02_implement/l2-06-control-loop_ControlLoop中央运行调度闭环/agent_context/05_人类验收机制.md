# L2-06 人类验收机制

## 1. 验收范围与安全原则

本页用于人类确认 L2-06 是否真实连接 L2-01～05。它不把“测试脚本运行过”当作通过，而要求检查真实对象、输出事实、失败位置和外部 BLOCKED 原因。

统一工作目录：

```bash
cd /home/hit/ROS/worktrees/l2-06-control-loop
```

安全原则：

- ROS dry-run、real-policy dry-run 与任何连接 ROS graph 的流程均保持 `command_output_enabled=False`。
- 只有纯进程内 FakeNode/FakePublisher 的 L2-05 outcome 合同测试可显式设 True，用于形成 PUBLISHED/BLOCKED/PARTIAL/FAILED；它不得连接 ROS graph、driver 或硬件。
- 未确认 permit source、E-stop、driver readiness、ROS topology 和操作者授权前，禁止真实 command。
- `PUBLISHED` 不代表 driver accepted 或 hardware reached。
- 任一代码级 FAIL 必须先修复；不得改写为环境 BLOCKED。

## 11. 验收项 10：真机命令（默认 BLOCKED）

必须同时具备：

- 独立操作者授权；
- E-stop 可用并已演练；
- `CommandPermitSource` 对 gate/deadman/E-stop/driver-ready 的可追踪证据；
- ROS graph 不存在未授权 bridge/subscriber；
- real-policy dry-run 原始记录；
- `safe_stop` 真实 driver contract，或明确声明只做逐 tick fail-closed/no-output、不主动 stop；
- 小范围/低速/单步执行方案与旁站人员。

任一缺失均保持 `BLOCKED_HARDWARE` 或 `BLOCKED_AUTHORIZATION`。本 Agent 不自动执行真机命令。
