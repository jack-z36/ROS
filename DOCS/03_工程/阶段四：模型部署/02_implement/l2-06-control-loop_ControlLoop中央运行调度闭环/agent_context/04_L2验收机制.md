# L2-06 验收机制（Agent Gate）

## 1. Gate 目标

证明 `ControlLoop.tick()` 在不等待推理的前提下，正确调度 latest observation、request/result queue、cursor、安全与输出，并把失败显式变成 fallback/status；不证明真机可运动。

## 2. 后续 L3 草案（本包不创建 L3）

1. 实现 `runtime/control_loop.py` 的状态、chunk 校验、tick 和单元测试。
2. 实现 UI 的 ROS timer/装配与 mock integration dry-run。
3. 实现 `05_acceptance/l2-06-control-loop/scripts/l2_06_verify.sh` 与 shadow-run 适配。

## 3. 验证层级与结果

| 层级 | 输入 / 命令占位 | PASS | FAIL / BLOCKED |
|---|---|---|---|
| import/unit | `pytest src/model_deploy/act/tests/runtime/test_control_loop.py` | cursor、request、fallback、metrics 断言通过 | 实现或依赖契约错误 |
| mock integration | `pytest .../tests/integration/test_control_loop_mock.py` | fake observation/worker/guard/publisher 完整闭环 | mock 接口不一致 |
| dry-run | `bash .../l2_06_verify.sh --mode dry-run` | ROS 不发硬件，输出状态可读 | ROS 环境缺失为 BLOCKED |
| shadow-run | `... --mode shadow` | topic 和 command_status 可见，`sent_to_driver=false` | topic/driver 未配置为 BLOCKED |
| real-robot | 仅获授权后执行 | gate、E-stop、shadow 证据齐全 | 默认 BLOCKED，绝不自动通过 |

下游 L2 可在 mock 契约通过后并行；合并至 `model_deploy` 必须至少 unit + mock + dry-run PASS，真实环境 BLOCKED 可保留但不得写成 PASS。

## 4. 验证脚本合同

后续 L3 在 `DOCS/03_工程/阶段四：模型部署/05_acceptance/l2-06-control-loop/scripts/l2_06_verify.sh` 创建脚本。它必须：

1. 按 `types/config/repo/service/runtime/ui·boundary` 分组输出（无产物层显示 `BLOCKED` 或明确跳过）。
2. 每行格式为 `PASS|FAIL|BLOCKED <label> <一句描述>`；FAIL 后紧跟文件、class、微元、pytest node、错误摘要。
3. 最后一行是 `N PASS / N FAIL / N BLOCKED`；任一 FAIL 退出 1，全 PASS 或只有 BLOCKED 退出 0。
4. 标签最少覆盖：`RUNTIME_CHUNK_VALIDATE`、`RUNTIME_REQUEST_PREFETCH`、`RUNTIME_CURSOR_FALLBACK`、`RUNTIME_SAFETY_HANDOFF`、`UI_TIMER_DRY_RUN`、`BOUNDARY_NO_SMOOTHING`。
5. BLOCKED 仅表示 ROS、topic、driver、硬件或授权不可用，不能掩盖代码断言失败。

## 5. 阻断项

真实 ROS topic/driver 名称、硬件 gate/E-stop、真机 fallback 行为及操作者授权未确认；它们只阻断 shadow/real-robot Gate，不阻断本 L2 设计或 mock L3。
