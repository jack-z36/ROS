# 场景五输出程序与文件

本文记录场景五“硬件信息映射为稳定设备名称和 topic 名称”已经形成或依赖的具体程序、文件地址和功能。

## 输出清单

| 类型 | 地址 | 功能 |
| --- | --- | --- |
| 硬件身份映射表 | `config/hardware_identity_map.yaml` | 将真实硬件身份映射到稳定逻辑名称、topic、配置项和固定设备名；当前重点覆盖 4 路触觉传感器。 |
| udev 规则文件 | `config/99-hwk-pressure.rules` | 为触觉串口生成稳定 `/dev/hwk_pressure_*` 软链接，避免 `/dev/ttyUSB*` 枚举顺序变化影响配置。 |
| 硬件身份扫描脚本 | `scripts/hardware_identity_scan.py` | 扫描串口和视频设备的 udev 属性、V4L2 能力和 HWK 协议身份；可根据映射表解析当前设备到逻辑目标。 |
| HWK 设备信息查询脚本 | `scripts/hwk_query_device_info.py` | 通过串口协议查询触觉传感器 UID、地址、版本等硬件身份字段，供身份映射使用。 |
| 触觉 USB 恢复脚本 | `scripts/hwk_pressure_usb_recover.sh` | 诊断 CH340 数量、expected by-path、udev 规则和近期内核事件；支持安装 udev 规则和 reset 右手触觉 USB hub。 |
| 传感器总配置 | `config/all_sensor_nodes.yaml` | 启用 `hardware_identity`，指定 `hardware_identity_map.yaml`，并声明 GoPro 与触觉逻辑配置。 |
| 总 launch | `launch/all_sensor_nodes.launch.py` | 启动前读取硬件身份解析结果，并把解析出的 GoPro 设备路径覆盖到运行配置中。 |
| 一键启动入口 | `start_all_sensor.sh` | 在 preflight 阶段调用硬件身份解析，并把解析结果写入 `hardware_identity_resolved.yaml` 供 launch 使用。 |
| 触觉驱动配置 | `src/hwk_pressure_driver/config/pressure_sensors.yaml` | 通过 `identity_map_file` 和 `strict_identity` 使用硬件身份映射，而不是依赖串口枚举顺序决定 topic。 |
| 触觉驱动架构文档 | `src/hwk_pressure_driver/hwk_pressure_driver_architecture.md` | 说明触觉驱动如何读取身份映射、查询 HWK_CHIP_UID、绑定固定 topic 并发布 PressureFrame。 |
| 触觉驱动配置模块 | `src/hwk_pressure_driver/hwk_pressure_driver/config.py` | 读取触觉驱动 YAML 配置和硬件身份映射。 |
| 触觉驱动节点 | `src/hwk_pressure_driver/hwk_pressure_driver/pressure_driver_node.py` | 启动时读取传感器身份，把真实硬件发布到固定 `/pressure/...` topic。 |
| 触觉接口架构文档 | `src/hwk_pressure_interfaces/hwk_pressure_interfaces_architecture.md` | 说明触觉消息字段、接口生成方式，以及驱动、Octopus 和 MCAP 的共享契约。 |

## 场景五目标输出

| 输出 | 地址或名称 | 功能 |
| --- | --- | --- |
| 稳定触觉设备名 | `/dev/hwk_pressure_left_gripper_1`、`/dev/hwk_pressure_left_gripper_2`、`/dev/hwk_pressure_right_gripper_1`、`/dev/hwk_pressure_right_gripper_2` | 固定表示四个触觉传感器，不受 `/dev/ttyUSB*` 枚举顺序影响。 |
| 稳定触觉 topic | `/pressure/left_hand/gripper_1`、`/pressure/left_hand/gripper_2`、`/pressure/right_hand/gripper_1`、`/pressure/right_hand/gripper_2` | 固定表示左右手与夹爪位置，供 Octopus 和 MCAP 录制使用。 |
| 硬件身份解析结果 | `log/start_all_sensor/hardware_identity_resolved.yaml` | 记录本次启动前扫描到的硬件到逻辑目标的解析结果。 |
| GoPro 稳定设备路径 | `/dev/v4l/by-path/...video-index0` | 用稳定 by-path 表示左右 GoPro 采集卡，减少 `/dev/video*` 编号变化影响。 |

## 使用边界

- 优先使用 `HWK_CHIP_UID`、`ID_SERIAL` 等强身份字段；`ID_PATH`、by-path 只能作为 USB 拓扑 fallback。
- 修改硬件身份映射后，必须重新执行 preflight 或 `start_all_sensor.sh`，确认解析结果正确。
- 设备身份映射只解决“哪个硬件对应哪个逻辑名称”，不负责 Octopus UI 显示或 MCAP 清洗。
