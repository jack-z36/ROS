# L2 能力模块说明：基础校验与输出契约检查

## 1. 能力名称

```text
基础校验与输出契约检查
```

## 2. 所属位置

阶段：阶段二：数据清洗
L1：service_s1
场景：场景一：提取夹爪开合以及位姿转换
模块类别：数据计算类
来源功能模块清单：`DOCS/阶段二：数据清洗/02_service/场景一/功能模块清单.md`

## 3. 一句话目标

```text
在场景一运行前后检查 raw MCAP、Scene1Config 和 CleanedMcap 是否满足可交给场景二的最低契约。
```

## 4. 能力角色

本能力是场景一的边界校验模块。它阻止缺 topic、错 schema、配置冲突、输出数量不一致等问题静默进入场景二。

## 5. 上游关系

- 依赖 [[Scene1Config]]。
- 依赖 raw MCAP summary 和输出后的 [[CleanedMcap]] 统计。

## 6. 下游关系

- [[Scene1CleanReport]] 读取校验结果和失败原因。
- Runtime 预检查和场景二接口对齐依赖这些结果。

## 7. 上游接口对齐检查

| 上游功能 | 上游接口 / 产物 | 本能力如何依赖 | 对齐状态 | 处理方式 |
|---|---|---|---|---|
| 配置加载 | [[Scene1Config]] | 校验 topic、`camera_from_tcp` + [[WorkFrameInBaseConfig]] + `work_frames`、[[GripperCalibrationConfig]] 参数 | 待改造 | service_s1_004/007 |
| MCAP 读取 | raw MCAP summary | 构建 topic inventory | 已对齐 | 复用现有 validator |
| MCAP 写出 | [[CleanedMcap]] 统计 | 校验输出 topic 和消息数量 | 部分对齐 | L3 补充测试和配置来源检查 |

## 8. 职责边界

本能力负责：

1. 检查输入 topic/schema/message count。
2. 检查 raw pose 保留状态、动态 arm-base TCP pose 数量、gripper 数量、配置完整性、RealMan SDK 可用性和 topic 冲突。

本能力不负责：

1. 判断数据质量是否适合训练。
2. 做滤波、补全、IK 或时间对齐。
3. 生成完整 Runtime run log。

## 9. 计算职责

| 计算项 | 输入 | 输出 | 影响下游 |
|---|---|---|---|
| 输入 inventory 检查 | raw MCAP summary、[[Scene1Config]] | pass/fail 和 reason | 阻塞无效输入 |
| 输出 contract 检查 | [[Scene1CleanReport]] 统计 | pass/fail 和 reason | 保证场景二可消费 |
| 配置来源检查 | config path、transform_file | pass/fail 和 reason | 保证配置可追溯 |

## 10. 计算规则

| 规则 | 触发条件 | 计算 / 判断方式 | 结果表达 |
|---|---|---|---|
| pose topic 必须存在 | 清洗前 | inventory 包含 input_topic 且 message_count > 0 | pass/fail |
| image topic 必须存在 | 清洗前 | inventory 包含 image_topic 且 message_count > 0 | pass/fail |
| gripper 输出 topic 不得已存在 | 清洗前 | output_topic 不在 input inventory | pass/fail |
| raw pose 可追溯 | 清洗后 | raw pose topic 保留或存在 raw 备份/报告字段 | pass/fail |
| arm-base pose 数量一致 | 清洗后 | raw_count = arm_base_tcp_count；旧 `tcp_common` / `camera_common` 数量仅做兼容检查 | pass/fail |
| 动态轨迹未退化 | 清洗后 | raw pose 有变化时，arm-base TCP pose 不得全部等于固定 TCP 偏移 | pass/fail |
| 生产配置完整 | 清洗前 | 左右 `camera_from_tcp`、`work_frames`、gripper 标定、arm-base 输出 topic 和 RealMan SDK 均 ready | pass/fail |
| gripper 数量等于 image 帧数 | 清洗后 | frame_count = gripper_count | pass/fail |

## 11. 输出结果结构

| 字段 | 类型 | 含义 | 有效性要求 | 下游使用方式 |
|---|---|---|---|---|
| `status` | string | success/failed/skipped | 合法枚举 | Runtime 状态 |
| `failure_reason` | string/null | 失败原因 | failed 时必填 | 人工和 Runtime 错误摘要 |
| `pose_topics` | list | raw/arm-base TCP pose topic 统计；旧 `tcp_common` / `camera_common` 标记为历史字段 | 数量一致 | 场景二接口检查 |
| `gripper_topics` | list | gripper topic 统计 | 数量一致 | 场景二接口检查 |

## 12. 异常与边界输入

| 边界情况 | 预期结果 | reason / error 表达 | 是否阻塞下游 |
|---|---|---|---|
| 缺 pose topic | 失败 | missing configured pose topic | 是 |
| 缺 image topic | 失败 | missing configured image topic | 是 |
| gripper topic 冲突 | 失败 | conflicts with existing topic | 是 |
| 输出数量不一致 | 失败 | count mismatch | 是 |
| RealMan SDK 不可用 | 失败 | realman sdk unavailable | 是 |
| work frame 缺失 | 失败 | missing work_frames config | 是 |

## 13. 可验证样例

| 样例 | 输入特征 | 预期输出 | 验证方式 |
|---|---|---|---|
| 合法输入 | topic/schema 完整 | 输出 contract 通过 | `python3` 最小契约测试 |
| 缺失输入 | 缺 image/pose topic | 失败 reason 清楚 | validator 单元测试 |
| 边界输入 | gripper topic 已存在 | 清洗前失败 | validator 单元测试 |

## 14. 整体完成标准

- [ ] [[Scene1CleanReport]] 能表达所有边界校验结果。
- [ ] L3 验收覆盖至少一个上游接口兼容性检查。
- [ ] 错误信息能定位到 topic、schema、配置或输出数量。

## 18. 开发者功能检验契约

本能力在 `./start_data_clean.sh --dev -> 场景一` 下对应的功能检验项：

```text
scene1_output_contract_validate
```

同时，本能力负责声明场景一完整 smoke test：

```text
scene1_smoke_test
```

检验目标：

- `scene1_output_contract_validate`：对已有或调试生成的场景一输出执行 contract validator。
- `scene1_smoke_test`：读取生产配置、小样本 raw MCAP 和临时输出目录，跑通场景一最小主链路。

测试产物：

- [[Scene1DevArtifact]]：`artifacts/output_contract_report.json`
- [[Scene1DevArtifact]]：`artifacts/smoke_summary.json`
- 可选 [[Scene1DevArtifact]]：`artifacts/debug_cleaned.mcap`
- [[Scene1DevRunLog]]：`logs/run_log.json`

临时覆盖：

- 允许覆盖小样本输入、调试输出目录、配置路径和 worker 数。
- 默认不写回正式配置。

输出隔离：

- smoke test 输出写入本次 [[Scene1DevRun]]，不得写入正式 canonical dataset 或生产 cleaned 输出目录。
