# 场景二输出程序与文件

本文记录场景二“一键启动所有的相机 ROS 节点”已经形成或依赖的具体程序、文件地址和功能。

## 输出清单

| 类型 | 地址 | 功能 |
| --- | --- | --- |
| 一键启动入口 | `start_all_sensor.sh` | 场景二的一键启动总入口；负责加载 ROS 环境、可选自动构建、执行启动前检查、启动总 launch、等待后执行 topic 检查，并在失败时清理残留进程。 |
| 总 launch | `launch/all_sensor_nodes.launch.py` | 根据 YAML 配置动态 include Baton Mini、GoPro 和触觉驱动 launch；场景二主要使用其中的 Baton Mini 与 GoPro 相机部分。 |
| 总配置 | `config/all_sensor_nodes.yaml` | 统一声明左右 Baton Mini、左右 GoPro 的启用状态、设备地址、节点名、namespace、frame_id、帧率和 topic 名称。 |
| 启动状态检查脚本 | `scripts/all_sensor_status.py` | 执行 preflight 和 postlaunch 检查；确认配置文件、硬件设备、ROS 节点和目标 topic 是否满足启动要求。 |
| ROS 残留清理脚本 | `cleanup_ros_residue.sh` | 清理残留 ROS2 节点、launch 进程或相关进程，避免上一次异常退出影响下一次一键启动。 |
| Baton Mini launch | `src/data_collection/baton_mini_sdk_demo/launch/baton_mini.launch.py` | 被总 launch include 两次，分别启动 `baton_mini_right` 与 `baton_mini_left`。 |
| Baton Mini 架构文档 | `src/data_collection/baton_mini_sdk_demo/baton_mini_architecture.md` | 说明 Baton Mini SDK Demo 的目录结构、ROS2 参数、数据流、发布 topic 和运行方式。 |
| GoPro launch | `src/data_collection/gopro_camera_launch/launch/gopro_pose_record.launch.py` | 被总 launch include 两次，分别启动 `gopro_right_camera` 与 `gopro_left_camera`；启动前设置采集卡帧率。 |
| GoPro 架构文档 | `src/data_collection/gopro_camera_launch/ARCHITECTURE.md` | 说明 GoPro 采集包的 launch 参数、V4L2 配置、图像发布链路和使用边界。 |
| GoPro V4L2 配置 | `src/data_collection/gopro_camera_launch/config/gopro_camera.yaml` | 被 GoPro launch 加载，提供图像采集参数。 |

## 场景二目标输出

| 输出 | 地址或名称 | 功能 |
| --- | --- | --- |
| 运行日志目录 | `log/start_all_sensor` | 保存每次一键启动的 launch 日志和硬件身份解析结果，便于复盘启动失败原因。 |
| 硬件身份解析结果 | `log/start_all_sensor/hardware_identity_resolved.yaml` | 当启用硬件身份映射时，保存本次扫描出的设备到逻辑名称的解析结果。 |
| 4 个相机 ROS 节点 | `baton_mini_right`、`baton_mini_left`、`gopro_right_camera`、`gopro_left_camera` | 一次性启动左右 Baton Mini 和左右 GoPro。 |
| 目标相机 topic | `/baton_mini_right/odometry`、`/baton_mini_left/odometry`、`/gopro_right/image_raw`、`/gopro_left/image_raw` | 场景二默认服务 Octopus 采集的相机数据源；其他调试 topic 可按配置启用。 |

## 使用边界

- 本场景只要求相机 ROS 节点可一键启动，不要求触觉 topic 全部可用。
- 如果 `start_all_sensor.sh` 用于启动触觉驱动，则该能力属于场景三扩展，不改变场景二的核心验收边界。
- 总配置中 GoPro 的稳定设备名和触觉硬件身份映射问题归场景五管理。
