L2-05 · 单步 Action 到执行器 Topic 适配发送闭环

l2-05-action-publisher：ACT 部署程序唯一 ROS command 出口。每个 control tick 接收 L2-04 已安全通过的 16D TCP action、L2-06 的最终发布授权与时间，把同一策略意图并行投影为观测通道和四路执行器 command。默认 shadow，不拥有调度、安全算法或硬件驱动。本页用 4 个维度交互呈现：功能边界、Pi0.5 对应部分如何运作、开发蓝图、人类验收标准。

本页只是人类快速浏览入口，不作为 L3 生成依据。
权威细节见 agent_context/00_INDEX.md 及其路由的 Markdown。HTML 与 MD 冲突时，以 MD 为准。

维度 1 · 功能边界

📖 阅读路径：下图展示 L2-05 消费什么、产出什么 → 模式门控和四路原子性（产出卡内展开）→ Pi0.5 源码怎么做见维度2，ACT 怎么落代码见维度3

L2-05 是被 L2-06 每 tick 同步调用的唯一 ROS action 输出端口：它把 L2-04 交付的 safe 16D TCP action 依次加工为 Topic 候选载荷和标准 ROS message，再依据 CLI 静态总开关与 L2-06 动态许可选择并发布 policy、四路 command 和逐 action status，最后把真实发布事实作为 ActionPublishResult 返回 L2-06。关键区分——它只做输出适配与门控，不做安全算法（归 L2-04）、调度/fallback（归 L2-06）、workspace/IK/硬件驱动（归外部 driver）。

L2-05 实际消费的字段：

字段类型L2-05 用途
statusSafetyStatusPASS/ADJUSTED 可发布；REJECTED 禁止 policy/command
actionActionSpec16D safe action：2×TCP7 + 2×gripper[0,1]（REJECTED 时 None）

L2-05 不重新校验 quaternion 模长 / TCP delta；只查 status + shape + finite + 夹爪域 [0,1]。注意：不存在 result.accepted 字段。

⚠ 夹爪尺度协调点（跨 L2 契约漂移）

本 L2 只接受夹爪输入 [0,1]；若上游传来 50/100（疑似已映射），即使 status=PASS 也整批失败。

这是暴露尺度漂移的硬门控，不做双尺度兼容。详见 01_L2功能边界.md §5。

L2-05 实际消费的配置语义：

L2-06 把汇总后的动态许可、当前 action_id、ROS 时间和单调时间随 ActionPublishRequest 同步传入。

图③ 四路原子性精确边界 + 负责/不负责

四路原子性：只到 RAM 构造层

允许声称：B1/B2 的五路候选消息必须全部在 RAM 构造成功，才开始 policy/command publish。禁止声称：ROS 多 topic 是事务，或四台设备同时接收/执行。运行期部分 publish 异常无法回滚，result 记录实际成功数与 PARTIAL，停止剩余 command。

✓ 负责

SafetyStatus 来源复核 · 三编排函数闭环 · 16D 拆分 · 单一 frame · [0,1]→[0,100] · CLI+permit 双门控 · 夹爪 deadband · policy/status publish · 逐调用 result

✗ 不负责（归其他 L2）

CLI 解析（→ 启动装配）· 原始 gate/deadman/estop（→ L2-06）· shape/NaN/quaternion/TCP delta 安全算法（→ L2-04）· arm/gripper 状态回读 · workspace · IK · TF · MoveIt · 碰撞（→ 外部 driver）· RM65 SDK · Modbus · USB-485（→ driver）· action smoothing / 跨 chunk 融合（后续优化）

command_plan_completed 只表示计划内 command publish 全部完成，不等于 driver accepted、硬件执行或到位。driver_accepted / hardware_reached 固定 None。

维度 2 · Pi0.5 这部分是如何运作的

📖 阅读路径：先懂 Pi0.5 旧输出职责分散在三个 node（骨架）→ 看旧命令四步怎么走 → 看一个旧命令的源码跟踪 → 看 Pi0.5 14D joint 与 ACT 16D TCP 的根本差异 → ACT 怎么改见维度3

这一维度只回答：Pi0.5 部署代码里，负责把 action 发到执行器的那部分是怎么跑的。不涉及 ACT 怎么改。关键认知——Pi0.5 没有独立 publisher，旧职责散在三个 node；旧链是 14D joint、串行订阅、shadow 也发 command。

这一节用白话讲。Pi0.5 没有一个独立 ActionPublisher。旧输出职责像三道转运站：第一站（DeployNode）发四个包裹，第二站（Bridge）订阅拆包转发，第三站（Mux）看 deadman/模式再选路。新 L2-05 取消中间订阅站，L2-06 先给最终通行证，L2-05 从 RAM 一次构造输出。
