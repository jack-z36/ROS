## 1. 白话运行机制

Pi0.5 没有一个独立 `ActionPublisher`。旧输出职责散落在三个 ROS node：

```text
ControlLoop.tick() 产出旧 14D BimanualAction
  -> Pi05VlaDeployNode：逐路发布 joint/hand command
  -> Pi05BridgeNode：订阅四路 command，再转换并转发
  -> CommandMuxNode：订阅 VLA/teleop/deadman/enable，按 mode/timeout 仲裁
  -> picotele driver
```

这条链能说明“publisher handle 应由长生命周期对象持有”“外部驱动仍要有最终 gate”，但不能直接成为 ACT L2-05：旧链是 14D joint、串行订阅、shadow 也发 command；新边界是 16D TCP、无订阅、L2-06 汇总授权、shadow 禁 command。

## 5. 复用结论

| 等级 | 结论 |
|---|---|
| 直接复用 | 无。Pi0.5 位于只读参考目录且核心契约均不相容。 |
| 结构复用 | frozen 数据对象；topic/config 注入；长生命周期对象持有 publisher；消息先在 RAM 构造；退出语义清晰。 |
| 参考理解 | bridge/mux 说明外部 driver 仍需 gate、timeout、manual takeover；这些事实由 L2-06 汇总。 |
| 不复用 | 14D codec、JointState 输出、旧 hand 映射、bridge/mux 订阅、raw deadman、joint delta clamp、shadow command、全局 metrics、硬件 launch、smoothstep/blend。 |

## 6. 对 ACT 设计的强制约束

1. 不创建兼容 Pi0.5 的串行 bridge；两条通道从同一 RAM safe action 并行派生。
2. 不把 `Pi05VlaDeployNode` 改名后继续吞并 ControlLoop/observation/inference。
3. 不使用旧 `publishes_command_topics` 判断 shadow command。
4. 不在 publish 成功前或 safety 通过时提前累计“已发送”。
5. 不从旧 14D gripper 量纲猜 ACT 输入；L2-05 明确要求 `[0,1]`。
6. 不把外部 driver launch、workspace/IK 或厂商接口纳入本 L2。
