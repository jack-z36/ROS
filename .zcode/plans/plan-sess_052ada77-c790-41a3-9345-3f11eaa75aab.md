# RM65 双臂 ROS 节点开发计划（C++ SDK 单节点版 + 微小运动安全闸）

## 0. 总览

从 `model_deploy` 开新分支 `feat/model_deploy/rm65-dual-arm-node`，新建两个 ament_cmake 包：
- `src/model_deploy/act_interfaces/`（ament_cmake + rosidl）—— 当前仓库完全缺失，是节点编译的硬依赖
- `src/model_deploy/rm65_dual_arm/`（ament_cmake + rclcpp + 官方 C/C++ SDK）—— **单节点承载双臂所有功能**

一句话功能：把左右 RM65 的真实 TCP 状态发布给 ACT，并在人工许可有效时把 ACT 的左右末端目标位姿交给 RM65 执行。

**核心安全原则**（贯穿全计划）：节点默认开机即受多重闸门保护，任何测试控制指令都被强制限制在微小范围内，**绝不产生大范围运动**。

## 4. ★ 微小运动安全闸（delta_guard）—— 核心安全约束

这是本次新增的安全核心，直接落实"测试控制指令必须尽可能小、避免大范围运动"。

**位置**：`target_validator` 之后、SDK 调用之前，每条目标 PoseStamped 在下发 `rm_movel` 前必须先过这道闸。

**机制**：维护每臂最近一次确认的"当前 TCP 位姿"（来自 `rm_get_current_arm_state`），目标位姿与之做差，超限即拒绝、不下发、记录 error、health 里 `reason` 标 `DELTA_EXCEEDED`。

**默认上限（最保守，可调但只能调小）**：
```yaml
safety:
  max_step_xyz_m: 0.010      # 单步位移上限 1cm（默认），编译期注释写明"测试期严禁放大"
  max_step_angle_rad: 0.05   # 单步角度上限 ~2.9°
```

`delta_guard.hpp` 签名：
```cpp
struct DeltaResult { bool ok; double xyz_m; double angle_rad; std::string reason; };
// 用当前真实 TCP（rm_pose_t）和目标（ROS pose）做差，超 max_step_xyz_m / max_step_angle_rad 拒绝
DeltaResult check_delta(const rm_pose_t& current_tcp,
                        const geometry_msgs::msg::Pose& target,
                        double max_step_xyz_m, double max_step_angle_rad);
```

**多重闸门组合**（每条目标必须全部通过才下发）：
1. `permit_guard`：CommandPermit allowed=true 且未 stale
2. `target_validator`：frame_id 正确、finite、quaternion norm≈1、未 stale
3. **`delta_guard`：相对当前 TCP 位移在 max_step_xyz_m / max_step_angle_rad 内**
4. emergency_stop 未激活
5. SDK 已连接

任一失败：不发 `rm_movel`，不伪造 accepted，health 记 reason。

**test_delta_guard.cpp 必覆盖**：
- 位移 0.5cm → 通过
- 位移 2cm → 拒绝（超 1cm 上限）
- 角度 5° → 拒绝（超 ~2.9° 上限）
- 当前 TCP 未初始化（首次）→ 拒绝并要求先读取真实状态（不假设零位）
- 当前 TCP 含 NaN → 拒绝

## 5. Topic / Service 清单（严格对齐你原文命名）

**唯一一处偏离**：TCP pose 发布用 `PoseStamped` 而非 `Pose`（契约和 ACT 都强制 frame_id + stamp，用 `Pose` 会违反契约并破坏过期判断）。

| 方向 | topic | 类型 | 说明 |
|---|---|---|---|
| 发布 | `/arm/left_tcp_pose` | `geometry_msgs/msg/PoseStamped` | frame_id=`left_arm_base`，来自 `rm_get_current_arm_state().pose.quaternion` |
| 发布 | `/arm/right_tcp_pose` | `geometry_msgs/msg/PoseStamped` | frame_id=`right_arm_base` |
| 发布 | `/hardware/rm65/health` | `act_interfaces/msg/HardwareHealth` | 定时发布左右臂连接/急停/错误码/拒绝原因 |
| 订阅 | `/act/command/arm/left_target` | `geometry_msgs/msg/PoseStamped` | frame_id 必须 `left_arm_base`，否则拒绝 |
| 订阅 | `/act/command/arm/right_target` | `geometry_msgs/msg/PoseStamped` | frame_id 必须 `right_arm_base` |
| 订阅 | `/act/command/permit` | `act_interfaces/msg/CommandPermit` | `allowed==True` 才执行新运动命令 |
| service | `/hardware/rm65/emergency_stop` | `std_srvs/srv/SetBool` | `true` 对两臂调 `rm_set_arm_emergency_stop(true)`；`false` 恢复 |

**许可逻辑**（fail-closed，对齐 `act_deploy_node.py:419`）：
- permit 超过 `permit_stale_sec` 未更新 → `allowed=false, reason=PERMIT_STALE`
- permit 异常 → `PERMIT_SOURCE_ERROR`
- emergency_stop 激活 → 拒绝，`reason=ESTOP_ACTIVE`

**launch 默认 remap**：`/arm/left_tcp_pose` → `/act/observation/arm/left_tcp_pose`（让 ACT 零配置订阅），参数可关。

## 6. SDK 集成（C++，对齐官方 rm_driver 实践）

- 头文件 `#include "rm_service.h"`（对应 `libRM_Service.so`）
- `rm_init(RM_TRIPLE_MODE_E)` 全局一次
- 双臂：两次 `rm_create_robot_arm(ip, 8080)`，存两个 `rm_robot_handle*`，每臂独立 IP，UDP 端口错开（左 8089 / 右 8090）
- 状态：`rm_get_current_arm_state(handle, &state)`，C++ 结构体含 `pose`(rm_pose_t)/`joint[ARM_DOF]`/`arm_err`/`sys_err`。**当前 TCP 优先用此值作为 delta_guard 基准**
- 运动：`rm_movel(handle, pose, v, r, 0, 0)` 默认非阻塞（block=0），pose 是 `rm_pose_t`（m + euler rad）
- 急停 service：`rm_set_arm_emergency_stop(handle, state)`
- 错误码标准化：0/1/-1..-6 + 控制器 0x1001.. + 关节位掩码
- 重连：监控 -1/-2 触发 `rm_delete_robot_arm` + `rm_create_robot_arm`
- 退出：`rm_destroy()` 关所有连接

**单位转换（pose_conversion.cpp）**：
- 睿尔曼 `rm_quat_t{w,x,y,z}` → ROS `{x,y,z,w}` 重排
- 位置 m 直接透传
- 目标 ROS quaternion → `rm_pose_t.euler`（rad，roll_pitch_yaw）

```yaml

      blend_radius_percent: 0
      block: false
      command_timeout_sec: 2.0
    safety:
      stale_target_sec: 0.5
      permit_stale_sec: 1.0
      max_step_xyz_m: 0.010     # ★ 单步位移上限 1cm
      max_step_angle_rad: 0.05  # ★ 单步角度上限 ~2.9°
    publish:
      pose_hz: 50.0
      health_hz: 10.0

      left_tcp_pose: /arm/left_tcp_pose
      right_tcp_pose: /arm/right_tcp_pose
```

## 9. ★ 真机测试规约（README 专章 + PR 必填）

**强制流程**（任何连接真机的测试都必须遵守）：

1. **物理急停就位**：测试全程必须有人站在物理急停按钮旁，手不离开。
2. **首次只验证读、不验证写**：第一次连真机只确认 `/arm/*_tcp_pose` 发布正常、位姿量级正确（手动拖动 10cm，topic 变化约 0.1m），不发任何运动命令。
3. **运动测试从最小指令开始**：第一个运动指令的位移目标设为**当前 TCP + 1mm 以内**，确认机械臂只做微动。
4. **单臂逐个验证**：先只连左臂验证，再只连右臂，最后双臂；禁止首次就双臂同时运动。
5. **速度锁低**：`speed_percent` 测试期固定 ≤ 20，确认轨迹无误后再议。
6. **delta_guard 不绕过**：任何真机测试不得通过改大 `max_step_xyz_m` 绕过闸门；如需调大，必须双人确认 + 物理急停就位。
7. **急停预演**：正式运动前先调一次 `/hardware/rm65/emergency_stop true` 确认能立即停臂。

**未验证项**：真机连接、TCP 位姿量级、急停真机响应、UDP 主动上报频率、SDK 重连、双臂同步、Jazzy 兼容性——均需 RM65 硬件在场，离线开发无法验证。

**真机风险**：
- Jazzy 兼容：官方只背书 humble/foxy，Jazzy/Ubuntu 24.04 需自行适配；SDK 库版本 v4.3.7。
- 单位陷阱：睿尔曼 quaternion `[w,x,y,z]` vs ROS `[x,y,z,w]`，`pose_conversion.cpp` 注释写死 + 单测覆盖。
- UDP 端口冲突：左右 udp_port 必须不同，否则数据串流。
- SDK 无心跳：断线重连依赖 -1/-2 返回码 + UDP 断流，真机需观察稳定性。

**依赖 PR**：`act_interfaces`（本分支同落）、`act/`（订阅方，已有，需 launch remap）。

## 10. 关键决策说明

1. **TCP pose 类型 `Pose` → `PoseStamped`**：契约和 ACT 强制 frame_id + stamp，`Pose` 无法满足。其余命名严格按你原文。
2. **本分支同落 `act_interfaces`**：`package.xml depend` 要求接口包先存在，否则不可编译。
3. **ament_cmake + rclcpp**：C/C++ SDK 只能 link .so，必须 ament_cmake。
4. **vendor SDK**：头文件和 .so 拷进包内（仿官方 rm_driver 布局），`install_libs.sh` 装系统库路径，因官方 SDK 无 find_package/pkg-config。
5. **★ 新增 `delta_guard` 微小运动闸**：每条目标相对当前 TCP 位移默认限 1cm/2.9°，超限即拒，编译期硬上限防误配——这是"测试指令尽可能小、避免大范围运动"的工程落实。
6. **★ 默认参数最保守**：`speed_percent=10`、`max_step_xyz_m=0.010`，测试规约强制物理急停就位 + 首次只读不写 + 单臂逐个验证。

如需调整任一决策（例如严格分两个分支、保留 `Pose` 类型、改订阅官方 rm_driver、调整 delta 上限数值），请告知。
