总览：6 个 L2 如何协作

L2-06 ControlLoop 居中调度：读 observation、提交推理、收 chunk、首版按 cursor 直取 raw action、调用 Safety、调用输出适配。

契约 推理 控制
第一版的动作消费是“可 debug 的最小闭环”：只维护 active chunk 与 cursor，直接取当前 step。平滑处理不在首版实现。

宏观数据流

从外部输入到执行器 topic 的关键 RAM 对象与所有权。

ControlLoop.tick()

tick 负责调度和状态转移。首版 chunk 消费只做直取和 fallback，不做平滑融合。

禁止在第一版把 smoothstep blend 或 RTC 对齐隐式塞入 ControlLoop。后续优化必须重新设计并同步文档。

失败传播

Metrics / status

L2-06 汇总运行状态，L2-05 额外暴露命令发送状态。

模块边界

展开查看每个 L2 的负责 / 不负责范围。

L2-01 外部参数加载与契约校验
  • 负责 DeployConfig、16D state/action spec、topic、bundle contract。
  • 不订阅 topic，不执行模型，不启动控制循环。
L2-02 ObservationSnapshot 组装
  • 负责 ROS observation topic 到 ObservationSnapshot 和 latest buffer。
  • 不决定推理节奏，不生成 action。
L2-03 ACT ActionChunk 推理
  • 负责 batch adapter、policy runtime、ActionChunk 输出。
  • 不决定 chunk 何时执行，不做 safety，不做平滑。
L2-04 单步 Action 安全检查
  • 负责 shape、NaN/Inf、quaternion、gripper、TCP 单步限制。
  • 不产生 raw action，不管理 chunk，不做硬件 gate。
L2-05 执行器 Topic 适配发送
  • 负责 policy_action、command topic、shadow / gate / command status。
  • 不替代 L2-04 通用 safety，不调用模型。
L2-06 ControlLoop 中央调度
  • 负责 tick、request、chunk 收集、cursor 直取、fallback、metrics。
  • 不做 ACT batch、模型前向、硬件 SDK、action 平滑。
后续优化项：smoothstep blend、跨 chunk 融合、RTC 类平滑和复杂时间对齐。恢复这些能力时必须重新同步 L1 Markdown 与本 HTML。
