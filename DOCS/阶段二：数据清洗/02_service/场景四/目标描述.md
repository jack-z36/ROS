# 阶段二场景四：构建标准 canonical dataset

## 一句话总结

从 aligned MCAP 构建 `canonical_dataset_mcap/`，把 topic 世界正式组织成 episode/step/observation/action 世界。

## 核心目标

本场景负责阶段二的核心汇聚：把前面清洗、验证和对齐后的数据，落成训练格式导出器唯一可信的 canonical dataset。

canonical dataset 不是某个训练框架的专用格式，而是本项目从 MCAP 到训练数据之间的稳定中间契约。

## 软件能力产出

本场景应形成以下中粒度软件能力：

- dataset 构建入口：用户可以从一批 aligned MCAP 构建 canonical dataset。
- schema 生成能力：定义 observation、action、frame、topic、quality 等全局契约。
- episode 构建能力：把每次示教组织成 episode 目录和 episode 元信息。
- step index 生成能力：把 topic 世界映射到 step 世界。
- action 生成能力：写入左右 arm-base 下的绝对 TCP 目标位姿；差分或相对化留给训练侧。
- mask 生成能力：标记字段级和 step 级可用性，并记录 invalid reason。
- 报告汇总能力：汇总对齐质量、数据质量和机器人约束结果。
- manifest 能力：记录输入、参数、处理过程和可追溯信息。
- dataset 校验能力：检查 schema、index、episode、masks、reports 是否一致。

具体脚本名、模块名、配置名和代码结构在实现时决定，不在本目标描述中提前固定。

## 自动化处理目标

用户运行本场景入口后，理想情况下应自动完成：

1. 初始化 canonical dataset 结构。
2. 生成 dataset 级元信息和 schema。
3. 为每个 aligned MCAP 创建 episode。
4. 写入或引用 episode 数据本体。
5. 生成 step index。
6. 生成绝对 TCP 目标 action。
7. 生成 masks 和 invalid reason。
8. 汇总 alignment、quality、robot constraint 等报告。
9. 生成 processing manifest。
10. 生成 dataset index。
11. 执行 dataset 完整性校验。

## 数据输出

```text
canonical_dataset_mcap/
├── dataset_meta.json
├── dataset_index.parquet
├── schema/
├── episodes/
│   └── episode_xxxxxx/
│       ├── episode_meta.json
│       ├── data.mcap
│       ├── step_index.parquet
│       ├── masks.parquet
│       ├── alignment_report.json
│       ├── quality_report.json
│       ├── robot_constraint_report.json
│       └── processing_manifest.json
└── exports/
```

## 成功标准

- schema 能解释所有 episode。
- dataset index 登记的路径真实存在。
- step index 能定位数据本体或派生字段。
- action 保存左右 arm-base 下的绝对 TCP 目标位姿，frame 与单位明确。
- 不要求阶段二生成 UMI 相对 action chunk；相对化或差分化属于训练侧 LeRobot 框架职责，不是阶段二输出阻塞条件。
- masks 包含 invalid reason。
- reports 和 manifest 能追溯上游处理质量。
- 删除 `exports/` 后仍可从 canonical dataset 重新导出训练格式。

## 与上下游关系

上游是场景三输出的 aligned MCAP 和 alignment report，同时继承场景二的质量/约束报告。下游是场景五训练格式导出器。

本场景负责 canonical dataset，不负责导出具体训练格式，也不回头修复上游数据。
