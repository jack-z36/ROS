# L2-05 验收机制

> [!info] 文档契约
> - 消费对象：L3 生成/验收 Agent、L2 Gate、Git 合入流程。
> - 权威性：定义 AI 侧 L2 Gate 与后续验证脚本设计。
> - 上游来源：`01_L2功能边界.md`、`03a_功能微元总览与组织结构.md`、`03_ACT微元设计与协作.md`。
> - 不负责范围：不伪造真实 ROS/硬件通过，不生成 L3 文件。
> - 读取时机：L3 生成前、每个 L3 验收后、L2 合入前。

## 1. Gate 目标

L2-05 Gate 必须证明：

1. B1/B2/B3 三编排函数边界清晰，L2-06 只调用 B3。
2. 未显式传入 CLI `--enable-command-output` 时，四路 command 永不发布。
3. CLI 已开启但 `CommandPermit.allowed=False` 时，四路 command 永不发布，reason 可读。
4. 只有 CLI 开启、permit=True、B1/B2 完整成功时才允许四路 command。
5. `SafetyStatus.PASS/ADJUSTED` 可发布，`REJECTED` 停止；不存在 `result.accepted`。
6. policy/command 候选消息全部先在 RAM 构造；最终 status 在真实发布事实形成后构造。
7. 部分 ROS publish 不伪造原子回滚，`ActionPublishResult` 保留真实 count/outcome。
8. 无 ROS/硬件时能区分本地 PASS、`BLOCKED_ENV` 和 `BLOCKED_HARDWARE_EXPECTED`。

## 2. Required L3 草案

下表只定义后续生成边界，不创建任务文件或 dispatch：

| 草案切片 | 目标 | 主要落点 | 贡献 |
|---|---|---|---|
| L3-A | C1-C7 公共 types 与 C7 config/CLI default-off | `types/action_publish.py`、`config/schema.py`、启动装配 | 稳定跨 L2 数据语言与人工总开关 |
| L3-B | B1 + C9-C11 Topic 载荷生成 | `service/action_output_adapter.py` | 纯 RAM 16D 拆分、frame、夹爪映射 |
| L3-C | B2 + C8/C12-C14 ROS message 打包 | `ui/action_publisher.py` | 无副作用消息 bundle；不含 status |
| L3-D | A1/B3 + C15-C21 publisher、deadband、result/status | `ui/action_publisher.py` | 真实门控、ROS 写出和失败事实 |
| L3-E | L2-05 verification + mock/ROS observation integration | `tests/`、`scripts/l2_05_verify.sh` | 汇总 L2 Gate，不含默认真机动作 |

L3 生成前必须再次读取 `03a`，不得把 C 层原子函数升级成新的 B 层编排函数。

## 3. Gate 验收矩阵

| ID | 层级 | 输入/场景 | 观察点 | PASS | FAIL |
|---|---|---|---|---|---|
| G01 | types | 构造 C1-C6 合法/非法组合 | frozen/invariants | 合法成功，非法在构造期失败 | 可变对象或矛盾字段被接受 |
| G02 | config | 不传 CLI | `command_output_enabled` | 严格为 False | 默认开启或 YAML 静默开启 |
| G03 | config | 显式 `--enable-command-output` | 最终 C7 | 严格为 True，审计可见 | 参数未生效或被 mode 覆盖 |
| G04 | service/B1 | PASS 与 ADJUSTED SafetyResult | C4 payload | 均使用非空 action 成功 | 仍读取 `accepted` 或丢失 ADJUSTED |
| G05 | service/B1 | REJECTED、shape、NaN/Inf、爪域错误 | 异常/调用数 | B1 失败，无部分 payload | 错误被 clip/猜尺度 |
| G06 | service/B1 | 已知 16D | 左右段、单一 frame、爪映射 | `[0:7]/[7:14]/[14]/[15]` 正确 | 左右交换、双 frame 贴值 |
| G07 | ui/B2 | 合法 C4 + ros_time | C8 五消息 | policy/2 Pose/2 Float 构造正确 | status 被提前塞进 C8 |
| G08 | ui/B2 | 任一 message builder 失败 | publisher calls | policy/command 调用均为 0 | 构造中途已经发布 |
| G09 | ui/B3 | CLI=False，permit 任意 | calls/result/status | policy/status=1，command=0，OBSERVED | command 泄漏 |
| G10 | ui/B3 | CLI=True，permit=False | calls/reason | policy/status=1，command=0，BLOCKED | permit 被忽略 |
| G11 | ui/B3 | CLI=True，permit=True | calls/messages | policy + 2 Pose + 计划内 2 Float；PUBLISHED | 计划未完成或错误 topic |
| G12 | ui/B3 | policy publisher 抛异常 | calls/result | command=0，FAILED | policy 失败仍发 command |
| G13 | ui/B3 | 第 n 路 command 抛异常 | count/outcome | `PARTIAL`，真实 count，停止剩余 | 伪造回滚/完整成功 |
| G14 | ui/state | gripper 重复/过快/失败 | cache/skip | 每侧独立；只在成功后更新 | skip 算失败或失败更新 cache |
| G15 | ui/status | OBSERVED/BLOCKED/PARTIAL 等 | JSON/result | 字段一致、unknown=null | status 在事实前构造或伪造硬件成功 |
| G16 | boundary | 静态扫描 | imports/APIs | 无 subscription/timer/runtime/TF/SDK/mode 消费 | 出现越界实现 |
| G17 | mock integration | 多 tick fake publisher | result 顺序 | 持续同步返回，L2-06 可消费 | L2-05 自行 retry/fallback |
| G18 | ROS observation | ROS 可用、command disabled | topic echo | policy/status 可观察，四路 command 静默 | 环境可用却行为错误 |
| G19 | hardware | 真实 driver/机器人 | 现场证据 | 只在人工授权、急停就绪后执行 | 默认自动执行或无安全准备 |

## 4. 验证脚本设计

后续 L3-E 实现统一入口：

```bash
bash src/model_deploy/act/scripts/l2_05_verify.sh
```

可选 case：

```bash
bash src/model_deploy/act/scripts/l2_05_verify.sh --case local
bash src/model_deploy/act/scripts/l2_05_verify.sh --case command-disabled
bash src/model_deploy/act/scripts/l2_05_verify.sh --case permit-blocked
bash src/model_deploy/act/scripts/l2_05_verify.sh --case command-enabled-mock
bash src/model_deploy/act/scripts/l2_05_verify.sh --case ros-observe
```

### 4.1 输出格式

脚本按六层 + boundary 分组，每个 label 一行：

```text
[types]
PASS TYPES_CONTRACT       C1-C6 frozen schema and invariants

[config]
PASS CLI_DEFAULT_OFF      C7 command_output_enabled=False without explicit CLI

[service]
PASS B1_TOPIC_PAYLOADS    16D -> C4 TopicPayloadBundle

[runtime]
PASS NO_RUNTIME_ARTIFACT  L2-06 owns permit/time/fallback

[ui]
FAIL B2_MESSAGE_BUNDLE    message builder rejected pose frame
  file: src/model_deploy/act/ui/action_publisher.py
  class: 无 class（模块级函数）
  micro-unit: B2 build_ros_messages（编排函数） -> C13 _build_arm_msg（计算函数）
  pytest: tests/ui/test_action_publisher.py::test_build_ros_messages
  error: invalid pose_frame_id

[boundary]
BLOCKED ROS_OBSERVE       ROS 2 environment unavailable; local/mock passed

SUMMARY: 4 PASS / 1 FAIL / 1 BLOCKED
```

FAIL 必须给出完整定位链：文件 → class（或无 class）→ B/C 微元 + 类型 → pytest node → error summary。

### 4.2 退出码

| 结果 | exit code |
|---|---:|
| 全部 required local/mock PASS，只有 expected BLOCKED | 0 |
| 任一 required local/mock FAIL | 1 |
| 脚本参数或环境自检错误 | 2 |

`BLOCKED_ENV` 和 `BLOCKED_HARDWARE_EXPECTED` 不是 PASS，也不应把 exit code 变成 1，只要本地 required 项全部通过且阻断说明完整。

### 4.3 label → 微元映射

| label | 层 | 完整位置链 | PASS 含义 / FAIL 排查 |
|---|---|---|---|
| `TYPES_CONTRACT` | types | `types/action_publish.py -> 无 class -> C1-C6（数据）` | 公共数据语言合法；失败查字段/invariant |
| `CLI_DEFAULT_OFF` | config | `config/schema.py/启动装配 -> CommandOutputConfig -> C7（数据）` | 未显式 CLI 永不启用 command |
| `B1_TOPIC_PAYLOADS` | service | `service/action_output_adapter.py -> 无 class -> B1（编排）/C9-C11（计算）` | safe action 正确转 C4 |
| `B2_MESSAGE_BUNDLE` | ui | `ui/action_publisher.py -> 无 class -> B2（编排）/C12-C14（计算）` | 五消息完整，不含 status |
| `B3_COMMAND_GATE` | ui | `ui/action_publisher.py -> ActionPublisher -> B3（编排）/C15-C21` | CLI/permit/IO/result/status 闭环 |
| `NO_RUNTIME_ARTIFACT` | runtime | `runtime/ -> 无 L2-05 class -> 无新增微元` | 调度未泄漏进 L2-05 |
| `BOUNDARY_CLEAN` | boundary | `L2-05 目标文件 -> 所有 class/function` | 无 subscription/timer/mode/TF/SDK |
| `ROS_OBSERVE` | ui·boundary | `ui/action_publisher.py -> ActionPublisher -> B3/C17` | command disabled 时只观察 policy/status |

## 5. 验证层级与术语

| 层级 | 本 L2 含义 |
|---|---|
| unit/import | C 层纯数据/纯函数与无 ROS import 测试。 |
| mock | fake publishers 验证 B3 调用顺序、门控、partial 和 status。 |
| dry-run | **仅指本地验证方法**：执行 B1/B2/B3 mock，不是 RuntimeConfig mode。 |
| shadow-run | **仅作为兼容验收术语**：等价于 `command_output_enabled=False` 的 ROS 观察运行，不是运行模式枚举。 |
| ROS observation | 真实 ROS graph，policy/status 可观察，四路 command 静默。 |
| real-robot | 必须人工授权、急停就绪、driver 可观察；默认 BLOCKED。 |

## 6. 阻断项与状态

| 阻断 | 状态 | Gate 处理 |
|---|---|---|
| 无 ROS 2 | `BLOCKED_ENV` | unit/mock 必须 PASS；ROS observation 后补。 |
| 无 driver/硬件 | `BLOCKED_HARDWARE_EXPECTED` | 不阻止本地 L2 Gate，但禁止写 real-robot PASS。 |
| HTML 未同步 | `BLOCKED_DOC_ALIGNMENT` | 阻止 L3 生成与 Git 合入。 |
| L1 未同步新边界 | `BLOCKED_UPSTREAM_ALIGNMENT` | 阻止 L3 生成与 Git 合入。 |
| 真机无人工授权/急停 | `BLOCKED_HARDWARE` | 禁止运行 command-enabled real-robot case。 |

## 7. 下游与 Git 放行

- L2-06 接口设计可在 C1/C2/C6 字段稳定后继续协作讨论。
- 生成 L3 前：HTML 与 L1 必须同步，validator 必须通过，用户确认无新增开放项。
- 合入 `model_deploy` 前：required local/mock PASS、人类验收签字、风险记录完整、真机项正确标记 PASS 或 BLOCKED。
- 任何 `RuntimeConfig.mode`、`result.accepted`、per-arm 无 TF frame 或旧 bridge/mux 进入 L2-05，Gate 直接失败。
