# Pi0.5 源码 3.5 层微元拆解：L2-06

## 源码证据与复用结论

| Pi0.5 路径 / 范围 | 证据 | ACT 复用判定 |
|---|---|---|
| `deploy/src/pi05/deploy/runtime/control_loop.py:37-56` | `is_action_chunk_usable()` 检查 rank、维度、有限值、年龄和可执行末端 | 结构复用；ACT 保留合法性语义，去掉对齐/平滑门槛 |
| `.../control_loop.py:59-138,151-222,316-333` | `ControlLoop.tick()` 收 result、投 request、取 action、安全、fallback | 结构复用；改为 L1 指定的最小 cursor 直取 |
| `.../shared_buffer.py:61-102,156-242` | `InferenceRequest`、`LatestQueue`、latest observation、metrics | 结构复用；对象归属以 L1/L2 为准 |
| `.../inference_worker.py:15-91` | daemon worker 消费最新 request，推理后写最新 result | 参考理解；实现属于 L2-03 |
| `.../ros_nodes/pi05_vla_deploy_node.py:42-89,196-218` | 装配对象、`create_timer()`、调用 tick、发布 metrics | 结构复用；ACT UI 仅保留 timer/装配边界 |

旧代码另有 `smoothstep_alpha()`、pending/next chunk 和 blend 状态（`control_loop.py:29-34,254-314`）。这与当前 L1 第一版边界冲突，**不复用**。

## 3.5 层微元表

| 类型 | Pi0.5 微元 | 状态/输入 → 输出 | ACT 含义 |
|---|---|---|---|
| 数据 | `ActionChunk`、`InferenceRequest`、`RuntimeMetrics` | ndarray、时间戳、request id、计数器 | 沿用公共契约；L2-06 只持有调度状态 |
| 计算函数 | `is_action_chunk_usable()` | chunk + now → `(ok, reason)` | `validate_chunk_for_cursor()`，纯 RAM 判定 |
| 内部状态更新函数 | `LatestQueue.put_latest()`、`_collect_result()`、cursor 递增、`record_*()` | queue/buffer/metrics → 更新 | 保留 latest-only 和最小状态更新 |
| 数据读写函数 | `latest_observation()`、queue get/put、node publish | RAM 队列或 ROS 边界 | queue 为 runtime RAM 交接；ROS publish 留给 L2-05/UI |
| 编排函数 | `tick()`、`_maybe_submit_request()`、`_fallback()`、ROS `_control_tick()` | 时间/状态/失败 → 调用序列 | `ControlLoop.tick()` 是 ACT 唯一中央调度点 |

## class 打包表

| class | state | 打包微元 | 生命周期 / 并发 | 为什么是 class | ACT 建议 |
|---|---|---|---|---|---|
| `ControlLoop` | active chunk、cursor、pending request、last safe action、metrics | 合法性、状态更新、tick、fallback | node 生命周期；timer 单线程调用、worker 异步交接 | 这些状态必须跨 tick 保持一致 | 保留 class，删除 blend state |
| `SharedBuffer` | latest observation、两条 latest queue、metrics、lock | RAM 读写/计数 | 被 callback、worker、tick 共享 | 有明确共享状态和并发边界 | 由相邻 L2 的 runtime 契约实现，L2-06 消费其接口 |
| `InferenceWorker` | thread/event/period | request→inference→result | 后台线程 | 把 GPU 等待从 tick 移走 | 属于 L2-03，不在本 L2 重实现 |
| `Pi05VlaDeployNode` | ROS handles、timer、publisher | 组装、timer、metrics publish | ROS node 生命周期 | 外部世界入口 | ACT `ActDeployNode` 只吸收 UI 装配部分 |

风险：Pi0.5 用 14D/26D `BimanualAction` 语义，当前 ACT L1 指定 16D；本设计只借控制结构，绝不搬运旧 action/state 规格。
