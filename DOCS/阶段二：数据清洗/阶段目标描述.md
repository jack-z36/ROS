## 阶段定位

阶段二负责把阶段一生成的 raw MCAP 从硬件原始 topic 日志，逐步转换为可靠的、对齐的、标准化的 canonical dataset，最终导出为模型训练所需的格式。

阶段二工作环境分为两层：阶段二总层负责入口索引、阶段级文档、架构路线图和真实数据产物落点；具体开发层分为 `01_runtime_mvp/` 与 `02_service/` 两条任务线。五个业务场景归入 `02_service/`。

## 五场景流水线

阶段二按以下五个场景顺序推进：

1. **场景一：提取夹爪开合以及位姿转换** — 从 raw MCAP 中提取夹爪宽度，完成左右 Baton Mini raw pose 到 common frame 相机位姿的转换，输出 cleaned MCAP；TCP offset 后续作为独立外参扩展。
2. **场景二：硬件数据可靠性验证** — 对 cleaned MCAP 中的位姿和触觉数据做滤波、异常值检测与补全；通过 IK 求解和 MuJoCo 物理仿真验证位姿在睿尔曼机械臂上的可行性，发现并修复问题数据。
3. **场景三：MCAP 多 topic 时间轴对齐** — 将验证后的 MCAP 中各 topic（图像、位姿、触觉、夹爪）统一到同一条时间轴，生成对齐报告。
4. **场景四：构建标准 canonical dataset** — 将时间对齐后的数据组织为 episode/step 结构，生成 schema、step_index、masks、action chunk 和质量报告，形成完整 canonical dataset。
5. **场景五：模型训练格式导出器** — 根据最终选定的模型及其数据格式要求，从 canonical dataset 导出训练所需格式。

## 核心目标

阶段二不只是改变文件格式，而是完成五件事：

- 提取原始数据中缺失的语义信息（夹爪宽度、common frame 位姿；TCP 位姿后续由相机位姿叠加 TCP 外参得到）。
- 确保硬件信号真实可靠，滤波后仍能忠实反映物理现实。
- 确保位姿可以通过 IK 求解为关节角，并在睿尔曼机械臂上安全执行。
- 把多 topic 数据按统一时间轴对齐，组织成标准的 observation/action step。
- 生成一套 canonical dataset，使后续可以稳定导出到训练格式。

## 数据流总览

```
raw MCAP
  → [场景一] 提取夹爪宽度 + 位姿转换 → cleaned MCAP
  → [场景二] 滤波/异常值处理 + IK 仿真验证 → validated MCAP
  → [场景三] 多 topic 时间轴对齐 → aligned MCAP + alignment_report
  → [场景四] episode/step 构建 + schema/masks/action → canonical_dataset_mcap
  → [场景五] 按模型需求导出 → exports/lerobot|hdf5|zarr|...
```

## canonical dataset 定义

canonical dataset 是阶段二输出给训练阶段的标准数据契约。它是 MCAP-centric 的标准中间态数据集，不是训练框架专用格式。

阶段二真实数据产物默认放在 `asset/阶段二：数据清洗/`。本文中的 `canonical_dataset_mcap/` 指该产物区下的 canonical dataset 目录。

### 最终目录结构

```text
canonical_dataset_mcap/
```

### dataset 级语义

`dataset_meta.json` 描述整批数据集，至少记录：`dataset_name`、`dataset_version`、`created_at`、`project_name`、`robot_setup`、`sensor_setup`、`schema_version`、`total_episodes`、`total_steps`、`task_list`、`description`。

`dataset_index.parquet` 是全局 episode 索引，至少记录：`episode_id`、`episode_path`、`task_name`、`language_instruction`、`num_steps`、`duration_sec`、`success`、`valid_for_training`、`quality_score`、`data_mcap_path`、`step_index_path`、`masks_path`。

### schema 级语义

- `observation_schema.json`：定义 observation 字段（左右图像、TCP pose、夹爪宽度、触觉、语言指令）的来源、shape、单位、是否必需、预处理方式。
- `action_schema.json`：定义 UMI 风格 relative trajectory action 的语义。
- `frame_schema.json`：定义 common frame 及左右 raw pose 的转换方式。
- `topic_schema.json`：定义 MCAP topic 与训练语义字段间的映射。
- `quality_schema.json`：定义 masks 和质量字段的解释规则。

### episode 级语义

每个 episode 目录表示一次完整示教，包含：

- `episode_meta.json`：任务语义、来源、起止时间、操作者、语言指令、是否成功。
- `data.mcap`：该 episode 的多模态时间序列数据本体。
- `step_index.parquet`：把 topic 世界映射到 step 世界的核心索引。
- `masks.parquet`：记录每个 step 各字段的有效性和训练可用性。
- `alignment_report.json`：同步质量汇总。
- `quality_report.json`：数据质量汇总。
- `robot_constraint_report.json`：机器人执行约束检查结果。
- `processing_manifest.json`：处理过程追溯。

### canonical dataset 的不变量

- dataset 级 schema 能解释所有 episode。
- `dataset_index.parquet` 登记的 episode 路径真实存在。
- `step_index.parquet` 能定位到 `data.mcap` 中的消息或派生字段。
- observation 必需字段要么可定位，要么在 masks 中标记无效。
- action 计算方式可从 common-frame TCP 轨迹和夹爪宽度复现。
- frame_schema 能解释所有位姿的坐标系和单位。
- masks 能让 exporter 过滤不可训练 step。
- processing_manifest 能追溯生成过程。

## 成功标准

阶段二成功时应满足：

- 夹爪宽度能从 GoPro 图像中稳定提取。
- 左右 raw pose 能转换到 common frame 下相机 pose，并为后续 TCP pose 扩展保留清晰外参边界。
- 位姿和触觉数据经过滤波，异常值被合理处理和补全。
- 位姿通过 IK 求解和 MuJoCo 仿真验证，确保在睿尔曼机械臂上安全可执行。
- 多 topic 统一时间轴和对齐质量可追溯。
- canonical dataset 结构完整，schema/index/masks/report 齐全。
- 训练格式能从 canonical dataset 稳定导出。
