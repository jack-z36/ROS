# 文档分类与目录规范

## 适用范围

- 阶段：全局
- 任务模式：文档体系维护、知识整理、约束整理、工程文档迁移
- 适用对象：`DOCS/` 下所有项目文档
- 不适用对象：源码包自带代码注释、外部工具自动生成缓存

## 强制规则

DOCS 一级目录固定为：

```text
DOCS/
├── 01_知识/
├── 02_约束/
├── 03_工程/
├── 98_archive/
└── 99_learning/
```

`01_知识/` 只承载稳定理解材料：项目是什么、数据是什么、为什么这样设计。知识目录按阶段组织；阶段三和阶段四在未启动开发前只保留空目录。

`02_约束/` 承载必须遵守的规则、上下文加载流程、工作流和模板。约束按主题域组织，不按阶段优先；只有规则确实阶段专属时才允许在文件名或适用范围中标注阶段。

`03_工程/` 承载具体推进工作台：当前进度、执行记录、输出程序与文件、L2/L3、dispatch、debug、运行手册。工程目录严格按阶段组织。

`98_archive/` 承载旧快照和迁移过程归档。它只用于追溯，不得作为默认任务上下文。

`99_learning/` 承载给人看的学习资料、外部厂商资料和长篇解释材料。它不得作为 Agent 默认加载入口。

## 禁止事项

- 禁止在根 `DOCS/` 下继续新增散落阶段目录或零散规则文件。
- 禁止把执行记录、当前进度、debug 过程写入 `01_知识/`。
- 禁止把业务知识或项目状态写入 `02_约束/`，除非它是规则适用范围的一部分。
- 禁止把学习笔记或外部大文档作为默认上下文入口。

## 维护规则

调整本目录规范前，必须同步检查根 `AGENTS.md` 与 `DOCS/02_约束/上下文加载/` 下的加载规则是否仍然正确。
