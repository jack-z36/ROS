## 1. `manifest/action_observation_schema.md`

说明 LeRobotDataset v3 的 `observation.state` 和 `action` 向量每一维的含义、单位、坐标系。

### observation.state（默认 32 维）

|   索引范围   | segment ID                | 维度  | 分量                      | 单位                  | 语义                         | 坐标系              |
| :------: | :------------------------ | :-: | :---------------------- | :------------------ | :------------------------- | :--------------- |
|  [0, 7)  | `left_tcp_pose`           |  7  | x, y, z, qx, qy, qz, qw | m + quaternion_xyzw | step t 时左手 arm-base TCP 位姿 | `left_arm_base`  |
| [7, 14)  | `right_tcp_pose`          |  7  | x, y, z, qx, qy, qz, qw | m + quaternion_xyzw | step t 时右手 arm-base TCP 位姿 | `right_arm_base` |
| [14, 15) | `left_gripper_width`      |  1  | width                   | normalized [0, 1]   | step t 时左夹爪宽度（0=闭合, 1=全开）  | -                |
| [15, 16) | `right_gripper_width`     |  1  | width                   | normalized [0, 1]   | step t 时右夹爪宽度（0=闭合, 1=全开）  | -                |


### action（默认 16 维）

| 索引范围 | segment ID | 维度 | 分量 | 单位 | 语义 | 时间偏移 |
|:---:|:---|:---:|:---|:---|:---|:---:|
| [0, 7) | `left_tcp_pose_t_plus_1` | 7 | x, y, z, qx, qy, qz, qw | m + quaternion_xyzw | step t+1 时左手 arm-base 绝对 TCP 目标位姿 | +1 step |
| [7, 8) | `left_gripper_width_t_plus_1` | 1 | width | normalized [0, 1] | step t+1 时左夹爪目标宽度 | +1 step |
| [8, 15) | `right_tcp_pose_t_plus_1` | 7 | x, y, z, qx, qy, qz, qw | m + quaternion_xyzw | step t+1 时右手 arm-base 绝对 TCP 目标位姿 | +1 step |
| [15, 16) | `right_gripper_width_t_plus_1` | 1 | width | normalized [0, 1] | step t+1 时右夹爪目标宽度 | +1 step |

**必选段落**：`left_tcp_pose_t_plus_1`、`right_tcp_pose_t_plus_1`（不可禁用）。
**可选段落**：`left_gripper_width_t_plus_1`、`right_gripper_width_t_plus_1`。

**关键语义**：action 是**绝对动作**（absolute），语义为 `action_t = target at step t+1`。差分/相对化属于训练侧策略，不在阶段二内改写。

> [!warning] action 段落排列与 state 不同
> state 按"所有左段 -> 所有右段"分组排列，而 action 按"左 pose + 左夹爪 -> 右 pose + 右夹爪"交替排列。这是 `lerobot_features.py` 中 `ACTION_SEGMENT_DEFINITIONS` 的定义顺序决定的，不是笔误。action 不包含触觉段落。

### 坐标系说明

- 左右手 TCP pose 分别属于 `left_arm_base` 和 `right_arm_base`，是两个独立物理坐标系。
- 除非有明确转换关系，不得将左右轨迹当成同一坐标系叠加解释。
- quaternion 采用 xyzw 顺序，归一化。

### 单位约定

| 字段 | 单位 | 备注 |
|:---|:---:|:---|
| TCP position (x, y, z) | m | 进入 Runtime 计算后统一为 m |
| TCP orientation (qx, qy, qz, qw) | quaternion | xyzw 顺序，归一化 |
| Gripper width | [0, 1] | 0=闭合, 1=全开，归一化 |
| Tactile summary | raw sensor value | 从 PressureFrame 6x15 矩阵在 half-step 窗口内聚合 |

      enabled: true

### 校验逻辑说明

- stats.json 由 `LeRobotV3Writer` 在写入所有 episode 后调用 `_aggregate_episode_stats()` 自动聚合生成。
- 聚合方法：pooled variance identity，跨 episode 汇总 min/max/mean/std/count。聚合后对方差做 `np.clip(pooled_var, 0.0, None)` 保证数值稳定性。
- 每个 feature 的 stats 结构：`{ "min": [...], "max": [...], "mean": [...], "std": [...], "count": [...] }`。
- 训练侧通过 min-max 归一化到 [-1, 1]：`y = 2 * (x - min) / (max - min) - 1`（实际实现中还会处理 `max == min` 的退化情况和 identity_indices）。

> [!warning] stats.json 可能被训练侧覆写
> `pi05/common/data/normalization.py` 中的 `ensure_vector_stats()` 会在检测到 stats 不兼容时重新扫描数据集并覆写 `meta/stats.json`。因此，若训练侧已运行过，stats.json 可能不再是 forge writer 的原始输出。校验时应确认 stats.json 的修改时间早于训练侧首次加载时间。
