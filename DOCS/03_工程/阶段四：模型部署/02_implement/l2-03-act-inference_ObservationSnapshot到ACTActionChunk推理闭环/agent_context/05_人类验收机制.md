# L2-03 人类验收机制

## 1. 人类验收目标

人类需要确认的不是“模型是否会操作机器人”，而是以下较小且可证明的事实：

```text
给定已加载 policy、两个 normalizer 和合法 ObservationSnapshot
L2-03 只做一次同步业务转换
并产出不带运行元数据的 physical ActionChunk
```

真机安全、单步选择、chunk 生命周期、fallback、ROS publish 均不属于本验收。

## 2. 自动验收

后续实现完成后，在仓库根目录运行：

```bash
bash src/model_deploy/act/scripts/l2_03_verify.sh
```

脚本的标签、分层输出、FAIL 定位和退出码定义见 `04_L2验收机制.md §4`。

人类判定标准：

- 汇总无 FAIL，允许仅真实 policy 补验为 BLOCKED。
- `service.full_chain`、`service.policy.predict_chunk`、`service.output.no_repair` 和全部 boundary 标签必须 PASS。
- 任何“以默认值、零动作或旧 chunk 替代失败”的结果都不是 PASS。

## 3. 人工审查清单

| 序号 | 审查对象 | 观察点 | 通过现象 |
|---|---|---|---|
| 1 | L2 边界 | 对照 `01_L2功能边界.md` | 输入只含四项稳定依赖和 snapshot；成功输出只含 ActionChunk actions |
| 2 | 三段封装 | 对照 `03_ACT微元设计与协作.md §4`～`§7` | snapshot->batch、policy forward、raw->ActionChunk 三段清晰；L2-06 只调用总入口 |
| 3 | State 二次解耦 | 对照阶段一 | tensor 表达转换与数值归一化是两个独立微元和测试点 |
| 4 | ACT API | 检查 service 实现和测试 spy | 只调用 `predict_action_chunk`，没有 `select_action` |
| 5 | 输出严格性 | 检查 stage three 场景 | 无 clamp/crop/pad/reorder；错误 shape 直接失败 |
| 6 | 层落点 | 检查新增文件列表 | 只新增 `types/`、`service/`、tests；没有 repo loader、runtime worker 或 ui node |
| 7 | 运行元数据 | 查看 `ActionChunk` 字段 | 不含 request/time/latency/cursor/error/metrics |
| 8 | 下游方向 | 查看协作图/集成测试 | ActionChunk 先给 L2-06；L2-04 只接收 L2-06 选择的单步 action |

## 4. 推荐的可视化数据追踪

使用包含唯一 sentinel 值的 stub policy 和 recording normalizer，检查完整轨迹：

```text
snapshot.encoded_state (16,)
-> physical CPU tensor (16,)
-> normalized tensor (16,)
-> batch["observation.state"] (1,16)
-> policy raw chunk (1,N,16)
-> physical actions (N,16)
-> ActionChunk.actions (N,16) float32
```

人工应能从 sentinel 值确认：

- state 没有被错误的 action normalizer 处理。
- action 没有被错误的 state normalizer 恢复。
- 16 个维度的顺序未变化。
- 超出训练常见范围的 raw 值没有被 L2-03 clamp。
- raw 输出维度错误时没有被裁剪或补齐。

## 5. 可选真实 policy dry-run

当 L2-01 已提供真实 policy、真实 normalizer 和满足训练契约的 snapshot 时，可补做一次无 ROS、无硬件输出的调用。

通过现象仅限：

```text
得到合法 ActionChunk
或得到可定位的模型/输入契约异常
```

无真实资源时应记录 `BLOCKED`。不得把 stub policy 通过写成真实模型通过，也不得把真实推理通过写成机器人执行通过。

## 7. 风险边界

L2-03 没有 ROS 或硬件副作用，因此它不会单独发送机械臂或夹爪命令。仍需明确：

- `ActionChunk` 合法只代表数据契约合法，不代表安全。
- L2-04 才检查单步 action 的必要安全条件。
- L2-05 才构造并发布 ROS command。
- L2-06 才决定哪一步 action 在何时进入 L2-04。

任何真实机器人行为验收都必须在 L2-04/L2-05/L2-06 的独立 Gate、明确授权、急停就绪和 shadow-run 证据具备后进行。
