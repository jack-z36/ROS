# 阶段二执行记录目录

本目录用于统一保存阶段二的数据清洗执行记录和当前状态快照。

## 目录职责

阶段二后续不再优先把新的执行过程追加到各级目录中的固定 `执行记录.md` 或 `当前进度.md`。

新的阶段二记录统一写入：

```text
DOCS/阶段二：数据清洗/执行记录/
```

本目录承载两类文件：

1. 执行记录：记录某次具体开发、整理、验证、迁移或讨论的执行过程。
2. 当前状态：记录某个 L1 / L2 / L3 / 场景在某一时刻的状态快照、未完成事项和下一步建议。

## 命名规则

文件名允许两类命名方式。

### 方式一：时间命名

适合零散维护、阶段性整理、对话沉淀、状态快照。

```text
MMDDHH_<简短主题>.md
```

示例：

```text
051518_执行记录目录统一.md
051520_service_s1状态快照.md
```

其中：

- `MM`：月份，两位数字。
- `DD`：日期，两位数字。
- `HH`：小时，24 小时制，两位数字。
- `<简短主题>`：用短中文或短英文描述记录对象。

### 方式二：时间 + 微元任务命名

适合 L3 微元任务执行后的正式记录。

```text
MMDDHH_<L3微元任务名>.md
```

示例：

```text
051520_service_s1_001_gripper_marker_detection.md
```

同一个文件内同时记录执行过程、当前状态、未完成事项和下一步建议，不再拆成多个文件。

## 文件内容建议

每个执行记录文件至少包含：

```text
# <记录标题>

## 基本信息

- 时间：
- 归属 L1：
- 归属场景：
- 关联 L2：
- 关联 L3：

## 用户请求

## 执行内容

## 涉及文件

## 观察结果

## 当前状态

## 未完成事项

## 下一步建议
```

## 与旧文件的关系

历史上已有的 `执行记录.md` 和 `当前进度.md` 暂时保留，避免破坏既有索引和历史引用。

从本规则建立后，阶段二新增记录优先写入本目录。必要时可以在旧文件中只保留入口说明或索引，不再持续堆叠长记录。

## 使用原则

- 不把一次 L3 执行记录散落到多个场景目录。
- 不把长执行过程继续追加进阶段级 `当前进度.md`。
- 阶段级、任务线级、场景级 `当前进度.md` 后续只保留粗粒度状态和指向本目录的索引。
- 如果一次任务无法明确归入阶段二，应继续写入 `DOCS/总执行日志.md`。
