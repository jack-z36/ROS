# 阶段二：数据清洗工作入口

本目录是阶段二数据清洗的工作环境入口。阶段二采用两层 Harness：

- 阶段二总层：阶段级目标、背景、进度、产出、架构路线图和真实数据产物落点。
- 具体开发层：`01_runtime_mvp/` 与 `02_service/` 两条并行任务线。
- 任务记录层：`03_tasks/` 记录 active/completed 任务计划和执行前对话确认。
- 执行记录层：`执行记录/` 统一保存阶段二新增执行记录和当前状态快照。
- 工作流层：`DOCS/工作流/阶段二开发范式.md` 负责把阶段二 L1/L2/L3 开发范式落成 L2 功能模块说明和 `03_tasks/active/` 下的 L3 微元任务。

## 必读顺序

处理任何阶段二任务前，先阅读：

1. `DOCS/public_rules.md`
2. `AGENTS.md`
3. `阶段目标描述.md`
4. `背景信息.md`
5. `当前进度.md`
6. `阶段产出.md`
7. **`文件存放规范.md`** — 创建、写入或输出任何文件前，必须遵守此规范。

当用户提到阶段二 pipeline、L1/L2/L3、功能模块拆解、功能模块说明文档或微元任务生成时，还必须读取：

- `DOCS/工作流/阶段二开发范式.md`

不要在进入阶段二开发范式时预读 L2 模板。只有当已经与用户深入交流并形成 L2 功能蓝图，准备将蓝图整理为正式 L2 能力模块说明文件时，才按工作流要求读取 `DOCS/工作流/attachments/L2能力模块说明文件模板.md`。

如果任务涉及总体架构、产物契约或路线图，继续阅读：

- `00_架构与路线图/数据清洗pipeline宏观蓝图.md`
- `00_架构与路线图/阶段二实现路线图.md`
- `00_架构与路线图/阶段二产物架构设计.md`
- `00_架构与路线图/架构设计约束.md`

## 任务线入口

阶段二 L1 开发任务固定为 `runtime_mvp` 与 `service_s1` 到 `service_s5`。L2 功能模块说明文档统一命名为 `功能模块拆解.md`，放在对应 L1 目录或 Service 场景目录；L3 微元任务统一进入 `03_tasks/active/`，按 L1 前缀编号。

## 执行记录入口

阶段二新增执行记录和当前状态快照统一写入：

```text
DOCS/阶段二：数据清洗/执行记录/
```

命名优先使用：

```text
MMDDHH_<简短主题>.md
```

如果记录来自明确的 L3 微元任务，也可以使用：

```text
MMDDHH_<L3微元任务名>.md
```

同一个文件内同时记录执行过程、当前状态、未完成事项和下一步建议，不再拆成多个文件。历史上的 `执行记录.md` 和 `当前进度.md` 暂时保留作为旧索引和历史资料；后续新增长记录不再优先追加到这些固定文件。

### Runtime MVP

目录：`01_runtime_mvp/`

- `目标描述.md`
- `背景信息.md`
- `执行约束.md`
- `执行记录.md`
- `当前进度.md`
- `输出程序与文件.md`

Runtime MVP 只负责流程编排、场景选择、配置读取、输入检查、run 目录、日志、manifest 和错误摘要，不实现真实清洗算法。

处理 Runtime MVP 任务前，还必须先阅读：

- `03_tasks/README.md`
- `03_tasks/active/001_runtime_mvp_harness.md`

### Service

目录：`02_service/`

先阅读 `02_service/` 任务级六件套，再按具体场景继续阅读对应 `场景一` 到 `场景五` 的六件套。

Service 任务线负责五个阶段二业务场景的真实处理能力：

1. 场景一：提取夹爪开合以及位姿转换。
2. 场景二：硬件数据可靠性验证。
3. 场景三：MCAP 多 topic 时间轴对齐。
4. 场景四：构建标准 canonical dataset。
5. 场景五：模型训练格式导出器。

## 数据产物落点

阶段二真实数据产物默认放在：

`asset/阶段二：数据清洗/`

该目录只放真实数据产物，不放文档契约。产物契约继续由 `00_架构与路线图/阶段二产物架构设计.md` 维护。

## 禁止事项

- 不得覆盖 raw MCAP。
- 不得把真实业务算法写进 Runtime。
- 不得让 exporter 回头读取 raw、cleaned、validated 或 aligned 来修复数据。
- 不得静默丢弃不可训练 step；必须进入 masks 和报告。
- 不得跳过当前任务线和场景对应的 Harness 文档。
- 不得跳过 `03_tasks/active/` 中当前任务的对话确认区。
