# 阶段二场景二：功能模块清单

## 一句话总结

场景二按现有预期程序拆为 9 个 L2 功能模块，目标是从场景一输出的 cleaned MCAP 生成可追溯的 validated MCAP，并输出异常、修复、IK、仿真与机器人约束相关报告。

## 上游接口状态

场景二直接依赖场景一产出的 cleaned MCAP、清洗报告、标定/转换参数。场景一接口已开始按 L2 数据定义固化，后续编写场景二 L2 前必须优先读取：

- `DOCS/阶段二：数据清洗/02_service/场景一/L2数据定义/CleanedMcap.md`
- `DOCS/阶段二：数据清洗/02_service/场景一/L2数据定义/Scene1Config.md`
- `DOCS/阶段二：数据清洗/02_service/场景一/L2数据定义/Scene1CleanReport.md`
- `DOCS/阶段二：数据清洗/02_service/场景一/L2数据定义/CommonFrameCameraPose.md`
- `DOCS/阶段二：数据清洗/02_service/场景一/L2数据定义/CommonFrameTcpPose.md`
- `DOCS/阶段二：数据清洗/02_service/场景一/L2数据定义/FrameAlignmentConfig.md`
- `DOCS/阶段二：数据清洗/02_service/场景一/L2数据定义/GripperWidthSample.md`

当前已稳定的接口结论：

- `CleanedMcap` 默认输出位置为 `asset/阶段二：数据清洗/dev/mcap_cleaned/*.mcap`。
- `/baton_mini_left/fast_odom`、`/baton_mini_right/fast_odom` 必须作为 raw pose 保留或可追溯。
- 场景二优先消费 `CommonFrameTcpPose`，必要时读取 `CommonFrameCameraPose` 和 raw pose 做调试追溯。
- common frame 默认是 `left_umi_start_frame`，由 `FrameAlignmentConfig.common_anchor: left` 定义。
- `/gopro_left/gripper_width`、`/gopro_right/gripper_width` 为新增 gripper width topic，消息类型为 `std_msgs/msg/Float32`，值域为归一化 `[0, 1]`。
- `Scene1CleanReport` 第一轮先作为契约定义，独立 JSON 文件写出仍待后续 L3 实现。

仍需场景一后续 L3 落地的事项：

- 默认配置路径迁移到阶段二规范目录。
- cleaned MCAP 输出契约测试覆盖 raw pose 保留、camera/TCP common pose 数量、gripper 数量、topic 冲突和配置来源。
- 浏览器夹爪配置生成接口和 frame_alignment 配置生成接口仍需完成代码改造。
- 场景一清洗报告从终端/RAW_JSON 摘要收敛为可追溯机器可读报告。

## 01 位姿滤波器

- 一句话目标：对 cleaned MCAP 中的位姿序列进行平滑，降低高频噪声且保留真实运动趋势。
- 模块类别：数据计算类。
- 输入：cleaned MCAP 中的 TCP / common frame 位姿序列。
- 输出：滤波后位姿序列，以及滤波参数、滤波前后差异摘要。
- 上游依赖：场景一 `CleanedMcap`；优先读取左右 `CommonFrameTcpPose`，并保留 raw pose 作为追溯对照。
- 下游消费者：异常值检测器、数据补全器、IK 求解器、验证报告生成器。
- 优先级：P0。
- 阻塞项 / 未知问题：滤波器类型、窗口或截止频率尚未确定；场景一 `service_s1_006` 到 `service_s1_008` 完成前，TCP pose topic 名和 raw pose 保留实现仍是接口落地项。
- 后续可拆 L3 方向：定义位姿序列输入契约；实现位姿滤波计算；补充滤波前后差异验收。

## 02 触觉滤波器

- 一句话目标：对 cleaned MCAP 中的触觉序列进行平滑，降低尖峰噪声且保留接触变化。
- 模块类别：数据计算类。
- 输入：cleaned MCAP 中的左右触觉序列。
- 输出：滤波后触觉序列，以及滤波参数、滤波前后差异摘要。
- 上游依赖：场景一 cleaned MCAP；触觉 topic 结构和数值单位需确认。
- 下游消费者：异常值检测器、数据补全器、验证报告生成器。
- 优先级：P0。
- 阻塞项 / 未知问题：触觉数据 shape、单位、合理范围和噪声特征尚未稳定。
- 后续可拆 L3 方向：定义触觉序列输入契约；实现触觉滤波计算；补充尖峰抑制验收。

## 03 异常值检测器

- 一句话目标：识别位姿、触觉、夹爪等序列中的跳变、缺失、非法值和异常变化片段。
- 模块类别：数据计算类。
- 输入：滤波后位姿序列、滤波后触觉序列、夹爪宽度序列，以及必要的原始序列对照。
- 输出：异常标记、异常位置列表、异常类型和异常原因摘要。
- 上游依赖：位姿滤波器、触觉滤波器；夹爪宽度来自场景一 cleaned MCAP。
- 下游消费者：数据补全器、问题数据修复器、验证报告生成器。
- 优先级：P0。
- 阻塞项 / 未知问题：异常阈值、缺失段判定、速度/加速度异常规则和触觉突变规则尚未确定。
- 后续可拆 L3 方向：定义异常标记数据概念；实现异常检测规则；补充典型异常样例验收。

## 04 数据补全器

- 一句话目标：对可修复异常片段进行插值、邻近补全或其他可追溯补全。
- 模块类别：数据计算类。
- 输入：原始序列、滤波后序列、异常标记和异常位置列表。
- 输出：补全后连续序列、补全标记和补全方法摘要。
- 上游依赖：异常值检测器；位姿滤波器；触觉滤波器。
- 下游消费者：IK 求解器、关节限制检查器、MuJoCo 仿真验证器、验证报告生成器。
- 优先级：P0。
- 阻塞项 / 未知问题：哪些异常允许补全、最长可补全缺失段、不可补全片段如何标记尚未确定。
- 后续可拆 L3 方向：定义补全策略契约；实现可修复片段补全；补充不可补全片段标记验收。

## 05 IK 求解器

- 一句话目标：将 TCP / common frame 位姿序列转换为机器人关节角候选序列。
- 模块类别：数据计算类。
- 输入：补全后 TCP / common frame 位姿序列，以及机器人运动学参数。
- 输出：关节角序列、IK 求解失败标记和求解摘要。
- 上游依赖：数据补全器；场景一位姿转换接口；机器人参数。
- 下游消费者：关节限制检查器、MuJoCo 仿真验证器、验证报告生成器。
- 优先级：P1。
- 阻塞项 / 未知问题：睿尔曼机械臂 DH 参数、关节限制、TCP 外参、IK 多解选择策略尚未稳定。
- 后续可拆 L3 方向：定义 IK 输入输出契约；接入或封装 IK 求解；补充失败标记验收。

## 06 关节限制检查器

- 一句话目标：检查关节角、关节速度、关节加速度和 workspace 是否满足机器人约束。
- 模块类别：数据计算类。
- 输入：关节角序列、时间戳序列、机器人约束参数。
- 输出：约束违规标记、违规位置列表、违规类型和约束检查摘要。
- 上游依赖：IK 求解器；机器人参数。
- 下游消费者：MuJoCo 仿真验证器、问题数据修复器、验证报告生成器；后续场景四 masks 和 robot constraint report。
- 优先级：P1。
- 阻塞项 / 未知问题：关节角范围、速度限制、加速度限制、workspace 边界和安全余量尚未稳定。
- 后续可拆 L3 方向：定义机器人约束数据概念；实现约束检查；补充违规样例验收。

## 07 MuJoCo 仿真验证器

- 一句话目标：在仿真环境中回放或检查关节轨迹，发现物理不可行片段。
- 模块类别：数据计算类。
- 输入：关节角序列、约束检查结果、MuJoCo 机器人模型和必要的仿真参数。
- 输出：仿真问题段、碰撞或力矩等问题摘要、仿真验证结论。
- 上游依赖：IK 求解器、关节限制检查器；MuJoCo 机器人模型。
- 下游消费者：问题数据修复器、验证报告生成器。
- 优先级：P2。
- 阻塞项 / 未知问题：MuJoCo 是否作为首版强依赖、机器人模型准确性、仿真耗时边界和失败处理策略尚未确定。
- 后续可拆 L3 方向：定义仿真输入契约；实现最小仿真验证；补充仿真问题摘要验收。

## 08 问题数据修复器

- 一句话目标：对 IK、约束或仿真发现的问题片段执行可追溯修复或标记不可用。
- 模块类别：数据计算类。
- 输入：补全后序列、IK 失败标记、约束违规标记、仿真问题段。
- 输出：修复后数据、不可修复标记、修复日志和 validated MCAP 写出所需的数据变更摘要。
- 上游依赖：数据补全器、IK 求解器、关节限制检查器、MuJoCo 仿真验证器。
- 下游消费者：验证报告生成器；场景三时间轴对齐；后续场景四 masks。
- 优先级：P2。
- 阻塞项 / 未知问题：机器人不可执行片段是否允许自动修复、何时只标记不可用、validated MCAP 如何保留追溯信息尚未确定。
- 后续可拆 L3 方向：定义修复日志数据概念；实现问题片段处理策略；补充不可修复片段传递验收。

## 09 验证报告生成器

- 一句话目标：汇总异常、补全、修复、约束违规和仿真问题，生成场景二报告产物。
- 模块类别：数据读写类。
- 输入：异常标记、补全摘要、IK 求解摘要、约束违规标记、仿真问题段、修复日志。
- 输出：异常值报告、IK 可行性报告、MuJoCo 仿真报告、修复日志，以及 validated MCAP 的验证摘要。
- 上游依赖：异常值检测器、数据补全器、IK 求解器、关节限制检查器、MuJoCo 仿真验证器、问题数据修复器。
- 下游消费者：场景三时间轴对齐；场景四 quality report、robot constraint report 和 masks；人工复查。
- 优先级：P0。
- 阻塞项 / 未知问题：报告字段、报告粒度、与后续 masks 的映射关系尚未稳定。
- 后续可拆 L3 方向：定义报告数据概念；实现报告写出；补充报告字段完整性验收。

## 后续推进顺序

1. 先等待或补齐场景一 cleaned MCAP 接口定义，尤其是 topic 结构、位姿字段、清洗报告和标定/转换参数。
2. 先生成 P0 模块的 L2 数据定义与能力模块说明：位姿滤波器、触觉滤波器、异常值检测器、数据补全器、验证报告生成器。
3. 再生成 P1 模块的 L2：IK 求解器、关节限制检查器。
4. 最后生成 P2 模块的 L2：MuJoCo 仿真验证器、问题数据修复器。
5. 任意 L2 生成前，必须先按 `L2能力模块与数据定义约束.md` 完成意图澄清，并按 `上游依赖接口对齐约束.md` 检查直接上游接口。
