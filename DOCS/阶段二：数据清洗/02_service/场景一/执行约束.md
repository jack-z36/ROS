## 环境约束

- 默认使用 `.conda-envs/data-clean/bin/python`。
- 不应依赖系统 Python 里的 OpenCV、MCAP 或 ROS2 Python 包状态。
- 不应要求用户手工设置长 `PYTHONPATH`，应通过 `./start_data_clean.sh` 完成。
- 如果更新依赖，应优先保持在 `data-clean` conda 环境内，避免污染 ROS 工作区环境。

## 配置边界

- 默认配置文件为 `config/data_clean/data_clean_smoke_test.yaml`。
- 标定向导和配置中心维护的正式配置文件为 `config/data_clean/data_clean_calibrated.yaml`。
- 启动配置优先级为：命令行 `--config` 或 `DATA_CLEAN_CONFIG` > `data_clean_calibrated.yaml` > `data_clean_smoke_test.yaml`。
- `batch.input_dir` 默认指向 `mcap`。
- `batch.output_dir` 默认指向 `mcap_cleaned`。
- `batch.file_glob` 保持 `*.mcap`，具体数量由交互式启动器控制。
- 不应把临时测试配置作为长期配置散落在 `/tmp` 或仓库根目录。
- 不应直接覆盖 `data_clean_smoke_test.yaml` 来写入真实标定结果。
- 不应把左右手 Baton Mini 的正式 transform 写成同一套顶层 `transform`。正式主链路使用独立 `camera_from_tcp.left/right.translation_mm` 与 `work_frames.left/right.position_mm / rotation_euler_rad`。
- 旧 `frame_alignment`、`start_from_common` 和 `pose_streams[].transform_file` 只可作为历史兼容读取对象，普通 Web 不再写入。

## 清洗行为约束

- 默认清洗最近 1 个文件。
- “最近 N 个”按 MCAP 文件名中的时间从新到旧选择。
- 默认覆盖同名输出。
- 如果某个文件失败，应删除该文件对应的半成品输出。
- 如果用户中断，应保留已成功文件，清理未完成输出。
- `DATA_CLEAN_RAW_JSON=1` 应只输出原始 JSON，不能混入中文提示。
- 普通 Web 生产任务必须 fail-closed：缺少左右夹爪标定、`camera_from_tcp`、`work_frames`、左右 arm-base 输出 topic、RealMan SDK 或 `Algo` 初始化能力时，不得启动清洗。
- 已标定配置应带 `calibration` 元数据，记录 gripper、arm-base 生产配置和来源状态。
- `production_readiness` 只有在左右夹爪、左右 `camera_from_tcp.translation_mm`、左右 `work_frames.position_mm / rotation_euler_rad`、左右 arm-base 输出 topic 和 RealMan SDK 均可用时才能返回 ready。
- 实时标定中心不得再要求用户选择闭合/张开 MCAP；夹爪标定只能使用实时 GoPro topic。
- 标定中心不得依赖 OpenCV GUI 窗口；当前 conda 环境使用 headless OpenCV，画面预览、夹爪标定和 common frame 标定应通过本地浏览器页面完成。
- GoPro-only 启动能力只能启动左右 GoPro，不应同时启动 Baton Mini、触觉节点或 Octopus。
- 标定中心自动启动的 GoPro 进程在退出、异常或 Ctrl+C 时默认停止；进入标定前已经存在的 GoPro 节点不由标定中心停止。
- 普通 Web 不再提供 common-frame 标定入口。旧 common-frame 标定能力只保留给开发者排错或历史数据兼容，不得作为正式生产配置来源。
- 位姿转换必须使用每帧 Baton Mini 动态 pose；不得把 `camera_from_tcp.translation_mm` 当成固定 arm-base 输出，也不得在缺少 SDK 或 work frame 时静默回退 common-frame。

## 验收边界

不能把以下情况算作最终完成：

- 只跑通 `--dry-run`，但没有跑通过真实清洗。
- 只清洗一个测试 MCAP，却声称全部数据已完成清洗。
- 终端输出可读，但输出 MCAP 没有验证 topic 数或新增 topic。
- 使用测试 gripper、camera_from_tcp 或 work frame 参数，却没有明确提醒用户这些参数未真实标定。
- 仅用普通采集 MCAP 估算闭合/张开范围，而没有使用实时 GoPro 标定中心采集真实完全闭合/完全张开状态。
