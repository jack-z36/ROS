# L2-03 人类验收机制

## 1. 人类验收目标

让人类确认：L2-03 能在 fake-policy 路径下把 `ObservationSnapshot` 变成 shape `(chunk_size, 16)` 的 `ActionChunk`；推理在后台线程异步执行不阻塞前台；推理失败被记录而非崩溃；第一版没有 action 平滑逻辑。real-policy 路径在有真实 bundle + GPU 时补验，否则标 `env-blocked`。

## 2. 人类验收清单

人类验收分为两部分：**A. 脚本自动验收**（一条命令跑完所有模块测试）和 **B. 文档审查**（人工逐条检查）。

### A. 脚本自动验收

```bash
# 仓库根目录，无 ROS / 无 GPU / 无真实 bundle 环境
bash src/model_deploy/act/scripts/l2_03_verify.sh
```

脚本自动执行所有子功能模块测试，终端按 `types / config / repo / service / runtime / integration / ui·边界` 分层分组打印。每行一个标签，结果为 PASS / FAIL / BLOCKED；末行汇总 `N PASS / N FAIL / N BLOCKED`。FAIL 行附文件/class/微元/pytest/错误摘要定位块。

**通过标准**：汇总行无 FAIL（允许 BLOCKED），退出码 0。

脚本设计需求详见 `04_L2验收机制.md §4`。脚本本身由后续 L3 微元任务生成。

终端输出每行的含义对照见 HTML 维度4 的「终端输出翻译表」。

### B. 文档审查（非脚本，人工逐条执行）

以下 5 项不在 `.sh` 脚本内，由人类逐条检查：

| 审查项 | 操作 | 通过现象 | 失败现象 |
|---|---|---|---|
| ① 设计包结构校验 | 运行 `python3 skills/stage4-l2-designer/scripts/validate_l2_design_package.py DOCS/03_工程/阶段四：模型部署/02_implement/l2-03-act-inference_ObservationSnapshot到ACTActionChunk推理闭环` | 输出 PASS | 报 ERROR |
| ② 边界审查 | 对照维度1 图③：L2-03 不订阅 topic、不发布 topic、不决定推理时机 | 无越界代码 | 出现 ROS subscribe/publish 或 ControlLoop 调度逻辑 |
| ③ Pi0.5 映射审查 | 对照维度2：InferenceWorker 结构复用、Pi0.5 VLA → ACT、14D → 16D | 复用判断准确、维度全部重写为 16D | 照搬 Pi0.5 14D 或 VLA 代码 |
| ④ HTML-MD 对齐检查 | 对照 `00_INDEX.md` HTML-MD 语义对齐表，逐行核对 data-agent-source | 每个 HTML view 指向存在的 MD 节 | data-agent-source 指向不存在的文件或节 |
| ⑤ GPU 真机边界 | real-policy dry-run：有 bundle+GPU 时跑，无则标 `env-blocked` | 标 `env-blocked` 且不写成通过 | 无 GPU 却标记 real-policy 通过 |

## 4. 真机风险

本 L2 不直接发送硬件命令、不发布 topic、不订阅 topic，**本身不触发真机动作**。真机风险点在于：

- 若 real-policy 输出异常 action（NaN/Inf/越界），下游 L2-04 safety 和 L2-05 publisher 是最后防线；本 L2 只负责产出 chunk 和记录错误。
- real-policy dry-run 必须在真实 bundle + GPU 环境下执行；无 bundle 时只能 fake-policy 验收，不得把 fake 输出当作 real 可用。
- real-robot smoke test 不属于本 L2 Gate；真机发送由 L2-05 在 shadow-run / gate / 急停就绪后执行。
