## 1. 一句话运行责任

L2-06 以 ROS control timer 为时钟驱动，在不等待模型推理的前提下，拥有推理 worker/queue、request/result 关联、active/pending chunk、cursor、fallback、permit/publish 结果归约、运行指标和进程生命周期，并只通过 L2-02～05 的真实公共接口协作。

## 2. 运行责任与真实接口

```text
L2:
  l2-06-control-loop

Runtime responsibility:
  worker 异步生产 ActionChunk；ControlLoop.tick 非阻塞消费、过 safety、构造发布请求并归约结果。

Inputs:
  L2-01 DeployConfig/RuntimeConfig/CommandOutputConfig
  L2-02 ObservationBuffer.latest_observation(max_age_s)
  L2-03 ActInferenceService.predict_action_chunk(observation)
  L2-04 SafetyGuard.filter_action(candidate, previous_safe_action, latest_observation)
  L2-05 ActionPublisher.publish(ActionPublishRequest)
  CommandPermitSource、ROS clock、monotonic clock

Outputs:
  L2-06 内部 InferenceRequest/InferenceResult
  L2-05 ActionPublishRequest
  ActionPublishResult 的状态归约
  /act/metrics RuntimeMetricsSnapshot

Owns:
  LatestQueue、InferenceWorker、request id/in-flight、active/pending chunk、cursor、age、fallback、metrics、fault latch、start/stop

Does not own:
  YAML/bundle/policy 文件读取、Observation ROS 解码与图像转换、ACT batch/forward 业务实现、安全算法、ROS action message 适配、driver 接收确认、硬件 stop 实现

Upstream L2:
  L2-01、L2-02、L2-03、L2-04

Downstream L2:
  L2-05 是唯一 action/status 输出端口；L2-06 自身只额外输出 runtime metrics
```

## 3. 精确协作签名

### L2-02 observation port

```python
observation_provider: Callable[[float | None], ObservationSnapshot | None]
```

生产绑定为 `ObservationBuffer.latest_observation`。`None` 表示没有满足 freshness 的 snapshot；A4 仍以本 tick `monotonic_s` 对返回值做第二道类型/时钟/age 防御校验。在多线程 ROS callback 刚好于 tick 取时后完成 snapshot 时，仅允许不超过一个 control period 的小幅“未来 capture”被延后到下一 tick；更大偏差是 `CLOCK_INVALID`。L2-06 不读取 collector 私有缓存，不重组 state，不转置图像。

### L2-03 inference port

```python
ActInferenceService.predict_action_chunk(
    observation: ObservationSnapshot,
) -> ActionChunk
```

该调用同步且可能抛异常。L2-06 的 `InferenceWorker` 串行调用它，并把成功或异常都转换成 `InferenceResult`。启动构造时 L2-03 必须接收 `ActRuntimeResources.policy_input_spec`，并以只读 `input_spec` property 返回同一对象，供 B12 与 L2-02 pipeline 做 identity check；运行时仍只有上述 predict capability。L2-03 不提供 thread、queue、request id、timestamp、metrics 或 cursor。

### L2-04 safety port

```python
SafetyGuard.filter_action(
    candidate: object,
    previous_safe_action: ActionSpec | None = None,
    latest_observation: ObservationSnapshot | None = None,
) -> SafetyResult
```

`PASS` 与 `ADJUSTED` 都可以进入发布；`REJECTED` 不包含 action。不存在 `.filter()` 或 `.accepted`。

### L2-05 publish port

```python
publish_action: Callable[[ActionPublishRequest], ActionPublishResult]
```

生产绑定为 `ActionPublisher.publish`。L2-06 必须创建：

```python
ActionPublishRequest(
    action_id: str,
    safety_result: SafetyResult,
    command_permit: CommandPermit,
    ros_time_s: float,
    monotonic_s: float,
)
```

不存在 `publish_safe()` 或 `emit_fallback()`。调用正常返回也不等于成功；必须归约 `REJECTED / OBSERVED / BLOCKED / PUBLISHED / PARTIAL / FAILED`。

## 4. L2-06 新增对象

| 对象 | 所有者 | 用途 | 禁止泄漏 |
|---|---|---|---|
| `InferenceRequest` | L2-06 runtime | observation + request id + monotonic submit time | 不写进 ObservationSnapshot/ActionChunk |
| `InferenceResult` | L2-06 runtime | chunk 或 error、request id、capture/submit/start/complete time | 不把 exception 对象跨线程保存 |
| `LatestQueue[T]` | L2-06 runtime | request/result latest-only RAM channel | 不归 L2-03，不放进 L2-02 ObservationBuffer |
| `RuntimeMetrics` / snapshot | L2-06 runtime | worker/loop 指标及 UI 不可变快照 | 不复用 L2-02 metrics dict 充当全局指标 |
| `InferenceWorker` | L2-06 runtime | 串行调用同步 L2-03 service | 不决定 safety/fallback/publish |
| `ControlLoop` | L2-06 runtime | active/pending/cursor/publish reducer/fault latch | 不 import UI，不解析 ROS message |
| `ActDeployNode` | L2-06 UI | composition、timer、permit、metrics、shutdown | 不实现图像、推理或安全算法 |

## 5. 调度不变量

1. `ControlLoop.tick()` 永不等待 policy inference；同一 policy 最大并发 forward 数为 1。
2. request/result queue 均为 latest-only，第一版容量固定为 1；worker 必须可被 `close/stop/join` 唤醒并退出。
3. worker 成功和异常都必须产生 terminal `InferenceResult`；匹配的成功/异常结果都推进 `last_completed_request_id`，异常不能让 in-flight 永久悬挂。
4. `ActionChunk` 继续只有 `actions`；age、request id 和 error 只存在于 L2-06 envelope。
5. result id 必须与当前 in-flight 匹配；旧结果丢弃，更大未知 id 触发 invariant fault。chunk 失效时不得清掉仍在执行的 in-flight id，只标记其 terminal result 到达后丢弃，始终保持最多一个 outstanding request。
6. age 从 observation 的 monotonic capture time 计算；不能从 result ready time 计算。
7. chunk 必须精确为 `(RuntimeConfig.chunk_size, 16)`、`float32`、finite；启动期还必须校验 policy chunk size 与 config 相等。
8. 新 result 先进入单一 pending slot；active 未到 `execute_horizon` 时不被截断。
9. 正常路径最多消费到 `execute_horizon`；只有 `continue_old_chunk` 可继续到 `chunk_size`，且仍受 freshness/age 约束。
10. 每个 candidate 只调用一次 L2-04、最多调用一次 L2-05；同一 tick 不因 safety reject 再发第二个 fallback action。
11. `/act/command/status` 只由 L2-05 写；L2-06 只发布 `/act/metrics`，避免双 writer/双 schema。
12. `PARTIAL/FAILED` 锁存输出故障并清空 chunk；本进程禁止自动继续 command。
13. `ActionSpec` 虽为 frozen dataclass，内部 ndarray 仍可写；active row、fallback previous 和 C19 保存 previous 时必须深复制，禁止跨 L2 保存可变 view/reference。
14. 未知更大 result id、queue closed/invariant、L2-05 result 与原 request 在 action-id、safety、startup command switch、permit、outcome/provenance 上矛盾，或未分类 runtime port 异常，均锁存独立 runtime fault；它与 `PARTIAL/FAILED` output fault 都只能由进程重启清除，不能进入普通 fallback 自动恢复。
15. `REJECTED/BLOCKED` 必须把 `SAFETY_REJECTED/COMMAND_BLOCKED` 同步保留为一次性 deferred state + metrics gauge；只在下一个有 fresh observation、无 normal candidate 的 tick 交 B8，若 normal 已恢复则同步清除而不回放旧故障。

## 6. fallback 语义

| policy | 允许条件 | 行为 | 不允许时 |
|---|---|---|---|
| `hold_last_action` | 有 previous-safe，observation 新鲜，且 `0 <= now - previous_source_captured_at_s <= max_action_age_sec`，无 fault latch | previous-safe 深复制后重新经过 L2-04，再以真实 request 调 L2-05；重复发布不得刷新 source age | status/metrics only；不制造全零 action |
| `continue_old_chunk` | active 未过期、仍有 row、observation 新鲜、无 pending 可切换 | 继续 cursor，最多到 `chunk_size`；pending 到达后下一 tick 切换 | status/metrics only |
| `safe_stop` | 无需 ActionSpec | 本 tick fail-closed：不生成 fallback candidate、不调用 L2-05 command，只记录 runtime reason；下一 tick 可用 fresh observation 重新推理 | 当前没有硬件 stop port，不得宣称已执行物理 stop；永久锁存只属于 `PARTIAL/FAILED` output fault |

非 safety 失败（无 observation、无 chunk、推理异常、结果过期）没有合法 `SafetyResult`，禁止伪造 `REJECTED` 交给 L2-05。SafetyGuard 真实返回 `REJECTED` 时，可把该真实结果交给 L2-05 产生 status-only `REJECTED`，然后下一 tick 再按 fallback policy 决策。

## 7. PublishOutcome 状态归约

| outcome | previous-safe | chunk/cursor | 后续状态 |
|---|---|---|---|
| `PUBLISHED` | 更新为本拍 `SafetyResult.action` | 提交 cursor，保留 active/pending | 正常继续；不推断 driver accepted |
| `OBSERVED` | command-disabled 进程中更新虚拟 previous；启动总开关不可热切换 | 提交 cursor | dry/shadow 链继续 |
| `BLOCKED` | 清 previous + source time，禁止解除 gate 后先 hold stale target | 清 active/pending；若有 in-flight，仅标记其结果待丢弃，不清 outstanding id | 一次性 `COMMAND_BLOCKED`；permit 恢复且旧 request terminal 后，用 fresh observation 重推理 |
| `REJECTED` | 不更新 | 清 active/pending | 保存 `SafetyFinding.code` 和一次性 `SAFETY_REJECTED`，下一个可决策 tick fallback |
| `PARTIAL` | 清空 previous，要求 fresh observation 重建基准 | 清全部 chunk | latch fault，禁止后续 command |
| `FAILED` | 清 previous + source time | 清全部 chunk | latch fault，禁止自动重试 |

## 8. 启动硬前置条件

以下是代码/接口条件；任何一项未满足都必须是 `FAIL`，不能因为无 ROS 或无真机写成 `BLOCKED`，也不能由 ControlLoop 私下补偿：

| ID | 必须先闭合的接口 | 当前源码问题 | 正确责任 |
|---|---|---|---|
| P0-01 | 默认 config 可加载 | 仓库默认 `bundle_dir: null` 被 schema 拒绝 | L2-01 config/repo |
| P0-02 | CLI command 开关透传 | `load_deploy_config(path)` 不接收 `command_output_enabled` | L2-01 public loader |
| P0-03 | canonical policy 启动资源 | 没有 `PolicyInputSpec`、`ActRuntimeResources`、`load_act_runtime_resources(config)` production public API；L2-01 旧设计又排除 policy load，而已确认的 L2-03 新边界要求它只接收 L2-01 已加载资源，当前存在 owner 断口 | 以已确认 L2-03 同步 service 边界为准，先回写 L2-01 边界并由其 repo 按 `08_repo层设计.md §2` 实现唯一 startup resource factory；L2-06 UI 只调用，不代偿加载 |
| P0-04 | config/bundle/policy 交叉校验 | state/action/chunk/image/normalizer 未形成统一启动 Gate；L2-03 重复派生 private input spec | L2-01 aggregate 唯一派生 spec；L2-02/03 消费同一对象；L2-06 B12 preflight |
| P0-05 | typed observation 装配与 fail-fast | adapter 要 Dict/images map，真实配置是 dataclass/flat topic；`create_subscriptions()` 吞配置/代码异常并一律置 env blocked | L2-02 public factory/adapter；只把 ROS package/graph 缺失归环境，其余异常必须向 A5 传播并中止原子启动 |
| P0-06 | camera contract | 缺 `topics.observation.images: logical policy camera key → ROS topic`，且没有与 canonical PolicyInputSpec 等值校验 | L2-01 schema + L2-02 factory + B12 |
| P0-07 | image/snapshot contract | L2-01 与 service 各有一套不兼容 `ImageConfig`；L2-02 HWC/无 [0,1]，L2-03 严格 CHW；snapshot shallow-copy并共享可写 ndarray | L2-02 public factory 只消费 L2-01 config + PolicyInputSpec，产出 owned CHW float32 [0,1] images/state/encoded copies；L2-03 只读；真实 pipeline/isolation test |
| P0-08 | gripper wire contract | subscription 用 Pose，handler 对 `msg.position`（Point）执行 `float(...)`，当前矛盾确定性 FAIL | L2-02 UI adapter 先消除内部矛盾；真实 message type/单位仍需 topology 确认，不能拿未知外部事实掩盖现有 FAIL |
| P0-09 | freshness clock | snapshot 文档称 monotonic，源码写 wall clock；没有独立 observation max age | L2-01 config + L2-02 type/runtime |
| P0-10 | L2-05 非法输入与错误追因 | `action_publish.py` 使用不存在的 `type(...).__r`；多个 REJECTED/FAILED/PARTIAL 未保留失败 stage/topic/reason | L2-05 修复稳定异常和 publish provenance；L2-06 metrics 另行保留原始 safety/fallback/publish stage，不能相互替代 |

## 9. 外部 BLOCKED 条件

只有以下外部条件可标 `BLOCKED`：ROS graph/消息包不可用、真实 bundle/GPU 不可用、permit/deadman/E-stop/driver-ready 来源未接入、硬件 stop API 未定义、操作者未授权。它们不得掩盖上节的代码级 FAIL。

## 10. 完成判据

1. P0-01～P0-10 的对应自动 Gate 无 FAIL。
2. worker 慢推理不阻塞 tick；异常 result 可恢复；shutdown 有界退出。
3. active/pending、prefetch、horizon、continue-old、age 和乱序规则均有确定性 fake-clock 测试。
4. 真实 `SafetyGuard -> ActionPublishRequest -> ActionPublisher` 链覆盖 PASS/ADJUSTED/REJECTED 和六种 publish outcome。
5. `PARTIAL/FAILED` 后没有任何后续 command 调用。
6. dry-run 中 policy/status 可观察而四路 command 始终为 0；L2-06 runtime reason 可从 `/act/metrics` 读取。
7. shutdown 与 tick 串行；顺序为 stopping/cancel timer → worker stop-event → close/清 request queue → bounded join → close result queue。join timeout 必须是 `SHUTDOWN_TIMEOUT` + Gate FAIL，不能写 `STOPPED`。
8. 全量源码测试、L2-06 Gate 和设计包 validator 全部无 FAIL。

## 11. 仍需用户或外部系统确认

- 真实 `CommandPermitSource` 的 gate/deadman/E-stop/driver-ready topic 或 driver API。
- `safe_stop` 是否需要主动硬件 stop；如需要，必须新增明确 driver port，不能用全零 16D action 代替。
- gripper 的真实 ROS message type、单位和 topic。

这些问题不阻塞纯 local mock runtime 的设计理解，但阻塞端到端 L3、shadow-run 和真机结论。
