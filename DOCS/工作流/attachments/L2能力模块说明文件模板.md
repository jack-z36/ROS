# L2 能力模块说明模板系统

本文件是 L2 模板系统入口，不再是唯一的大而全模板。生成 L2 能力模块说明时，必须先判断功能类别，再拼装对应模板组件。

## 模板拼装方式

```text
L2 文件 =
L2_common_header.md
+
一个或多个 L2 类别主体模板
+
L2_common_footer.md
```

模板组件目录：

```text
DOCS/工作流/attachments/templates/
```

## 四类 L2 模板

| 模块类别 | 本质问题 | 适合任务 | 主体模板 |
|---|---|---|---|
| 数据定义类 | 数据长什么样 | `RunContext`、`SceneResult`、schema、枚举、配置对象 | `templates/L2_data_definition.md` |
| 数据读写类 | 数据从哪里来、写到哪里 | run 目录、配置快照、日志、manifest、MCAP/JSON/YAML/Parquet 读写 | `templates/L2_data_io.md` |
| 数据计算类 | 输入如何变成新结果 | 配置校验、输入检查、统计、转换、异常检测、mask 生成 | `templates/L2_data_compute.md` |
| 流程编排类 | 谁先做、谁后做、失败怎么办 | `SceneRunner`、`PipelineRunner`、fake pipeline、入口调度 | `templates/L2_orchestration.md` |

## 通用字段

所有 L2 都必须包含：

1. 能力名称
2. 所属 L1
3. 模块类别
4. 一句话目标
5. 能力角色
6. 上游关系
7. 下游关系
8. 上游接口对齐检查
9. 职责边界
10. 完成标准
11. 可拆分 L3 清单
12. 未知问题

这些字段由以下组件承载：

- `templates/L2_common_header.md`
- `templates/L2_common_footer.md`

## 类别选择规则

### 数据定义类

选择信号：

- 目标是定义对象、枚举、schema、字段或配置结构。
- 主要问题是字段含义、类型、合法值、默认值和谁会使用它。

不重点写：

- 复杂处理流程
- 文件读写细节
- 调度顺序
- 算法步骤

### 数据读写类

选择信号：

- 目标是读取、写入、创建、保存或加载文件。
- 主要问题是路径、格式、覆盖策略、幂等性和失败处理。

不重点写：

- 复杂业务算法
- 字段推导逻辑
- 完整 pipeline 调度

### 数据计算类

选择信号：

- 目标是检查、计算、转换、统计或判断。
- 主要问题是输入规则、计算规则、异常表达和下游影响。

不重点写：

- 文件组织结构
- UI 交互
- 完整 pipeline 调度

### 流程编排类

选择信号：

- 目标是调用多个模块并控制顺序。
- 主要问题是依赖关系、失败策略、状态流转、停止或恢复。

不重点写：

- 底层算法细节
- 具体字段计算
- 文件格式细节

## 复合模块处理

如果一个 L2 同时跨两类，允许拼接多个类别主体模板，但必须遵守：

1. 先确认主类别。
2. 只有确实需要时才追加第二个类别模板。
3. 不得把三个以上类别混入同一个 L2；如果需要三类以上，优先拆成多个 L2。

常见复合例子：

| 模块 | 推荐模板 |
|---|---|
| Manifest 与错误摘要模块 | 数据读写类 + 数据定义类 |
| Runtime smoke test 模块 | 流程编排类 + 数据计算类 |

## Runtime MVP 模块模板映射

| 模块 | 推荐模板 |
|---|---|
| Runtime 运行上下文定义 | 数据定义类 |
| Run 目录管理模块 | 数据读写类 |
| 配置加载与配置快照模块 | 数据读写类 |
| 配置预检查模块 | 数据计算类 |
| 输入产物预检查模块 | 数据计算类 |
| 场景注册与 Service 调度模块 | 流程编排类 |
| Fake Service 模块 | 数据计算类 |
| 结构化日志模块 | 数据读写类 |
| Manifest 与错误摘要模块 | 数据读写类 + 数据定义类 |
| Runtime smoke test 模块 | 流程编排类 + 数据计算类 |

## 使用流程

1. 先按阶段二开发范式和 `L2能力模块与数据定义约束.md` 完成意图澄清。
2. 判断 L2 主类别。
3. 读取 `templates/L2_common_header.md`。
4. 读取对应类别主体模板。
5. 如确实需要，读取第二个类别主体模板。
6. 读取 `templates/L2_common_footer.md`。
7. 拼装并填写正式 L2 能力模块说明。

## 合格 L2 文件判断

写完后必须能回答：

1. 这个能力属于哪类模块？
2. 它在 pipeline 哪一段？
3. 它吃什么？
4. 它产出什么？
5. 它不负责什么？
6. 它的类别专用问题是否被回答？
7. 它能拆成哪些 L3 小任务？
8. 未知问题是否显式记录？
