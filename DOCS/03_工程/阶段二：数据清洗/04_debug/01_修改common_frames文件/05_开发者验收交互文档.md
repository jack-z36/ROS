# 05 开发者验收交互文档

## 1. 文档目标

本文描述 common_frames 修复完成后，用户通过开发者入口做最终人工验收时，终端应该展示哪些交互画面、应该优先点击什么、失败后如何进入单项 debug、每一步应该输出什么文件，以及什么现象代表功能完善。

本文只描述验收交互，不实现菜单代码，不修改源码、配置、L2 数据定义或现有功能描述文档。

## 2. 验收入口

最终验收使用阶段二开发者引导入口：

```text
./start_data_clean.sh --dev
```

如果口头简写为 `./start_data_clean.sh`，在本文语境中仍指进入开发者验收模式的 `--dev` 入口。`--dev` 不直接执行正式生产流程，只进入开发调试和人工验收菜单。

启动后应看到：

```text
开发者引导界面
  1. 场景一：提取夹爪开合以及位姿转换
  2. 场景二：硬件数据可靠性验证
  3. 场景三：MCAP 多 topic 时间轴对齐
  4. 场景四：构建标准 canonical dataset
  5. 场景五：模型训练格式导出器
  0. 退出

请选择要检验的场景：
```

本次 common_frames 修复的最终验收只覆盖：

- 场景一：raw MCAP 到 cleaned MCAP。
- 场景二：cleaned MCAP 到 MCAP_A。

## 3. 核心验收策略

每个场景最优先测试 `0. 全流程运行测试`。

只有 `0. 全流程运行测试` 失败时，才进入该场景的单项功能菜单做 debug。单项功能不是默认验收顺序，而是失败定位工具。

推荐顺序：

```text
1. 场景一 -> 0 全流程运行测试
2. 如果失败，再运行场景一 1/2/3/4 定位问题
3. 场景二 -> 0 全流程运行测试
4. 如果失败，再运行场景二 1/2/3/4/5 定位问题
```

如果场景一 `0` 成功，说明场景一主链路已通过；不需要再逐项运行 `1` 到 `4`。如果场景二 `0` 成功，说明截止到 MCAP_A 的主链路已通过；不需要再逐项运行 `1` 到 `5`。

## 4. 文件地址规范

本文所有输出地址必须遵守阶段二文件存放规范。

真实数据产物：

```text
raw MCAP:
  asset/阶段二：数据清洗/dev/mcap_raw/<sample>.mcap

场景一 cleaned MCAP:
  asset/阶段二：数据清洗/dev/mcap_cleaned/<sample>.mcap

场景二 MCAP_A:
  asset/阶段二：数据清洗/dev/mcap_validated/<sample>_mcap_a.mcap
```

运行记录和调试产物：

```text
run_dir:
  src/data_clean/runs/{run_id}/

run_log:
  src/data_clean/runs/{run_id}/run_log.json

config_snapshot:
  src/data_clean/runs/{run_id}/config_snapshot.yaml

调试摘要、检查结果、diff summary、sidecar:
  src/data_clean/runs/{run_id}/outputs/
```

关键边界：

- 真实 MCAP 数据产物不得写入 `src/data_clean/runs/{run_id}/outputs/`。
- `outputs/` 只放调试摘要、检查结果、diff summary、索引或 sidecar。
- 原始 MCAP 只读，不得覆盖 `asset/阶段二：数据清洗/dev/mcap_raw/` 中的文件。
- 调试运行不得污染正式 canonical dataset 或 production exports。

## 5. 全流程进度展示要求

场景一和场景二的 `0. 全流程运行测试` 都必须显示进度。

全流程启动前必须显示：

```text
输入文件:
  <input_path>

输出文件:
  <output_path>

运行目录:
  src/data_clean/runs/{run_id}/

配置快照:
  src/data_clean/runs/{run_id}/config_snapshot.yaml
```

全流程执行中必须显示：

```text
[当前文件/总文件数] <input_file>
[当前步骤/总步骤] <步骤名称> ... RUNNING
[当前步骤/总步骤] <步骤名称> ... PASS/FAIL/SKIPPED, 耗时 <duration>
```

失败时必须显示：

```text
失败步骤:
  <step_name>

错误摘要:
  <error_summary>

建议下一步:
  返回当前场景菜单，选择 <编号> <功能名> 做单项 debug

运行日志:
  src/data_clean/runs/{run_id}/run_log.json
```

成功时必须显示输入输出文件地址和最终结论。

## 6. 场景一验收画面

选择一级菜单 `1` 后，应看到：

```text
场景一功能检验菜单
  0. 全流程运行测试
  1. 自动检验配置文件是否有效？（包含夹爪开合以及位姿转换）
  2. 自动生成夹爪开合配置文件运行测试
  3. 夹爪开合提取运行测试
  4. 位姿转换运行测试

请选择功能：
```

### 6.1 场景一 0：全流程运行测试

这是场景一最优先的验收入口。

进入后应看到：

```text
本功能目标:
  按场景一主链路跑通 raw MCAP 到 cleaned MCAP 的最小真实样本闭环。

执行链路:
  检查配置
  -> 读取真实小样本 raw MCAP
  -> 生成或读取夹爪开合配置
  -> 提取夹爪开合
  -> 执行位姿转换
  -> 写出 cleaned MCAP
  -> 写出运行日志和摘要

默认输入:
  asset/阶段二：数据清洗/dev/mcap_raw/<sample>.mcap

默认输出:
  asset/阶段二：数据清洗/dev/mcap_cleaned/<sample>.mcap

请选择:
  回车使用默认真实小样本
  输入 raw MCAP 路径临时覆盖
  输入 q 返回
```

执行中应显示：

```text
[1/1] 输入文件: asset/阶段二：数据清洗/dev/mcap_raw/<sample>.mcap
输出文件: asset/阶段二：数据清洗/dev/mcap_cleaned/<sample>.mcap
run_dir: src/data_clean/runs/{run_id}/

[1/5] 检查配置 ... PASS, 耗时 <duration>
[2/5] 夹爪开合配置准备 ... PASS, 耗时 <duration>
[3/5] 夹爪开合提取 ... PASS, 耗时 <duration>
[4/5] 位姿转换 ... PASS, 耗时 <duration>
[5/5] 写出 cleaned MCAP ... PASS, 耗时 <duration>
```

执行后应输出：

```text
[PASS/FAIL] 场景一全流程运行测试

输入:
  raw_mcap: asset/阶段二：数据清洗/dev/mcap_raw/<sample>.mcap
  config: config/data_clean/<config>.yaml

输出:
  cleaned_mcap: asset/阶段二：数据清洗/dev/mcap_cleaned/<sample>.mcap
  run_dir: src/data_clean/runs/{run_id}/
  run_log: src/data_clean/runs/{run_id}/run_log.json
  config_snapshot: src/data_clean/runs/{run_id}/config_snapshot.yaml
  summary: src/data_clean/runs/{run_id}/outputs/scene1_smoke_summary.json

下游提示:
  该 cleaned MCAP 可作为场景二默认输入候选。
```

代表功能完善的现象：

- 场景一所有关键步骤均为 PASS。
- cleaned MCAP 文件存在且非空。
- cleaned MCAP 位于 `asset/阶段二：数据清洗/dev/mcap_cleaned/`。
- cleaned MCAP 中包含夹爪宽度和左右 arm-base TCP pose 主位姿产物。
- 运行日志能追溯输入 raw MCAP、配置文件、输出 cleaned MCAP 和关键步骤状态。

如果失败：

- 配置检查失败：选择场景一 `1`。
- 夹爪配置准备失败：选择场景一 `2`。
- 夹爪开合提取失败：选择场景一 `3`。
- 位姿转换失败：选择场景一 `4`。

### 6.2 场景一 1：自动检验配置文件是否有效

本项只在场景一 `0` 的配置检查失败时优先使用。

进入后应看到：

```text
本功能目标:
  自动检查场景一所需配置是否有效，包含夹爪开合配置和位姿转换配置。

默认读取:
  config/data_clean/<config>.yaml

系统检查:
  - 夹爪开合配置字段是否完整
  - 夹爪 marker、单位、阈值和输出 topic 是否有效
  - 位姿转换所需输入是否完整
  - left/right 工作坐标系是否分别绑定到 left_arm_base/right_arm_base
  - 不再要求 FrameAlignmentConfig/common_anchor 作为主链路配置

请选择:
  回车使用默认配置
  输入配置文件路径临时覆盖
  输入 q 返回
```

执行后应输出：

```text
[PASS/FAIL] 场景一配置文件自动检验

测试产物:
  src/data_clean/runs/{run_id}/outputs/config_check_summary.json

运行记录:
  src/data_clean/runs/{run_id}/run_log.json
  src/data_clean/runs/{run_id}/config_snapshot.yaml
```

代表功能完善的现象：

- 夹爪开合配置字段完整。
- 位姿转换配置字段完整。
- 左手工作坐标系绑定到 `left_arm_base`。
- 右手工作坐标系绑定到 `right_arm_base`。
- 检查摘要中明确 `FrameAlignmentConfig/common_anchor` 不是当前主链路必需配置。
- `config_check_summary.json` 和 `run_log.json` 均存在且可解析。

这是场景二最优先的验收入口。

```text
默认输出:
```

```text
[1/1] 输入文件: asset/阶段二：数据清洗/dev/mcap_cleaned/<sample>.mcap

```

执行后应输出：

```text
[PASS/FAIL] 场景二全流程运行测试

输入:
  cleaned_mcap: asset/阶段二：数据清洗/dev/mcap_cleaned/<sample>.mcap

  mcap_a: asset/阶段二：数据清洗/dev/mcap_validated/<sample>_mcap_a.mcap

  config_snapshot: src/data_clean/runs/{run_id}/config_snapshot.yaml
```

代表功能完善的现象：

- 场景二 `1` 到 `5` 的主链路全部成功。
- MCAP_A 文件存在且非空。
- MCAP_A 位于 `asset/阶段二：数据清洗/dev/mcap_validated/`。
- MCAP_A 可追溯到场景一 cleaned MCAP。
- 位姿链路保持左右 arm-base TCP pose 语义。
- 不再依赖 IK / MCAP_B / 关节限制检查。

如果失败：

- 异常检测失败：选择场景二 `1`。
- 数据补全失败：选择场景二 `2`。
- 位姿滤波失败：选择场景二 `3`。
- 触觉滤波失败：选择场景二 `4`。
- MCAP_A 写出失败：选择场景二 `5`。
