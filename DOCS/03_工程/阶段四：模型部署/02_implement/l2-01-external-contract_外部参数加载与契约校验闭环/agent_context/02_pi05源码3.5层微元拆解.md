> - **Pi0.5 源码是只读参考**。本文不继承 Pi0.5 的任务边界、topic 命名空间或旧 L2 卡片，只提取结构启发。

## 0. 参考源码根与范围

Pi0.5 参考源码根（只读）：

```text
DOCS/03_工程/阶段四：模型部署/pi05_old/pi05_test/pi05/
├── deploy/
│   ├── config/deploy.yaml                          # 运行配置数据
│   └── src/pi05/deploy/
│       ├── config/schema.py                        # DeployConfig + 子配置 + 校验器（L2-01 主参考）
│       ├── models/policy_loader.py                 # bundle 打开/校验/加载（bundle contract 参考）
│       └── ros_nodes/                              # 调用 load_deploy_config 的节点（非 L2-01 范围）

    ├── runtime/bundle.py                           # bundle 文件名常量 + manifest/normalizer loader
```

**范围匹配结论**：Pi0.5 中实现"外部参数加载与契约校验"职责的源码集中在 `deploy/src/pi05/deploy/config/schema.py`（配置加载主轴）+ `common/src/pi05/common/runtime/bundle.py`（bundle 契约）+ `common/src/pi05/common/robot/action_spec.py` 等（数据规格）。`policy_loader.py` 的 `_validate_bundle` 段做 bundle 存在性校验，但完整 policy 加载属 L2-03 范围，本文只取其契约校验段。

## 2. class 封装盘点表

判断口径：有状态/缓存/队列/metrics/buffer→class；有线程/timer/起停生命周期→class；ROS node 生命周期→ROS node class；纯输入→输出→函数；"看起来 OOP"→不做成 class。

| class | Pi0.5 路径 | 封装的微元 | 内部状态 | 生命周期/并发 | 为何是 class | ACT 处理建议 |
|---|---|---|---|---|---|---|
| `DeployConfig` + 子 dataclass 群 | `deploy/config/schema.py:239` | 数据（配置对象树）+ 计算（`__post_init__` 校验） | 不可变（frozen） | 无生命周期，构造后只读 | 聚合多子配置 + 携带校验不变式 | **结构复用**：ACT 自有 `DeployConfig`，frozen + `__post_init__`，去 bridge/mux。 |

## 4. 关键差异与风险（写入 L2 设计需关注）

1. **维度差异（已解决）**：Pi0.5 是 14D action / 26D state；ACT 是 **16D/16D**。ACT 的 16D 段序源自阶段二数据清洗交付说明：
   - 16D state（去触觉）：`left_tcp_pose(7) + right_tcp_pose(7) + left_gripper_width(1) + right_gripper_width(1)`。
   - 16D action：`left_tcp_pose_t_plus_1(7) + left_gripper_width_t_plus_1(1) + right_tcp_pose_t_plus_1(7) + right_gripper_width_t_plus_1(1)`。
   - 关键语义差：Pi0.5 action 是关节空间（6 臂关节 + 1 夹爪 ×2），ACT action 是 **TCP 笛卡尔绝对位姿**（xyz+quaternion+夹爪宽度）。Pi0.5 state 含 EE pos/rpy，ACT state 是 **TCP pose**（xyz+quaternion）。这影响 safety 检查方式（关节 delta vs TCP 步长）。
2. **bundle 校验缺口**：Pi0.5 `_validate_bundle` 只检查文件存在，不校验 manifest 元数据正确性、不校验 normalizer dim 与契约一致、不交叉校验三处 dim。ACT 应补强（这是 L2-01 的增量价值）。
3. **frozen 覆写反模式**：Pi0.5 在 `_load_bundle_experiment_config` 用 `object.__setattr__` 覆写已校验的 frozen 配置——这是妥协。ACT 应避免，改为读取后构造新对象，保持"校验后即不可变"契约。
4. **safety 字段缺口**：Pi0.5 无 TCP 步长限制、无 quaternion 检查（全关节空间）。ACT 需新建（TCP 步长 + quaternion norm 检查），Pi0.5 无参考；本 L2 占位，L2-05 填具体值。
5. **三处 dim 一致性**：`RuntimeConfig`（deploy.yaml）、`experiment_config.yaml`（bundle 内）、`manifest.json` 三处都有 dim，Pi0.5 不强制一致（加载时覆写）。ACT 契约校验应强制三处一致（且==16），不一致即判 contract 非法。
6. **命名空间**：Pi0.5 `/pi05_vla`；ACT `/act`。所有 topic 默认名需重新生成。
7. **normalizer dim**：Pi0.5 normalizer 按 14D/26D 训练；ACT normalizer 应按 16D/16D。契约校验必须确认 normalizer dim==16。
