# 双机协作写入边界

本文约束阶段二在 Win 主机和 Ubuntu 主机之间的职责与写入范围，目标是减少 Git 同步冲突。

阶段二默认采用 L1 feature 分支接力流程，详见 `DOCS/阶段二：数据清洗/约束文件/功能分支接力流程.md`。`main` 只保存稳定完成结果，不作为日常工作台。

## 一、机器职责

### Win 主机

Win 主机负责规划、拆解和文档生成：

- 阶段二架构讨论与路线图维护。
- L1 / L2 / L3 拆解。
- L2 能力模块说明与数据定义文档。
- L3 微元任务文件生成与整理。
- 必要的 Win 端规划记录和总执行日志。
- 创建、推进并最终合并阶段二 L1 feature 分支。

### Ubuntu 主机

Ubuntu 主机负责代码执行：

- 读取并执行单个 L3 微元任务。
- 修改代码、测试和必要的代码架构说明。
- 运行验收命令。
- 更新当前 L3 文件自身。
- 将完成的 L3 从 `03_tasks/task/active/<功能组>/` 移动到 `03_tasks/task/completed/<L1归档目录>/<功能组>/`。
- 如果原 `03_tasks/task/active/<功能组>/` 已经为空，删除该空目录。
- 在当前 L3 所属 L1 feature 分支上提交并推送实现结果。

## 二、Win 主机允许写入

Win 主机可以写入：

- `DOCS/工作流/`
- `DOCS/阶段二：数据清洗/00_架构与路线图/`
- `DOCS/阶段二：数据清洗/01_runtime_mvp/`
- `DOCS/阶段二：数据清洗/02_service/`
- `DOCS/阶段二：数据清洗/03_tasks/task/active/<功能组>/`
- `DOCS/阶段二：数据清洗/约束文件/`
- `DOCS/阶段二：数据清洗/执行记录/`
- `DOCS/总执行日志.md`

Win 主机不负责执行 L3 代码任务，不应把 L3 移动到 `task/completed/<L1归档目录>/<功能组>/`，除非用户明确要求整理历史任务状态。

Win 主机合并阶段二成果时，必须先拉取对应 L1 feature 分支最新内容并完成验收，再从 `main` 执行 `merge --no-ff`。不得在 `main` 上直接继续规划或开发阶段二内容。

## 三、Ubuntu 主机允许写入

Ubuntu 主机执行 L3 时，只允许写入：

- 当前 L3 文件自身。
- 当前 L3 明确允许修改的源码、测试、代码架构说明。
- `DOCS/阶段二：数据清洗/03_tasks/task/completed/<L1归档目录>/<功能组>/`，仅用于归档当前已完成 L3。
- 当前 L3 原所在的 `DOCS/阶段二：数据清洗/03_tasks/task/active/<功能组>/` 空目录，仅用于在任务清空后删除。

Ubuntu 主机完成 L3 后，执行摘要必须追加到当前 L3 文件末尾，不再额外创建集中执行记录。

Ubuntu 主机执行 L3 前必须确认当前分支是该 L3 所属 L1 的 feature 分支：

- Runtime MVP：`runtime-mvp`
- Service：`feature/stage2-service`

如果当前分支不是对应 feature 分支，必须先停止并提示切换，不得在 `main` 或其他分支上继续执行。

## 四、Ubuntu 主机禁止写入

Ubuntu 主机执行 L3 时，禁止写入：

- `DOCS/总执行日志.md`
- `DOCS/阶段二：数据清洗/执行记录/`
- `DOCS/阶段二：数据清洗/当前进度.md`
- `DOCS/阶段二：数据清洗/阶段产出.md`
- `DOCS/阶段二：数据清洗/**/当前进度.md`
- `DOCS/阶段二：数据清洗/**/执行记录.md`
- 与当前 L3 无关的 L2/L3 规划文档。
- `main` 分支上的任何阶段二日常开发提交或推送。

如果 Ubuntu 执行端发现需要更新这些共享文档，只能在当前 L3 的执行摘要中写明“建议 Win 端同步整理”，由 Win 主机在拉取代码后统一处理。

## 五、完成交接格式

Ubuntu 主机完成 L3 后，当前 L3 文件末尾的执行摘要至少包含：

1. 实际修改了哪些文件。
2. TDD red / green / refactor 如何执行。
3. 运行了哪些验收命令，命令必须使用 `python3`。
4. 哪些成功标准已勾选，哪些未勾选以及原因。
5. 当前没做什么。
6. 建议 Win 端后续同步整理什么。

Win 主机后续需要阶段汇总时，应批量读取 `03_tasks/task/completed/<L1归档目录>/<功能组>/` 下的 L3 执行摘要，再统一更新阶段文档或规划记录。
