## 已发现并处理的问题

- 直接运行 `python3 src/data_clean/core/mcap_clean_batch.py` 会找不到 `core` 包，现通过 `start_data_clean.sh` 设置 `PYTHONPATH`。
- 当前系统 Python 环境缺少可直接使用的 `mcap`、`mcap_ros2`、`zstandard`，已建立独立 conda 环境。
- Octopus 写入的 ROS2 schema 存在缩进，`mcap_ros2` 动态解析前需要规范化 schema。
- 系统自带 OpenCV ArUco 检测曾出现 segfault，conda 环境中使用可用的 `opencv-contrib-python-headless`。
- `file_glob` 已从单个测试文件改为 `*.mcap`，实际清洗数量由交互式 launcher 控制。
- 已将配置/标定向导升级为浏览器版实时 GoPro 标定中心：
  - 不再要求用户选择夹爪完全闭合/完全张开的 MCAP。
  - 自动检查并在必要时启动左右 GoPro-only 节点，只订阅 `/gopro_left/image_raw` 和 `/gopro_right/image_raw`。
  - 由于 conda 环境中的 OpenCV 是 `opencv-contrib-python-headless`，`cv2.getBuildInformation()` 显示 `GUI: NONE`，标定中心不再使用 `cv2.imshow()`，而是通过 `http://127.0.0.1:<port>` 浏览器页面显示画面。
  - 夹爪标定按左闭合、左张开、右闭合、右张开的顺序实时采样，每步 2 秒，要求至少 30 帧、成对 marker 检测率 >= 90%、距离波动 <= 3 px。
  - 浏览器不可用时，夹爪标定可在终端输入 `g` 进入数字反馈兜底；TCP 点选必须使用浏览器页面。
  - TCP 标定作为浏览器独立页面，通过 GoPro 截图点选四个点：Baton Mini 参考点、夹爪 TCP 点、比例尺点 A、比例尺点 B，再按毫米比例尺计算 `tcp_offset.x/z`。
  - TCP 写入前会从最近 MCAP 抽样判断每个 pose stream 单位是 `m` 还是 `mm`，再将网页测得的毫米偏移转换为该 stream 的配置单位。
  - 输出新配置 `config/data_clean_calibrated.yaml`，并在覆盖前自动备份旧配置。
  - GoPro-only 子进程日志写入 `/home/hit/ROS/log/data_clean_gopro_only_*.log`，不刷标定终端。
- 清洗配置优先级为：命令行 `--config` 或 `DATA_CLEAN_CONFIG` > `config/data_clean_calibrated.yaml` > `config/data_clean_smoke_test.yaml`。

## 已验证结果

已验证：

- `./start_data_clean.sh --dry-run --latest 5` 可预览最近 5 个文件。
- `./start_data_clean.sh --latest 1` 可成功清洗最近 1 个文件。
- `DATA_CLEAN_RAW_JSON=1 ./start_data_clean.sh --latest 1` 可输出原始 JSON。
- `./start_data_clean.sh --dry-run --all --workers auto` 可选择全部 49 个文件，并将并行数解析为 6。
- 配置错误时会显示清晰的 topic 检查失败原因。
- `./start_data_clean.sh --dry-run --latest 1` 会显示当前配置是否已标定。
- 实时标定中心入口、配置状态解析和 GoPro-only 启动脚本已通过静态/入口验证。

## 尚未完全确认

- `transform` 中的 base position、base orientation、tcp offset 目前仍是测试值。
- ArUco 的 `marker_min`、`marker_max` 仍需用实时 GoPro 标定中心在真实闭合/张开动作下确认。
- `config/data_clean_calibrated.yaml` 尚未由真实标定数据正式生成。
- 已验证单文件真实清洗，全部 49 个文件的完整批量清洗尚未作为最终验收完成。
